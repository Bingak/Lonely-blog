1. 本节目标与前置知识

目标：

  1. 说清 DS1302 的三线协议：RST / SCLK / IO 各自管什么，为什么一根 IO 能双向传数据，为什么「RST 拉高 → 发命令 → 读/写 → RST 拉低」这四步一步都不能少。

2. 场景引入：从「会点灯的板子」到「一台仪器」

回头看你的 51 学习轨迹，其实是一条很清晰的线。

最开始，你让一个引脚变低，一盏灯亮了。那是输出——你告诉世界一个比特，世界用光回答你。然后你学会数码管：8 个段脚拼出一个数字，你开始表达信息，虽然只能表达 0~9 和 A~F。再后来是按键：你第一次让板子听你说话，虽然它只会分辨「按下」和「松开」。定时器教会你时间，串口教会你远距离说话，EEPROM 教会你记住。

但这些东西加起来，仍然只是一块「会按程序做动作」的板子。它不知道现在几点，不知道屋子里多热，也没法把「此刻」保存下来再拿出来给你看。

这一篇要做的三件事，恰好补上这三块：

  • 知道几点——DS1302 是一颗自带电池的日历芯片，它替你数秒、数分、数年月日星期，掉电了还在数。你的单片机不用再靠 delay 去「估」时间。
  • 会显示——LCD1602 是一块能显示 32 个字符的屏。从此你的输出不再是「亮/灭」「0~9」，而是一整行「2025-10-25 13:14」。
  • 能感知——AD 把电压变成一个数，DS18B20 把温度变成一个数。板子第一次有了「外界」这个概念。

把这三样装进一个工程，再加一个状态机，你就得到了一台仪器：它有自己的时间、自己的显示、自己的传感器、自己的输入（按键 + 串口），而且能在一个上电周期里从头到尾地「运行」，而不是「跑一遍就完」。

3. 核心概念一：DS1302——三根线，把时间问出来

3.1 为什么时间要交给一颗专门的芯片

51 内部有定时器。你已经会用定时器数 1ms、数 50ms，攒够 20 次就是 1 秒。那为什么还要外挂一颗 DS1302？

三个理由，一个比一个致命：

  1. 掉电就归零。 定时器靠电源活着，一断电，你数的「13:14:30」立刻蒸发。而 DS1302 有一颗纽扣电池（或超级电容）接在备用电源脚上，主电源断了它就切到电池，只消耗微安级电流，继续数。
  2. 长时间累积误差。 12MHz 晶振本身有几十 ppm 的偏差，再叠加中断响应延迟，一天差几秒很正常。DS1302 用专门的 32.768kHz 晶振（2^15 Hz，正好被 15 级二分频得到 1Hz），精度和稳定性都不是「定时器 + 软件计数」能比的。
  3. 它替你算好了年月日星期。 闰年、大小月、星期几，这些逻辑如果自己写，是一堆 if；DS1302 内部有寄存器直接存着，进位它自己处理。

所以 DS1302 的定位是：一个独立的、带电池的、会用 BCD 码说话的日历。你的单片机只需要在要用的时候「问它一句」。

3.2 三根线：RST、SCLK、IO

DS1302 和单片机之间只有三根信号线（电源和地另算）：

线名 常见叫法 方向 干什么
RST CE、复位、片选 单片机 → 芯片 拉高表示「我要开始一帧通信」，拉低表示「这一帧结束」。它是整帧的开关，也是同步的起点
SCLK 串行时钟 单片机 → 芯片 每一个上升沿，双方交换一个比特。时钟永远由主机给
IO 数据线 双向 写的时候单片机驱动它，读的时候芯片驱动它。同一根线，分时复用

注意 IO 的「双向」。这不是什么高级技术，就是一个很朴素的约定：谁在说话，谁驱动线；不说话的那一方必须松手（高阻）。如果两边同时驱动，一个想输出 1、一个想输出 0，那就是电气上的「打架」，轻则读数乱，重则烧引脚。

所以一条完整的读操作，方向要切换两次：

RST  ──┐                    ┌──────────────────────────┐
       └────────────────────┘                          └────
SCLK     _┌─┐_┌─┐_ ... _┌─┐_  (8 个命令位)  _┌─┐_ ... _┌─┐_
IO    ────< 命令字节，单片机驱动 >────< 数据字节，芯片驱动 >───
                (方向：MCU→芯片)            (方向：芯片→MCU)

3.3 命令字节：8 个位，各有各的活

每一次通信，单片机发的第一个字节叫命令字节。它的 8 个位是硬性规定的，不是随便定的：

位 含义 说明
bit7 固定为 1 数据手册要求。写 0 芯片不理你
bit6 RAM / CK 0 = 访问时钟寄存器（秒分时日月星期年），1 = 访问那 31 字节 RAM
bit5~1 A4~A0 寄存器地址。注意是 5 位，但实际寄存器只用到低 3 位
bit0 RD/W 1 = 读，0 = 写

于是所有的命令都可以由「寄存器地址」推出来，根本不用背：

你要动的 寄存器地址 写命令 读命令
秒 0x80 0x80 0x81
分 0x82 0x82 0x83
时 0x84 0x84 0x85
日 0x86 0x86 0x87
月 0x88 0x88 0x89
星期 0x8A 0x8A 0x8B
年 0x8C 0x8C 0x8D
写保护 0x8E 0x8E 0x8F

规律：地址都是偶数，读命令就是地址 +1（因为 bit0 从 0 变 1）。所以代码里根本不用写 0x81、0x83，统一写成 (addr & 0xFE) | 0x01，让人一眼看出「这是在拼读命令」。

RAM 的地址从 0xC0 开始，每个字节占一个偶地址（0xC0、0xC2、0xC4……）。命令字节里 bit6 = 1 就是在说「我要去 RAM 那边」。任务 8 的 k1 要把当前时间存起来、k2 再拿出来显示，最省事的做法就是存进这片 RAM——它有备用电池保着，掉电也不丢。

3.4 一帧的四步，和「低位在前」这个坑

一次完整的读写，永远是这四步：

① RST 拉低（先确保总线是干净的）→ SCLK 拉低
② RST 拉高                       ← 从这里开始，每个 SCLK 上升沿算一位
③ 发 8 位命令（低位在前）
④ 发 8 位数据（写）或收 8 位数据（读），也是低位在前
⑤ RST 拉低                       ← 一帧结束，芯片的移位寄存器复位

三个必须记住的细节：

  • 低位在前（LSB first）。 这和 SPI 的「高位在前」正好相反。你要是按 MSB 发，芯片收到的命令字节会整个反过来——0x84 变成 0x21，于是你「写小时」的指令被它理解成「读某个不存在的东西」，读回来全是 0 或 0xFF。这是 DS1302 最常见的第一个 bug。
  • 写的时候，芯片在上升沿采样；读的时候，芯片在下降沿把下一位推上来。 所以主机读数据要在上升沿之后采样，写完/读完一位要把 SCLK 拉低，为下一位做准备。
  • RST 拉低会复位芯片的接口状态机。 如果上一帧因为干扰只发了 5 位就断了，你不拉低 RST，芯片还在等剩下的 3 位，下一帧的命令就会错位。每帧结束必须拉低 RST，这不是礼貌，是清场。

真实 Keil 里，这三根线就是三个 sbit：

/* ===== 真实 Keil C51 写法：本机 GCC 不可编译，仅作对照 ===== */
sbit RST  = P3^5;
sbit SCLK = P3^6;
sbit IO   = P3^4;

void ds1302_write_byte(unsigned char dat)
{
    unsigned char i;
    for (i = 0; i < 8; ++i) {
        IO = dat & 0x01;        /* 先摆好这一位 */
        SCLK = 1;               /* 上升沿：芯片采样 */
        SCLK = 0;
        dat >>= 1;              /* 低位在前 */
    }
}

本机的 GCC 不认识 sbit，所以配套示例把这三根线换成了三个普通函数 wire_rst / wire_sclk / wire_io_write，再配一个「假装自己是 DS1302」的结构体。时序的动作一模一样，只是电平变成了变量。

4. 核心概念二：BCD 码——为什么 0x25 表示 25

4.1 硬件的世界观：一个字节装两位十进制

DS1302 内部是十进制计数器。为了让「读出来直接能看」，它不用二进制存时间，而用 BCD（Binary-Coded Decimal，二-十进制编码）：一个字节的高 4 位存十位，低 4 位存个位。

十进制 二进制存储 BCD 存储 看上去
9 0x09 0x09 一样
10 0x0A 0x10 不一样了
25 0x19 0x25 完全不一样
59 0x3B 0x59 完全不一样

所以当你在调试器里看到秒寄存器是 0x59，那不是 89，是 59 秒；看到 0x25，不是 37，是 25。

这就是那个经典 bug 的来源：你从 DS1302 读回 0x25，直接 printf("%d", 0x25)，屏幕上出现 37；你以为是芯片坏了，其实是自己没解码。更隐蔽的一种：你用 hour = 0x25 去和 24 比较，37 > 24，程序判定「时间非法」，于是时间永远不显示。

4.2 两个方向，四行代码

/* BCD -> 二进制：高四位当十位，低四位当个位 */
static unsigned char bcd2bin(unsigned char bcd)
{
    return (unsigned char)(((bcd >> 4) & 0x0F) * 10u + (bcd & 0x0F));
}

/* 二进制 -> BCD：十位左移到高四位，个位留在低四位 */
static unsigned char bin2bcd(unsigned char bin)
{
    return (unsigned char)(((bin / 10u) << 4) | (bin % 10u));
}

代入验证：bcd2bin(0x25) = 2 * 10 + 5 = 25；bin2bcd(25) = (2 << 4) | 5 = 0x25。这两个函数请默写到不用想。

4.3 掩码：BCD 之外，那些位还兼职干别的

DS1302 的寄存器不是「8 位全给数字」，最高位往往被征用了：

寄存器 有效数据位 高位被谁占了
秒 0x80 bit60（059） bit7 = CH（时钟停止位）
分 0x82 bit6~0 bit7 恒 0
时 0x84 bit5~0（24 小时制） bit7 = 12/24 小时选择，bit6 = AM/PM 或小时的十位
日 0x86 bit5~0 高位保留
月 0x88 bit4~0 高位保留
星期 0x8A bit20（17） 高位保留
年 0x8C bit70（0099） 无

所以读出来必须先掩码，再转 BCD：

sec  = bcd2bin(ds1302_read_reg(0x80) & 0x7F);   /* 去掉 CH */
hour = bcd2bin(ds1302_read_reg(0x84) & 0x3F);   /* 只留 6 位，按 24 小时制解释 */
mon  = bcd2bin(ds1302_read_reg(0x88) & 0x1F);

顺序不能反。 先 bcd2bin 再掩码，等于把 0x80 当成数字算了一遍，结果毫无意义。记住这句话：掩码管「哪些位是数据」，BCD 转换管「这些位怎么读成十进制」，两件事分开做。

4.4 反向也要一样小心

往芯片里写时间时，同样要「先转 BCD，再拼高位」：

/* 写秒：转 BCD，清 CH（bit7 = 0 才起振），其他高位保持 0 */
ds1302_write_reg(0x80, (unsigned char)(bin2bcd(sec) & 0x7F));

如果你写的是 bin2bcd(sec) | 0x80，那就等于每次写时间都把 CH 置 1——晶振停振，时间永远停在那一刻。这个 bug 极其阴险：读回来数字都对，就是不往下走。

5. 核心概念三：写保护、掉电走时与突发模式

5.1 WP：一颗必须认识的「锁」

DS1302 有一个专门的写保护寄存器，地址 0x8E，只有最高位有意义：

  • bit7 = 1：锁上。此后所有对时钟寄存器（0x80~0x8C）的写操作一律无效，读不受影响；
  • bit7 = 0：解锁，可以改时间。

注意三个容易踩的点：

  1. 锁只锁时钟寄存器，不锁 RAM。 你把 WP 置 1 之后往 0xC0 写数据，照样写得进去。任务 8 里「按 k1 保存当前时刻」如果存 RAM，根本不用管 WP。
  2. 控制寄存器自己永远可写。 否则你一旦锁上就再也解不开了。所以写 0x8E 这个动作本身不受 WP 限制。
  3. 上电默认状态不确定。 有的模块出厂就锁着，有的没锁。规范做法是：每次写时间前先写 0x8E, 0x00 解锁，写完立刻写 0x8E, 0x80 上锁。 这两行不是多余的，它们防止你程序跑飞时把时间写乱。
/* 写时间的标准五步，顺序就是纪律 */
ds1302_write_reg(0x8E, 0x00);   /* ① 解锁 */
ds1302_write_reg(0x80, sec_bcd);/* ② 逐个写 */
ds1302_write_reg(0x82, min_bcd);
/* ... */
ds1302_write_reg(0x8E, 0x80);   /* ③ 重新上锁 */

5.2 CH：那个让时间「不走」的位

秒寄存器的 bit7 叫 CH（Clock Halt）。它为 1 时，芯片内部的晶振停振，所有寄存器冻结；为 0 才正常走时。

很多 DS1302 模块（尤其是带电池的新模块）出厂时 CH = 1，目的是「运输途中不耗电」。你第一次上电，读出来时间永远是 00:00:00，改了也不走——十有八九就是没清 CH。

这也是「时间不走」排在第一位的真因，比晶振坏、电池没电常见得多。

5.3 备用电池：掉电之后它靠什么活着

DS1302 有两个电源脚：一个接主电源（板子上的 5V），一个接备用电源（纽扣电池或超级电容）。内部有个比较电路，主电源正常时用主电源、顺便给电池涓流充电（是否充电取决于模块电路，以你的模块原理图为准）；主电源掉下去，立刻切到备用电源，只保留晶振和计数电路工作。

掉电要走时，需要三个条件同时成立：

  1. 备用电源有电（电池装反、没装、没电，都会归零）；
  2. 晶振在振（32.768kHz 晶振 + 两个小电容，虚焊或电容错会停振）；
  3. CH = 0（上一节说过）。

三个条件缺一个，你看到的现象都一样：上电时间回到 00:00:00 或某个固定值。所以排查时不要只怀疑电池，按「电池电压 → 晶振是否起振 → CH 位」的顺序查。

5.4 突发模式：为什么要有「一次搬完」

假设你要读「2025-10-25 13:59:59」这个时刻。按普通方式，你得读 7 次：秒、分、时、日、月、星期、年。每次读都是一帧完整的「RST 高 → 命令 → 数据 → RST 低」。

问题来了：如果你读完秒（0x59），芯片在你读分的那一瞬间进位了，你读到的分就是 0x00，拼出来是「13:00:59」——一个根本不存在的时刻。这种错误概率很低，但一旦发生，显示会闪一下鬼时间，而且极难复现。

突发模式（Burst Mode） 就是为解决这个而生的：一条命令，芯片把 8 个时钟寄存器连续吐出来（或者连续收进去），中途不允许进位插进来，等于给你一个「原子快照」。

模式 命令字节 说明
时钟突发写 0xBE 一次写入秒~年 8 个字节
时钟突发读 0xBF 一次读出秒~年 8 个字节
RAM 突发写 0xFE 一次写完 31 字节 RAM
RAM 突发读 0xFF 一次读完 31 字节 RAM

（这几个字节是「命令字节规则」的直接推论：bit7=1、bit6 选区、地址全 1 表示「突发」、bit0 读写。具体行为以数据手册为准。）

任务 8 只显示时分秒，用不用突发都行；但任务 A 要显示年月日星期时分秒，建议用突发读，一次拿全，省得自己拼出鬼时间。

5.5 把这几节拼起来：一个能跑的 DS1302 模型

下面这个文件把「三线时序 + 命令字节 + BCD + 写保护 + CH + RAM」全部走了一遍。它跑在 PC 上，芯片是一个结构体，但每一次读写都真的经过了「RST 拉高 → 移位 8 位命令 → 移位 8 位数据 → RST 拉低」这条路径——你将来在 Keil 里写的，就是把这些 wire_xxx() 换成 sbit 赋值。

/* 01_ds1302_clock.c —— DS1302 三线读写 + BCD 转换 + 写保护（PC 模拟版）
 * 编译：gcc -Wall -Wextra -std=c99 01_ds1302_clock.c -o 01_ds1302_clock.exe
 *
 * 真实 Keil C51 里，三根线是三个位：
 *     sbit RST  = P3^5;   sbit SCLK = P3^6;   sbit IO = P3^4;
 * 本文件用普通函数 wire_rst / wire_sclk / wire_io_write 代替它们，
 * 但时序顺序一模一样：RST 拉高 -> 发命令字节 -> 读/写数据字节 -> RST 拉低。
 */
#include <stdio.h>

#define REG_NUM 8
#define RAM_NUM 31

/* ============================================================
 * 一、器件模型：用一片数组冒充 DS1302 内部那点寄存器
 * ============================================================ */
typedef struct {
    unsigned char reg[REG_NUM];   /* 0 秒 1 分 2 时 3 日 4 月 5 星期 6 年 7 控制 */
    unsigned char ram[RAM_NUM];   /* 31 字节静态 RAM，掉电由备用电池保住 */

    int wp;                       /* 写保护：1 = 时钟寄存器锁定 */

    int rst;                      /* 三根线的电平 */
    int sclk;
    int io_mcu;                   /* 单片机想往 IO 上送的电平 */
    int io_chip;                  /* 芯片想往 IO 上送的电平 */
    int chip_driving;             /* 1 = 此刻由芯片驱动 IO（读数据阶段） */

    int phase;                    /* 0 收命令  1 收数据  2 发数据 */
    int bit_idx;                  /* 当前字节收到/发出第几位 */
    unsigned char shift;          /* 移位寄存器 */
    unsigned char cmd;            /* 刚收到的命令字节 */
    int is_ram;                   /* 命令字节 bit6：0 时钟，1 RAM */
    int addr;                     /* 命令字节 bit5~1：寄存器地址 */
} ds1302_t;

static ds1302_t chip;

/* ============================================================
 * 二、BCD 码：硬件用十六进制存十进制，人用十进制读
 * ============================================================ */
static unsigned char bcd2bin(unsigned char bcd)
{
    return (unsigned char)(((bcd >> 4) & 0x0F) * 10u + (bcd & 0x0F));
}

static unsigned char bin2bcd(unsigned char bin)
{
    return (unsigned char)(((bin / 10u) << 4) | (bin % 10u));
}

/* ============================================================
 * 三、芯片内部：收到一个完整字节之后做什么
 * ============================================================ */
static unsigned char chip_read(int is_ram, int addr)
{
    if (is_ram) {
        return chip.ram[addr % RAM_NUM];
    }
    return chip.reg[addr % REG_NUM];
}

static void chip_write(int is_ram, int addr, unsigned char val)
{
    if (is_ram) {
        chip.ram[addr % RAM_NUM] = val;      /* 写保护只管时钟寄存器，不管 RAM */
        return;
    }
    if (addr == 7) {                         /* 0x8E 控制寄存器：bit7 就是 WP */
        chip.reg[7] = val;
        chip.wp = (val & 0x80) ? 1 : 0;
        return;
    }
    if (chip.wp) {
        return;                              /* 锁着：时钟寄存器一律写不进去 */
    }
    chip.reg[addr % REG_NUM] = val;
}

/* 每个 SCLK 上升沿，芯片要么采样一位（写），要么推出一位（读） */
static void chip_on_rising_edge(void)
{
    int bit = chip.chip_driving ? chip.io_chip : chip.io_mcu;

    if (chip.phase == 0) {                   /* 收命令字节：低位在前 */
        chip.shift = (unsigned char)((chip.shift >> 1) | (bit << 7));
        if (++chip.bit_idx == 8) {
            chip.cmd  = chip.shift;
            chip.shift = 0;
            chip.bit_idx = 0;
            chip.is_ram = (chip.cmd & 0x40) ? 1 : 0;
            chip.addr   = (chip.cmd >> 1) & 0x1F;
            if (chip.cmd & 0x01) {           /* bit0 = 1：这次是读 */
                chip.phase = 2;
                chip.chip_driving = 1;
                chip.shift = chip_read(chip.is_ram, chip.addr);
            } else {
                chip.phase = 1;
            }
        }
    } else if (chip.phase == 1) {            /* 收数据字节 */
        chip.shift = (unsigned char)((chip.shift >> 1) | (bit << 7));
        if (++chip.bit_idx == 8) {
            chip_write(chip.is_ram, chip.addr, chip.shift);
            chip.shift = 0;
            chip.bit_idx = 0;
            chip.phase = 0;
        }
    } else {                                 /* 发数据字节：低位在前 */
        chip.io_chip = chip.shift & 0x01;
        chip.shift = (unsigned char)(chip.shift >> 1);
        if (++chip.bit_idx == 8) {
            chip.bit_idx = 0;
            chip.phase = 0;      /* 这一位还要保持到下降沿，主机会在上升沿之后采样 */
        }
    }
}

/* ============================================================
 * 四、单片机侧：三根线的动作
 * ============================================================ */
static void wire_rst(int level)
{
    chip.rst = level;
}

static void wire_sclk(int level)
{
    int prev = chip.sclk;
    chip.sclk = level;
    if (prev == 0 && level == 1) {
        if (chip.rst) {
            chip_on_rising_edge();           /* 只有 RST 高时的上升沿才算数 */
        }
    } else if (prev == 1 && level == 0) {
        if (chip.chip_driving && chip.phase == 0) {
            chip.chip_driving = 0;           /* 一帧读完，芯片在下降沿放开 IO */
            chip.io_chip = 0;
        }
    }
}

static void wire_io_write(int level)
{
    if (!chip.chip_driving) {                /* 芯片在驱动时，主机必须"松手" */
        chip.io_mcu = level;
    }
}

static int wire_io_read(void)
{
    return chip.chip_driving ? chip.io_chip : chip.io_mcu;
}

/* 一个字节 8 位，低位在前；读的时候 out 传 0xFF 当占位 */
static unsigned char ds1302_transfer(unsigned char out)
{
    unsigned char in = 0;
    int i;

    for (i = 0; i < 8; ++i) {
        wire_io_write(out & 0x01);
        out = (unsigned char)(out >> 1);
        wire_sclk(1);                        /* 上升沿：芯片采样或输出 */
        in = (unsigned char)(in >> 1);
        if (wire_io_read()) {
            in |= 0x80;
        }
        wire_sclk(0);
    }
    return in;
}

/* ============================================================
 * 五、对外接口：写/读一个寄存器
 * ============================================================ */
static void ds1302_write_reg(unsigned char addr, unsigned char val)
{
    wire_rst(1);                                       /* ① 拉高 RST，开始一帧 */
    ds1302_transfer((unsigned char)(addr & 0xFE));     /* ② 写命令：bit0 = 0 */
    ds1302_transfer(val);                              /* ③ 数据 */
    wire_rst(0);                                       /* ④ 拉低 RST，结束一帧 */
}

static unsigned char ds1302_read_reg(unsigned char addr)
{
    unsigned char v;

    wire_rst(1);
    ds1302_transfer((unsigned char)((addr & 0xFE) | 0x01)); /* 写命令：bit0 = 1 */
    v = ds1302_transfer(0xFF);                              /* 芯片把数据推回来 */
    wire_rst(0);
    return v;
}

/* ============================================================
 * 六、把「一串 BCD 寄存器」翻译成人能看的时间
 * ============================================================ */
typedef struct {
    unsigned char year, month, day, week, hour, min, sec;
} rtc_time_t;

static void clock_set(const rtc_time_t *t)
{
    ds1302_write_reg(0x8E, 0x00);                                  /* 先解锁 WP */
    ds1302_write_reg(0x80, (unsigned char)(bin2bcd(t->sec) & 0x7F)); /* 顺手清 CH，晶振才起振 */
    ds1302_write_reg(0x82, bin2bcd(t->min));
    ds1302_write_reg(0x84, bin2bcd(t->hour));
    ds1302_write_reg(0x86, bin2bcd(t->day));
    ds1302_write_reg(0x88, bin2bcd(t->month));
    ds1302_write_reg(0x8A, bin2bcd(t->week));
    ds1302_write_reg(0x8C, bin2bcd(t->year));
    ds1302_write_reg(0x8E, 0x80);                                  /* 写完重新上锁 */
}

static void clock_get(rtc_time_t *t)
{
    t->sec   = (unsigned char)(bcd2bin((unsigned char)(ds1302_read_reg(0x80) & 0x7F)));
    t->min   = (unsigned char)(bcd2bin((unsigned char)(ds1302_read_reg(0x82) & 0x7F)));
    t->hour  = (unsigned char)(bcd2bin((unsigned char)(ds1302_read_reg(0x84) & 0x3F)));
    t->day   = (unsigned char)(bcd2bin((unsigned char)(ds1302_read_reg(0x86) & 0x3F)));
    t->month = (unsigned char)(bcd2bin((unsigned char)(ds1302_read_reg(0x88) & 0x1F)));
    t->week  = (unsigned char)(bcd2bin((unsigned char)(ds1302_read_reg(0x8A) & 0x07)));
    t->year  = (unsigned char)(bcd2bin(ds1302_read_reg(0x8C)));
}

static void clock_dump(const char *tag)
{
    rtc_time_t t;
    unsigned char raw[7];
    int i;

    raw[0] = ds1302_read_reg(0x80);
    raw[1] = ds1302_read_reg(0x82);
    raw[2] = ds1302_read_reg(0x84);
    raw[3] = ds1302_read_reg(0x86);
    raw[4] = ds1302_read_reg(0x88);
    raw[5] = ds1302_read_reg(0x8A);
    raw[6] = ds1302_read_reg(0x8C);
    clock_get(&t);

    printf("%s\n  原始 BCD :", tag);
    for (i = 0; i < 7; ++i) {
        printf(" %02X", (unsigned)raw[i]);
    }
    printf("\n  翻译之后 : 20%02u-%02u-%02u 星期%u  %02u:%02u:%02u\n\n",
           (unsigned)t.year, (unsigned)t.month, (unsigned)t.day, (unsigned)t.week,
           (unsigned)t.hour, (unsigned)t.min, (unsigned)t.sec);
}

/* 让芯片"走一秒"：真实芯片由 32.768kHz 晶振 + 内部分频器自己走，这里手动加 */
static void chip_tick_1s(void)
{
    unsigned char s, m, h;

    if (chip.reg[0] & 0x80) {
        return;                                     /* CH = 1：停振 */
    }
    s = bcd2bin((unsigned char)(chip.reg[0] & 0x7F));
    m = bcd2bin((unsigned char)(chip.reg[1] & 0x7F));
    h = bcd2bin((unsigned char)(chip.reg[2] & 0x3F));

    if (++s >= 60u) {
        s = 0;
        if (++m >= 60u) {
            m = 0;
            h = (unsigned char)((h + 1u) % 24u);
        }
    }
    chip.reg[0] = (unsigned char)(bin2bcd(s) | (chip.reg[0] & 0x80));
    chip.reg[1] = bin2bcd(m);
    chip.reg[2] = (unsigned char)(bin2bcd(h) | (chip.reg[2] & 0x80));
}

int main(void)
{
    const unsigned char addr_list[7] = {0x80, 0x82, 0x84, 0x86, 0x88, 0x8A, 0x8C};

6. 核心概念四：LCD1602——一块会认字的玻璃

6.1 它不是「屏幕」，是一块带控制器的玻璃

先把一个误解拆掉：LCD1602 不是「像素屏」，你不能往上面画任意图形。它是一块 16 列 × 2 行 的字符玻璃，每个字符位置是一个 5×8 的点阵。整块屏最多显示 32 个字符，每个字符 40 个点，一共 1280 个点。

关键在于：这 1280 个点不需要你管。玻璃背后贴着一颗控制器（市面上绝大多数是 HD44780 兼容芯片），里面有两样东西：

  • CGROM（字符发生器）：一张字库表。你送一个字节 0x41，它去表里查出「A」的 5×8 点阵，点亮对应的点；
  • DDRAM（显示数据 RAM）：一块 80 字节的显存。屏幕上每个字符位置对应 DDRAM 里的一个地址，你把字符码写进那个地址，屏幕上的对应位置就变成那个字。

所以你的工作只有一件事：把正确的字符码，写到正确的 DDRAM 地址上。 剩下的「怎么点亮那些点」是控制器的事。

   你写的：  0x80|0x00  然后依次写 '2' '0' '2' '5' ...
              │
              ▼
   DDRAM： [ '2' ][ '0' ][ '2' ][ '5' ] ...  （80 字节，只有 32 个位置在玻璃上）
              │
              ▼
   CGROM： '2' -> 5x8 点阵    '0' -> 5x8 点阵
              │
              ▼
   玻璃：  ┌─┐ ┌─┐ ┌─┐ ┌─┐
           │2│ │0│ │2│ │5│ ...

6.2 十六只脚，其实只有三类

引脚 名字 作用 新手最常踩的坑
电源 VSS / VDD 地 / +5V 接反必烧
对比度 VO（有的板标 V0） 调对比度的分压输入 调太高：满屏黑方块；调太低：什么都不显示。这是「黑屏」第一大真因
控制 RS 0 = 我发的是指令，1 = 我发的是数据 搞反了：把字符当指令执行，屏幕乱跳
控制 RW 0 = 我写，1 = 我读（读忙标志/读 DDRAM） 很多模块把它焊死接地，于是你永远读不到忙标志
控制 E 使能。下降沿把数据锁进控制器 忘了给下降沿，或者高电平时间太短
数据 D0~D7 8 位并行总线 只接了 4 根却按 8 位发（或反过来）
背光 A / K 背光阳极 / 阴极 不串限流电阻，烧背光

RS 和 RW 组合起来只有四种意思，背下来：

RS RW 含义
0 0 写指令（清屏、定位、开关显示……）
0 1 读忙标志 BF 和地址计数器 AC
1 0 写数据（写一个字符进 DDRAM/CGRAM）
1 1 读数据（从 DDRAM/CGRAM 读回来）

E 脚的动作是「高 → 低」：先把 RS/RW/D0~D7 都摆好，E 拉高（控制器开始看总线），保持一小会儿（几百纳秒），E 拉低（控制器在这一刻把数据锁进去）。所以「送一个字节」在真实代码里是六步：摆 RS、摆 RW、摆数据、E=1、延时、E=0。

6.3 指令集：只需要记住六条

LCD1602 的指令有十几条，但 95% 的场合只用这六条：

指令 二进制 含义 什么时候用
0x38 0011 1000 功能设置：8 位总线、2 行显示、5×8 点阵 初始化（发三次）
0x0C 0000 1100 显示开、光标关、不闪烁 初始化；不想看见光标时
0x0E 0000 1110 显示开、光标开、不闪烁 想让用户看见光标（比如输入密码）
0x06 0000 0110 输入模式：写入后地址 +1、画面不移动 初始化
0x01 0000 0001 清屏：DDRAM 全填空格、地址归零 换整屏内容时（慢，1.52ms）
0x80 + addr 1xxx xxxx 设置 DDRAM 地址（光标定位） 每写一行之前

逐位拆开看 0x38，你就明白「指令」不是魔法数字：

位 值 名字 含义
bit7~bit5 001 指令编号 「功能设置」这条指令
bit4 1 DL 数据总线宽度：1 = 8 位
bit3 1 N 显示行数：1 = 2 行
bit2 0 F 字符点阵：0 = 5×8
bit1~bit0 00 — 不用（写 0）

同理 0x0C = 0000 1100：D=1（显示开）、C=0（光标关）、B=0（不闪）。想要「显示开 + 光标开 + 闪烁」，就是 0x0F。

6.4 为什么显示不了汉字

因为一个汉字至少要 16×16 个点，而 1602 的一个字符位置只有 5×8。CGROM 里那 192 个字符是 ASCII + 日文假名 + 一些符号，没有汉字。要显示汉字，得换 12864 那种带中文字库的屏——那是另一个任务，不在本篇范围。

（顺带说：用 CGRAM 自定义 8 个 5×8 的小图形是可以的，见 §8.5。）

7. 核心概念五：初始化序列——为什么每条指令都要发，为什么都要等

7.1 上电那一刻，控制器是「懵」的

你把 5V 接上，控制器内部的复位电路需要时间才稳定。数据手册给的典型值是 上电后等 15ms 以上（保守一点等 40~50ms 更好）。这段时间里，你发什么它都可能听不懂。

所以初始化的第一步不是发指令，是等：

lcd_delay_ms(20);        /* 上电后先等 20ms，让控制器内部复位完成 */

只写这一行、别的都不写，是新手最常见的「LCD 黑屏」原因之一。 有人上电就跑 lcd_init()，第一字节在控制器还没醒的时候就发出去了，后面全乱。

7.2 为什么 0x38 要发三次

这是 LCD1602 最著名的「玄学」，其实讲清楚很简单。

控制器上电后的总线宽度可能是 8 位，也可能是 4 位（取决于上一次运行或干扰），而你不知道它现在是哪种。如果你现在发一个 8 位的 0x38，而它正处在 4 位模式，它会把这个字节当成「两个 4 位半字节」处理，状态就更乱了。

破解办法是利用一个巧合：0x38 的高 4 位是 0x3，而 0x3 在 4 位模式下恰好也表示「切换成 8 位模式」。所以无论控制器现在处于什么模式，连发三次 0x38（每次之间留够时间），它一定会被拽回「8 位、2 行、5×8」这个确定状态。

第 1 次 0x38：可能是 8 位下的一条完整指令，也可能是 4 位下的半个字节
             ↓ 无论哪种，控制器都开始往"8 位模式"靠
第 2 次 0x38：此时大概率已经是 8 位，指令被正确执行
             ↓
第 3 次 0x38：确认状态，顺便把不稳定的残留清掉

这就是为什么几乎所有 1602 例程里都有连续三个 0x38——它不是抄来的仪式，是把不确定状态收敛到确定状态的标准做法。

7.3 完整序列，一句一句解释

lcd_delay_ms(20);       /* ① 等内部复位 */
lcd_write_cmd(0x38);    /* ② 8 位总线、2 行、5x8 —— 第 1 次 */
lcd_delay_ms(5);
lcd_write_cmd(0x38);    /* ③ 第 2 次 */
lcd_delay_us(200);
lcd_write_cmd(0x38);    /* ④ 第 3 次，状态确定 */
lcd_write_cmd(0x0C);    /* ⑤ 开显示、关光标、不闪 */
lcd_write_cmd(0x06);    /* ⑥ 写入后地址 +1，画面不动 */
lcd_write_cmd(0x01);    /* ⑦ 清屏 */
lcd_wait_busy();        /* ⑧ 清屏要 1.52ms，必须等 */

为什么 0x06 要在 0x01 前面？因为清屏会把地址归零，而输入模式决定「下一个字符写哪里」。顺序反了不会立刻出错，但会让你在「清屏后第一次写」时拿到一个不想要的光标位置。顺序是有讲究的，别乱调。

7.4 忙标志 BF：芯片在干活时，别烦它

控制器执行指令需要时间。普通指令约 37~40μs，清屏和回 Home 要 1.52ms。这段时间里它不接新指令，你要是硬发，它要么丢掉，要么执行错。

它提供了一个「我正在忙」的信号：RS=0、RW=1 时读 D7，就是 BF。BF=1 表示忙，BF=0 表示可以发下一条。

于是有了两条路：

查忙（读 BF） 延时（死等）
硬件要求 RW 必须能由单片机控制，D7 要能读 RW 可以接地，D7 不用读
速度 快，芯片一空就继续 慢，每条都等最坏情况
代码 while (BF) ; delay_us(50); / delay_ms(2);
风险 总线死锁会卡死（必须加超时） 延时不够就丢指令
适合 自己画的板子、RW 可控 模块化 1602、RW 焊死、I2C 转接板

你的板子属于哪种，看原理图。 大多数成品 1602 模块把 RW 引出来了，但很多「I2C 转 1602」的小板子把 RW 直接接地——那种板子你永远读不到 BF，只能老老实实延时。这就是「结论依赖原理图」在这一节的版本。

还有一个细节：初始化阶段不要用查忙。因为此时总线宽度还没确定，读回来的 D7 未必是 BF。初始化靠延时，正常工作靠查忙，这是标准做法。

7.5 4 位模式：省 4 根线，代价是多一次操作

1602 支持 4 位总线：只用 D4~D7，一个字节分两次送（先高 4 位，再低 4 位）。省下 4 根 IO，代价是每次传输多一个 E 脉冲，代码也更容易写错。

本阶段建议：能用 8 位就用 8 位。51 的 IO 本来就够，没必要为了省线给自己找麻烦。等你以后用 I2C 转接板（PCF8574 那种），它内部就是 4 位模式，你只需要调用库函数，不用自己拼半字节。

8. 核心概念六：光标定位、显示缓冲与自定义字符

8.1 DDRAM 地址：两行不是连着的

这是 1602 最容易被算错的地方。它的 80 字节 DDRAM 里，第一行从 0x00 开始，第二行从 0x40 开始：

列 0 1 2 … 14 15 16 … 39
第一行地址 0x00 0x01 0x02 … 0x0E 0x0F 0x10 … 0x27
第二行地址 0x40 0x41 0x42 … 0x4E 0x4F 0x50 … 0x67

看明白两件事：

  1. 第二行不是从 0x10 开始，是从 0x40 开始。 所以「第 2 行第 7 列」的地址是 0x40 + 7 = 0x47，不是 0x10 + 7。
  2. 地址 0x10~0x27 和 0x50~0x67 是「存得下但看不见」的区域。 玻璃只有 16 列，所以第一行的 0x10 之后、第二行的 0x50 之后，写进去的字符不会显示。

定位一条指令就够：

/* 行号 0/1，列号 0~15 */
unsigned char addr = (unsigned char)((row == 0 ? 0x00 : 0x40) + col);
lcd_write_cmd((unsigned char)(0x80 | addr));   /* 0x80 是"设置地址"指令的编号 */

0x80 | addr 这个写法要理解，不要背。 0x80 是「设置 DDRAM 地址」这条指令的固定高 bit，低 7 位才是地址。因为地址最大 0x67，不会碰到 bit7，所以直接按位或就行。

8.2 写超一行会怎样

1602 不会自动换行。你在第一行写第 17 个字符，地址从 0x0F 加到 0x10——那里存得下，但玻璃上没有这个位置，字符就「消失」了。

想换行，必须自己算：

lcd_set_cursor(1, 0);        /* 手动跳到第二行开头 */

这也是「整屏移动」必须自己实现的原因：屏幕不会帮你滚动。

8.3 影子缓冲：不要在屏幕上直接拼字符串

一个很常见的写法是「每次刷新都 0x01 清屏，然后重写 32 个字符」。它能用，但有两个毛病：

  1. 闪。 清屏那一瞬间屏幕是空的，人眼能看到一下白闪；每秒刷一次就闪一次；
  2. 慢。 清屏 1.52ms + 32 个字符 × 40μs ≈ 2.8ms，这期间主循环什么都干不了。

工程做法是加一层影子缓冲（shadow buffer）：在 RAM 里开 char shadow[2][17]，所有「要显示什么」先写进影子，再由一个刷新函数只把变化的字符送到屏幕。

/* 思路示意，不是完整代码 */
char shadow[2][17];                 /* 32 个字符 + 两个 '\0' */
char shown[2][17];                  /* 屏幕上现在是什么 */

void ui_refresh(void)
{
    int r, c;
    for (r = 0; r < 2; ++r) {
        for (c = 0; c < 16; ++c) {
            if (shadow[r][c] != shown[r][c]) {   /* 只写变化的格子 */
                lcd_set_cursor(r, c);
                lcd_write_data((unsigned char)shadow[r][c]);
                shown[r][c] = shadow[r][c];
            }
        }
    }
}

好处有三个：不闪（没有整屏清空）、快（大部分时候只改几个字符）、好测（影子缓冲是纯内存，可以脱离硬件检查内容对不对）。

代价是 64 字节 RAM。51 的 RAM 只有 128/256 字节，64 字节不是小数目——这就是为什么 51 工程里「缓冲多大」是要算的，不能随手开 char buf[256]。

如果一次要改的字符还是太多（比如整屏滚动），就再切一刀：一轮节拍只刷一行，下一拍刷另一行。写屏是慢活，慢活就要切片——这和实战一里数码管动态扫描的思路是同一个。

8.4 整屏移动的两种做法

任务 A 要求「显示时间+温度并可整屏移动」。实现有两条路：

  1. 改 DDRAM 内容：把影子缓冲整体左移一位，再刷新 32 个字符。灵活，能实现任意滚动，但每移一次要重写全屏（用影子缓冲的差分刷新，其实只改 32 个格子，代价可接受）。
  2. 用显示移位指令：0x18（画面左移一位）/ 0x1C（画面右移一位）。它不改 DDRAM，只是把「玻璃窗口」在 80 字节显存上滑动。极快（一条指令），但内容是被「窗口」裁掉的，移出去的字不会绕回来。
DDRAM:  [H][e][l][l][o][ ][ ][ ]...       窗口原本对着 0x00
0x18 后:   [H][e][l][l][o][ ][ ]...       窗口右移一格，看起来字往左跑了

建议：先用方案 1 把「移动」这件事做出来（逻辑清楚、可控），有余力再试方案 2（体会「硬件帮你干活」的爽感）。两条路都试过，你才算真的懂 DDRAM 和「窗口」的区别。

8.5 CGRAM：8 个你自己画的字

CGROM 是只读的，但控制器还留了 64 字节 CGRAM，可以存 8 个自定义的 5×8 字符。地址 0x40~0x7F，每个字符占 8 个字节（每字节低 5 位是一行点阵）。

典型用法：画一个「℃」、一个「↑」、一个电池图标、一个笑脸。步骤是：

  1. 发 0x40 | (n * 8) 定位到第 n 个自定义字符；
  2. 连续写 8 个字节（每个字节的低 5 位就是那一行的点）；
  3. 之后写字符码 n（0~7），屏幕上就出现你画的图案。
自定义字符 0 的 8 行（每行 5 位，1 = 亮点）：
  0b01110   ← 0x0E
  0b10001   ← 0x11
  0b10001
  0b01110
  0b00000
  0b00000
  0b00000
  0b00000

这个功能任务里不一定要用，但你应该知道它存在——很多「1602 显示温度」的例程里那个小小的度数圈，就是这么画出来的。

8.6 把这几节拼起来：完整的 1602 模拟

下面这个文件把「指令 / 数据 / 忙标志 / DDRAM / 光标」全部按真实规则模拟了一遍。它不接硬件，但每一行指令都真的被执行了，你能看到 DDRAM 里的字符怎么变成屏幕上的两行。

/* 02_lcd1602_display.c —— LCD1602 指令/数据模拟 + 初始化序列 + 光标定位
 * 编译：gcc -Wall -Wextra -std=c99 02_lcd1602_display.c -o 02_lcd1602_display.exe
 *
 * 真实 Keil C51 里，8 根数据线 + 3 根控制线都是位：
 *     sbit RS = P2^6;  sbit RW = P2^5;  sbit E = P2^7;
 *     P0 = 数据字节;   E 拉高 -> 拉低，一个字节就送进去了
 * 本文件把"送一个字节"抽象成 lcd_write_cmd / lcd_write_data，
 * 但 RS / RW / 忙标志 / 指令码 / DDRAM 地址全部按真实芯片的规矩来。
 */
#include <stdio.h>
#include <string.h>

#define LCD_COLS 16
#define LCD_ROWS 2

/* ============================================================
 * 一、器件模型：HD44780 兼容控制器 + 2 行 x 16 列的玻璃
 * ============================================================ */
typedef struct {
    unsigned char ddram[LCD_ROWS][LCD_COLS];  /* 屏上看得见的 32 个格子 */
    unsigned char addr;                       /* 当前 DDRAM 地址（光标在哪） */

    int display_on, cursor_on, blink_on;      /* 0x08 那条指令的三位 */
    int entry_inc;                            /* 1 = 写入后地址 +1 */
    int two_line, eight_bit;                  /* 0x38 那条指令 */

    unsigned long now_us;                     /* 虚拟时钟：模拟"过了多少微秒" */
    unsigned long busy_until_us;              /* 忙标志什么时候落下 */
    unsigned long busy_polls;                 /* 查忙查了多少次 */
    unsigned long offscreen;                  /* 写到玻璃外面的字符数 */

    int rs;                                   /* 0 指令 1 数据 */
    int rw;                                   /* 0 写 1 读 */
    unsigned char bus;                        /* D0~D7 上的字节 */
} lcd_t;

static lcd_t lcd;

static void lcd_delay_us(unsigned int us)
{
    lcd.now_us += us;
}

static void lcd_delay_ms(unsigned int ms)
{
    lcd.now_us += (unsigned long)ms * 1000UL;
}

/* 读忙标志：RS=0、RW=1，D7 就是 BF。这里用虚拟时钟表示"还在忙" */
static int lcd_is_busy(void)
{
    lcd.rs = 0;
    lcd.rw = 1;
    return lcd.now_us < lcd.busy_until_us;
}

static void lcd_wait_busy(void)
{
    lcd.busy_polls = 0;
    while (lcd_is_busy()) {
        ++lcd.now_us;                 /* 读一次 BF 也要花时间 */
        ++lcd.busy_polls;
    }
    lcd.rw = 0;
}

/* 不同指令要等的微秒数：清屏/回 Home 最慢，1.52ms；其余约 37~40us */
static unsigned int lcd_cmd_time_us(unsigned char cmd)
{
    if (cmd & 0x01) {
        return 1520;
    }
    if (cmd & 0x02) {
        return 1520;
    }
    return 40;
}

static const char *lcd_cmd_name(unsigned char cmd)
{
    if (cmd == 0x38) { return "功能设置：8 位总线、2 行显示、5x8 点阵"; }
    if (cmd == 0x0C) { return "显示开、光标关、不闪烁"; }
    if (cmd == 0x0E) { return "显示开、光标开"; }
    if (cmd == 0x06) { return "输入模式：写入后地址 +1，画面不动"; }
    if (cmd == 0x01) { return "清屏（DDRAM 全填空格，光标回 0x00）"; }
    if (cmd == 0x02) { return "光标回 Home（不清 DDRAM）"; }
    if (cmd & 0x80)  { return "设置 DDRAM 地址（光标定位）"; }
    return "其他指令";
}

/* 把一条指令"执行"掉：只实现本阶段真正会用到的那些 */
static void lcd_apply(unsigned char cmd)
{
    int r, c;

    if (cmd & 0x80) {                       /* 1xxxxxxx：设置 DDRAM 地址 */
        lcd.addr = (unsigned char)(cmd & 0x7F);
        return;
    }
    if (cmd & 0x20) {                       /* 001DL N F **：功能设置 */
        lcd.eight_bit = (cmd & 0x10) ? 1 : 0;
        lcd.two_line  = (cmd & 0x08) ? 1 : 0;
        return;
    }
    if (cmd & 0x10) {                       /* 光标/画面移动：本文件不模拟 */
        return;
    }
    if (cmd & 0x08) {                       /* 00001DCB：显示开关 */
        lcd.display_on = (cmd & 0x04) ? 1 : 0;
        lcd.cursor_on  = (cmd & 0x02) ? 1 : 0;
        lcd.blink_on   = (cmd & 0x01) ? 1 : 0;
        return;
    }
    if (cmd & 0x04) {                       /* 000001I/D：输入模式 */
        lcd.entry_inc = (cmd & 0x02) ? 1 : 0;
        return;
    }
    if (cmd & 0x02) {                       /* 光标回 Home */
        lcd.addr = 0;
        return;
    }
    if (cmd & 0x01) {                       /* 清屏：DDRAM 全部写空格 */
        for (r = 0; r < LCD_ROWS; ++r) {
            for (c = 0; c < LCD_COLS; ++c) {
                lcd.ddram[r][c] = ' ';
            }
        }
        lcd.addr = 0;
    }
}

/* ============================================================
 * 二、单片机侧：送指令 / 送数据
 * ============================================================ */
static void lcd_write_cmd(unsigned char cmd)
{
    lcd.rs = 0;                             /* RS = 0：这是指令 */
    lcd.rw = 0;                             /* RW = 0：我要写 */
    lcd.bus = cmd;
    lcd_apply(cmd);
    lcd.busy_until_us = lcd.now_us + lcd_cmd_time_us(cmd);
}

static void lcd_write_data(unsigned char ch)
{
    unsigned char a = lcd.addr;
    int row, col;

    lcd.rs = 1;                             /* RS = 1：这是数据 */
    lcd.rw = 0;
    lcd.bus = ch;

    if (a < 0x40) {                          /* 第一行：0x00~0x27 */
        row = 0;
        col = (int)a;
    } else {                                 /* 第二行：0x40~0x67 */
        row = 1;
        col = (int)(a - 0x40);
    }

    if (row < LCD_ROWS && col >= 0 && col < LCD_COLS) {
        lcd.ddram[row][col] = ch;
    } else {
        ++lcd.offscreen;                     /* 地址还在加，但玻璃上没有这个位置 */
    }

    if (lcd.entry_inc) {
        ++lcd.addr;
    } else {
        --lcd.addr;
    }
    lcd.busy_until_us = lcd.now_us + 40;
}

/* 初始化：这七步的顺序不能乱 */
static void lcd_init(void)
{
    memset(&lcd, 0, sizeof lcd);
    lcd.addr = 0;
    lcd.entry_inc = 1;
    lcd.eight_bit = 1;
    lcd.two_line = 1;

    printf("  上电等 20ms（控制器内部复位要用掉 15ms 以上）\n");
    lcd_delay_ms(20);

    printf("  发 0x38 第 1 次：%s\n", lcd_cmd_name(0x38));
    lcd_write_cmd(0x38);
    lcd_delay_ms(5);

    printf("  发 0x38 第 2 次\n");
    lcd_write_cmd(0x38);
    lcd_delay_us(200);

    printf("  发 0x38 第 3 次（三次是为了把控制器从任何状态拽回 8 位模式）\n");
    lcd_write_cmd(0x38);

    printf("  发 0x0C：%s\n", lcd_cmd_name(0x0C));
    lcd_write_cmd(0x0C);

    printf("  发 0x06：%s\n", lcd_cmd_name(0x06));
    lcd_write_cmd(0x06);

    printf("  发 0x01：%s\n", lcd_cmd_name(0x01));
    lcd_write_cmd(0x01);
    lcd_wait_busy();
}

/* ============================================================
 * 三、给人用的接口：定位 + 写字符串
 * ============================================================ */
static void lcd_set_cursor(int row, int col)
{
    unsigned char addr;

    if (row < 0 || row >= LCD_ROWS || col < 0 || col >= LCD_COLS) {
        return;                              /* 越界请求直接不理，绝不去写别人的格子 */
    }
    /* 第一行从 0x00 起，第二行从 0x40 起 —— 这就是全部秘密 */
    addr = (unsigned char)((row == 0 ? 0x00 : 0x40) + col);
    lcd_write_cmd((unsigned char)(0x80 | addr));
}

static void lcd_puts(int row, int col, const char *s)
{
    lcd_set_cursor(row, col);
    while (*s != '\0') {
        lcd_write_data((unsigned char)*s);
        ++s;
    }
}

static void lcd_show(const char *tag)
{
    int r, c;

    printf("\n  %s\n", tag);
    printf("  +----------------+\n");
    for (r = 0; r < LCD_ROWS; ++r) {
        printf("  |");
        for (c = 0; c < LCD_COLS; ++c) {
            printf("%c", lcd.ddram[r][c]);
        }
        printf("|\n");
    }
    printf("  +----------------+\n");
    printf("  光标地址 0x%02X：下一个字符会写到这里\n", (unsigned)lcd.addr);
}

int main(void)
{
    int i;

    printf("== 1. 初始化序列：每条指令为什么要发 ==\n");
    lcd_init();
    printf("  初始化完成：display_on=%d, cursor_on=%d, entry_inc=%d, two_line=%d\n\n",
           lcd.display_on, lcd.cursor_on, lcd.entry_inc, lcd.two_line);

    printf("== 2. DDRAM 地址表：第一行 0x00~0x0F，第二行 0x40~0x4F ==\n");
    printf("  列   :");
    for (i = 0; i < LCD_COLS; ++i) {
        printf(" %2d", i);
    }
    printf("\n  第一行:");
    for (i = 0; i < LCD_COLS; ++i) {
        printf(" %02X", (unsigned)(0x00 + i));
    }
    printf("\n  第二行:");
    for (i = 0; i < LCD_COLS; ++i) {
        printf(" %02X", (unsigned)(0x40 + i));
    }
    printf("\n  两行不是连续的：第一行末尾 0x0F 的下一格是 0x10，那格不在玻璃上。\n\n");

    printf("== 3. 写满两行：16 个字符正好一行 ==\n");
    lcd_puts(0, 0, "2025-10-25 13:14");
    lcd_puts(1, 0, "SAT  25.4C");
    lcd_show("两行都写满之后");

    printf("\n== 4. 光标定位：把 0x40 这个偏移用对 ==\n");
    lcd_puts(1, 15, "!");
    lcd_show("在 (1,15) 写一个感叹号");
    lcd_puts(0, 0, "#");
    lcd_show("在 (0,0) 写一个井号");

    printf("\n== 5. 写超一行会怎样：地址继续加，字符掉进看不见的地方 ==\n");
    lcd.offscreen = 0;
    lcd_puts(0, 0, "ABCDEFGHIJKLMNOPQR");   /* 18 个字符 */
    lcd_show("往第一行硬塞 18 个字符");
    printf("  掉在玻璃外面的字符数 = %lu\n", lcd.offscreen);
    printf("  所以换行必须自己算：写完第 16 个，手动 set_cursor(1,0)。\n");

    printf("\n== 6. 查忙 vs 延时：清屏到底要等多久 ==\n");
    lcd_write_cmd(0x01);
    printf("  刚发完 0x01，BF = %d（还在忙）\n", lcd_is_busy());
    lcd_wait_busy();
    printf("  查忙循环转了 %lu 次才放行（约 1.52ms）\n", lcd.busy_polls);

9. 核心概念七：AD 转换——把电压变成一个数

9.1 单片机只认 0 和 1，可世界是连续的

你的板子上，电位器转到一个位置，滑动端对地是 2.37V。这个「2.37」是连续的、有无穷多可能的。而单片机只会读引脚的高低电平——要么 0，要么 1。

AD 转换器（ADC）就是这两者之间的翻译官：它把「0~Vref 之间的某个电压」翻译成「0~2^n-1 之间的某个整数」。

   连续的世界                      AD 转换                      数字的世界
  0V ─────────────────────────────────────────────►  0
       2.37V  ──►  [ 采样 ] ─► [ 比较 ] ─► [ 编码 ]  ──►  1942   （12 位、5V 基准）
  5V ─────────────────────────────────────────────►  4095

翻译的精度由两个东西决定：位数 n（有多少个刻度）和 参考电压 Vref（满量程到底是多少伏）。

9.2 分辨率：刻度有多密

n 位的 ADC，输出码值的范围是 0 ~ 2^n - 1，一共 2^n 个刻度。

位数 码值范围 刻度数 每个刻度（Vref = 5.000V） 能分辨
8 位 0~255 256 19.608 mV 百分之一伏左右
10 位 0~1023 1024 4.888 mV 千分之一伏
12 位 0~4095 4096 1.221 mV 万分之一伏

记住一个换算：每多 1 位，刻度数翻倍，每个刻度减半。 12 位比 8 位多 4 位，所以细 16 倍（2^4）。

但「细」不等于「准」。一个 12 位的 ADC，如果参考电压本身飘了 5%，那你算出来的电压也飘 5%——位数决定分辨率，参考电压和电路决定精度，这是两件事。 很多新手看到「12 位」就以为能测到 0.1mV，实际上电路噪声早就把低 4 位淹了。

9.3 换算公式与量化误差

公式只有一条：

电压 = 码值 / (2^n - 1) × Vref

代入 12 位、5V、码值 2048：2048 / 4095 × 5.000 = 2.5006V。

为什么分母是 2^n - 1 而不是 2^n？因为「满量程码值」2^n - 1 对应的是 Vref（或 Vref 减一个 LSB，取决于芯片定义）。有些数据手册按 2^n 算，本质是「满量程对应 Vref + 1LSB」的另一种约定。两种写法差半个 LSB，工程上无所谓；但同一份代码里必须统一，不能这里除 4095、那里除 4096。

量化误差是原理性的：真实电压落在两个刻度之间时，ADC 只能给你最近的那个整数。所以：

真实 2.5000V，12 位、5V 基准
  理论码值 = 2047.5
  ADC 可能给 2047（= 2.4994V），也可能给 2048（= 2.5006V）
  误差 ±0.0006V = ±0.5 LSB

这半个 LSB 消不掉，因为信息在「取整」那一刻就丢了。你能做的只有两件事：换更高位数的 ADC，或者多采几次求平均，让随机的那部分误差互相抵消（§10）。

9.4 采样保持与转换时间

ADC 内部不是瞬间完成比较的。逐次逼近型（SAR）ADC 的工作方式是「二分查找」：

输入 2.37V，Vref 5V：
  试 2.5V  -> 太大 -> 最高位 0
  试 1.25V -> 太小 -> 下一位 1
  试 1.875V-> 太小 -> 1
  ...一共 n 次比较，n 位就 n 个周期

在比较的这段时间里，输入电压必须保持不变，否则比较到一半电压变了，结果就是错的。所以 ADC 前面有一级采样保持电路：一个开关 + 一个电容，先把电压「抓」到电容上，再慢慢比较。

这带来两个实际后果：

  1. 信号源内阻不能太大。 采样电容要充电，源内阻大（比如 100kΩ 的电位器）就充不满，读数偏低。解决办法是加一级运放跟随器，或者选采样时间更长的通道。
  2. 转换需要时间。 ADC0809 大约 100μs，STC 内部 AD 几微秒到几十微秒不等（跟配置的转换速度有关）。这段时间 CPU 要么等，要么去干别的，等中断。

9.5 ADC0809 与「单片机内部 AD」的区别

ADC0809（外挂） STC12/15/8 内部 AD
位数 8 位 8/10/12 位（看型号）
通道 8 通道，靠 3 根地址线选 通常 8 通道，靠寄存器选
接口 8 根数据线 + ALE/START/EOC/OE 特殊功能寄存器
时钟 需要外部时钟（常用 51 的 ALE 分频） 内部时钟，配置分频
转换时间 约 100μs 几 μs~几十 μs
参考电压 外部给（0~5V） 常用 VCC，也有外部 Vref 脚
经典 8051 只能外挂 不支持

ADC0809 的四根控制线，各自管什么，必须分清：

信号 全称 作用 时序要点
ALE Address Latch Enable 把 A0~A2 上的通道号锁进芯片 上升沿锁存，之后地址线可以改
START 启动转换 高脉冲启动一次转换 上升沿复位内部寄存器，下降沿开始转换
EOC End Of Conversion 转换结束标志 转换中为低，结束时变高（注意极性！）
OE Output Enable 允许芯片把结果放到数据总线上 高有效，读完要拉低

写 ADC0809 的顺序：送通道号 → ALE 一个脉冲 → START 一个脉冲 → 等 EOC 变高 → OE 拉高 → 读 P0 → OE 拉低。

经典 8051 没有内部 AD，这是它和 STC 增强型 51 的一个硬差别。你的板子到底是哪种，看芯片型号和原理图，不要照抄别人的寄存器名。

9.6 参考电压：那个比滤波重要一百倍的常数

假设真实电压 2.500V，ADC 的 Vref 实际是 3.3V，你的代码却按 5.0V 算：

码值 = 2.500 / 3.300 × 4095 = 3102
你的结果 = 3102 / 4095 × 5.000 = 3.788V     ← 误差 +51.5%

误差一半，滤波做得再漂亮也没用。 所以换板子、换基准源、改供电，第一件事是核对这个常数。

反过来有一个好消息：比例测量。如果你的电位器接在 VCC 上，ADC 的 Vref 也是同一个 VCC，那么：

码值 = (位置比例 × VCC) / VCC × 4095 = 位置比例 × 4095

VCC 从 5.0V 掉到 4.5V，码值一点不变——因为分子分母一起降。这就是为什么「用电位器测位置」的电路几乎都不需要精密基准。但如果 Vref 是单独的 5.0V 基准、电位器接在 4.5V 上，码值就会掉到 1474。

9.7 完整示例：换算、量化误差、滤波、Vref 陷阱

/* 03_adc_voltage.c —— AD 码值 -> 电压换算：分辨率、量化误差、滤波
 * 编译：gcc -Wall -Wextra -std=c99 03_adc_voltage.c -o 03_adc_voltage.exe
 *
 * 说明：本文件里没有"真的 AD 芯片"，只有换算与滤波的数学。
 *       51 读到的永远是一个整数码值；把它变成"几伏"是你的事。
 */
#include <stdio.h>

#define SAMPLE_N 9

/* 浮点版：电压 = 码值 / (2^n - 1) * Vref */
static double code_to_voltage(unsigned int code, int bits, double vref)
{
    double full = (double)((1UL << bits) - 1);   /* 8 位 255，10 位 1023，12 位 4095 */
    return (double)code / full * vref;
}

/* 整数版：返回毫伏。51 上没有浮点单元，工程里更常用这一版 */
static unsigned int code_to_mv(unsigned int code, int bits, unsigned int vref_mv)
{
    unsigned long full = (1UL << bits) - 1;
    unsigned long num = (unsigned long)code * vref_mv;

    return (unsigned int)((num + full / 2) / full);   /* +full/2 是四舍五入 */
}

/* 算术平均：噪声按 1/sqrt(N) 下降，代价是 N 次转换 */
static unsigned int mean_code(const unsigned int *a, int n)
{
    unsigned long sum = 0;
    int i;

    for (i = 0; i < n; ++i) {
        sum += a[i];
    }
    return (unsigned int)((sum + (unsigned long)n / 2) / (unsigned long)n);
}

/* 中值：先排序取中间。对"一根毛刺"免疫，代价是要排序 */
static unsigned int median_code(const unsigned int *a, int n)
{
    unsigned int buf[SAMPLE_N];
    unsigned int key;
    int i, j;

    if (n > SAMPLE_N) {
        n = SAMPLE_N;
    }
    for (i = 0; i < n; ++i) {
        buf[i] = a[i];
    }
    for (i = 1; i < n; ++i) {              /* 插入排序：数据少，够用且稳定 */
        key = buf[i];
        j = i - 1;
        while (j >= 0 && buf[j] > key) {
            buf[j + 1] = buf[j];
            --j;
        }
        buf[j + 1] = key;
    }
    return buf[n / 2];
}

/* 去极值平均：丢掉最大最小，剩下的求平均 —— 均值和中值的折中 */
static unsigned int trimmed_mean(const unsigned int *a, int n)
{
    unsigned int buf[SAMPLE_N];
    unsigned long sum = 0;
    int i, j;

    if (n < 3) {
        return mean_code(a, n);
    }
    if (n > SAMPLE_N) {
        n = SAMPLE_N;
    }
    for (i = 0; i < n; ++i) {
        buf[i] = a[i];
    }
    for (i = 1; i < n; ++i) {
        unsigned int key = buf[i];
        j = i - 1;
        while (j >= 0 && buf[j] > key) {
            buf[j + 1] = buf[j];
            --j;
        }
        buf[j + 1] = key;
    }
    for (i = 1; i < n - 1; ++i) {          /* 掐头去尾 */
        sum += buf[i];
    }
    return (unsigned int)((sum + (unsigned long)(n - 2) / 2) / (unsigned long)(n - 2));
}

10. 核心概念八：采样滤波——为什么你的电压读数在跳

10.1 抖动的四个来源

AD 读数在小数点后第二位来回跳，几乎不是芯片坏了，而是这四件事：

  1. 电源纹波：5V 上有几十毫伏的开关噪声，参考电压跟着抖；
  2. 数字噪声：单片机自己在开关 IO、刷数码管，地线上有毛刺；
  3. 布线：AD 输入线太长、离晶振太近、没有滤波电容；
  4. 量化：最后一位本来就在两个刻度之间来回（±0.5 LSB）。

前三个是硬件问题，先改硬件再谈滤波：给 AD 输入并一个 0.1μF 电容、缩短走线、参考电压加去耦。硬件噪声是「系统性」的，滤波只能压住随机部分。

10.2 三种软件滤波，各有各的脾气

方法 怎么做 压得住什么 代价 适合
算术平均 采 N 次求平均 白噪声（随机小误差），按 1/√N 下降 N 次转换时间 缓慢变化的量（温度、电压）
中值 采 N 次（奇数）排序取中间 偶发的大毛刺 排序的 CPU 时间 有尖峰干扰的场合
去极值平均 去掉最大最小，剩下求平均 毛刺 + 白噪声 排序 + 平均 工程上最常用
一阶低通（IIR） y += (x - y) / 2^k 高频噪声 一个状态变量，纯整数 需要连续跟踪、RAM 紧张

用 §9 那组样本（9 个里混了一个 4095 的毛刺）实测：

一根毛刺，把平均值拉偏了 0.28V。 这就是为什么工业现场测温度、测电压，几乎不会只用算术平均。

10.3 采样窗口与刷新率的取舍

任务 9 要求「每 500ms 上报一次」。这 500ms 就是你的预算：

500ms 预算
  ├── 采 16 次 AD（每次 100μs）        ≈ 1.6ms
  ├── 采 1 次温度（转换 750ms！）      ← 不能在这里死等
  ├── 刷 LCD（差分刷新）               ≈ 1ms
  └── 剩下 497ms 给按键、串口、状态机

注意温度那一行：DS18B20 的 12 位转换要 750ms，比整个上报周期还长。所以正确做法是「上一轮启动转换，这一轮来取结果」——先启动、等一会儿再读，而不是 delay_ms(750)。§11.5 会讲。

10.4 51 上的整数实现

51 没有浮点单元，一次 double 除法要几百个机器周期。所以滤波和换算尽量用整数：

/* 采 N 次求平均，全程整数；N 取 2 的幂时可以用移位代替除法 */
static unsigned int mean_u16(const unsigned int *a, int n)
{
    unsigned long sum = 0;
    int i;
    for (i = 0; i < n; ++i) {
        sum += a[i];
    }
    return (unsigned int)(sum / (unsigned long)n);   /* n = 8/16 时编译器会优化成移位 */
}

温度也一样，用「毫摄氏度」存：0.0625℃ = 62.5 毫度，raw × 625 / 10 就是毫度，全程 long，不碰浮点。这是嵌入式的基本功：能用整数就别用浮点。

11. 核心概念九：DS18B20——一根线上的双向对话

11.1 一根线怎么做到双向

DS18B20 只有三根线：VDD、GND、DQ（数据）。有些用法甚至只要两根（寄生供电，VDD 接 GND，靠 DQ 在总线高电平时偷电）。

DQ 是开漏 + 上拉电阻的结构：芯片只能把线拉低，不能主动拉高；线回到高电平靠一颗 4.7kΩ 的上拉电阻。这样就天然不会「打架」——谁想说话就把线拉低，不想说话就松手。

但只有一根线，没有时钟线，怎么区分「0」和「1」？答案是时间：

写 1：主机拉低 1~15us，然后松手，整个时隙 60~120us
      ┌┐
  ────┘└──────────────────────────
      ↑短低

写 0：主机拉低 60us 以上，然后松手
      ┌──────────┐
  ────┘          └──────────────
      ↑长低

读：  主机拉低 1us 启动时隙，然后松手，
      器件在 15us 内「拉低 = 0」或「不动 = 1」，主机在 15us 内采样
      ┌┐         ┌┐
  ────┘└─────────┘└─────────────
      ↑启动     ↑采样点

一线总线的本质是：主机用「拉低多久」当比特，用「什么时候采样」当时钟。 所以它对你 delay_us 的精度要求很高——这也是为什么很多人「一线总线调不通」，不是逻辑错，是延时不准。

11.2 复位脉冲与存在脉冲：先敲门，再确认有人

每次通信前，主机必须先「敲门」：

主机拉低 >= 480us          释放，等 15~60us        器件拉低 60~240us
     ┌──────────────┐                  ┌────┐
─────┘              └──────────────────┘    └──────────
                     ↑ 主机松手            ↑ 存在脉冲：器件说"我在"
  • 复位脉冲：主机拉低至少 480μs；
  • 存在脉冲（Presence Pulse）：主机松手后，如果在线的器件存在，它会在 15~60μs 内把线拉低 60~240μs。

主机在松手后约 70μs 采样：读到 0 说明「有器件」，读到 1 说明「没人理你」。这一个比特，是你判断「传感器接好没有」的唯一依据。 读不到存在脉冲，后面所有命令都是白费。

11.3 命令：先报名字，再说干什么

DS18B20 的命令分两层：

第一层：ROM 命令（先选定「跟谁说话」）

命令 含义 什么时候用
0x33 读 ROM 想知道器件的 64 位 ID
0xCC 跳过 ROM 总线上只有一个器件时，最常用
0x55 匹配 ROM 一条线上挂多个，指定其中一个
0xF0 搜索 ROM 枚举总线上所有器件的 ID
0xEC 报警搜索 找出超过 TH/TL 的器件

第二层：功能命令（再说「干什么」）

命令 含义 说明
0x44 启动温度转换 转换完结果写进暂存器前两字节
0xBE 读暂存器 连续读 9 个字节
0x4E 写暂存器 写 TH、TL、配置寄存器
0x48 复制暂存器到 EEPROM 掉电保存 TH/TL/配置
0xB8 从 EEPROM 恢复 上电自动恢复

一次完整的读温度，就是「复位 → 0xCC → 0x44 → 等 → 复位 → 0xCC → 0xBE → 读 9 字节」。为什么每次都要重新复位？ 因为一线总线没有「会话」的概念，一次复位就是一次清场，中间隔了 750ms 的转换，不复位你没法保证状态还对不对。

11.4 12 位温度值：补码，低 4 位是小数

暂存器的前两个字节拼成一个 16 位有符号数：

  bit15  bit14 ... bit11  bit10 ... bit4   bit3 bit2 bit1 bit0
    │                      │                └────┬───────────┘
    │                      │                     └─ 小数部分，1 LSB = 0.0625℃
    │                      └─ 整数部分
    └─ 符号位：0 正，1 负（整个 16 位是补码）

举几个必须记住的值：

温度 16 位原始值 十进制（int16_t） 说明
+125.0000℃ 0x07D0 2000 上限
+85.0000℃ 0x0550 1360 上电默认值
+25.0625℃ 0x0191 401 常见室温
+0.5000℃ 0x0008 8 最小正小数
0.0000℃ 0x0000 0
-0.5000℃ 0xFFF8 -8 补码：65536-8
-10.1250℃ 0xFF5E -162
-25.0625℃ 0xFE6F -401 经典负温测试值
-55.0000℃ 0xFC90 -880 下限

负温度的处理，一行代码就够，但前提是类型对：

int16_t raw = (int16_t)(((uint16_t)msb << 8) | lsb);   /* 必须是有符号 16 位 */
double  celsius = (double)raw * 0.0625;

如果你写成 unsigned int raw = (msb << 8) | lsb;，0xFF5E 会变成 65374，乘 0.0625 得到 4085.875℃。这个数字很荒唐，但在串口助手里看到它的人不少——因为 C 里的「符号」是类型给的，不是你看出来的。

11.5 85℃：一个必须认识的特殊值

DS18B20 上电后，暂存器里的温度默认是 +85.0℃（0x0550）。这不是测量结果，是「我还没量过」的占位值。

所以你看到 85℃，正确的反应是：

  1. 转换命令（0x44）发出去了吗？
  2. 转换时间等够了吗（12 位要 750ms）？
  3. 复位/存在脉冲正常吗？读回的是不是全 0xFF（说明根本没连上）？
  4. 供电够吗（寄生供电时转换期间需要强上拉）？

千万不要把它当室温解释。 一个 25℃ 的屋子显示 85℃，只可能是「没转换」或「没读到」，不可能是「真的很热」。

转换时间与分辨率是绑定的：

分辨率 1 LSB 最长转换时间
9 位 0.5℃ 93.75ms
10 位 0.25℃ 187.5ms
11 位 0.125℃ 375ms
12 位 0.0625℃ 750ms

11.6 先启动、等一会儿再读

任务 9 要每 500ms 上报，任务 A 要同时刷屏、扫按键、收串口。没有人在主循环里 delay_ms(750)。

正确姿势是把「读温度」拆成两个状态：

状态 A（发起）：复位 -> 0xCC -> 0x44 -> 记下当前时间 -> 进入状态 B
状态 B（取回）：每次 tick 检查「距离发起已过 750ms 吗？」
                没过 -> 直接返回，干别的
                过了 -> 复位 -> 0xCC -> 0xBE -> 读 9 字节 -> 解析 -> 回状态 A

这叫非阻塞，和你阶段十写的「时间片流水灯」是同一个思想：把「等」变成「下次再来看看」。

11.7 完整示例：时序、补码、负温、85℃

/* 04_ds18b20_temp.c —— 一线总线时序模拟 + 12 位温度补码解析
 * 编译：gcc -Wall -Wextra -std=c99 04_ds18b20_temp.c -o 04_ds18b20_temp.exe
 *
 * 真实 Keil C51 里，只有一根线：
 *     sbit DQ = P3^7;
 * 拉低、释放、读电平，全靠这一根线；没有时钟线，时间就是协议本身。
 * 本文件保留了主机侧全部时序动作（拉低多久、什么时候采样），
 * 器件侧用一个按字节回应的模型代替——它内部也有个状态机。
 */
#include <stdio.h>
#include <stdint.h>

/* ============================================================
 * 一、器件模型：DS18B20 的 9 字节暂存器 + 一个命令状态机
 * ============================================================ */
typedef struct {
    unsigned char scratch[9];    /* [0]温度低 [1]温度高 [2]TH [3]TL [4]配置 ... [8]CRC */
    int state;                   /* 0 等 ROM 命令  1 等功能命令  2 正在往外发数据 */
    int bit_idx;
    unsigned char shift;         /* 主机写进来的位拼成字节 */
    unsigned char cmd;           /* 最近一条 ROM 命令 */
    int out_idx;                 /* 往外发到第几个字节 */
    int out_bit;                 /* 发到该字节第几位 */
    int16_t pending_raw;         /* 下一次 0x44 转换要写进暂存器的值 */
} ds18b20_t;

static ds18b20_t dev;
static int g_line = 1;           /* 总线电平：0 低，1 释放（由 4.7k 上拉拉高） */
static unsigned long ow_us;      /* 虚拟时钟：这一根线上的"时间" */

static void ow_delay_us(unsigned int us)
{
    ow_us += us;
}

/* 上电：暂存器里躺着 85.0℃。这不是巧合，是芯片的默认值 */
static void dev_power_on(void)
{
    int i;

    for (i = 0; i < 9; ++i) {
        dev.scratch[i] = 0;
    }
    dev.scratch[0] = 0x50;       /* +85.0℃ = 1360 = 0x0550 */
    dev.scratch[1] = 0x05;
    dev.scratch[2] = 0x4B;       /* TH = 75℃（报警上限默认值） */
    dev.scratch[3] = 0x46;       /* TL = 70℃（报警下限默认值） */
    dev.scratch[4] = 0x7F;       /* 配置：12 位分辨率 */
    dev.state = 0;
    dev.bit_idx = 0;
    dev.shift = 0;
    dev.pending_raw = 0x0550;
}

/* 器件收到一个完整字节 */
static void dev_handle_byte(unsigned char b)
{
    if (dev.state == 0) {
        dev.cmd = b;
        if (b == 0xCC) {                 /* 跳过 ROM：总线上只有一个器件时用它 */
            dev.state = 1;
        } else if (b == 0x33) {          /* 读 ROM：8 字节 ID，本文件不模拟 */
            dev.state = 0;
        } else {
            dev.state = 0;
        }
    } else if (dev.state == 1) {
        if (b == 0x44) {                 /* 启动一次温度转换 */
            dev.scratch[0] = (unsigned char)(dev.pending_raw & 0xFF);
            dev.scratch[1] = (unsigned char)((dev.pending_raw >> 8) & 0xFF);
            dev.state = 0;
        } else if (b == 0xBE) {          /* 读暂存器：9 个字节，低位先出 */
            dev.out_idx = 0;
            dev.out_bit = 0;
            dev.state = 2;
        } else {
            dev.state = 0;
        }
    }
}

/* 主机每写一位，器件在时隙里采样一次 */
static void dev_sample_bit(int b)
{
    if (dev.state == 2) {
        return;                          /* 正在发数据，主机写什么都当没看见 */
    }
    dev.shift = (unsigned char)((dev.shift >> 1) | (b << 7));
    if (++dev.bit_idx == 8) {
        dev_handle_byte(dev.shift);
        dev.shift = 0;
        dev.bit_idx = 0;
    }
}

/* 主机读一位时，器件决定把线拉低（0）还是放开（1） */
static int dev_drive_bit(void)
{
    int b;

    if (dev.state != 2) {
        return 1;                        /* 没在发数据：线保持高 */
    }
    b = (dev.scratch[dev.out_idx] >> dev.out_bit) & 1;
    if (++dev.out_bit == 8) {
        dev.out_bit = 0;
        if (++dev.out_idx >= 9) {
            dev.out_idx = 0;
            dev.state = 0;               /* 9 个字节发完，回到等命令 */
        }
    }
    return b;
}

/* ============================================================
 * 二、主机侧：一线总线的四个基本动作
 * ============================================================ */

/* 复位 + 等存在脉冲。返回 1 表示器件在线 */
static int ow_reset(void)
{
    int presence;

    g_line = 0;                          /* ① 主机把线拉低 */
    ow_delay_us(480);                    /*    至少 480us */
    g_line = 1;                          /* ② 释放，上拉电阻把线拉高 */
    ow_delay_us(30);                     /*    器件会在 15~60us 内响应 */
    g_line = 0;                          /* ③ 器件拉低 60~240us：这就是"存在脉冲" */
    presence = (g_line == 0);
    ow_delay_us(420);                    /* ④ 等它说完，整个复位时隙约 960us */
    g_line = 1;
    return presence;
}

/* 写一位：靠"拉低多久"区分 0 和 1 */
static void ow_write_bit(int b)
{
    g_line = 0;                          /* 每个时隙都从拉低开始 */
    if (b) {
        ow_delay_us(2);                  /* 短低（1~15us）后释放 = 写 1 */
        g_line = 1;
        ow_delay_us(60);
    } else {
        ow_delay_us(60);                 /* 长低（>=60us）= 写 0 */
        g_line = 1;
        ow_delay_us(2);
    }
    dev_sample_bit(b);
}

/* 读一位：主机先拉低启动时隙，然后松手，让器件说话 */
static int ow_read_bit(void)
{
    int b;

    g_line = 0;
    ow_delay_us(2);                      /* 拉低至少 1us 启动时隙 */
    g_line = 1;                          /* 松手，把线交给器件 */
    ow_delay_us(10);                     /* 器件必须在 15us 内给出数据 */
    b = dev_drive_bit();
    if (b == 0) {
        g_line = 0;                      /* 器件拉低 = 0 */
    }
    ow_delay_us(50);
    g_line = 1;
    return b;
}

static void ow_write_byte(unsigned char v)
{
    int i;

    for (i = 0; i < 8; ++i) {            /* 低位在前 */
        ow_write_bit(v & 0x01);
        v = (unsigned char)(v >> 1);
    }
}

static unsigned char ow_read_byte(void)
{
    unsigned char v = 0;
    int i;

    for (i = 0; i < 8; ++i) {
        v = (unsigned char)(v >> 1);
        if (ow_read_bit()) {
            v |= 0x80;
        }
    }
    return v;
}

/* ============================================================
 * 三、一次完整的温度读取：复位 -> 跳过 ROM -> 转换 -> 等 -> 读
 * ============================================================ */
static unsigned char g_sp[9];            /* 最近一次读到的暂存器，留着给演示用 */

static int ds18b20_read_raw(int16_t *raw)
{
    int i;

    if (!ow_reset()) {
        return 0;
    }
    ow_write_byte(0xCC);                 /* 跳过 ROM：只有一个器件，不用报 ID */
    ow_write_byte(0x44);                 /* 启动转换 */
    ow_delay_us(750000);                 /* 12 位最长 750ms；这段时间可以去干别的 */

    if (!ow_reset()) {
        return 0;
    }
    ow_write_byte(0xCC);
    ow_write_byte(0xBE);                 /* 读暂存器 */
    for (i = 0; i < 9; ++i) {
        g_sp[i] = ow_read_byte();
    }
    *raw = (int16_t)(((uint16_t)g_sp[1] << 8) | g_sp[0]);
    return 1;
}

/* 12 位补码 -> 摄氏度。低 4 位是小数，1 个 LSB = 0.0625℃ */
static double raw_to_celsius(int16_t raw)
{
    return (double)raw * 0.0625;
}

int main(void)
{
    int16_t raw;
    int i;

    printf("== 1. 上电默认值：85.0℃（还没转换过）==\n");

12. 核心概念十：把芯片当「黑盒 + 时序」——怎么读数据手册

12.1 你不需要「懂」一颗芯片，只需要会「用」它

DS1302 内部有分频器、比较器、充电电路；DS18B20 内部有带隙基准、ADC、CRC 发生器。这些你一辈子都不用懂。

你只需要建立一个模型：芯片 = 一个状态机 + 一堆寄存器 + 一层物理层协议。

  • 状态机：它现在在等什么？（等命令？等数据？正在转换？）
  • 寄存器：我把什么写进去，能把什么读出来？
  • 物理层：电平时序是什么？拉高多久算一个脉冲？在哪个边沿采样？

数据手册就是这三样东西的说明书。读它不需要从头读到尾，只需要按需抄五样。

12.2 五步抄书法

步骤 看手册哪一节 你要抄下来的东西
① 它是干什么的 第一页 Description / Features 一句话定位（"带电池的日历"、"一线数字温度计"）
② 怎么接线 Pin Configuration + Typical Application Circuit 每个脚接哪、上拉电阻多大、要不要外部晶振
③ 怎么说话 Command Set / Register Map 命令字节格式、寄存器地址、读写位、数据格式（BCD？补码？）
④ 什么时候能采样 AC/DC Characteristics + Timing Diagram 最小/典型/最大时间：脉冲宽度、建立时间、转换时间
⑤ 什么会弄坏它 Absolute Maximum Ratings 电压上限、温度上限、ESD 注意事项

注意第 ④ 步里的「min / typ / max」三列。 写代码时要按 min 和 max 留余量，不能按 typ 写。比如手册说复位脉冲「min 480μs」，你就写 500μs，不要写 480μs——晶振误差、中断延迟都会吃掉那 20μs。

12.3 三条纪律

  1. 不信博客，信手册。 网上的 1602 初始化代码有一半漏了 15ms 延时；DS18B20 的延时参数在不同批次、不同主频下都要重算。手册是唯一权威。
  2. 不确定的地方，写「以数据手册为准」。 这句话不是偷懒，是工程素养——它提醒你「这里有个假设，换芯片要重新确认」。
  3. 时序留余量，不要卡在边界上。 手册说「最小 1μs」，你写 2μs；说「最长 750ms」，你等 800ms。在嵌入式中，「刚好满足」等于「随时会坏」。

12.4 芯片「不回应」时的排查顺序

按这个顺序，不要跳：

① 量电源和地        VCC 真的是 5V 吗？GND 真的通吗？（万用表，30 秒）
② 量上拉 / 晶振      一线总线的 4.7k 装了吗？DS1302 的 32.768kHz 起振了吗？
③ 量控制线          RST 真的被拉高了吗？E 真的有下降沿吗？（示波器/逻辑分析仪）
④ 慢速重放          把延时全部放大 100 倍，看能不能通——能通说明是时序太快，不是逻辑错
⑤ 只发一个字节      只发命令、不读数据，用逻辑分析仪看波形对不对
⑥ 换一颗芯片        以上都对他还不理你，可能真的坏了

第 ④ 步是穷人的示波器：把时序放慢 100 倍，如果芯片开始回应，说明你的逻辑是对的、延时算错了；如果还是不回应，说明接线或命令字节错了。这一招救过无数没有示波器的夜晚。

13. 核心概念十一：综合项目架构——状态机 + 多文件分层 + 模块接口

13.1 任务 A 是一道架构题，不是功能题

把任务 A 的需求摊开看：

  • 上电显示时间 + 温度，可整屏移动；
  • K1 进密码页，串口提示，每输一个字符液晶多一个 *；
  • K4 验证，通过则显示时间 + 个人信息 + 设置菜单；失败提示重试；三次失败回上电页且 K1/K4 失效；
  • 菜单四项：设时间、设闹钟、开关闹钟、退出；
  • 闹钟到点响 15 秒；
  • 时间要年月日星期时分秒；
  • 必须多文件模块化。

这里面没有一个是「难写的算法」。难的是：这些事要同时活着。

  • 你在等用户输密码，闹钟到点了要不要响？
  • 你在设置时间，500ms 的刷新要不要继续？
  • 你在响闹钟的 15 秒里，按键要不要响应？
  • 串口来一个字符，它到底是密码的第 3 位，还是菜单的选项 2？

如果你写成「一个 while(1) 里顺序执行 + 一堆 delay」，上面四个问题的答案全是「不行」。架构不是为了好看，是为了让这些事能同时发生。

13.2 分层：谁可以调用谁

        ┌────────────────────────────────────────────────┐
        │ main.c     上电初始化、主循环、把事件喂给状态机    │
        ├────────────────────────────────────────────────┤
        │ app.c      状态机：状态 × 事件 → 新状态 + 动作     │
        ├───────────────┬────────────────┬───────────────┤
        │ ui.c          │ clock.c        │ sensor.c      │
        │ 屏幕怎么画     │ 时间从哪来      │ 温度从哪来     │
        ├───────────────┴────────────────┴───────────────┤
        │ comm.c     串口收行、发提示、解析命令             │
        ├────────────────────────────────────────────────┤
        │ bsp.c      sbit、delay_us、三线 / 一线时序       │
        └────────────────────────────────────────────────┘
              依赖只能从上往下，不能从下往上

规矩只有一条：箭头只能向下。 ui.c 不许 #include "clock.h" 去直接读 DS1302；clock.c 不许知道屏幕有几行；bsp.c 更不许知道「密码」是什么。

为什么？因为下层是「会变的」，上层是「相对稳定的」。

  • 换一块屏（1602 → 12864），只改 ui.c 和 bsp.c；
  • 换一颗时钟（DS1302 → DS3231），只改 clock.c 和 bsp.c；
  • 换一种输入（按键 → 矩阵键盘），只改 main.c 的事件采集。

如果依赖反了（比如 clock.c 里直接 lcd_puts 显示时间），那换屏就要动时钟模块，换时钟就要动显示模块——这就是「耦合」的代价。

13.3 模块职责表：每个模块「知道什么、不知道什么」

模块 负责 不该知道 对外接口（形状）
main.c 初始化、1ms 节拍、采集按键/串口事件、调用 app_step 任何芯片时序、任何屏幕坐标 int main(void);
app.c 状态机、守卫判断、动作编排、超时与重试计数 字节怎么移位、字符怎么写进 DDRAM app_state_t app_step(app_state_t, app_event_t, const char **why);

13.4 接口形状：签名先定，实现后填

接口不需要写实现，但必须先定下来，因为它是模块之间的合同：

/* clock.h —— 时间从哪来，由这个接口说了算，不由 DS1302 说了算 */
typedef struct {
    unsigned char year, month, day, week, hour, min, sec;
} rtc_time_t;

typedef struct {
    const char *name;
    int (*read)(rtc_time_t *out);
    int (*write)(const rtc_time_t *t);
} time_source_t;

/* sensor.h —— 温度也一样，单位统一用毫摄氏度，避免浮点 */
int sensor_read_temp(int *milli_c);

/* ui.h —— 界面只认"模型"，不认芯片 */
typedef struct {
    rtc_time_t now;
    int temp_milli_c;
    unsigned char alarm_on;
} app_model_t;

void ui_init(void);
void ui_render(app_state_t st, const app_model_t *m);
void ui_message(const char *line);        /* 临时提示，如 "Password Error" */

/* comm.h —— 通信层只负责"收一行/发一行" */
int  comm_poll(char *line, int cap);      /* 1 = 收到完整一行 */
void comm_send_line(const char *s);

注意 time_source_t 里的函数指针——这正是阶段八讲过的「函数指针数组做菜单分派」的复用。有了它，app.c 只写 g_clock.read(&t)，根本不知道背后是 DS1302、是数组、还是串口来的时间。

这就是「把时间从哪来抽象成接口」。 它不是炫技，它带来三个实打实的好处：

  1. 可测试：PC 上用假时钟跑 ui.c，不用接硬件；
  2. 可替换：明天换 DS3231，只写一个新的 read 函数；
  3. 可并行：队友写 clock.c，你写 ui.c，接口定了就能同时开工。

13.5 状态机：把「现在在哪」画出来

任务 A 的主流程，本质是七个状态：

状态 屏幕在显示什么 响应什么 绝对不能做什么
BOOT 时间 + 温度（可整屏移动） K1、500ms 节拍 收串口字符当密码
PASSWORD 串口提示 + 若干个 * 串口字符、K4 显示时间、响应菜单
MAIN 时间 + 个人信息 + 菜单 菜单选择、闹钟、节拍 再进一次密码
SET_TIME 设置界面 选择/确认/取消 直接改 DS1302 而不校验
SET_ALARM 闹钟设置界面 选择/确认/取消 把非法时间写进芯片
ALARM_ONOFF 开关状态 选择/确认/取消 忘记保存状态
LOCKED 上电页（但 K1/K4 失效） 只有复位/重新上电 响应 K1、K4

事件（输入只有这几类，别再多）：

事件 来源 说明
EV_K1 / EV_K4 按键扫描（消抖后） 只在「按下那一刻」产生一次
EV_UART_LINE 串口收到一行/一个字符 密码字符也走这里
EV_TICK 定时器 500ms 刷新、比较闹钟、超时计数
EV_ALARM 时间比较命中 触发蜂鸣 15s
EV_CHOICE_1~4 菜单选择 由 app_map_line 或按键映射而来

转移图（这张图建议手画一遍）：

                 ┌──────────────────────────────────────────┐
                 │                                          │
                 v                                          │
   ┌─────────┐  K1   ┌──────────┐  密码对 + K4   ┌────────┐  │ 菜单4
   │  BOOT   │──────>│ PASSWORD │──────────────>│  MAIN  │──┘
   │ 上电页  │       │  密码页   │               │ 主界面 │
   └─────────┘       └──────────┘               └────────┘
        ^                  │  密码错且还有次数        │
        │                  └──────────┐             ├──菜单1──> SET_TIME
        │                             v             ├──菜单2──> SET_ALARM
        │                        (留在 PASSWORD)    └──菜单3──> ALARM_ONOFF
        │                  │  三次都错
        │                  v
        │            ┌──────────┐
        └────────────│  LOCKED  │   （没有出口，只有复位）
         重新上电     └──────────┘

画完这张图，你会发现两件事：

  1. LOCKED 是「没有出口」的状态——只要转移表里不给它任何入口，K1/K4 自然就失效了。你不需要写 if (locked) return;。
  2. 密码页和主界面是两个平行的状态，不是「登录成功后再套一个循环」。这正是阶段八 §10.2 讲过的那件事。

13.6 表驱动 vs switch：两种写法都要会

状态机有两种常见实现：

对比项 switch (state) 大函数 转移表 TRANS[]
可读性 一个状态一个 case，流程直观 流程变成数据，一眼看全
加状态 改函数、加 case 加几行数据
守卫（条件） 嵌套 if，容易越写越深 (from, event, guard, to) 四元组，清爽
调试 打断点方便 打印一条转移日志就够
适合 状态少于 5 个、逻辑简单 状态多、事件多、要反复改

建议：先用 switch 写出能跑的版本（直观、好调），再把「状态 × 事件」的部分抽成表。任务 A 有七个状态、九类事件，用表会明显省心——尤其是「三次失败」这种带守卫的转移，表里一行就说完，switch 里要嵌三层 if。

13.7 串口命令与菜单的耦合：同一个字符，两种含义

这是任务 A 最容易写乱的地方。

串口只有一个入口，但它在不同状态下含义完全不同：

收到 "1" 时所在状态 它是什么意思
PASSWORD 密码的第 1 个字符
MAIN 菜单的第 1 项

所以解析不能在通信层做。通信层只负责「收一行，交上去」；翻译是状态机的事：

/* 同一行字符，在不同状态下的含义不同 —— 这就是"命令解析与菜单的耦合" */
static app_event_t app_map_line(app_state_t st, const char *line)
{
    if (st == ST_PASSWORD) {
        return EV_UART_LINE;              /* 密码阶段：每个字符都是密码的一部分 */
    }
    if (line[0] >= '1' && line[0] <= '4' && line[1] == '\0') {
        return (app_event_t)(EV_CHOICE_1 + (line[0] - '1'));
    }
    return EV_NONE;
}

反面教材：在串口中断里直接 if (c == '1') set_time();。这样写，密码页永远收不到 '1'，而且中断里干了重活（改时间、刷屏），主循环的时间全乱。

13.8 超时、重试与非阻塞：三件必须提前设计的事

① 重试：密码三次失败。计数放在 app.c（状态机的一部分），不放在 ui.c（界面不该记仇）。

② 超时：

  • 串口收行：如果只收到半个行、迟迟没有换行，要有超时把它清掉，否则缓冲区永远是脏的；
  • 密码输入：用户按了 K1 进去又不动，要不要超时退回上电页？按任务要求决定；
  • 传感器：ow_reset 读不到存在脉冲，不能死等，下一拍再试；
  • while (BF) ; 查忙循环必须加超时，否则一根线松了，整机卡死。
/* 带超时的等待，是嵌入式的保命写法 */
static int lcd_wait_busy_timeout(unsigned int max_us)
{
    unsigned int n = 0;
    while (lcd_is_busy()) {
        if (++n > max_us) {
            return 0;              /* 超时：报错、复位、或者干脆放弃这次操作 */
        }
        delay_us(1);
    }
    return 1;
}

③ 非阻塞：闹钟响 15 秒、温度转换 750ms、整屏移动的动画——都不能用 delay。

记下开始时刻 t0，每次 tick 判断 (now - t0) < 15000
  是 -> 继续响、继续等
  否 -> 关蜂鸣器、清标志

这三件事，在写第一行代码之前就要在架构里留好位置。等写到一半再补，通常意味着推倒重来。

13.9 可测试性：不接硬件也能验证一半的逻辑

有了 time_source_t 这个接口，你可以在 PC 上做这些事：

  • 把 g_clock.read 换成「返回一个固定时间」的假函数，验证 ui_render 画出来是不是 16 个字符、有没有越界；
  • 把时间设成 23:59:59，验证进位那一秒的显示；
  • 把时间设成闹钟前 1 秒，验证 15 秒计时逻辑；
  • 喂一串「错、错、错」的密码结果，验证第三次之后是否进 LOCKED。

这些都不需要一块板子。 阶段十你已经在 PC 上模拟过 SFR 和引脚，这里是同一套思路的升级版：模拟的不是引脚，是「数据源」。

/* 核心：给一个状态和一个事件，算出下一个状态 */
static app_state_t app_step(app_state_t st, app_event_t ev, const char **why)
{
    size_t i;
    int matched = 0;
    int unimplemented = 0;

    *why = "该状态没定义这个事件：忽略";
    for (i = 0; i < sizeof TRANS / sizeof TRANS[0]; ++i) {
        int ok;

        if (TRANS[i].from != st || TRANS[i].event != ev) {
            continue;
        }
        matched = 1;
        ok = guard_run(TRANS[i].guard);
        if (ok < 0) {
            unimplemented = 1;
            continue;
        }
        if (ok == 0) {
            continue;
        }
        *why = TRANS[i].note;
        return TRANS[i].to;
    }
    if (unimplemented) {
        *why = "守卫尚未实现（返回 -1）：本次不转移";
    } else if (matched) {
        *why = "候选守卫全部拒绝：本次不转移";
    }
    return st;
}

        }
        g_ctx.password_ok = DEMO[i].password_ok;

    printf("\n把 fake_clock_read 换成 DS1302 的读函数，ui_draw 一行都不用改。\n");

}

跑完看三件事：

  1. LOCKED 状态下按 K1、K4 都没有转移——因为表里根本没有这两行。这就是「用数据结构表达规则」；

17. 安全与规范：本阶段三条铁律

铁律一：接线先断电，电源和地不许「试错」。

  • 插拔任何模块（DS1302、1602、DS18B20）之前先断电。带电插拔最容易把 VCC 和 GND 短暂短在一起；
  • DS1302 的备用电池有极性，装反可能鼓包甚至漏液；换电池前先看模块丝印；
  • 1602 的背光（A/K）必须串限流电阻，直接接 5V 会烧背光；VO 对比度脚不要直接接 VCC 或 GND，用分压或电位器；
  • DS18B20 的 DQ 需要 4.7kΩ 上拉，不要用单片机内部上拉代替（太弱，长线拉不起来）。

铁律二：每一条「等芯片」的循环，都必须有超时。

  • while (BF) ;、while (!EOC) ;、while (!presence) ;——这三个是嵌入式最经典的死机点。总线一松、芯片一坏，程序就永远停在那里，看门狗都救不回来（如果你没开）；
  • 正确写法是「计数 + 上限」：for (n = 0; n < MAX; ++n) { if (ok) break; }，超时就报错、重试或跳过；
  • 同理，串口收行要有时限，密码输入要有时限，温度转换要有「最晚什么时候必须回来」的兜底。

铁律三：任何来自外部的时间、温度、串口字节，进显示或存储前必须做范围检查。

  • BCD 只允许 0x00~0x99 且低四位 ≤ 9；用户输入的「25:99」必须被拒绝，而不是写进芯片；
  • 数组下标、DDRAM 列号、密码缓冲区长度，全部要在写入前判断；lcd_puts 里那句 if (col >= LCD_COLS) return; 不是多余的；
  • 串口来的一行可能超长、可能没有 \0、可能全是控制字符；缓冲区永远留一个字节给 '\0'，超长部分丢弃；
  • 浮点只用在上位机或调试输出；51 里能用整数（毫伏、毫度、毫秒）就用整数。

20.2 回望三篇 51 实战

  • 实战一《数码管、按键与蜂鸣器》，你让四个数字同时活着：动态扫描、消隐、时间片、按键消抖、矩阵键盘。那时候你第一次发现，「同时做几件事」靠的不是 CPU 更快，而是把时间切片。
  • 实战二《定时器、串口与 I2C》，你让设备有了真实的时间、听懂人话、记住事情：定时器给出 1ms 节拍，串口把一句话送出板子，EEPROM 把参数留在掉电之后。那时候你明白了「延时不可靠，硬件才可靠」。
  • 实战三（这一篇），你让板子有了「时间感」和「感知」：它知道今天几号星期几，知道屋子里多少度，能把此刻存下来再拿出来，能在你输错三次密码之后把自己锁上。

三篇连起来，是一条很完整的线：表达 → 时序 → 通信 → 感知 → 决策。这也是任何一台嵌入式设备的内核。

20.3 复盘四问

  1. 时间为什么必须交给外部芯片？ 如果让你用 51 的定时器 + 软件计数自己做一个万年历，你会遇到哪三个麻烦（掉电、累积误差、闰年/大小月）？你能接受哪个，不能接受哪个？
  2. LCD 的初始化序列里，哪一步是「防不确定状态」的？ 为什么它比「多延时一会儿」更可靠？这个「把不确定收敛到确定」的思路，能不能搬到别的地方——比如串口帧同步、状态机复位、通信重连？
  3. 任务 A 的「三次失败锁死」，用状态表实现和用一串 if 实现，差别在哪？ 如果需求改成「锁死 30 秒后自动解锁」，你的架构要改几处？改一处还是改五处，就是架构好坏的试金石。
  4. 把「时间从哪来」抽象成接口，除了「换芯片方便」，还给你带来了什么？ 如果面试官问你「你怎么测试一个没有屏幕、没有键盘的单片机程序」，你会拿这一篇的哪个例子回答？

20.4 之后往哪走

51 任务线到这里就收官了。接下来有三条路，可以并行，也可以按顺序：

① STM32（最自然的下一步）。 32 位内核、几百个寄存器、有库函数和 HAL、有 DMA、有真正的调试器（SWD + 断点）。你会发现：GPIO 还是那些 GPIO，串口还是那些串口，只是「配置」从「写一个 SFR」变成了「填一个结构体再调 HAL_Init」。你在 51 上练出来的「看手册、算时序、分层写代码」的能力，一点都不会浪费。

② RTOS（FreeRTOS / RT-Thread）。 你在这一篇里写的那个「每 1ms 被调用一次、自己判断该不该干活」的 tick 状态机，就是 RTOS 调度器的手工版。到了 RTOS，app_step 会变成一个任务，EV_TICK 会变成一个软件定时器，TRANS[] 会变成一张事件表——概念是通的，只是内核替你管了栈和优先级。

③ 参加比赛（实验室的机器人项目）。 比赛和作业最大的区别是：作业只要「跑通一次」，比赛要「稳定跑 10 分钟不重启」。你会发现这一篇里那些「多余」的东西——超时、重试、边界检查、非阻塞、可测试的接口——全都是为「稳定」准备的。能跑是及格，稳定才是成绩。

20.5 最后一段话

从阶段一你在控制台打出第一行 printf，到今天你能让一块 8 位单片机知道「2025 年 10 月 25 日，星期六，13:14:05，室温 25.4℃」，中间隔着十几个阶段、几十个练习、几百个 bug。

这一路你学的东西，说到底是同一件事：把「我以为它会怎样」变成「我知道它为什么这样」。

  • 灯不亮，你知道去查接法，而不是乱改代码；
  • 时间不走，你知道先看 CH，而不是怀疑芯片坏了；
  • 屏是黑的，你知道先调 VO、再看初始化延时，而不是重装整个工程；
  • 温度是 85℃，你知道那是「没量过」，而不是「真的很热」。

这种「知道先看哪里」的直觉，才是这套资料真正想给你的东西。 语法会忘，寄存器名会忘，但这种直觉会跟着你进 STM32、进 RTOS、进比赛、进工作。
