2. 场景引入：你让灯亮 200ms，靠的其实是「数数」

阶段十最后一节，我们停在一句话上：

真正的单片机工程里，时间从来不是「数出来的」，是「硬件量出来的」。

那句话当时只是个结论。今天，它是你要拆的第一颗螺丝。

先把你上个月写过的那个延时搬出来：

/* 片段：51 教程里最常见的延时，靠空循环"磨"时间。
 * 先别急着编译——它的毛病不在语法，在"它凭什么准"。 */
void delay_ms(unsigned int ms)
{
    unsigned int i, j;
    for (i = 0; i < ms; ++i) {
        for (j = 0; j < 110; ++j) {
            /* 空转 */
        }
    }
}

110 这个数是从哪来的？是某篇教程在 12MHz 的板子上一次一次试出来的。也就是说，这段代码的「准确」，建立在一串非常脆弱的前提上：

  • 前提一：编译器不优化它。 阶段十 §6 你亲眼见过：-O2 会把没有副作用的空循环整个删掉，延时从 34ms 直接变成 0ms；
  • 前提二：晶振正好是 12MHz。 换成 11.0592MHz（串口常用），同样的 110 次，时间变成 1.085 倍；换成 1T 单片机，快 12 倍；
  • 前提三：没有任何中断插队。 定时器一响、串口一收，CPU 跑去处理，你的 200ms 就变成 200ms 加几毫秒——而且每次加多少还不一样。

三个前提，你一个都控制不了。

于是「让灯亮 200ms」这件事，本质上是这样一个过程：你写了一串指令，然后祈祷它们花的时间刚好是 200ms。 点灯时这没问题，差 10% 人眼看不出来。但如果任务变成这样呢？

做一个 10 秒的计时游戏，五位数码管显示 00.000 到 19.999，key1 启动、key2 暂停、key3 清零，还有后门 key4。

「暂停」这两个字，直接把软件延时判了死刑：你没法让一个 for 循环暂停，它只会跑完。 而硬件定时器可以——它就是一个计数器，你把它的时钟源一关、或者干脆把 TR0 清 0，它就真的停在那个数上，等着你。

所以这一篇要解决的，其实是三个问题：

问题 人话 硬件答案
时间从哪来 我要一个真的、能走能停的毫秒 定时器/计数器 T0、T1
设备怎么听懂人话 上位机发 m1，我怎么知道这是一条命令、而不是一堆散字符 UART 串口 + 命令解析状态机
设备怎么记住事 断电重来，计数得从上次那个数接着走 I2C 总线 + AT24C02 EEPROM

三块硬件，三套规矩。难点不在「C 语言怎么写」——那些你都会了；难点在「规矩怎么用代码满足」。这一篇就是把这三套规矩一条一条拆开，拆完再拼回去。

3. 定时器的硬件结构：一个会自己加一的 16 位加法器

3.1 它其实只会一件事：+1

51 内部有两个定时器/计数器，叫 T0 和 T1。名字里带「计数器」三个字，是因为它本质上就是一个加法器：

  • 设成定时器模式，它数的是机器周期（内部时钟）；
  • 设成计数器模式，它数的是T0/T1 引脚上进来的脉冲（外部事件）。

数到 65536 装不下，就叫溢出，硬件把标志位 TF0 置 1。就这么简单。

它没有「秒」的概念，也没有「毫秒」的概念。它只知道「我又数了一个」。把「数了多少个」翻译成「过了多久」，是你的事，不是它的事。

3.2 为什么拆成 TH0 和 TL0 两个字节

16 位计数器在芯片里叫 TH0（高 8 位）和 TL0（低 8 位），因为 51 是 8 位机，内部总线一次只能搬一个字节。你想读一个 16 位的计数值，CPU 得读两次：

       TH0            TL0
   ┌──────────┬──────────┐
   │ 高 8 位   │ 低 8 位   │   合起来 = 0 ~ 65535
   └──────────┴──────────┘

这个「读两次」埋了一个坑：你读完 TH0、还没读 TL0 的时候，TL0 可能刚好溢出并向 TH0 进位。 于是你读到的「高字节」是进位前的、「低字节」是进位后的，拼起来差了一大截。这个坑在 §5.6 讲临界区时再收拾。

3.3 TMOD：四个开关决定它怎么数

TMOD 一个字节管两个定时器，高 4 位管 T1，低 4 位管 T0，两边布局一模一样：

位 名字 = 0 = 1
bit3 GATE 只由 TR 控制启停 还要 INT 引脚为高才启动（测脉宽用）
bit2 C/T 定时器：数内部机器周期 计数器：数 T 引脚上的下降沿
bit1 M1 和 M0 一起选方式 同上
bit0 M0 同上 同上

四种工作方式：

M1 M0 方式 位数 12MHz 下最多定时 溢出后 典型用途
0 0 方式 0 13 位 8.192ms 归零，要软件重装 兼容老 8048，基本不用
0 1 方式 1 16 位 65.536ms 归零，要软件重装 最常用：1ms / 10ms / 50ms 节拍
1 0 方式 2 8 位 256μs 硬件自动从 TH 重装 波特率发生器；很短的定时
1 1 方式 3 拆分 — — T0 拆成两个 8 位；T1 停用

这张表里有三个地方要停一下：

  1. 方式 0 是历史包袱。 它是给 8048 时代留的兼容模式，今天没人用。你在别人的代码里看到 TMOD = 0x00，八成是从一本很老的书上抄的。
  2. 方式 1 是主力。 16 位、能数 65.5ms，几乎所有「毫秒节拍」都用它。代价是溢出后必须手动重装初值。
  3. 方式 2 是「自动重装」，但只有 8 位。 它溢出时硬件自动把 TH0 的值再装进 TL0，中间不经过软件，所以没有软件延迟导致的误差——这正是它被拿去做波特率发生器的原因（§8.3 会用到）。

3.4 TCON：启停和溢出标志

TCON 的 8 个位是这样的：

位 名字 含义
bit7 TF1 T1 溢出标志，硬件置 1
bit6 TR1 T1 运行控制，软件置 1 启动、清 0 停止
bit5 TF0 T0 溢出标志
bit4 TR0 T0 运行控制
bit3/2 IE1 / IT1 外部中断 1 的标志与触发方式
bit1/0 IE0 / IT0 外部中断 0 的标志与触发方式

记住两句话：TR 是你要写的（启动/停止），TF 是硬件帮你写的（溢出了）。 你想让时间「暂停」，清 TR0 就够了；你想知道「到点了没有」，看 TF0。

3.5 机器周期：一秒有多长，取决于晶振

51 的一个机器周期 = 12 个时钟周期。于是：

晶振 一个时钟 一个机器周期 定时器每 +1 的时间
12MHz 83.3ns 12 / 12MHz = 1μs 1μs
11.0592MHz 90.4ns 12 / 11.0592MHz ≈ 1.0851μs 1.0851μs

12MHz 是个「整数友好」的晶振，1μs 一个计数，心算特别舒服。11.0592MHz 的数很丑，但它有一个别的晶振给不了的好处——串口能用它算出一丝不差的 9600（§8.3 细讲）。

换芯片就废：STC 的 1T 系列单片机一个时钟就是一个机器周期，同样 12MHz，速度是传统 12T 的 12 倍。你那套「110 次 = 1ms」的延时搬过去，直接快 12 倍。这就是为什么工程里不能有魔数。

3.6 把 TMOD 翻译成人话

下面这个小程序把任意一个 TMOD 值拆开，逐位解释它在说什么。你先在纸上猜 0x21 是什么，再跑：

/* 教学版：把 TMOD 的 8 个比特翻译成人话 */
#include <stdio.h>

/* TMOD 的位布局：高 4 位管 T1，低 4 位管 T0，两边完全一样。
 *   bit3 GATE ：1 = 启停还要看 INT 引脚（测脉宽用），0 = 只由 TR 控制
 *   bit2 C/T  ：1 = 计数器（数 T 引脚上的下降沿），0 = 定时器（数机器周期）
 *   bit1 M1   ：和 M0 一起选工作方式
 *   bit0 M0
 */
static const char *mode_name(unsigned char m)
{
    switch (m) {
    case 0:  return "方式0（13 位）";
    case 1:  return "方式1（16 位）";
    case 2:  return "方式2（8 位自动重装）";
    default: return "方式3（T0 拆成两个 8 位 / T1 停用）";
    }
}

static void explain_one(const char *who, unsigned char nibble)
{
    printf("  %s: GATE=%u  C/T=%u  M1M0=%u%u  ->  %s，%s\n",
           who,
           (unsigned)((nibble >> 3) & 1u),
           (unsigned)((nibble >> 2) & 1u),
           (unsigned)((nibble >> 1) & 1u),
           (unsigned)(nibble & 1u),
           mode_name((unsigned char)(nibble & 3u)),
           ((nibble >> 2) & 1u) ? "计数器（数引脚）" : "定时器（数机器周期）");
}

static void explain_tmod(unsigned char tmod, const char *note)
{
    printf("TMOD = 0x%02X  %s\n", (unsigned)tmod, note);
    explain_one("T1", (unsigned char)((tmod >> 4) & 0x0Fu));
    explain_one("T0", (unsigned char)(tmod & 0x0Fu));
    putchar('\n');
}

int main(void)
{
    puts("== TMOD 四个实例：同一张表，四种意图 ==\n");

    explain_tmod(0x01, "T0 方式1 定时：最常用的「16 位定时」");
    explain_tmod(0x02, "T0 方式2 定时：8 位自动重装，波特率发生器也用它");
    explain_tmod(0x21, "T1 方式2 做波特率 + T0 方式1 做 1ms 节拍");
    explain_tmod(0x05, "T0 方式1 计数：数 T0 引脚上来了多少个脉冲");
    explain_tmod(0x10, "T1 方式1 定时，T0 完全不动");

4. TH0/TL0 初值怎么算：一条公式，两种晶振

4.1 公式只有一行

方式 1 是「从初值数到 65536 溢出」。所以想让它在 t 微秒后溢出，就要让它数 t ÷ 机器周期 次，也就是：

初值 = 65536 − 定时时长 ÷ 机器周期
TH0 = 初值的高 8 位
TL0 = 初值的低 8 位

12MHz 下机器周期是 1μs，于是：

想要 计数 初值 TH0 TL0
1ms 1000 64536 0xFC 0x18
2ms 2000 63536 0xF8 0x30
5ms 5000 60536 0xEC 0x78
10ms 10000 55536 0xD8 0xF0
20ms 20000 45536 0xB1 0xE0
50ms 50000 15536 0x3C 0xB0

手算方法（以 1ms 为例）：65536 − 1000 = 64536，64536 = 0xFC18，高字节 0xFC 给 TH0，低字节 0x18 给 TL0。先减、再转十六进制、再拆两个字节，三步，别跳。

4.2 11.0592MHz：数出来的不是整数

换晶振，机器周期变成 1.0851μs，于是 1ms 需要的计数是：

1000μs ÷ 1.0851μs ≈ 921.6   →  只能取 922

65536 − 922 = 64614 = 0xFC66，实际定时 922 × 1.0851μs ≈ 1.0004ms，误差 +0.04%。

0.04% 听起来很小，但你要算长账：一天 86400 秒，累积误差约 35 秒。如果你的设备要做「一分钟不差」的时钟，靠 1ms 中断累加是不行的——要么用 12MHz 那种能整除的晶振，要么在软件里做补偿，要么用专门的时钟芯片（下一篇的 DS1302 就是这个答案）。

4.3 让程序把两种晶振的表都打出来

/* 01_timer_tick.c 教学版：12MHz 与 11.0592MHz 下的 TH0/TL0 对照 */
#include <stdio.h>

#define FOSC_12M     12000000UL
#define FOSC_110592  11059200UL
#define CAP_16BIT    65536UL    /* 方式 1 的 16 位计数器数到这里就溢出 */

/* 机器周期 = 12 / fosc 秒。要定 us 微秒，需要数多少个机器周期？
 *   counts = us / (12 / fosc) = us * fosc / 12000000  （四舍五入）
 * 中间结果超过 32 位，所以用 unsigned long long 过渡一下；
 * 真机 C51 没有 64 位，工程里的做法是提前算好常数、直接写成宏。 */
static unsigned long counts_for(unsigned long fosc, unsigned long us)
{
    unsigned long long v = (unsigned long long)us * (unsigned long long)fosc;
    return (unsigned long)((v + 6000000ULL) / 12000000ULL);
}

static void show_one(unsigned long fosc, unsigned long us)
{
    unsigned long counts = counts_for(fosc, us);
    unsigned long reload;
    double actual_us;

    if (counts > CAP_16BIT) {
        printf("  %5lu ms | %6lu | %s\n", us / 1000UL, counts,
               "装不下！超过 65.536ms，必须软件分频");
        return;
    }
    reload = CAP_16BIT - counts;
    /* 实际定时 = counts 个机器周期 = counts * 12 / fosc 秒 */
    actual_us = (double)counts * 12.0 / ((double)fosc / 1000000.0);

    printf("  %5lu ms | %6lu | %5lu | 0x%02lX | 0x%02lX | %8.4f ms\n",
           us / 1000UL, counts, reload,
           (reload >> 8) & 0xFFUL, reload & 0xFFUL, actual_us / 1000.0);
}

static void table(unsigned long fosc, const char *name)
{
    static const unsigned long want_ms[] = { 1, 2, 5, 10, 20, 50, 70 };

    printf("【%s】\n", name);
    printf("   需求   | 计数   | 初值  | TH   | TL   | 实际定时\n");
    printf("  --------+--------+-------+------+------+-----------\n");

        show_one(fosc, want_ms[i] * 1000UL);
    }

}

int main(void)

    puts("1. 12MHz 下「1ms = 1000 个计数」是白送的；11.0592MHz 下是 922 个，不是整数；");
    puts("2. 方式 1 一次最多 65.536ms（12MHz）/ 71.11ms（11.0592MHz），");
    puts("   想要 1 秒，就得在中断里再数 20 次 50ms —— 这叫「软件分频」。");

4.4 溢出之后：重装，以及「重装」带来的误差

方式 1 一溢出，TH0/TL0 就变成 0 了。你必须自己把初值再装回去，否则下一次要等 65.5ms。

问题在于「装回去」的时机。中断响应是有延迟的：从 TF0 置 1，到 CPU 跳进你的 ISR，通常要 3~8 个机器周期（以具体内核为准）。这段时间里计数器已经从 0 开始数了。如果你在 ISR 里装的是「标准初值」，那你每一次定时都少了那几个微秒。1ms 定时少 5μs，误差 0.5%，一天差 7 分钟。

三种补救，按代价从低到高：

  1. 在 ISR 第一行就重装，别先干别的。这只解决不了响应延迟，但能避免「装得更晚」；
  2. 把初值补偿一下：TH0/TL0 装「标准初值 + 响应延迟的计数」。粗糙但有效，代价是换个晶振就要重算；
  3. 用方式 2（自动重装）：硬件在溢出的同一瞬间把 TH0 的值装进 TL0，一分不差。可惜只有 8 位——12MHz 下最多 256μs，11.0592MHz 下最多 277μs。所以方式 2 通常只用来做波特率或几十微秒级的高频节拍。

4.5 软件分频：从 50ms 到 1 秒

方式 1 一次最多 65.5ms，可任务 5 要 10 秒、任务 7 要 1 秒。办法是软件分频：中断里只数 50ms，数 20 次就是 1 秒。

/* 片段：软件分频的骨架（真实 Keil 写法，仅作对照） */
static unsigned char g_50ms = 0;
static volatile unsigned int g_sec = 0;

void timer0_isr(void) interrupt 1
{
    TH0 = 0x3C;  TL0 = 0xB0;          /* 先重装：12MHz 下 50ms */
    if (++g_50ms >= 20) {             /* 20 个 50ms = 1 秒 */
        g_50ms = 0;
        ++g_sec;
    }
}

这个「外层再数一圈」的结构，你以后会在所有实时系统里看到：硬件出一个基准节拍，软件在节拍上做分频。 RTOS 的 SysTick 也是这么干的。

4.6 真实 Keil 里的完整配置（只看结构，别在 GCC 里编译）

/* ===== 真实 Keil C51 写法：本机 GCC 不可编译，仅作对照 ===== */
#include <reg52.h>

static volatile unsigned int g_ms = 0;

void timer0_isr(void) interrupt 1     /* interrupt 1 = 定时器 0 的中断号 */
{
    TH0 = 0xFC;  TL0 = 0x18;          /* 12MHz 下 1ms：先重装，再干活 */
    ++g_ms;                           /* ISR 里只做加法 */
}

void main(void)
{
    TMOD = 0x01;                      /* T0 方式1（16 位定时） */
    TH0  = 0xFC;  TL0 = 0x18;         /* 65536 - 1000 = 64536 = 0xFC18 */
    ET0  = 1;                         /* 允许 T0 中断（分开关） */
    EA   = 1;                         /* 打开总中断（总开关） */
    TR0  = 1;                         /* 启动 T0，时间开始走 */

    while (1) {
        /* 主循环自由了：计时的事交给中断，这里干别的 */
    }
}

这六行配置的顺序，建议照抄成肌肉记忆：TMOD 选方式 → 装初值 → 开分开关 → 开总开关 → TR 启动。少一行，现象就是「什么都不发生」（§14 速查表第 2 行）。

5. 中断：让硬件替你按门铃

5.1 五个门铃，五个编号

51 有五个中断源，每个有一个固定的中断号（Keil 的 interrupt n 用的就是它）：

中断源 中断号 标志位 使能位 说明
外部中断 0（INT0，P3.2） 0 IE0 EX0 按键、编码器
定时器 0 1 TF0 ET0 毫秒节拍的主力
外部中断 1（INT1，P3.3） 2 IE1 EX1 同上
定时器 1 3 TF1 ET1 常被拿去做波特率
串口（RI 或 TI） 4 RI/TI ES 收和发共用一个号

优先级只有两级（高/低），由 IP 寄存器设定，默认全是低。同级之间按自然优先级排队：INT0 > T0 > INT1 > T1 > 串口。高优先级可以打断正在执行的低优先级 ISR，同级不能。

第一年别碰优先级。 你现在写的所有程序，一个中断源就够用了。等你真的需要「串口必须在定时器之前响应」时再回来设 IP——而且那时候你要问的第一个问题不是「怎么设」，是「我的 ISR 是不是写太长了」。

5.2 使能链：总开关 + 分开关

中断要响，必须两个开关都打开：

        EA = 1  （总开关，IE 的 bit7）
          │
          ├── ET0 = 1  →  定时器 0 可以打断 CPU
          ├── ET1 = 1  →  定时器 1
          ├── ES  = 1  →  串口
          └── EX0/EX1  →  外部中断

家里总闸和房间开关的比喻最贴切：EA 是总闸，ET0 是房间开关。只开房间不开总闸，灯不会亮——这是新手第一大「中断不触发」的原因（§14 第 2 行）。

5.3 ISR 怎么写：Keil 的 interrupt 关键字

/* ===== 真实 Keil C51 写法：本机 GCC 不可编译，仅作对照 ===== */
void timer0_isr(void) interrupt 1     /* 定时器 0 */
{
    TH0 = 0xFC;  TL0 = 0x18;          /* 重装初值 */
    ++g_ms;                           /* 干活（越少越好） */
}

void uart_isr(void) interrupt 4       /* 串口：收和发共用 */
{
    if (RI) {
        RI = 0;
        g_rx_byte = SBUF;             /* 先读 SBUF，再清 RI */
    }
}

interrupt 1 里的 1 是中断号，不是优先级——这点常被搞混。Keil 看到这个关键字会做三件事：在中断向量表里放一条跳转、在函数开头保存现场、在结尾用 RETI 而不是 RET 返回。

GCC 不认识 interrupt 这个字，所以本篇的模拟版把它写成普通函数 timer0_isr()，由「模拟硬件」去调用。你写的逻辑一模一样，变的只是「谁来叫你」。

还有一个 Keil 的 using n（切换寄存器组），能省几个周期的现场保护。新手别用：一旦编译器判断失误、或者你在 ISR 里调了普通函数，现场就会串。省下的那几个周期，不值得你调一晚上。

5.4 ISR 纪律：它是「欠条」，不是「另一个 main」

中断服务程序最重要的性质是：它随时可能发生，而且发生的时候主循环正在干别的事。 所以它的第一原则是「尽快还回去」。

应该做 绝对不要做
置一个标志（g_flag = 1） delay_ms() 之类的等待
计数器 +1 printf（一次几百上千个周期）
翻转一个 IO 浮点运算（51 没有 FPU，一次除法几百周期）
从 SBUF 读一个字节进缓冲区 擦写 EEPROM（5ms，主循环会被冻住）
重装定时器初值 等另一个标志变成 1
清自己那个标志 清别人的标志（会丢事件）

一句话总结：ISR 只「记账」，主循环才「干活」。 账记的是「发生了一件事」，活是「这件事该怎么办」。

5.6 临界区：读一个 16 位变量也会被「劈开」

这是本篇最隐蔽的一个坑。51 的 unsigned int 是 16 位，而 CPU 一次只能搬 8 位，所以读 g_ms 在汇编里是两条 MOV：

/* 反面教材（真机上才会出事，PC 上因为 int 是 32 位，复现不出来） */
unsigned int t = g_ms;    /* 高字节、低字节分两次读 */

如果读完高字节、还没读低字节时，定时器中断进来把 g_ms 从 0x00FF 加成了 0x0100，你读到的就是「高字节 0x00 + 低字节 0x00」 = 0，而真实值是 256。显示会突然跳一下，或者计时倒退。

两种修法：

/* 修法一：读的时候关掉这个中断，读完再开（临界区） */
ET0 = 0;
t = g_ms;
ET0 = 1;

/* 修法二：连读两次，两次一样才认（适合读得很快的场合） */
do {
    t  = g_ms;
    t2 = g_ms;
} while (t != t2);

修法一更可靠，代价是关了中断会推迟一次节拍（几个周期，可以忽略）。这就是「volatile 不保证原子性」那句话的现场——阶段十 §6 提醒过一次，这里是它第一次真的咬人。

6. 查询 vs 中断：同一块硬件，两种命运

6.1 先看差别

查询方式 中断方式
CPU 占用 100% 盯着，什么都干不了 几乎为 0，主循环照跑
实时性 取决于你多久看一次 硬件立刻响应
会不会丢事件 会：主循环忙的时候，溢出了也没人管 不会：标志位挂着，早晚被处理

标志谁来清 软件清 TF0 硬件在响应时自动清 TF0

注意第 5 行那个不对称：定时器的 TF0，中断方式下硬件自动清；查询方式下必须你自己清。 而串口的 TI/RI 是两种情况都要软件清。这是两套规矩，混用就是 bug（§14 第 4 行）。

6.2 让程序把两种命运跑给你看

/* 教学版：查询方式与中断方式，谁丢事件 */
#include <stdio.h>

/* ============================================================
 * 模拟硬件：12MHz，定时器方式 1，每 1ms 溢出一次并把 TF0 置 1。
 * 真机上 hw_run_us 不需要写 —— 晶振在替你跑。
 * ============================================================ */
static volatile unsigned char TF0 = 0;   /* 真机上在 TCON 里，溢出置 1，软件清 0 */
static unsigned int hw_us = 0;           /* 硬件时间，只增不减 */

static void hw_reset(void)
{
    TF0 = 0;
    hw_us = 0;
}

static void hw_run_us(unsigned int us)
{
    unsigned int i;
    for (i = 0; i < us; ++i) {
        ++hw_us;
        if ((hw_us % 1000u) == 0u) {
            TF0 = 1;                     /* 每过 1ms，硬件把 TF0 抬起来 */
        }
    }
}

/* ============================================================
 * 一、查询方式（规矩写法）：看见 TF0 -> 手动清零 -> 计一次
 * ============================================================ */
static unsigned int poll_ok(unsigned int samples, unsigned int sample_us)
{
    unsigned int i, ms = 0;

    for (i = 0; i < samples; ++i) {
        hw_run_us(sample_us);
        if (TF0 != 0) {
            TF0 = 0;                     /* 这一句不能少，否则下一次还是「有新事件」 */
            ++ms;
        }
    }
    return ms;
}

/* ============================================================
 * 二、查询方式的经典死法：忘了 TF0 = 0
 * TF0 一旦变 1 就永远不清，于是每一次采样都被当成「新的一毫秒」，
 * 计时跑得飞快 —— 这是新手最常撞的一次。
 * ============================================================ */
static unsigned int poll_forget_clear(unsigned int samples, unsigned int sample_us)
{
    unsigned int i, ms = 0;

    for (i = 0; i < samples; ++i) {
        hw_run_us(sample_us);
        if (TF0 != 0) {
            ++ms;                        /* 漏了 TF0 = 0; */
        }
    }
    return ms;
}

/* ============================================================
 * 三、中断方式：硬件每 1ms 自己叫一次 ISR，主循环爱干多久干多久
 * ============================================================ */
static volatile unsigned int g_isr_ticks = 0;

static void timer0_isr(void)             /* 真机：void timer0_isr(void) interrupt 1 */
{
    ++g_isr_ticks;                       /* ISR 里只做一件事：数数 */
}

static unsigned int run_isr_version(unsigned int work_chunk_ms, unsigned int total_ms)
{
    unsigned int t = 0;

    g_isr_ticks = 0;
    hw_reset();
    while (t < total_ms) {
        unsigned int step = work_chunk_ms;   /* 主循环一次干这么多毫秒的活 */
        while (step > 0 && t < total_ms) {
            hw_run_us(1000);
            timer0_isr();                /* 真机：硬件自动跳进来，主循环管不着 */
            ++t;
            --step;
        }
        /* 主循环回来时，ticks 里已经攒好了这段时间的每一次溢出 */
    }
    return (unsigned int)g_isr_ticks;
}

int main(void)
{
    unsigned int real_ms, got;

    puts("场景一：主循环每 300us 采一次样，总时长 30ms（100 次采样）");
    hw_reset();
    got = poll_ok(100, 300);
    real_ms = hw_us / 1000;
    printf("  规矩写法      ：报告 %2u ms，真实过了 %2u ms  -> 对得上\n\n", got, real_ms);

    hw_reset();
    got = poll_forget_clear(100, 300);
    real_ms = hw_us / 1000;
    printf("  忘了清 TF0   ：报告 %2u ms，真实过了 %2u ms  -> 快了 %.1f 倍\n\n",
           got, real_ms, (double)got / (double)(real_ms ? real_ms : 1));

    puts("场景二：主循环一次要干 3ms 的活（比如刷一屏数码管），总时长 300ms");
    hw_reset();

6.3 那什么时候还用查询？

初始化阶段。比如上电时要等 EEPROM 的写周期、要等某个芯片上电稳定，这时候主循环还没有别的事可做，一个 while 反而最清楚。判断标准就一句：

「我等的时候，有没有别的事要干？」 有 → 中断；没有 → 查询。

7. 方波与占空比：把「时间」变成「波形」

7.1 一次翻转只完成半个周期

定时器溢出一次，你在 ISR 里把 IO 翻转一下。IO 高 → 低 → 高，这才是一个完整周期，需要两次溢出：

        ┌─────────┐         ┌─────────┐
   ─────┘         └─────────┘         └─────
        ←── T ──→←── T ──→
        ←────── 一个周期 = 2T ──────→

所以：

f = 1 / (2 × T)，  T 是定时器每次溢出的时间（半周期）

12MHz 下想要 100Hz：2T = 10ms，T = 5ms，计数 5000，初值 65536 − 5000 = 60536 = 0xEC78。「那个 2」是方波题最容易漏的一步——漏了它，频率正好差一倍。

7.2 1~100Hz 的尴尬：一半频率装不下

任务 7 要求 1~100Hz。换算成半周期：

频率 半周期 T 12MHz 下需要的计数 方式 1 装得下吗
1Hz 500ms 500000 装不下（> 65536）
2Hz 250ms 250000 装不下
5Hz 100ms 100000 装不下
10Hz 50ms 50000 装得下
20Hz 25ms 25000 装得下
50Hz 10ms 10000 装得下
100Hz 5ms 5000 装得下

这个表说明一件事：任务 7 的 1~100Hz 正好横跨「能装下」和「装不下」的分界线。 所以你不能只写一个「装初值」的函数就完事——低频那几个必须靠软件分频（数 8 次 62.5ms 才翻转一次）。这就是为什么这一节要先把 §4.5 的分频讲透。

/* 02_timer_square_wave.c 教学版：算频率、算分频、算占空比 */
#include <stdio.h>

#define CAP_16BIT  65536UL      /* 方式 1 最多数到这里 */
#define FOSC_MHZ   12UL         /* 这一节按 12MHz 讲：1 个计数 = 1us */

/* 定时器每 half_us 微秒溢出一次，ISR 里把 IO 翻转一次。
 * 翻转两次才凑成一个完整周期，所以  T = 2 * half_us，f = 1e6 / (2 * half_us)。
 * 返回值单位是「毫赫兹」（Hz * 1000），避免浮点。 */
static unsigned long freq_mhz(unsigned long half_us)
{
    if (half_us == 0) {
        return 0;
    }
    return 1000000000UL / (2UL * half_us);
}

/* 给定想要的半周期（微秒），算出方式 1 的初值和需要的软件分频次数 */
static void plan(unsigned long half_us)
{
    unsigned long counts = half_us;          /* 12MHz：1us = 1 个计数 */
    unsigned long prescale = 1;
    unsigned long per_over;
    unsigned long reload;
    unsigned long real_half_us;
    unsigned long f = freq_mhz(half_us);
    unsigned long f_real;

    while (counts > CAP_16BIT) {             /* 一次装不下，就让硬件多数几轮 */
        counts = (counts + 1UL) / 2UL;
        prescale *= 2UL;
    }
    per_over = counts;
    reload = CAP_16BIT - per_over;
    real_half_us = per_over * prescale;
    f_real = freq_mhz(real_half_us);

    printf("  %6lu.%03lu Hz | %6lu us | %6lu | 0x%02lX%02lX | x%-2lu | %6lu.%03lu Hz\n",
           f / 1000UL, f % 1000UL, half_us, per_over,
           (reload >> 8) & 0xFFUL, reload & 0xFFUL, prescale,
           f_real / 1000UL, f_real % 1000UL);
}

/* 占空比：把一个周期切成「高段」和「低段」，两段各装一次初值。
 * duty_permille 是千分比（300 = 30%），整数运算不碰浮点。 */
static void duty_plan(unsigned long period_us, unsigned int duty_permille)
{
    unsigned long hi = period_us * (unsigned long)duty_permille / 1000UL;
    unsigned long lo = period_us - hi;
    unsigned long hi_counts = hi;
    unsigned long lo_counts = lo;
    unsigned long hi_reload = CAP_16BIT - hi_counts;
    unsigned long lo_reload = CAP_16BIT - lo_counts;

    printf("  周期 %6lu us，占空比 %3u.%u%%：高 %6lu us（初值 0x%04lX），"
           "低 %6lu us（初值 0x%04lX）\n",
           period_us, duty_permille / 10U, duty_permille % 10U,
           hi, hi_reload, lo, lo_reload);
}

int main(void)
{
    puts("一、1~100Hz 要多少半周期？哪些装得下？\n");
    puts("     频率     | 半周期   | 计数   | 初值     | 分频 | 实际频率");
    puts("  ------------+----------+--------+----------+------+----------");
    plan(500000UL);      /* 1Hz   */
    plan(250000UL);      /* 2Hz   */
    plan(100000UL);      /* 5Hz   */
    plan(50000UL);       /* 10Hz  */
    plan(25000UL);       /* 20Hz  */
    plan(10000UL);       /* 50Hz  */
    plan(5000UL);        /* 100Hz */
    putchar('\n');

    puts("二、占空比不是「改一个数」，是「改两段的时间」\n");
    duty_plan(20000UL, 500U);   /* 20ms 周期，50%  */
    duty_plan(20000UL, 300U);   /* 20ms 周期，30%  */
    duty_plan(20000UL, 50U);    /* 20ms 周期， 5%  */
    putchar('\n');

    puts("三、为什么高频之下不能再用软件延时");
    puts("  100Hz 的半周期是 5ms，一套 for 空循环的误差就有几十微秒；");
    puts("  1kHz 的半周期是 500us，误差占比已经上到 10%；");
    puts("  10kHz 的半周期是 50us，一次中断响应就要十几微秒 —— 软件延时彻底失效。");
    puts("  频率越高，「时间」越不像「你写了几行代码」，越像「晶振震了几下」。");

7.3 占空比：改的是「两段的长度」

占空比 = 高电平时间 ÷ 周期。实现上它不是「改一个数」，而是在周期不变的前提下，把两段定时器的时间重新分配：

周期 20ms，占空比 30%：
   ┌── 6ms ──┐┌──────── 14ms ────────┐
   ‾‾‾‾‾‾‾‾‾‾‾‾______________________
   装 0xE890    装 0xC950

这个结构就是 PWM（脉宽调制）。它为什么重要？因为它是用「数字引脚」控制「模拟量」的唯一便宜办法：LED 的亮度、电机的转速、舵机的角度，全靠调整高电平占多少。举个你会立刻用上的例子：常见舵机要 50Hz（周期 20ms）的信号，高电平 0.5ms~2.5ms 对应 0°~180°——正好就是 2.5%~12.5% 的占空比。你看，7.2 那张表和 7.3 这张图，合起来就是舵机驱动。

7.4 为什么高频之下软件延时彻底失效

软件延时的误差来源有三个：指令周期不齐、编译器优化、中断插队。前两个是固定偏差，可以「试」出来；第三个是随机抖动：

  • 定时器中断一响，CPU 去执行 ISR，你的延时立刻变长；
  • 如果 ISR 里还有分支，变长多少还不固定；
  • 中断响应本身要 3~8 个机器周期，抖动就是几个微秒量级。

100Hz 时半周期 5ms，几微秒抖动占 0.1%，无所谓。10kHz 时半周期 50μs，同样的抖动占 10% 以上——波形肉眼可见地抖。频率越高，「时间」越不像「你写了几行代码」，越像「晶振震了几下」。

7.5 频率显示：你显示的是「设定值」还是「真值」？

任务 7 要求「频率显示在数码管上」。这里有个容易被忽略的选择：

  • 显示设定值：你按 k1/k2 改的那个变量，直接格式化显示。简单，但它只能证明「你的变量变了」，不能证明「引脚上真的有这个频率」；
  • 显示实测值：用定时器计数功能（C/T = 1）去数一段时间里 IO 翻转了多少次，再换算成频率。麻烦，但它是「闭环」的——你能证明波形真的出来了。

两种都能交差。区别在于：板子上什么都没接、示波器也没有的时候，只有第二种能让你自己相信。 这就是「自检」思维，也是工程师和「能跑就行」的分界线。

8. 串口：一帧十位，一位一百微秒

8.1 帧格式：起始、数据、停止

异步串口没有时钟线，收发双方靠「约定好的速度」对齐。每一帧长这样：

 空闲(高)  起始  D0  D1  D2  D3  D4  D5  D6  D7  停止  空闲(高)
 ────────┐    ┌──┬──┬──┬──┬──┬──┬──┬──┐    ┌────────
         └────┘  │  │  │  │  │  │  │  └────┘
          0      ←── 8 个数据位，低位先发 ──→   1
  • 起始位：一个低电平。它唯一的作用是「把接收方的时钟对齐」——从这一位的下降沿开始计时；
  • 8 个数据位：低位先发（LSB first）。所以发 0x01 时，波形上是 1 0 0 0 0 0 0 0（按时间顺序），别以为是自己发错了；
  • 停止位：一个高电平。它给接收方一个「这一帧结束了」的确认，也留出一点处理时间。

9600-8-N-1 这串咒语就是逐字解释上面这张图：

字段 值 含义
9600 波特率 每秒 9600 个位，每位约 104μs
8 数据位 8 位，正好一个字节
N 校验 None，无校验位
1 停止位 1 位

一帧 10 位（1 + 8 + 1），所以 9600 波特率下每秒最多 960 帧，一帧约 1.04ms。

电平要注意：板子上 P3.0/P3.1 出来的是 TTL 电平（0V / 5V），电脑上是 USB。中间靠 CH340 这类「USB 转串口」芯片翻译。接线是 TX 接对方的 RX、RX 接对方的 TX、GND 必须共地——这三句话解决了 80% 的「串口没反应」。

8.2 波特率误差能容忍多少

接收方是在每一位的中间采样的。十位一帧，如果累计错位超过半位，就会把这一帧读错。工程经验：误差控制在 2%~3% 以内基本可靠，超过 5% 必然乱码。

这个数字请记住，下一节要用它解释一个「看起来很玄」的现象。

8.3 波特率公式与 11.0592MHz 的秘密

51 的串口方式 1，波特率由定时器 1 的溢出率决定，而 T1 通常工作在方式 2（8 位自动重装）：

baud = (2^SMOD / 32) × ( fosc / (12 × (256 − TH1)) )
     = 2^SMOD × fosc / (384 × (256 − TH1))

SMOD 是 PCON 的最高位（bit7），置 1 就把波特率翻倍。256 − TH1 就是 T1 每次溢出前数的机器周期数。

现在把 9600 代进去，让 256 − TH1 = 3：

  • 11.0592MHz：11059200 / (384 × 3) = 11059200 / 1152 = 9600。一丝不差。
  • 12MHz：12000000 / 1152 = 10416.67。偏了 +8.5%。

8.5% 远超 2%~3% 的容忍线，所以 12MHz 的板子跑 9600 就是满屏乱码——这不是你代码写错了，是晶振选错了。

11.0592 这个怪数字的来历是：11059200 / 12 / 32 = 28800，而 28800 能被 2400、4800、9600、19200 整除。它不是为「好算」选的，是为「能整除」选的。 这就是为什么老工程师看到一块板子上焊着 11.0592，就知道「这板子要用串口」。

/* 03_uart_frame.c 教学版：让程序把 TH1 全试一遍，挑误差最小的 */
#include <stdio.h>

/* 方式 1（8 位 UART，1 起始 + 8 数据 + 1 停止）的波特率公式，
 * 前提是定时器 1 工作在方式 2（8 位自动重装）：
 *
 *     baud = (2^SMOD / 32) * ( fosc / (12 * (256 - TH1)) )
 *          = 2^SMOD * fosc / (384 * (256 - TH1))
 *
 * 12 是「12 个时钟一个机器周期」，32 是「16 倍采样再除以 2」——
 * 这两个常数是 8051 串口的硬件设计，记不住就记住整条公式。 */
static unsigned long baud_of(unsigned long fosc, int smod, unsigned char th1)
{
    unsigned long num = fosc * (smod ? 2UL : 1UL);
    unsigned long den = 384UL * (unsigned long)(256U - (unsigned int)th1);
    return num / den;
}

/* 与其背表，不如让程序把 256 个 TH1 全试一遍，挑误差最小的那个 */
static void best_for(unsigned long fosc, unsigned long target)
{
    int smod, best_smod = 0;
    unsigned int t, best_th1 = 0;
    unsigned long best_err = 0, best_baud = 0;
    int first = 1;

    for (smod = 0; smod <= 1; ++smod) {
        for (t = 0; t <= 255; ++t) {
            unsigned long b = baud_of(fosc, smod, (unsigned char)t);
            unsigned long diff, err;

            if (b == 0) {
                continue;
            }
            diff = (b > target) ? (b - target) : (target - b);
            err = diff * 1000UL / target;          /* 相对误差，单位千分之一 */
            if (first || err < best_err) {
                first = 0;
                best_err = err;
                best_smod = smod;
                best_th1 = t;
                best_baud = b;
            }
        }
    }
    printf("  %6lu bps -> TH1 = 0x%02X，SMOD = %d，实际 %6lu bps，误差 %5.2f%%\n",
           target, best_th1, best_smod, best_baud, (double)best_err / 10.0);
}

static void table(unsigned long fosc, const char *name)
{
    static const unsigned long want[] = { 2400, 4800, 9600, 19200 };
    unsigned long i;

    printf("【%s】\n", name);
    for (i = 0; i < sizeof(want) / sizeof(want[0]); ++i) {
        best_for(fosc, want[i]);
    }
    putchar('\n');
}

8.4 SCON 与 SBUF：收发的门面

SCON 的 8 个位：

位 名字 作用
bit7/6 SM0 SM1 选工作方式。01 = 方式 1（8 位 UART），最常用
bit5 SM2 多机通信/校验位控制，方式 1 一般清 0
bit4 REN 允许接收。置 1 才能收，忘了它就只能发不能收
bit3/2 TB8 RB8 第 9 位（方式 2/3 或校验位用），方式 1 不用
bit1 TI 发送完成标志，硬件置 1，软件清 0
bit0 RI 接收完成标志，硬件置 1，软件清 0

方式 1 + 允许接收，就是 SCON = 0x50;（0101 0000）。这个值建议直接背下来。

SBUF 是这一篇里唯一一个「反例」：它一个地址，却是两个物理寄存器——你写 SBUF 是写发送寄存器，读 SBUF 是读接收寄存器。阶段十说「寄存器就是有地址的内存」，这里要补一句：也有例外，SBUF 就是同名不同物的那一个。 所以读和写永远不会互相踩，不用担心。

PCON 的 bit7 是 SMOD。PCON 不能位寻址（地址 0x87 不是 8 的倍数），所以只能整字节操作：PCON |= 0x80;，不能写 SMOD = 1;。

8.5 查询方式收发：三行代码，一个坑

/* ===== 真实 Keil C51 写法：本机 GCC 不可编译，仅作对照 ===== */

/* 发一个字节 */
void uart_send(unsigned char ch)
{
    SBUF = ch;                 /* 写 SBUF = 启动发送 */
    while (TI == 0) { }        /* 等硬件把 TI 置 1 */
    TI = 0;                    /* 必须软件清零，硬件不清 */
}

/* 收一个字节（查询） */
unsigned char uart_recv(void)
{
    unsigned char ch;
    while (RI == 0) { }        /* 死等：主循环被完全拴住 */
    ch = SBUF;                 /* 先读数据 */
    RI = 0;                    /* 再清标志 */
    return ch;
}

TI 那个坑值得单独说：它是「我发完了」的旗子，硬件置 1，软件清 0。 忘了清，下一次 while (TI == 0) 会立刻通过（因为 TI 还是 1），你以为发出去了，其实第二个字节把第一个字节覆盖了。现象是「发一串字符，只收到第一个」或者「全乱」。

8.6 中断方式接收：一个中断号，两种事件

串口的收和发共用中断号 4，所以 ISR 一进来必须先分清是谁：

/* ===== 真实 Keil C51 写法：本机 GCC 不可编译，仅作对照 ===== */
void uart_isr(void) interrupt 4
{
    if (RI) {                  /* 是「收到一个字节」 */
        RI = 0;                /* 软件清 */
        g_rx = SBUF;           /* 读走数据 */
        g_rx_flag = 1;         /* 只记一笔，解析交给主循环 */
    }
    if (TI) {                  /* 是「发完一个字节」 */
        TI = 0;
        g_tx_busy = 0;
    }
}

初始化是三行：SCON = 0x50;、ES = 1;、EA = 1;。少一个 ES，你就只能查询；少一个 EA，ES 白开。

9. 串口收发：从「字节流」到「一条命令」

9.1 串口没有「消息边界」

这是本节最重要的一句话：串口送过来的是一条连续的字节流，它不告诉你「一条命令从哪开始、到哪结束」。

上位机点一下「发送」，你收到的是 'm' 然后 '1'。但问题是：你收到 'm' 的那一刻，你并不知道后面还有没有 '1'。 可能它马上就来，可能它永远不会来（上位机崩了），可能它是下一条命令的开头。

这就是任务 6 里那个「分两次发 m 和 1」的测试想问你的事。它的答案取决于上位机怎么发：

  • 如果串口助手每次发送都补一个换行（大多数助手的默认行为），你收到的是 "m\n" 和 "1\n" 两行。两行都不完整，所以两条都应该报错；
  • 如果它不补换行，两半会被你拼成 "m1"，设备会当成一条合法命令执行——而且设备没有任何办法分辨这两种情况。

所以「处理错误输入」的本质不是「识别出用户手抖了」，而是：协议要有边界（换行符），解析要严格（完全匹配），出错要可控（报错、不执行、不崩溃）。 这三件事做到了，无论上位机怎么发，设备都不会干出奇怪的事。

9.2 两级状态机：收字节是一级，解析是另一级

字节流 → [接收状态机] → 一整行 → [解析器] → 命令 / 错误
         IDLE/COLLECT/OVERFLOW        完全匹配

接收状态机只关心「这一行收完了没有、有没有超长」；解析器只关心「这一行是不是合法命令」。分开写的好处是：将来协议变了（比如改成 #m1;），只改解析器；缓冲区大小变了，只改接收状态机。

9.3 完整示例：五种输入，五种结局

/* 04_uart_command.c 教学版：命令解析状态机 */
#include <stdio.h>
#include <string.h>

#define LINE_MAX 16          /* 一行最多 16 个字符，超了就是协议出问题 */

typedef enum {
    CMD_NONE = 0,        /* 还没收完，继续等 */
    CMD_DIGIT,           /* m1：改数码管显示 */
    CMD_LED,             /* L1~L4：控制某一盏灯 */
    CMD_BEEP,            /* beer：蜂鸣器 */
    CMD_ERR_EMPTY,       /* 空行（常见于 \r\n 被当成两次换行） */
    CMD_ERR_INCOMPLETE,  /* "m" / "b"：命令只发了一半 */
    CMD_ERR_UNKNOWN,     /* "hello" / "M1"：根本不认识 */
    CMD_ERR_TRAILING,    /* "m1 m2" / "m12"：命令后面还挂着东西 */
    CMD_ERR_LONG         /* 一直没收到换行，缓冲区爆了 */
} cmd_t;

static const char *cmd_name(cmd_t c)
{
    switch (c) {
    case CMD_NONE:          return "（未完成）";
    case CMD_DIGIT:         return "m1  数码管";
    case CMD_LED:           return "Lx  点灯";
    case CMD_BEEP:          return "beer 蜂鸣器";
    case CMD_ERR_EMPTY:     return "错误：空行";
    case CMD_ERR_INCOMPLETE:return "错误：命令不完整";
    case CMD_ERR_UNKNOWN:   return "错误：不认识的命令";
    case CMD_ERR_TRAILING:  return "错误：命令后面有多余字符";
    case CMD_ERR_LONG:      return "错误：没有换行，缓冲区溢出";
    }
    return "?";
}

/* ============================================================
 * 一、解析一整行：只认「完全匹配」，多一个字符都不算
 * ============================================================ */
static cmd_t parse_line(const char *line)
{
    size_t n = strlen(line);

    if (n == 0) {
        return CMD_ERR_EMPTY;
    }
    if (strcmp(line, "beer") == 0) {
        return CMD_BEEP;
    }

    if (line[0] == 'm') {
        if (n == 1) {
            return CMD_ERR_INCOMPLETE;                  /* 只发了 m */
        }
        if (line[1] < '1' || line[1] > '9') {
            return CMD_ERR_UNKNOWN;                     /* m + 非数字 */
        }
        if (n > 2) {
            return CMD_ERR_TRAILING;                    /* m1 m2 / m12 */
        }
        return CMD_DIGIT;
    }

    if (line[0] == 'L') {
        if (n == 1) {
            return CMD_ERR_INCOMPLETE;
        }
        if (line[1] < '1' || line[1] > '4') {
            return CMD_ERR_UNKNOWN;                     /* 只有 4 盏灯 */
        }
        if (n > 2) {
            return CMD_ERR_TRAILING;
        }
        return CMD_LED;
    }

    if (line[0] == 'b') {
        return CMD_ERR_INCOMPLETE;                      /* beer 打了半截 */
    }
    return CMD_ERR_UNKNOWN;
}

/* ============================================================
 * 二、接收状态机：字节流进来，行交给 parse_line
 * ============================================================ */
typedef enum {
    RX_IDLE = 0,     /* 等第一个字符 */
    RX_COLLECT,      /* 正在攒一行 */
    RX_OVERFLOW      /* 攒爆了，丢字符直到换行 */
} rx_state_t;

static char g_line[LINE_MAX + 1];
static unsigned char g_len = 0;
static rx_state_t g_rx = RX_IDLE;

static cmd_t uart_feed(char c)
{
    if (c == '\r') {
        return CMD_NONE;                 /* 忽略 \r：很多助手发的是 \r\n */
    }
    if (c == '\n') {
        cmd_t r;
        if (g_rx == RX_OVERFLOW) {       /* 这一行已经废了，整行丢弃 */
            g_rx = RX_IDLE;
            g_len = 0;
            return CMD_ERR_LONG;
        }
        g_line[g_len] = '\0';
        r = parse_line(g_line);
        g_rx = RX_IDLE;
        g_len = 0;
        return r;
    }
    if (g_rx == RX_OVERFLOW) {
        return CMD_NONE;                 /* 溢出后继续丢，直到换行才收尾 */
    }
    if (g_len >= LINE_MAX) {
        g_rx = RX_OVERFLOW;
        return CMD_NONE;
    }
    g_line[g_len++] = c;
    g_rx = RX_COLLECT;
    return CMD_NONE;
}

/* 把不可见字符打成可见的：\n 打成 "\n"，免得输出排版乱掉 */
static void print_escaped(const char *s)
{
    const char *p;

    for (p = s; *p != '\0'; ++p) {
        if (*p == '\n') {
            printf("\\n");
        } else if (*p == '\r') {
            printf("\\r");
        } else {
            putchar(*p);
        }
    }
}

static void feed(const char *s)
{
    const char *p;
    int hits = 0;

    printf("  发 \"");
    print_escaped(s);
    printf("\"\n");
    for (p = s; *p != '\0'; ++p) {
        cmd_t r = uart_feed(*p);
        if (r != CMD_NONE) {
            printf("      -> %s\n", cmd_name(r));
            ++hits;
        }
    }
    if (hits == 0) {
        printf("      -> （还没凑够一行，什么都不做）\n");
    }
}

int main(void)
{
    puts("== 上位机发的每一行，设备怎么理解 ==\n");

    feed("m1\n");            /* 正例：改数码管 */
    feed("L3\n");            /* 正例：点第 3 盏灯 */
    feed("beer\n");          /* 正例：蜂鸣器 */
    putchar('\n');

    feed("m1 m2\n");         /* 一条行里塞两条命令 */
    feed("m12\n");           /* 两位数字 */
    feed("m\n");             /* 分两次发的第一半 */
    feed("1\n");             /* 分两次发的第二半 */
    feed("M1\n");            /* 大小写 */
    feed("\n");              /* 空行 */
    feed("m12345678901234567890\n");   /* 一口气 21 个字符，没换行 */
    putchar('\n');

    puts("四条规矩：");
    puts("1. 只有「收到换行」才解析 —— 半截命令永远不执行；");
    puts("2. 解析要「完全匹配」：m1 是命令，m1 m2 和 m12 都是错；");
    puts("3. 出错只回一句话、不崩溃、不猜 —— 猜错一次比报错十次更糟；");
    puts("4. 缓冲有上限：没人发换行时，攒到上限就整行丢弃，绝不越界。");
    return 0;
}

输出：

  发 "m1\n"
      -> m1  数码管
  发 "L3\n"
      -> Lx  点灯
  发 "beer\n"
      -> beer 蜂鸣器

  发 "m1 m2\n"
      -> 错误：命令后面有多余字符
  发 "m12\n"
      -> 错误：命令后面有多余字符
  发 "m\n"
      -> 错误：命令不完整
  发 "1\n"
      -> 错误：不认识的命令
  发 "M1\n"
      -> 错误：不认识的命令
  发 "\n"
      -> 错误：空行
  发 "m12345678901234567890\n"

十种输入，十种明确的结局，没有一个会让程序崩掉、也没有一个会被「猜」成别的命令。这就是「帧完整性」的落地。

9.4 三个容易忽略的细节

  1. \r 与 \n：很多串口助手发的是 \r\n。如果你把两个都当换行，每条命令后面会多出一个「空行错误」——现象是「命令执行了，但每次都回一句错」。本节的写法是只认 \n，忽略 \r；
  2. 大小写：M1 和 m1 是两条不同的命令。要么约定「全小写」，要么在解析时统一转小写。别让硬件去猜用户的心情；
  3. 缓冲区上限：LINE_MAX 不是形式主义。上位机断线时可能只发来半行，如果没有上限、又一直收不到换行，你的缓冲区就会一直涨——在 51 上，那是直接踩穿 RAM。

9.5 中断接收 + 环形队列（概念）

正式工程里的串口接收一般长这样：

  串口中断：收到一个字节 → 塞进环形队列 → 立刻返回
  主循环：  队列不空 → 取出字节 → 喂给接收状态机

环形队列就是「一个数组 + 两个下标」：head 写、tail 读，走到末尾回 0。中断只管 head，主循环只管 tail，两边互不干扰。这就是「ISR 记账、主循环干活」最标准的样子。

顺便说个反直觉的建议：调试串口不要用 printf。 C51 的 printf 要重定向 putchar、要链接浮点库，动辄吃掉几 KB Flash；而且它是阻塞的，一句 printf 能让你的 1ms 节拍抖成 5ms。要打印就自己写一个「只发字符串、不发格式」的小函数。

10. I2C 与 AT24C02：两根线，记住一件事

10.1 开漏与上拉：为什么必须有两个电阻

I2C 只有两根线：SCL（时钟）和 SDA（数据）。这两根线都是开漏输出：

        +5V
         │
        [4.7k]        上拉电阻（必需！）
         │
   ──────┼───────  SCL / SDA
         │
      ┌──┴──┐
      │ 芯片 │  只能把线「拉低」，不能「推高」
      └─────┘

开漏的意思是：芯片内部只有一个到地的开关。它要么把线拉到 0V，要么「松手」让线浮空；它没有能力把线推到 5V。所以必须外接上拉电阻，把「松手」变成高电平。

这么设计有三个好处：① 多个设备并联不会打架（谁拉低都算低，这叫「线与」）；② 不同电压的器件可以挂在同一条总线上；③ 一根线坏了不会把另一根也拖死。

代价是上升沿变慢：上拉电阻越大，线电容充电越慢，波形上升越缓。所以 4.7k~10k 是常见值，太大（比如 100k）高速时就上不去。忘了接上拉，SDA 永远是 0 或者乱跳——这是 I2C 调试第一大坑（§14 第 12 行）。

10.2 五个动作：起始、数据、应答、停止、重复起始

动作 怎么产生 含义
起始 SCL 高电平期间，SDA 由高变低 我要开始说话了
数据位 SCL 低时改 SDA，SCL 高时采样 一位数据

非应答 NACK 第 9 个时钟，接收方不拉低（保持高） 不要了 / 没这个地址
停止 SCL 高电平期间，SDA 由低变高 说完了，总线释放 
        起始                          停止
   SCL ─┐  ┌───────────────       ─────┐  ┌─────
        └──┘                           └──┘
   SDA ────┐                      ──┐
           └──────────────           └────────
        ↑ SCL 高时 SDA 下降      ↑ SCL 高时 SDA 上升

一句话记住位传输的规矩：「低改高读」——SCL 低电平期间允许改 SDA，SCL 高电平期间必须稳定（除了起始/停止这两个特例）。

10.3 7 位地址与 0xA0 的来历

I2C 的每个从机有一个 7 位地址。主机发完 7 位地址后，紧跟一位读写方向（0 = 写，1 = 读），凑成一个字节：

   ┌─────── 7 位地址 ───────┐ ┌ R/W ┐
   1  0  1  0  A2 A1 A0     0/1
   └───────────────────────┘ └─────┘

AT24C02 的地址高 4 位固定是 1010，低 3 位由芯片上的 A2/A1/A0 三个引脚决定（接地 = 0，接高 = 1）。开发板上通常三个都接地，于是 7 位地址是 1010000 = 0x50。

  • 写：(0x50 << 1) | 0 = 0xA0
  • 读：(0x50 << 1) | 1 = 0xA1

0xA0 不是随便定的数，它是「地址左移一位、最低位放方向」。 记住这个来历，你换一颗 EEPROM（比如 AT24C32）时就知道该改哪几位。

10.4 字节写、页写、随机读

字节写（一次写一个字节）：

START → 0xA0 → ACK → 字地址 → ACK → 数据 → ACK → STOP → 等 twr

随机读（先定位再读）：

START → 0xA0 → ACK → 字地址 → ACK → 重复START → 0xA1 → ACK → 读数据 → NACK → STOP

为什么读之前要先「写」一次地址？因为地址指针在芯片内部，你得先把它挪到你要的位置。这就像查字典：先翻到那一页，再读。中间那个「重复起始」是为了换方向但不释放总线——如果先 STOP 再 START，另一个主机可能插进来把地址指针改掉。

页写：AT24C02 一页 8 字节。你连续发多个数据字节，芯片内部地址自动 +1，写到页边界会回卷到页首。页写比「一个一个字节写」快得多，但跨页会覆盖，这是 EEPROM 的经典坑。

10.5 twr：写完为什么必须等

EEPROM 的写入不是「写完就完」，芯片内部要把电荷真正塞进浮栅，这需要时间。AT24C02 的写周期 twr 最大约 5ms（以数据手册为准）。这 5ms 里芯片不理总线——你发地址它不回 ACK。

于是有两个后果：

  1. 写完立刻读，读到的可能是旧值。 这是最迷惑人的现象：明明写成功了（ACK 了），读回来却是 0xFF；
  2. 别在主循环里死等 5ms。 那 5ms 里按键不响应、数码管会闪。正确做法是「发起写 → 记下时间 → 下次循环再看时间到没到」（§11 的骨架就是这么写的）。

比死等更聪明的做法叫应答轮询：发一次器件地址，如果 NACK 说明还在写，过一会儿再发；等到 ACK 就是写完了。这样既不浪费 5ms，也不怕芯片快慢不同。

10.6 时钟拉伸与总线仲裁（概念，知道就行）

  • 时钟拉伸：从机忙不过来时，可以把 SCL 拉低不放，主机看到 SCL 一直是低就只能等着。这叫「从机给主机踩刹车」。EEPROM 在写周期里就会这么干；
  • 总线仲裁：两个主机同时发，靠「线与」决胜负——谁发 1 而线上是 0，谁就输了，自动退出。赢的那个甚至察觉不到有人抢过。这就是开漏设计的精妙之处。

你现在不需要实现这两个，但看到示波器上 SCL 被拉长，别以为是坏了。

10.7 掉电保存的原理

EEPROM 的每个存储单元是一个浮栅 MOS 管：写入时用高电压把电子「打」进一层绝缘的栅极里，电子出不来，于是阈值电压变了，读出来就是 0 或 1。断电之后电子仍然被困在绝缘层里，所以数据不丢——标称能存几十年（以数据手册为准）。

代价是：擦写次数有限。AT24C02 大约 100 万次（以数据手册为准）。这个数字听起来很多，但如果你在主循环里「每 1ms 存一次」，一天就是 8640 万次——几小时就写废了。所以任务 7 的一个隐形考点是：只在「计数变了」的时候写，而且要合并写、限频率。

10.8 完整示例：从写入到「断电」再读回

/* 05_i2c_eeprom.c 教学版：I2C 位时序 + 假 AT24C02 + 掉电再读回 */
#include <stdio.h>

#define EE_SIZE 256        /* AT24C02：2Kbit = 256 字节 */

/* ============================================================
 * 一、总线层：SCL / SDA 两条线，都是「开漏 + 上拉」
 * 写 1 的真实含义是「松手」，让上拉电阻把线拉高；
 * 谁拉低，线就是 0。这里用两个变量记录线上的电平。
 * ============================================================ */
static int SCL = 1;
static int SDA = 1;
static unsigned long g_clocks = 0;      /* 数一数打了多少个 SCL 高脉冲 */

static void bus_scl(int v)
{
    SCL = v;
}

static void bus_sda(int v)
{
    SDA = v;
}

/* 一个完整的时钟脉冲：高 -> 低。数据只在 SCL 高电平期间有效 */
static void scl_pulse(void)
{
    bus_scl(1);
    ++g_clocks;
    bus_scl(0);
}

/* ============================================================
 * 二、假 AT24C02：只模拟「时序 + 应答 + 存储」，不模拟电气
 * ============================================================ */
typedef struct {
    unsigned char nv[EE_SIZE];        /* 非易失区：掉电不丢 */
    unsigned char stage[EE_SIZE];     /* 已收到、还没落盘的字节 */
    unsigned char ptr;                /* 字地址指针，每传一个字节自动 +1 */
    unsigned char pending;            /* 有没有等着落盘的字节 */
    unsigned char pending_addr;
    int present;                      /* 器件在不在板上（1 = 焊好了） */
    int rw;                           /* 0 = 主机要写，1 = 主机要读 */
    int phase;                        /* 0 等器件地址 / 1 等字地址 / 2 传数据 */
    unsigned char cur;                /* 正在被读出的字节 */
    int bitpos;                       /* 读到第几位了 0~7 */
} at24c02_t;

static at24c02_t g_ee;

static void ee_init(void)
{
    int i;

    for (i = 0; i < EE_SIZE; ++i) {
        g_ee.nv[i] = 0xFF;            /* 出厂/擦除后的状态：全 1 */
        g_ee.stage[i] = 0xFF;
    }
    g_ee.ptr = 0;
    g_ee.pending = 0;
    g_ee.pending_addr = 0;
    g_ee.present = 1;
    g_ee.rw = 0;
    g_ee.phase = 0;
    g_ee.cur = 0;
    g_ee.bitpos = 0;
}

/* 起始条件把从机的「收字节状态机」复位：它在等一个新的器件地址 */
static void slave_on_start(void)
{
    g_ee.phase = 0;
    g_ee.bitpos = 0;
}

/* 从机收到一个字节后做什么。返回 1 = 拉低 SDA 应答（ACK），0 = 不理（NACK） */
static int slave_on_byte(unsigned char b)
{
    if (g_ee.present == 0) {
        return 0;                                  /* 器件不在：没人应答 */
    }
    if (g_ee.phase == 0) {                         /* 第 1 个字节：7 位地址 + R/W */
        if ((b & 0xFEu) != 0xA0u) {
            return 0;                              /* 地址对不上：NACK */
        }
        g_ee.rw = b & 1u;
        g_ee.phase = (g_ee.rw == 0) ? 1 : 2;       /* 写还要收字地址，读直接开始 */
        return 1;
    }
    if (g_ee.phase == 1) {                         /* 第 2 个字节：字地址 */
        g_ee.ptr = b;
        g_ee.phase = 2;
        return 1;
    }
    if (g_ee.rw == 0) {                            /* 数据字节：先收下，等 twr 才落盘 */
        g_ee.stage[g_ee.ptr] = b;
        g_ee.pending = 1;
        g_ee.pending_addr = g_ee.ptr;
        ++g_ee.ptr;                                /* 地址自增：页写的硬件基础 */
    }
    return 1;
}

/* 从机把当前字节一位一位送到 SDA 上（高位先出） */
static int slave_read_bit(void)
{
    int bit;

    if (g_ee.present == 0) {
        return 1;                                  /* 没人驱动，上拉把线拉高 */
    }
    if (g_ee.bitpos == 0) {
        g_ee.cur = g_ee.nv[g_ee.ptr];
    }
    bit = (g_ee.cur >> (7 - g_ee.bitpos)) & 1u;
    ++g_ee.bitpos;
    if (g_ee.bitpos == 8) {
        g_ee.bitpos = 0;
        ++g_ee.ptr;
    }
    return bit;
}

/* ============================================================
 * 三、主机侧：起始 / 停止 / 写一个字节 / 读一个字节
 * ============================================================ */
static void i2c_start(void)
{
    bus_sda(1);
    bus_scl(1);
    bus_sda(0);                    /* SCL 高电平期间 SDA 下降 = 起始条件 */
    bus_scl(0);
    slave_on_start();
}

static void i2c_stop(void)
{
    bus_sda(0);
    bus_scl(1);
    bus_sda(1);                    /* SCL 高电平期间 SDA 上升 = 停止条件 */
}

/* 写一个字节，返回 1 表示从机应答了。第 9 个时钟就是 ACK 位 */
static int i2c_write_byte(unsigned char b)
{
    int i, ack;

    for (i = 7; i >= 0; --i) {
        bus_sda((b >> i) & 1);     /* 高位先发 */
        scl_pulse();
    }
    bus_sda(1);                    /* 主机松手，把 SDA 让给从机 */
    ack = slave_on_byte(b);
    scl_pulse();                   /* 第 9 个时钟 */
    return ack;
}

/* 读一个字节。send_ack = 1 表示「我还要下一个」，0 表示「够了，NACK」 */
static unsigned char i2c_read_byte(int send_ack)
{
    int i;
    unsigned char b = 0;

    bus_sda(1);                    /* 主机松手，从机来驱动 SDA */
    for (i = 0; i < 8; ++i) {
        bus_scl(1);
        ++g_clocks;
        b = (unsigned char)((b << 1) | (unsigned char)(slave_read_bit() & 1));
        bus_scl(0);
    }
    bus_sda(send_ack ? 0 : 1);
    scl_pulse();
    return b;
}

/* ============================================================
 * 四、AT24C02 的两个基本操作：字节写、随机读
 * ============================================================ */
static int ee_write_byte(unsigned char addr, unsigned char val)
{
    i2c_start();
    if (!i2c_write_byte(0xA0)) {   /* 器件地址 + 写方向 */
        i2c_stop();
        return 0;
    }
    if (!i2c_write_byte(addr)) {   /* 字地址 */
        i2c_stop();
        return 0;
    }
    if (!i2c_write_byte(val)) {    /* 数据 */
        i2c_stop();
        return 0;
    }
    i2c_stop();
    return 1;                      /* 1 = 总线上有人应答，芯片已收下 */
}

static int ee_read_byte(unsigned char addr, unsigned char *out)
{
    i2c_start();
    if (!i2c_write_byte(0xA0)) {   /* 先用「写」把地址指针设进去 */
        i2c_stop();
        return 0;
    }
    if (!i2c_write_byte(addr)) {
        i2c_stop();
        return 0;
    }
    i2c_start();                   /* 重复起始：换方向但不断开总线 */
    if (!i2c_write_byte(0xA1)) {   /* 器件地址 + 读方向 */
        i2c_stop();
        return 0;
    }
    *out = i2c_read_byte(0);       /* 只读一个字节，所以回 NACK */
    i2c_stop();
    return 1;
}

/* 写周期 twr：手册给的典型值是 5ms。这 5ms 里芯片「不理总线」 */
static void ee_wait_write_cycle(void)
{
    int i;

    if (g_ee.pending == 0) {
        return;
    }
    for (i = 0; i < 5; ++i) {
        /* 真机上可以空等 5ms，也可以「发地址探一下，没 ACK 就再等」 */
    }
    g_ee.nv[g_ee.pending_addr] = g_ee.stage[g_ee.pending_addr];
    g_ee.pending = 0;
}

11. 把机制拼起来：一个最小系统的骨架

到这里你有了三块积木。但真实设备不是「三个 demo 摆在一起」，而是它们共享一个时间轴：

时间尺度 谁在管 干什么 为什么是这个尺度
1ms 定时器中断 累计毫秒、给别的任务「报时」 硬件能保证不丢
10ms 主循环（按 1ms 节拍分频） 扫按键、消抖、刷一位数码管 人眼和手指都够用
100ms 主循环 检查「要不要保存」 别写太勤，护 EEPROM 寿命
5ms 主循环（切片轮询） EEPROM 写周期 不能死等，否则别的任务全停
不定 串口中断 + 主循环 收字节、拼行、解析 中断只收，解析给主循环

这张表就是「实时系统」的雏形。下面这个骨架把五条线串起来：

/* 教学版骨架：1ms 节拍 + 串口命令 + 掉电保存 */
#include <stdio.h>
#include <string.h>

/* ============================================================
 * 一、EEPROM：只有两个操作，写要等 twr，读是立刻的
 * ============================================================ */
static unsigned char ee_nv[256];          /* 掉电不丢的那 256 字节 */
static unsigned char ee_stage;            /* 已收到、还没落盘的值 */
static unsigned char ee_pending;          /* 有没有正在进行的写 */
static unsigned char ee_pending_addr;
static unsigned char ee_wait_ms;

static void eeprom_init(void)
{
    int i;

    for (i = 0; i < 256; ++i) {
        ee_nv[i] = 0xFF;                  /* 擦除后的状态 */
    }
    ee_pending = 0;
    ee_wait_ms = 0;
}

static void eeprom_write_request(unsigned char addr, unsigned char val)
{
    ee_pending_addr = addr;
    ee_stage = val;
    ee_pending = 1;
    ee_wait_ms = 0;
}

/* 每 1ms 问一次：写周期过了没有。绝不在这里空等 5ms */
static void eeprom_task_1ms(void)
{
    if (ee_pending == 0) {
        return;
    }
    if (++ee_wait_ms < 5) {               /* twr 约 5ms，以数据手册为准 */
        return;
    }
    ee_nv[ee_pending_addr] = ee_stage;
    ee_pending = 0;
}

static unsigned char eeprom_read(unsigned char addr)
{
    return ee_nv[addr];
}

/* ============================================================
 * 二、节拍：中断里只做加法
 * ============================================================ */
static volatile unsigned int g_ms = 0;

static void timer0_isr(void)              /* 真机：interrupt 1 */
{
    ++g_ms;
}

/* ============================================================
 * 三、串口：中断里只收字节、拼行；解析留给主循环
 * ============================================================ */
#define RX_MAX 8

static char g_rx[RX_MAX + 1];
static unsigned char g_rx_len = 0;
static char g_cmd[RX_MAX + 1];
static volatile unsigned char g_cmd_pending = 0;

static void uart_rx_isr(char c)
{
    if (c == '\r') {
        return;                           /* \r 丢掉，只认 \n 作为一行的结束 */
    }
    if (c == '\n') {
        if (g_cmd_pending == 0) {         /* 主循环还没取走上一条，就丢掉这条 */
            unsigned char i;
            for (i = 0; i <= g_rx_len; ++i) {
                g_cmd[i] = g_rx[i];
            }
            g_cmd_pending = 1;
        }
        g_rx_len = 0;
        g_rx[0] = '\0';
        return;
    }
    if (g_rx_len < RX_MAX) {
        g_rx[g_rx_len++] = c;
        g_rx[g_rx_len] = '\0';
    }
}

/* ============================================================
 * 四、业务：计数、显示、保存
 * ============================================================ */
static unsigned char g_count = 0;         /* 正在显示的数字 */
static unsigned char g_dirty = 0;         /* 变了但还没存 */

static void handle_command(void)
{
    if (g_cmd_pending == 0) {
        return;
    }
    g_cmd_pending = 0;

    if (strcmp(g_cmd, "m1") == 0) {
        ++g_count;
        if (g_count > 99) {
            g_count = 0;
        }
        g_dirty = 1;
        printf("  [%4ums] 收到 m1 -> 计数 = %u，标记待保存\n",
               g_ms, (unsigned)g_count);
    } else if (strcmp(g_cmd, "beer") == 0) {
        printf("  [%4ums] 收到 beer -> 蜂鸣器响一声（不碰 EEPROM）\n", g_ms);
    } else {
        printf("  [%4ums] 收到 \"%s\" -> 不认识，回一句错误提示\n", g_ms, g_cmd);
    }
}

/* 每 100ms 一次：把「变了」的东西排进 EEPROM 的写入队列 */
static void save_task_100ms(void)
{
    if (g_dirty == 0 || ee_pending != 0) {
        return;                           /* 没变，或者上一次还没写完 */
    }
    eeprom_write_request(0x00, g_count);
    g_dirty = 0;
    printf("  [%4ums] 发起保存：0x00 <- %u（接下来 5ms 不能断电）\n",
           g_ms, (unsigned)g_count);
}

static void display_task_500ms(void)
{
    printf("  [%4ums] 数码管显示 %02u\n", g_ms, (unsigned)g_count);
}

int main(void)
{
    static const struct {
        unsigned int at_ms;
        const char *text;
    } script[] = {
        {  600, "m1\n"   },
        {  900, "m1\n"   },
        { 1500, "beer\n" },
        { 1700, "m12\n"  }
    };
    const unsigned int script_n = (unsigned int)(sizeof(script) / sizeof(script[0]));
    unsigned int t, k;

    eeprom_init();
    g_count = eeprom_read(0x00);
    if (g_count > 99) {                   /* 第一次上电：EEPROM 是 0xFF，无效 */
        g_count = 0;
    }
    printf("上电：从 EEPROM 读回计数 = %u\n\n", (unsigned)g_count);

    for (t = 0; t < 2200; ++t) {
        timer0_isr();                     /* 真机：硬件每 1ms 自己调一次 */

        /* 串口字节按脚本在这一毫秒到达（真机：串口中断随时进来） */
        for (k = 0; k < script_n; ++k) {
            if (script[k].at_ms == t) {
                const char *p;
                for (p = script[k].text; *p != '\0'; ++p) {
                    uart_rx_isr(*p);
                }
            }
        }

        handle_command();                 /* 主循环：解析、执行业务 */
        eeprom_task_1ms();                /* 主循环：推进写周期 */
        if ((t % 100u) == 0u) {
            save_task_100ms();
        }
        if ((t % 500u) == 0u) {
            display_task_500ms();
        }
    }

    puts("\n---- 断电，再上电 ----");
    g_count = 0;                          /* 单片机 RAM 全丢 */
    g_dirty = 0;
    g_ms = 0;
    g_cmd_pending = 0;
    g_count = eeprom_read(0x00);          /* 开机第一件事：把值捡回来 */
    printf("重启：从 EEPROM 读回计数 = %u（断电前的值）\n", (unsigned)g_count);
    return 0;
}

四件事在这个骨架里各就各位：

  1. ISR 只做加法（++g_ms、收一个字节），没有一行阻塞代码；
  2. 主循环按不同周期调用不同的任务（1ms / 100ms / 500ms），谁也不 blocking 谁；
  3. EEPROM 写是「发起 + 轮询」，5ms 的等待被摊平到 5 次 1ms 里，中间还能刷显示；
  4. 命令解析只认完整行，m12 这种直接报错。

这四条加起来，就是「能当设备用」和「能跑 demo」的区别。

还有一条必须提前知道的差异：Keil C51 基本是 C89。

  • 变量必须在语句块开头声明，不能「用的时候再声明」；

  • 本篇代码用了 unsigned long long 做中间计算——那只是 PC 上的教学写法，Keil 里要改成「提前算好的常数」或者用浮点（能不用就不用）。

15. 安全与规范：本篇三条铁律

铁律一：时间只信硬件，空循环只用来「给人看」。

  • 任何需要「准」的时间——节拍、超时、波特率、方波——一律交给定时器；
  • delay_ms() 只允许出现在两种地方：点灯给人看、跟传感器打粗略时序（比如 DS18B20 的微秒级配合，还要小心）；
  • 中断里绝不调用延时函数。ISR 里「等 100μs」，整个系统的实时性就没了。

铁律二：中断只记账，不干活。

  • ISR 里只允许：置标志、加计数、翻转一个 IO、读写一个字节的硬件寄存器、重装初值；
  • 任何可能超过几十个机器周期的操作（printf、浮点、循环、EEPROM 写、等标志），全部搬到主循环；
  • 所有「ISR 改、主循环读」的变量必须 volatile，读 16 位变量要防「劈开」。

铁律三：一切「等外部世界」的操作，必须有超时；一切共享变量，必须有 volatile。

  • 等 I2C 的 ACK、等串口的字节、等 EEPROM 的写周期——都要有计数器兜底。总线一挂，没有超时的 while 会让整台设备变砖；
  • 上电初始化时，对外设的「等待」尤其危险：那时候没有人会来救你；
  • 硬件侧的三条底线：I2C 必须有上拉电阻、串口必须共地、接线拔线先断电。5V 和 GND 直接短接，烧的不是代码，是稳压芯片。

18. 本阶段复盘与下一步衔接

复盘三问：

  1. 阶段十你写过一句 delay_ms(200)，今天你知道它至少有三重不可靠。如果明天有人给你一块 11.0592MHz 的板子、要求「每 200ms 精确翻转一次 IO」，你会怎么改？ 改动会落在哪几行？为什么不是「多试几个数」？
  2. 中断那一节说「ISR 只记账，不干活」。回头看任务 6 的串口接收：如果 ISR 里直接解析命令、直接点亮 LED、直接回一句英文，会发生什么？在主循环正在刷数码管的时候，那一帧显示会怎样？
  3. I2C 那一节说「两根线、一个应答位」。如果某天你的 EEPROM 突然全部 NACK，你会按什么顺序排查？（提示：供电 → 上拉 → 地址 → 焊接。顺序错了，你会花两小时在一个 4.7k 电阻上。）

从阶段十到这两篇实战，你真正学会的东西：

不是「定时器怎么配」，也不是「串口怎么写」——那些查手册就有。你学会的是三件更硬的事：

  • 把时间交给硬件：从「数指令」到「数晶振」，这是「玩具」和「设备」的分界；
  • 把并发拆成两层：中断记账、主循环干活，这是所有实时系统的骨架，从 51 到 STM32 到 RTOS 都一样；
  • 把不确定关进笼子：超时、上限、完全匹配、ACK 检查——这四样东西写进代码，设备才不会「偶尔抽风」。

衔接预告（51 实战三：时钟、液晶、AD 与综合项目）：

下一篇你会遇到四样新东西，但你会发现它们用的全是这一篇的功夫：

  • DS1302 时钟芯片：它自己带电池和晶振，走的是「类 SPI」的三根线。你会发现它和 I2C 一样，都是「按时序翻引脚」——手法一样，只是协议换了；
  • 1602 / 12864 液晶：并口或串口，本质是「往它内部的 RAM 里写字符」。你会用到 §11 的分工表：写屏是慢活，必须切片；
  • AD 转换（比如 ADC0809 或内部 AD）：把电压变成数字。你会第一次遇到「采样时间」这个概念，它和 §7 的「定时」是一回事；
  • 综合项目：一个「能看时间、能显示、能按键设置、断电还记得」的小设备——这一篇的三块积木，就是它的全部地基。

再往远看一层：51 之后是 STM32（同样是定时器、串口、I2C，只是寄存器名字变了、多了库函数），再之后是 RTOS（把「1ms 节拍 + 任务分频」升级成调度器）。你在这篇里写的那个 for 循环里按不同周期调用不同任务的骨架，就是 RTOS 任务调度的手工版——到时候你会认出来：「这不就是我那个 1ms 节拍吗。」

验收清单全勾了吗？勾了，就把你的方波接到示波器上，看着那条真正由晶振决定的线——从今天起，你的设备有了自己的时间。
