1. 本节目标与前置知识

目标： 1. 掌握 struct 的定义、三种初始化（顺序 / {0} / 指定初始化 .x=）、成员访问 .。 2. 理解结构体是值语义：能整体赋值、能整体复印——与阶段四「数组不能整体赋值」形成对照，并讲清原因。 3. 掌握结构体作函数参数的两条路：传值（整个复印）vs 传指针（const 保护）——回收阶段三的复印件定理、阶段五的指针手法。 4. 掌握 -> 运算符及其与 (*p).field 的等价关系，会用「传指针」在函数里修改结构体原件。 5. 掌握结构体数组（遍历、追加、擂台法找最值——阶段四功夫原样复用）与结构体嵌套（日期套进事项）。 6. 对 sizeof 结构体与内存对齐建立「有印象即可」的认知（深讲留给阶段七/九）。 7. 掌握 enum 消灭魔法数字（菜单、星期），并与 #define 对比。 8. 掌握 union 的「同一块内存多种解读」，会用 union 做字节观察实验（阶段七字节序的预告）。 9. 独立完成任务四与任务六。

前置： 阶段五全部内容。特别提醒一条：阶段五你已经会「把变量的地址传给函数，函数顺着地址改原件」——本阶段 §5 只是把那个「变量」换成一个结构体，手法一模一样。

2. 场景引入：散装的 x、y——而不是一个点

阶段五之前，你的数据全是「散装」的。想象程序里要处理一个二维坐标点：你得定义 double x, y; 两个变量；想把点传给函数，得 f(x, y) 两个参数地传；想处理 10 个点，得 x[10], y[10] 两个数组对齐着用——「这是一个点」这件事，代码里根本看不出来，全靠你脑子记着「x 和 y 是一对」。

结构体 = 把相关的数据装进一个盒子，贴上标签。定义一次「图纸」：struct Point { double x; double y; };，之后 struct Point p; 就是一个完整的点——传函数只传一个 p，数组只要一排盒子 struct Point pts[10];。盒子里的 x、y 永远绑在一起，想散都散不了。

同样的道理：一本图书 = 书名 + 年份 + 定价；一个日期 = 年 + 月 + 日。凡是「几个数据天然属于一体」的地方，就是结构体的战场。任务四的三个分量（x,y,z）天然属于一个向量、任务六的几项信息天然属于一条记录——它们等你学完本阶段就能动手。

3. 核心概念一：struct——定义图纸、三种出生、点访问

3.1 先造图纸，再声明变量

struct Point {                 /* 定义「图纸」：一个点有两个 double 成员 */
    double x;
    double y;
};

struct Point p1;               /* 用图纸声明一个变量：p1 是一个完整的点 */

struct Point 合起来是一个类型名（struct 二字不能省，C 语言的规矩）。图纸本身不占内存，声明出变量才真的开出一块内存——就像 int 是图纸，int a; 才占 4 字节。

3.2 三种出生方式（与阶段四数组的初始化一一对应）

struct Point p1 = {3.0, 4.0};            /* 顺序初始化：按成员顺序逐个给 */
struct Point p2 = {0};                   /* 惯用法：所有成员清零（数组 {0} 的同族） */
struct Point p3 = {.y = 2.5, .x = 1.5};  /* 指定初始化：点名给，顺序随意 */

指定初始化（.成员 = 值）强烈推荐：成员一多，「按顺序给」很容易对错位置；点名给则一眼看清谁是谁，漏给的成员自动清零。

3.3 点访问 .：成员就是普通变量

p1.x = 10.0;                    /* 写 */
printf("%.1f\n", p1.y);         /* 读 */

p1.x 读作「p1 这个盒子里贴着 x 的那一格」。它就是一个普通的 double，能运算、能取地址（&p1.x 合法）、能 scanf。

3.4 typedef 两种风格

/* 风格一：裸 struct，每次声明都写全 struct Point */
struct Point a;

/* 风格二：typedef 起短名，之后 Vec2 b; 即可 */
typedef struct {
    double x;
    double y;
} Vec2;
Vec2 b;

两种风格都合法、都常见。翁恺课程以风格一为主，工程代码风格二居多——两种都要看得懂，因为网上的代码两种都有。配套 01_struct_basics.c 把两种风格并排演示。

4. 核心概念二：结构体整体赋值——值语义（与字符串的对照实验）

阶段四你背过一条纪律：char t[10]; t = "hello"; 编译错误，数组不能整体赋值；s1 == s2 比的是地址不是内容。

结构体恰好相反：

struct Point p1 = {10.0, 4.0};
struct Point p5;
p5 = p1;        /* ✔ 合法！整个盒子逐字节复印一份 */
p5.x = 99.0;    /* 改 p5，p1 纹丝不动——两个独立的盒子 */

为什么数组不行、结构体行？因为 C 语言里结构体是值语义：它和 int、double 一样是「一个值」，赋值就是整个复印。而数组名在表达式里会退化成首地址（阶段五），t = "hello" 想做的其实是「把一个地址赋给另一个地址」——数组的地址是定死的，当然不行。

记住这条对照，能一次解释阶段四和本阶段的两堆现象：

操作 数组 结构体
整体赋值 b = a; ✘ 编译错误 ✔ 整个复印
a == b 比内容 ✘ 比的是地址 ✘ 也不能！结构体连 == 都不支持，要逐成员比
传函数 退化为首地址（改的是原件） 传值（整个复印，改的是复印件）

配套 01_struct_basics.c 的「整体赋值」段：跑一遍，亲眼看看改 p5 之后 p1 纹丝不动。

5. 核心概念三：结构体与函数——复印件定理的回收站

5.1 传值：整个复印！

void translate_fail(struct Point p, double dx, double dy)
{
    p.x += dx;   /* 改的是复印件，原件不动 */
}

阶段三的复印件定理原样适用，只是复印件从「4 字节的 int」变成了「16 字节的整个结构体」。后果有二：

  1. 改不动原件（老现象）；
  2. 浪费（新现象）：一个 100 字节的结构体每调一次函数就复印 100 字节，结构体越大越心疼。

5.2 传指针 + const：大结构体的标准姿势

void print_point(const char *label, const struct Point *p)
{
    printf("%s: (%.1f, %.1f)\n", label, p->x, p->y);
}

只传一个地址（8 字节），不管结构体多大都不浪费；const 承诺只读——阶段五学的 const 指针在这里正式上岗：以后看到「结构体 + 函数」，默认就该想到「传 const 指针」。

5.3 -> 与 (*p).field 等价

p->x      /* 读作「p 指向的那个结构体的 x」 */
(*p).x    /* 完全等价：先 * 解引用找到原件，再 . 取成员 */

(*p).x 的括号不能省：. 的优先级比 * 高，*p.x 会被理解成 *(p.x)——编译器报错。正因为括号太烦，C 专门给了 -> 这个语法糖。看到 p->x，脑子里翻译成 (*p).x，本质就清楚了。

5.4 传指针改原件：阶段五 swap 的同一手法

void translate(struct Point *p, double dx, double dy)
{
    p->x += dx;      /* 顺着地址改原件 */
    p->y += dy;
}
/* 调用：translate(&a, 3.0, 4.0);  把 a 的地址抄给函数 */

对照阶段五的 swap(&x, &y)：手法一字不差，只是「原件」从 int 变成了结构体。这就是任务六的全部技术内核——教程把知识交给你，任务代码由你自己组织。

配套 02_struct_function.c：三条路并排跑一遍——传值失败现场、传指针成功、const 只读打印。先预测每行输出，再运行。

6. 核心概念四：结构体数组与嵌套

6.1 结构体数组：一排盒子

struct Book shelf[10] = {
    {"C Primer Plus", 2015, 128.00},
    {"The C Programming Language", 1988, 45.00},
};

遍历、追加、找最值——阶段四的四大基本功原样复用，只是「一格」从 int 变成了一个盒子：

int best = 0;                                   /* 擂台法记下标 */
for (i = 1; i < n; i++) {
    if (shelf[i].year < shelf[best].year) best = i;
}

注意结构体里装数组（char title[40]）完全合法——盒子里面还可以有小格子；反过来，给这种成员赋值时遵守阶段四纪律：字符串成员只能逐格写或初始化时给（03_struct_array.c 里追加那本书就是这么做的）。

6.2 嵌套：盒子里装盒子

struct Date { int year; int month; int day; };

struct Event {
    char what[40];
    struct Date date;      /* 事项里装着一个日期 */
    int done;
};

struct Event e = {"机器人实验课", {2026, 10, 25}, 0};   /* 大括号套大括号 */
e.date.year        /* 层层点下去：盒子里的盒子里的格子 */

访问规则一句话：从外往里，一层一层点。传指针时则 e->date.month（-> 优先于 .，从左往右读）。配套 05_date_nested.c 演示嵌套初始化、层层访问、以及「整体赋值会把嵌套的 Date 一起复印」这件事。

7. 核心概念五：sizeof 结构体与内存对齐（有印象即可）

sizeof(struct Point) = 16（两个 double，8+8，刚好）。但别急着推广：

struct Demo {
    char c;     /* 1 字节 */
    int  n;     /* 4 字节 */
};              /* sizeof 是多少？不是 5！通常是 8 */

内存对齐：编译器为了让 CPU 访问更快，会让 int 从「4 的倍数」的地址开始放，char 后面可能空出 3 字节「 padding（填充）」。所以：

  • sizeof 结构体 ≥ 各成员之和，具体多少由对齐规则决定；
  • 用 sizeof 问编译器，永远不要自己算——这是唯一可靠的办法；
  • 想省内存？把大成员排前面、小成员排后面（印象即可）。

深讲留给阶段七（配合类型大小一起看）和阶段九（动态内存分配要算准大小）。现在只需要一个印象：结构体在内存里不一定是严丝合缝的，sizeof 说了算。练习 3（纸上作业）会让你推演几个，建立起这个直觉。

8. 核心概念六：enum 枚举——消灭魔法数字

阶段二的单位换算菜单里你写过 if (choice == 1) ... else if (choice == 2)——这个 1、2 就是魔法数字：三个月后回头看，2 是啥意思？谁也不知道。

enum Menu { MENU_EXIT = 0, MENU_SHOW = 1, MENU_ADD = 2, MENU_DEL = 3 };

enum Menu choice = MENU_ADD;
switch (choice) {
case MENU_ADD:  /* 一眼看懂 */  break;
...
}

要点三条：

  1. 枚举值就是整数：MENU_ADD 就是 2，printf("%d", MENU_ADD) 打印 2；不指定初值则从 0 开始自动 +1，指定了初值（如 MON = 1）则后面的接着数。
  2. 与 #define 的对比：#define MENU_ADD 2 也能做到，但#define 是「预处理期文本替换」，没有类型、不进调试器；enum 是「编译器认识的常量」，调试时能看到名字、switch 漏处理某个枚举值时 -Wall 还可能提醒你。一组相关的常量，优先 enum。
  3. enum + switch 是黄金搭档：菜单、星期、状态机，凡是「有限几种取值」的场合都这么写。任务四的菜单、考核的菜单，都该用 enum 写。

配套 04_enum_union.c 上半段。练习 7 会让你亲手把一个魔法数字菜单重构成 enum 版。

9. 核心概念七：union 联合——同一块内存的多种解读

结构体是「几个成员各占各的格子，并排摆放」；联合是「几个成员挤在同一块内存，互相覆盖」：

union IntViewer {
    int          whole;      /* 4 字节 */
    unsigned char bytes[4];  /* 也是 4 字节——和 whole 占同一块内存！ */
};

union IntViewer v;
v.whole = 0x01020304;        /* 按 int 写入 */
v.bytes[0]                   /* 按字节读出：04（x86 小端） */

要点三条：

  1. sizeof(union) = 最大成员的大小（大家合住一间房，房间只要装得下最大那位）；
  2. 写谁就用谁读是规矩；「写 whole 读 bytes」属于有意为之的类型双关——合法的观察手法，但要清楚自己在干什么；
  3. 它是观察内存的显微镜：04_enum_union.c 下半段把 0x01020304 写进去再逐字节看，你会亲眼看到字节顺序是 04 03 02 01——最小的字节存在最前面，这叫「小端」。这个实验手法就是阶段七「字节序、类型截断」的预告，也是任务七的隐形地基。

union 在初学阶段用途不多，记住一句话就够：结构体是并排摆，联合是叠着放。

12. 常见错误与调试速查（本阶段相关）

症状 真因 一句话药方
expected identifier before ... 一堆错 结构体定义末尾忘了分号 }; 图纸结尾必须有分号
成员改完打印还是垃圾值 声明了没初始化就用 = {0} 起手，纪律同阶段二
*p.x 报错 / 行为诡异 . 优先级高于 *，变成 *(p.x) 写 p->x 或 (*p).x
函数里改了结构体，外面没变 传值——改的是复印件 改原件要传 &变量，参数用指针
scanf 直接读进结构体里的字符数组溢出 %s 没写宽度 阶段四纪律原样适用：%39s 或 fgets
结构体 == 编译报错 结构体不支持整体比较 逐成员比（练习 4 专门练）
sizeof 结果比自己算的大 内存对齐（padding） sizeof 说了算，别自己算
结构体数组越界 老问题新场地 下标 0~n-1，纪律同阶段四

调试手段：断点 + VARIABLES 面板展开结构体（VSCode 可以逐层展开 p 看到 x、y）；传指针时在函数里悬停看 p 的地址，和 main 里 &a 对比——地址相同 = 改的就是原件（阶段五的验证法原样复用）。

13. 安全与规范：本阶段三条铁律

  1. 结构体变量出生时必须给值——= {0} 是最便宜的安全带；只给部分成员时，其余成员自动清零（仅限初始化，赋值语句没这待遇）。
  2. 结构体里的数组成员，遵守阶段四全部纪律——越界照样不设防，title[40] 写 title[40] 格就是越界；字符串成员照样要留 \0 的位置。
  3. 函数要改结构体，参数必须是指针；只读就加 const——传值改不动原件（复印件定理），传指针不加 const 就是放弃了编译器的保护。

数学提示（属于知识，不属于代码）： - 向量模长：|v| = √(x² + y² + z²)，sqrt 在 <math.h> 里，MinGW 下直接链接无需额外参数； - 两向量垂直 ⟺ 点积为 0，即 x₁x₂ + y₁y₂ + z₁z₂ = 0； - 两向量共线 ⟺ 对应分量成比例（等价说法：叉积为零向量）； - 浮点数不许用 == 判等：用 fabs(差) < 1e-9（阶段二教过，fabs 也在 <math.h>）； - 输出格式要对上示例：任务四给的示例写的是「模长 3.741657」。这个数不是随便写的——1²+2²+3² = 14，√14 = 3.7416573867…，保留 6 位小数正好截成 3.741657。所以打印用 printf("%.6f", r)（%f 默认也是 6 位，等价）；别自作主张改成 %.2f 或 %.10f，格式对不上批改时会被当成算错； - 用除法求「比例」会遇到分量为 0 的麻烦——想一想：能否把「成比例」改写成只用乘法和减法的形式？（提示：a/b = c/d 两边同乘 bd；三个分量两两都要满足。）
