1. 本节目标与前置知识

目标： 1. 理解地址是什么，会用 & 取地址、%p 打印地址。 2. 掌握指针变量的定义（int *p）、解引用（*p），建立「门牌号」心智模型。 3. 建立指针初始化纪律（int *p = NULL;）——你的「未初始化」老毛病在指针上会升级成灾难。 4. 写出真正的 swap（传指针改原件），亲手收网阶段三 swap_wrong 的悬念。 5. 理解 a[i] ≡ *(a+i)，指针算术 p+1 的步长 = sizeof(元素)，彻底明白下标为什么从 0 开始。 6. 分清 const 的四种位置：const int *p 与 int *const p 各管什么。 7. 用指针遍历字符串，写出指针版 my_strlen，纸上推演 *p++ 与 (*p)++。 8. 认识野指针三大场景，学会用 -Wall 和调试器把它们抓出来。 9. 掌握传出参数模式（void divmod(int a, int b, int *q, int *r)）——「一个返回值不够用」的正解。

前置： 阶段三的「复印件定理」、阶段四的「下标本源是偏移量」「数组参数传的是地址」。本阶段就是把这三个反复出现的现象统一收网。

2. 场景引入：两条悬念，一个答案

阶段三你做过一个「失败」的实验（02_swap_fail.c）：swap_wrong(x, y) 在函数内部明明交换成功了，回到 main 一看，x 和 y 纹丝不动。当时我们给了它一个名字——复印件定理：传值调用时，函数拿到的是值的复印件，改复印件改不到原件。你还亲手画了那张内存图（阶段三练习 3）：x、y 和 a、b 住在四个不同的格子里。

同样是阶段三，另一个实验却「成功」得莫名其妙：把数组传给函数，函数里改 arr[0]，main 里的真数组真的变了。为什么变量传过去是复印件，数组传过去就能改原件？

阶段四又添了几条线索：「s1 == s2 比的是地址不是内容」「a[i] 的下标本源是偏移量」「%p 打印出来的是地址」。

现在统一收网：C 函数之间真正能传递的「遥控器」，就是地址。 数组参数能改真数组，是因为传过去的本质是数组首元素的地址；swap_wrong 失败，是因为你只给了值、没给地址。想让别人改你的变量，你不能给他复印件，得给他你家的门牌号——这就是指针。

指针不神秘：它就是一个存地址的变量。 你已经用过它的全部现象，本阶段只是补上名字和原理。

3. 核心概念一：地址、& 与 %p

3.1 每个变量都有地址

程序运行时，每个变量都住在内存的某个格子里，格子的编号就是地址。用取地址运算符 & 拿到它，用 %p 打印它：

int x = 42;
double pi = 3.14;
char c = 'A';

printf("x  的值=%d, 地址=%p\n", x, (void *)&x);
printf("pi 的值=%.2f, 地址=%p\n", pi, (void *)&pi);
printf("c  的值=%c, 地址=%p\n", c, (void *)&c);

三件事要记住：

  1. %p 配 (void *) 强制转换是标准写法，能消除 -Wall 下的类型警告；
  2. 地址长这样：000000000061FE1C——一串十六进制数。每次运行都可能不同（操作系统随机摆放），所以别背地址，看规律；
  3. 你在阶段三调试器里悬停变量时见过的「地址」，和 %p 打印的是同一个东西——调试器和 printf 在互相印证。

配套 01_pointer_basics.c：打印三种类型变量的值与地址，再观察相邻变量的地址差——你会发现 int 邻居地址差 4、double 差 8，这不是巧合，是 sizeof 在内存里的实体化。

4. 核心概念二：指针变量——门牌号写在纸条上

4.1 定义与解引用

int x = 42;
int *p = &x;      /* p 是一个「指向 int 的指针」，装着 x 的地址 */

printf("%p\n", (void *)p);    /* p 的内容：x 的地址（那张门牌号） */
printf("%d\n", *p);           /* *p：按门牌号找到房子，取里面的东西 → 42 */

*p = 99;          /* 按门牌号找到房子，把里面的东西换成 99 */
printf("%d\n", x);            /* x 真的变成了 99 —— 复印件定理被打破 */

两个 * 千万别混：

  • 定义时 int *p;：* 是类型的一部分，读作「p 是指向 int 的指针」；
  • 使用时 *p：* 是解引用运算符，读作「p 指向的那个东西」。

4.2 门牌号心智模型（贴冰箱上）

说法 对应
变量 = 房子 int x = 42; 一间叫 x 的房子，里面住着 42
地址 = 门牌号 &x 这间房子的门牌号（如 幸福路 61FE1C 号）
指针 = 记着门牌号的纸条 int *p = &x; 纸条上写着 x 的门牌号
解引用 = 按门牌号找上门 *p 照纸条找到那间房子，对里面的东西读写

swap_wrong 为什么失败？你给了函数一张写着「42」的纸条（值），它怎么改都只是改纸条。真 swap 为什么成功？你给了函数写着门牌号的纸条，它按图索骥，改的是房子本身。

4.3 指针自己也是变量

纸条本身也占格子：int *p 在 64 位 MinGW 下 sizeof(p) 是 8（字节），不管它指向 int 还是 double——门牌号的纸条大小统一，区别在于「按这个门牌号找到的房子是几居室」（指针的类型决定解引用时读几个字节、指针算术时一步跨多远，§6 展开）。

5. 核心概念三：NULL 与指针初始化纪律

阶段二你的老毛病是「未初始化变量读出垃圾值」。指针不初始化，后果升维：

int *p;         /* 危险！p 里是随机垃圾地址 */
*p = 42;        /* 灾难：往一个随机地址写数据，可能改坏任何东西、可能直接崩 */

未初始化的 int 顶多是算错数；未初始化的指针是拿着一张乱写的门牌号去撬别人家的门。这就是为什么本阶段第一条铁律是：

int *p = NULL;    /* 出生先置空：明确的「暂时没有指向」 */

NULL 是地址 0，是一块谁都知道不能碰的禁区。纪律用法：

int *p = NULL;
/* ... 某个时刻 p = &x; ... */
if (p != NULL) {
    *p = 42;               /* 确认纸条上有真门牌号，才敢上门 */
}

好处有两个：① 忘了赋值时，p != NULL 检查能拦住你；② 万一没拦住，对 NULL 解引用通常立刻崩溃——「立刻崩」是好消息，bug 在案发现场被抓，比「跑了一小时才算错一个数」强一百倍。配套 01_pointer_basics.c 演示这个 if 守卫的完整写法。

6. 核心概念四：传指针改原件——真 swap（收网时刻）

阶段三的悬念，今天结案：

void swap(int *a, int *b)     /* 收两张门牌号纸条 */
{
    int t = *a;     /* 按 a 的纸条，取出那间房子里的值 */
    *a = *b;        /* 按 b 的纸条取值，写进 a 纸条指向的房子 */
    *b = t;         /* 把暂存的值写进 b 纸条指向的房子 */
}

int main(void)
{
    int x = 1, y = 2;
    swap(&x, &y);             /* 把 x、y 的门牌号交出去 */
    printf("x=%d y=%d\n", x, y);   /* x=2 y=1 —— 真的换了！ */
    return 0;
}

对照记忆（这张表请背下来）：

swap_wrong（阶段三） swap（本阶段）
形参 int a, int b（复印件） int *a, int *b（门牌号）
调用 swap_wrong(x, y) swap(&x, &y)
函数内 改 a、b 这两个复印件 *a、*b 按门牌号改原件
结果 main 里 x、y 不变 main 里 x、y 互换

内存图（把阶段三练习 3 那张图升级画完）：

main 的地盘                    swap 的地盘
┌───────┐ 幸福路...1C         ┌───────┐
│ x = 2 │◄────────────────────│ a =...1C │──┐ 纸条写着 x 的门牌号
└───────┘                     └───────┘  │ *a 就顺藤摸到 x
┌───────┐ 幸福路...18         ┌───────┐  │
│ y = 1 │◄────────────────────│ b =...18 │──┘
└───────┘                     └───────┘

a、b 本身依然是复印件（传值调用没有例外！）——但这次复印的是地址。复印件定理没有被违反，而是你复印了「能找上门的钥匙」。配套 02_swap_real.c 把新旧两个 swap 放在同一个程序里对拍，并打印地址亲眼验证「*a 就是 x」。

预告：任务六要交换的是两个 student 结构体。现在你先吃透「交换两个 int」；阶段六结构体一学，同样的门牌号手法原封不动搬过去——变的只是纸条上写的是什么房子的门牌号。

7. 核心概念五：指针与数组——a[i] 的真身是 *(a+i)

7.1 一等式

阶段四埋的伏笔揭晓：数组名 a 在绝大多数场合会自动退化为「指向首元素的指针」（&a[0]）。于是有恒等式：

a[i]  ≡  *(a + i)

下标访问只是语法糖，编译器内部一律翻译成「首地址 + 偏移，再解引用」。这就是为什么阶段四说「数组参数能改真数组」——函数收到的 arr 本质就是首元素地址，arr[i] = ... 就是 *(arr+i) = ...，改的是原件。

下标从 0 开始的终极解释：a[i] 的地址 = 首地址 + i × sizeof（元素）。第一个元素就在首地址上，偏移 0。下标不是「第几个」，是「离起点几格」——所以第一个元素是 a[0]。这不是习惯，是地址算术的必然。

7.2 指针算术：步长由类型决定

int a[5] = {10, 20, 30, 40, 50};
int *p = a;                 /* p 指向 a[0] */

printf("%d\n", *p);         /* 10 */
printf("%d\n", *(p + 1));   /* 20 —— p+1 不是地址+1 字节，而是「前进 1 个 int」 */
printf("%d\n", *(p + 4));   /* 50 */

p + 1 的真实地址变化是 +sizeof(int) = +4 字节；换成 double *，p + 1 就是 +8 字节。指针算术以「几个元素」为单位，编译器自动乘上 sizeof——这正是 3.1 节你亲眼看到的「int 邻居地址差 4」的用途。指针的类型不是装饰，它决定一步跨多远。

7.3 指针遍历数组

int sum = 0;
int *p;
for (p = a; p < a + 5; p++) {   /* 从首元素走到「末尾再往后一格」之前 */
    sum += *p;
}

a + 5 是「末尾再往后一格」的位置，它是合法的哨兵（可以比较、不能解引用）——p < a + 5 就是指针版的 i < 5。配套 03_pointer_array.c：四种等价写法（a[i]、*(a+i)、p[i]、*(p+i)）打印同一数组，再用指针遍历求和。四种写法打印结果完全一样，这就是恒等式的实证。

8. 核心概念六：const 的四种位置

你在阶段三就见过 void print_array(const int arr[], int n)——那个 const 是什么意思？四种位置一张表：

int x = 1, y = 2;
const int *p1 = &x;   /* ① 指向「常量 int」的指针：不许通过 p1 改值，纸条可以换 */
int const *p2 = &x;   /* ② 与 ① 完全相同（const 在 * 左边 = 管值） */
int *const p3 = &x;   /* ③ 指针本身是常量：纸条不许换（永远指着 x），值可以改 */
const int *const p4 = &x;  /* ④ 双锁：值不许改，纸条也不许换 */

判读口诀：从右往左读，const 修饰它左边最近的东西；const 在最左就修饰右边的类型。

  • *p1 = 99; ✘ 编译错（承诺了只读）；p1 = &y; ✔ 可以换纸条；
  • p3 = &y; ✘ 编译错（纸条钉死了）；*p3 = 99; ✔ 可以改值。

实战意义：函数参数写 const int arr[] 就是向调用者立誓「我只读不改」。这既防自己手滑，也让别人敢把数据交给你。考核若要求「不得修改原串」，函数签名挂 const 就是标准答案的姿态。配套 03_pointer_array.c 的打印函数示范了这个写法。

9. 核心概念七：指针与字符串——考核手写库的升级版

9.1 指针遍历字符串

阶段四你用下标走字符串，现在用指针走：

char s[] = "UPRE";
char *p = s;                  /* 指向 'U' */

while (*p != '\0') {          /* 没撞见封底就继续 */
    printf("%c ", *p);
    p++;                      /* 门牌号往右挪一格 */
}

while (*p != '\0') 是指针版的 s[i] != '\0'，惯用缩写是 while (*p)（'\0' 就是 0，0 即假）。两种写法都要认识——别人的代码里后者遍地都是。

9.2 指针版 my_strlen

int my_strlen_ptr(const char *s)
{
    const char *p = s;        /* 记住起点（const：只读承诺） */
    while (*p != '\0') {
        p++;                  /* p 一路走到封底 */
    }
    return (int)(p - s);      /* 终点地址 - 起点地址 = 走了几格 = 长度 */
}

新思想：指针减指针 = 之间隔了几个元素（不是字节数，是元素数——char 的元素就是 1 字节，所以对字符串二者相等）。p - s 的差就是 '\0' 前面字符的个数，连计数器变量都省了。这就是考核「手写库函数」的指针升级版——原理和下标版一模一样（走到封底为止），武器从「下标 i」换成了「指针 p」。

9.3 *p++ 与 (*p)++——纸上推演（必做）

这两个东西是 C 的招牌谜题，拆开来全是旧知识（优先级 + 后缀 ++）：

  • *p++ ≡ *(p++)：++ 优先级高于 *，且后缀 ++ 「先用后加」——先取 *p 的值，然后 p 前进一格。经典用途：边取值边挪窝，while ((*dest++ = *src++) != '\0'); 一行就是一个 strcpy。
  • (*p)++：括号强制先解引用——p 不动，p 指向的那个值 +1。*p 是个 int，(*p)++ 就是给那个 int 加一。

纸上推演（配套 04_pointer_string.c 会跑给你看，但先自己推）：

char s[] = "abc";
char *p = s;
char c = *p++;    /* 推演：c = ?  p 现在指向 ? */

答案：c = 'a'，p 指向 'b'。再推 int n = 5; int *q = &n; int r = (*q)++;——r = 5、n = 6、q 仍指向 n。推不出来的，画门牌号纸条图，一目了然。

10. 核心概念八：野指针三大场景（血的教训集中营）

野指针 = 指向无效内存的指针。三大出生场景：

10.1 未初始化指针

int *p;      /* 垃圾地址 */
*p = 42;     /* 撬错门：未定义行为 */

药方：§5 的纪律，int *p = NULL; 起步。

10.2 指向已销毁的局部变量（返回局部变量的地址）

int *bad_func(void)
{
    int local = 42;
    return &local;    /* 经典错误！函数一结束，local 的房子就被拆了 */
}                     /* 返回的是一张「已拆除房屋」的门牌号 */

调用者拿到这个指针去解引用，读到的是废墟上的残值——可能「碰巧正确」一百次，第一百零一次塌了。好消息：-Wall 能直接抓到它（warning: function returns address of local variable）。这是「编译警告必须清零」最硬的理由之一。配套 05_wild_pointer.c 里有这个错误写法的完整注释展示（只展示、不执行），以及安全观察版。

10.3 越界指针

int a[3] = {1, 2, 3};
int *p = a + 3;    /* 「末尾再往后一格」：合法的哨兵，可以比较 */
/* *p 就是越界！ */ /* 解引用它 = 阶段四的数组越界，换了个马甲 */

指针越界和数组越界是同一件事的两张脸——a[i] 本来就是 *(a+i)，越界的护栏依然为零。药方：写每个 *p 前，心算一遍 p 的合法区间；循环结束条件用 p < a + n 而不是 p <= a + n。

抓野指针的三件武器：① -Wall -Wextra 警告清零（抓场景 2）；② 断点调试，VARIABLES 里盯着指针的值，看它是谁的地址、越没越界（抓场景 3）；③ NULL 初始化 + if 守卫（防场景 1）。05_wild_pointer.c 用「只打印地址、绝不解引用」的安全方式演示三种场景的地址证据。

11. 核心概念九：函数设计——传出参数模式

一个老问题：函数只能 return 一个值，想「算两个结果」怎么办？比如整数除法想同时要商和余数。错误姿势：开全局变量（污染、不可重入）。正解：把多余的「返回值」通过指针参数传出来：

void divmod(int a, int b, int *q, int *r)
{
    *q = a / b;     /* 商：按 q 的门牌号写回调用者的变量 */
    *r = a % b;     /* 余数：按 r 的门牌号写回 */
}

int main(void)
{
    int shang, yu;
    divmod(17, 5, &shang, &yu);   /* 交出两个空盒子的门牌号 */
    printf("17 / 5 = %d ... %d\n", shang, yu);   /* 3 ... 2 */
    return 0;
}

模式总结：调用者准备空变量 → 把地址交给函数 → 函数通过 *形参 往里填。这就是「返回值不够用」的标准答案，也是 scanf 的设计原理——scanf("%d", &x) 那个 & 你抄了一个学期，今天终于知道它就是传出参数！配套 02_swap_real.c 末尾也演示了这个模式。练习 5 专门练它（含 b == 0 时怎么办的设计决策——用 return 值报告「成功/失败」，指针只负责传数据，双通道分工）。

13.5 零基础补充：指针的「门牌号模型」总复习

13.5.1 一个等式贯穿全部内容

  int a[5] = {10,20,30,40,50};

  a[i]    ≡    *(a + i)    ≡    *(p + i)   （p 指向 a[0] 时）
  &a[i]   ≡    a + i       ≡    p + i

指针运算的「步长」由类型决定，不是字节数：

指针类型 p + 1 实际跳过 为什么
int * 4 字节 sizeof(int) = 4
double * 8 字节 sizeof(double) = 8
char * 1 字节 sizeof(char) = 1
struct student * 结构体大小 由成员决定

所以 p + i 永远指向「第 i 个元素」，编译器自动帮你乘了 sizeof。 这也是为什么 void * 不能做算术——它不知道步长。

13.5.2 四种 const 位置（一次记牢）

const int *p1;      /* 指向常量：*p1 不能改，p1 可以改指向 */
int const *p2;      /* 同 p1，两种写法等价 */
int * const p3; ...;/* 常量指针：p3 不能改指向，*p3 可以改 */
const int * const p4 = &x;  /* 都不能改 */

记法：const 右边的东西不能改。

13.5.3 *p++ 与 (*p)++：纸上推演一遍

int a[3] = {1, 2, 3};
int *p = a;

int x = *p++;   /* x = 1；p 现在指向 a[1]。先取 *p，再 p++ */
int y = (*p)++; /* y = 2；a[1] 变成 3；p 不变。先取 *p，再把 *p 加一 */

推演表（自己画一遍，这是最值得花的 5 分钟）：

语句 p 的指向 *p 的值 赋值结果
int x = *p++; a[0] → a[1] 1 x = 1
int y = (*p)++; a[1]（不变） 2 → 3 y = 2

字符串遍历里 *p++ 极其常用：for (p = s; *p; p++) 就是「从头走到 \0」。

13.5.4 指针作参数：真 swap 的完整代码

#include <stdio.h>

/* 形参是指针：a、b 里装的是调用者变量的地址 */
void swap(int *a, int *b) {
    int tmp = *a;   /* 把 a 指向的那个值取出来 */
    *a = *b;        /* 改写调用者的 x */
    *b = tmp;       /* 改写调用者的 y */
}

int main(void) {
    int x = 10, y = 20;
    swap(&x, &y);              /* 传地址，不是传值 */
    printf("%d %d\n", x, y);  /* 20 10 —— 真的换了 */
    return 0;
}

对照记忆：swap(x, y) 换的是函数里的复印件；swap(&x, &y) 换的是原件。

13.5.5 指针问题的「三看」调试法

断点停在指针操作行，VARIABLES 面板里看三样：

  1. p 本身——门牌号是多少？是 NULL 还是野值？
  2. *p——房子里住的是不是你以为的那个值？
  3. &p——纸条自己放在哪？（理解「指针也是变量」用）

段错误（Segmentation fault）99% 是这三样里有一样不对：p 是 NULL、p 是野指针、或 p 越过了数组末尾。

13.5.6 五分钟自测

  1. int a[5]; int *p = a + 3; —— p[-1] 是哪个元素？合法吗？
  2. char s[] = "abc"; char *p = s; 之后 *p 和 s[0] 是什么关系？p + 1 指向谁？
  3. 为什么 int *p; *p = 5; 一运行就崩，而 int *p = NULL; if (p) *p = 5; 不会？

14. 常见错误与调试速查（本阶段相关）

症状 真因 一句话药方
一运行就崩（段错误） 解引用了 NULL 或野指针 指针出生置 NULL、用前 if (p != NULL)
警告 returns address of local variable 返回了局部变量的地址 改用传出参数：调用者出变量、传地址进函数
swap 后 main 里没变 调用写成了 swap(x, y) 或函数内没用 * 传 &x, &y；函数内一律 *a、*b
*p+1 结果不对 想要 *(p+1) 却写成 *p+1（优先级） *p+1 是「值加一」；要「下一格」加括号
*p++ 与 (*p)++ 搞反 没分清「p 动」还是「值动」 纸上推演一遍（练习 3），画纸条图
指针遍历数组多走一格 循环条件写成 p <= a+n 哨兵是 a+n，条件用 <
%p 打印报警告 没转 (void *) printf("%p", (void *)&x);
指针减指针结果离谱 两个指针不属于同一个数组 指针相减只对「同数组内」有意义
通过 const 指针改值，编译报错 const int *p 不许 *p = ... 报错是 const 在保护你——去掉修改，或重新设计

调试手段：指针问题的断点大法——在指针操作行打断点，VARIABLES 里看三样东西：指针自己的值（门牌号）、*p（房子里的东西）、&p（纸条住哪）。VSCode 悬停指针变量也能看到地址。把 02_swap_real.c 单步走一遍，看 *a 与 x 如何同生同灭，比背十遍定义都管用。

15. 安全与规范：本阶段三条铁律

  1. 每个指针出生时必须初始化——要么指向真变量，要么 = NULL，没有第三种出生方式；
  2. 每次解引用前，指针的来源必须可证——要么是某变量的 &，要么在已知数组的 [a, a+n) 区间内，要么刚判过 != NULL；
  3. 函数要改调用者的变量，只走两条正道——return 一个值，或传出参数；永不返回局部变量的地址。
