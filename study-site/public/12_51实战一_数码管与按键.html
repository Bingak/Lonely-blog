2. 场景引入：四个数字，一条段选线

阶段十的最后一晚，你让一盏灯按你的意思亮了。那一刻你觉得自己已经摸到单片机了。

现在任务 2 的题面摆在你面前：四位一体数码管，显示 0~999，每 300ms 加 1，到 999 回 0。

你想了想，觉得不难：段码表阶段十就推过，四位嘛，送四次不就完了？于是你写下人生第一版「四位显示」：

/* 直觉写法（错的）。别急着编译，先看它错在哪 */
P0 = SEG_CC[1];      /* 想在第 1 位显示 1 */
P0 = SEG_CC[2];      /* 想在第 2 位显示 2 */
P0 = SEG_CC[3];      /* 想在第 3 位显示 3 */

烧进去，四位全都显示 3。

不是接触不良，不是段码表抄错，也不是芯片坏了。是这四行代码从第一行起就注定是这个结果：P0 只有一份。你写第二行的时候，第一行写进去的东西已经被覆盖了；写第三行的时候，第二行又没了。最后留在段选线上的，永远是最后一次写进去的那个字节。

这就是本篇要解的第一个死结：

段选线是广播，不是四个人各自的笔记本。 你把「1」喊出来，四个位置同时听见；你把「2」喊出来，四个位置又同时改口。它们没有记忆，它们只是同一根线上挂着的 8 只 LED。

那为什么市面上卖的四位一体数码管，明明能显示 1234？

因为它从来就不是同时显示四个数字。它是「先只让第 1 位通电，喊 1；再只让第 2 位通电，喊 2；……」——四个动作在 1 毫秒的尺度上轮流发生，你的眼睛跟不上，于是你以为它们同时亮着。这门手艺叫动态扫描，本篇 §4 到 §6 都在拆它。

第二个死结紧接着就来。任务 3 要求：按键按一下，显示加一，同时 LED 亮 200ms；任务 3 的第三小问换成矩阵键盘；任务 4 还要让某一位闪着等你输入。你手上只有一个 CPU，而这三件事都想要「同时」：

  • 数码管要每 2ms 被喂一次，不然就闪；
  • 按键要每 5~10ms 被看一次，不然就漏；
  • 蜂鸣器要在 500ms 之后自己停，不然就一直叫。

而阶段十你学会的 delay_ms()，是把 CPU 按在地上不许动。你在等 500ms 的时候，数码管黑着、按键没人看。三个「同时」和一个 delay，是这个死结的全部内容。

第三个死结最小，但最容易翻车：8 个按键怎么接？ 一个键一根线要 8 根，加上 4 位位选、8 段段选，51 的 32 根 IO 就快见底了。于是有了矩阵键盘——用 6 根线读 8 个键，用 8 根线读 16 个键。

三个死结，对应本篇的三条主线：

   ① 一条段选线要喂四位    ->  动态扫描 + 消隐 + 刷新率      (§3 ~ §6)
   ② 三件事都想同时干      ->  时间片 + 非阻塞状态机         (§6、§7、§10)
   ③ 键太多、线太少        ->  矩阵行列扫描                 (§8)
                                         再加一个会叫的：蜂鸣器 (§9)

这一篇的写法会和前面不太一样：我们先造一个人机界面，再回头讲它每个零件为什么长这样。 因为这三块东西是咬在一起的——扫描的节拍同时是按键的采样节拍，也是蜂鸣器的计时基准；拆开讲任何一块，你都会觉得「道理懂了，但拼不起来」。

3. 核心概念一：数码管——8 只 LED 装在一个壳里

3.1 一个字符 = 一个字节

阶段十的 §8 已经把这件事讲透了，这里只做三句话的复习，因为后面所有代码都建立在它上面：

  1. 一位数码管里有 8 只 LED：a b c d e f g 七段加一个小数点 dp；
  2. 这 8 只 LED 的一端接在一起，叫公共端，另一端分别引出 8 个段脚；
  3. 8 个段脚接在一个 8 位端口上，于是「显示什么」就等于「往这个端口写哪个字节」——这个字节叫段码。

段序（哪一段接 bit0）由原理图决定。本教程继续沿用阶段十的约定：dp g f e d c b a，bit7 = dp，bit0 = a。你的板子如果相反，把表重排一遍即可——表可以改，方法不能错。

3.2 共阳与共阴：一个字决定「0 亮还是 1 亮」

公共端接哪儿，决定了「亮」这个动作对应高电平还是低电平：

公共端接 段脚给什么才亮 段码表 常见搭配
共阴（common cathode） GND 高电平（1） 1 = 亮 P0 段选 + 上拉；或经 74HC245 驱动
共阳（common anode） VCC 低电平（0） 0 = 亮 P0 段选直驱（灌电流正好）

两套表互为按位取反，阶段十验算过：~0x3F = 0xC0。所以你只需要会推一套。

下面这段程序把「同一个数字，两套管子上分别送什么」并排打出来，顺便把位选也演示了。它是本篇第一段能跑的代码，请务必先自己推一遍 3 和 8 的段码，再看输出。

/* 示例 A —— 段选与位选的电平关系：共阴 / 共阳各是什么样（PC 模拟版） */
#include <stdio.h>

/* 段序 dp g f e d c b a（bit7 ... bit0），与阶段十的表一致 */
static const unsigned char SEG_CC[10] = {
    0x3F, 0x06, 0x5B, 0x4F, 0x66, 0x6D, 0x7D, 0x07, 0x7F, 0x6F
};

static void print_binary(unsigned char v)
{
    int i;
    for (i = 7; i >= 0; --i) {
        putchar(((v >> i) & 1u) ? '1' : '0');
        if (i == 4) {
            putchar(' ');
        }
    }
}

/* active_low = 1 表示共阳：某一位是 0 才算这一段亮 */
static void print_lit(unsigned char code, int active_low)
{
    static const char *const NAME[8] = {"a", "b", "c", "d", "e", "f", "g", "dp"};
    int i, first = 1;

    for (i = 0; i < 8; ++i) {
        int bit = (code >> i) & 1u;
        int on = active_low ? (bit == 0) : (bit != 0);
        if (on) {
            printf("%s%s", first ? "" : "+", NAME[i]);
            first = 0;
        }
    }
    if (first) {
        printf("(全灭)");
    }
}

int main(void)
{
    static const int demo[4] = {0, 1, 3, 8};
    int k, pos;

    puts("== 一、同一个数字，两套管子的段码 ==");
    for (k = 0; k < 4; ++k) {
        int d = demo[k];
        unsigned char cc = SEG_CC[d];
        unsigned char ca = (unsigned char)~cc;

        printf("数字 %d\n", d);
        printf("  共阴段选 0x%02X  ", (unsigned)cc);
        print_binary(cc);
        printf("  亮段 ");
        print_lit(cc, 0);
        printf("\n");
        printf("  共阳段选 0x%02X  ", (unsigned)ca);
        print_binary(ca);
        printf("  亮段 ");
        print_lit(ca, 1);
        printf("\n");
    }

    puts("");
    puts("== 二、位选：4 位里只让一位通电 ==");
    puts("前提：4 位公共端接 P2.0~P2.3，低电平选通（经三极管或直接灌电流）");
    printf("%-6s %-10s %-12s %s\n", "位置", "P2", "二进制", "谁被选通");
    for (pos = 0; pos < 4; ++pos) {
        unsigned char p2 = (unsigned char)~(1u << pos);   /* 只有第 pos 位是 0 */
        printf("  第%d位  0x%02X      ", pos, (unsigned)p2);
        print_binary(p2);
        printf("    P2.%d 为低 -> 只有这一位通电\n", pos);
    }

    puts("");
    puts("== 三、一次完整的「选位 + 送段」= 一位数字 ==");
    for (pos = 0; pos < 4; ++pos) {
        unsigned char p2 = (unsigned char)~(1u << pos);
        unsigned char p0 = SEG_CC[(pos + 1) % 10];
        printf("  P0 = 0x%02X（段码），P2 = 0x%02X（位选） -> 第 %d 位显示 %d\n",
               (unsigned)p0, (unsigned)p2, pos, (pos + 1) % 10);
    }
    return 0;
}

  P0 = 0x4F（段码），P2 = 0xFB（位选） -> 第 2 位显示 3
  P0 = 0x66（段码），P2 = 0xF7（位选） -> 第 3 位显示 4

看第一段：数字 0 的共阴段码是 0x3F（a b c d e f 亮），共阳段码是 0xC0。同一个「0」，两个字节没有一位相同——因为它们对「亮」的定义正好相反。这就是为什么阶段十反复强调：写代码前先确认你的板子是共阳还是共阴，搞反了不是「显示不对」，是「该亮的全灭、该灭的全亮」，一眼看去像段码表整个抄错了。

3.3 位选与段选：一个管「说什么」，一个管「谁来说」

四位一体的数码管，内部其实是四只独立的数码管，它们：

  • 共用 8 根段选线（a~dp 全并在一起）；
  • 各自有一根公共端引出来，叫位选线（也叫位码、com 线）。

于是驱动一位数字需要两步：

  1. 段选：把「要显示的那个字符的段码」送到段选口（8 根线，所有位共享）；
  2. 位选：把「这一位的公共端」接通（4 根线，每位一根）。

两步都到位，那一位才亮。少一步，什么也不亮；两步错位，就亮错地方。 这就是为什么 §2 里那三行代码注定失败：你只做了第一步，而且做了三次。

位选的极性比段选更容易搞错，因为它中间常常隔着器件：

板子上的常见做法 位选「选通」是 你要写
公共端直接接 IO（共阴，靠 IO 灌电流） 低电平 P2 = ~(1u << pos)
公共端经 NPN 三极管接地（共阴，三极管导通） 高电平（基极给高） P2 = (1u << pos)
公共端经 PNP 三极管接 VCC（共阳，三极管导通） 低电平 P2 = ~(1u << pos)
位选经 74HC138 译码（输出低有效） 低电平 先算 138 的输入码，再取反

看最后一行：一块板子上如果既有 138 译码、又有三极管反相，那「写 0 选通」这句话就要数一遍反相次数才能确定。所以本教程给的每一行位选代码，前面都写着前提。你的板子以原理图为准——这句话在数码管这一节里的分量，比在点灯那一节重十倍。

3.4 限流电阻：不是可选项，是保命符

LED 是二极管。二极管的脾气是：正向导通之后，电流随电压指数上升。你把 5V 直接加在一只红色 LED 上（正向压降约 1.8~2.2V），多出来的 3V 全落在它那点内阻上，电流会冲到几百毫安——LED 一秒之内发烫、发黑、断路，或者先把你那颗 IO 脚烧掉。

所以每只 LED 必须串一个电阻。算一下（以红色 LED、正向压降 1.9V、5V 供电为例）：

串联电阻上的电压 = 5.0 - 1.9 = 3.1V
串 330Ω  ->  电流 ≈ 3.1 / 330 ≈ 9.4mA
串 1kΩ   ->  电流 ≈ 3.1 / 1000 ≈ 3.1mA

两个数都落在「亮得清楚」和「不烧器件」之间。开发板上常见的是 330Ω~1kΩ，具体用多少，看厂家的原理图。

但数码管还有一个单只 LED 没有的问题：一位全亮 = 8 段同时亮。

一位显示「8」：8 段 × 9.4mA ≈ 75mA
四位同时全亮：            ≈ 300mA

这两个数字都远超「一个 IO 该干的活」。51 单个引脚的灌电流大约 10~20mA，整片所有引脚加起来还有一个总上限（具体数值以数据手册为准，不同厂家、不同型号不一样）。所以：

  • 静态显示（四位一直全亮）在 51 上基本不可行，不是软件问题，是电流问题；
  • 动态扫描恰好救了这个场：任意时刻只有一位亮，总电流只有一位的量级；虽然每一位的峰值还是那么大，但平均电流被占空比摊薄了（§4.4 细算）。

这也解释了一个新手常问的问题：「为什么我的数码管比别人的暗？」——先别怀疑代码，看看段选电阻是不是 1k，再看看是不是四位一起亮了。亮度是电流问题，不是代码问题。

3.5 P0 开漏：为什么它总要拖一个上拉电阻

51 的四个端口里，P0 最特殊：它内部没有上拉电阻，作为普通 IO 使用时是开漏输出。

「开漏」是什么意思？一句话：它只能主动拉低，不能主动拉高。

  • 你写 P0 = 0x00：内部那只 MOS 管导通，把引脚拽到地——这是它能主动做的事；
  • 你写 P0 = 0xFF：内部那只 MOS 管关断，引脚悬空（高阻态）。它并没有把引脚「推」到 5V，只是「松手」了。

如果没有外部上拉，悬空的引脚电压是不确定的，读回来可能是 0 也可能是 1，驱动能力更是零。所以 P0 要当普通 IO 用，必须外接上拉电阻（开发板上常见一排 4.7k~10k 的排阻）。

这件事在数码管上会变成两种完全不同的命运：

你的数码管 段脚需要 P0 直接驱动行不行
共阳（段脚给 0 才亮） 灌电流（把段脚拉低） 行——P0 最擅长的就是这个
共阴（段脚给 1 才亮） 拉电流（把段脚推高） 不行——开漏推不高，必须加上拉排阻

所以你会看到两种典型板子：一种是「共阳数码管 + P0 直驱段选」，另一种是「共阴数码管 + P0 段选 + 10k 排阻」。两种都对，取决于设计者怎么算这笔账。 你要做的不是背结论，而是拿到板子先看两件事：公共端接哪、P0 上有没有那排电阻。

至于 P1/P2/P3，它们内部有弱上拉，是「准双向口」，能拉高，但那个上拉很弱（大约几百微安量级），只能当信号，不能当电源。拿它直接点亮一只 LED，你会发现灯是「暗红」的——不是代码写错了，是电流不够。引脚是信号，不是电源，这条铁律在阶段十说过，在数码管这一节会第三次出现。

4. 核心概念二：静态显示 vs 动态扫描

4.1 静态显示：一位一套线，奢侈但老实

最直接的做法：每一位数码管配一套独立的段选线。

4 位 × 8 段 = 32 根 IO

51 一共多少根 IO？P0、P1、P2、P3 各 8 根，正好 32 根。也就是说，静态显示四位数字，要把整片芯片的 IO 全部交出去——按键没了、蜂鸣器没了、串口也没了（P3.0/P3.1 被占）。

静态显示的优点很实在：不用扫描。你把段码写进去，它就自己亮着，CPU 可以去干任何事，不会有重影、不会有闪烁、亮度也是满的。缺点是：要线。而要线这件事，在 51 上是硬约束。

4.2 动态扫描：用时间换引脚

四位一体的数码管已经把「共用段选」这件事做在内部了。我们要做的，是接受这个限制，然后用时间绕开它：

8 根段选（共用） + 4 根位选 = 12 根 IO

从 32 根降到 12 根。省下来的 20 根，正好留给按键、蜂鸣器和将来的串口。

代价是：同一时刻只有一位亮。四位要「看起来同时亮」，就得让它们轮流亮，而且轮得足够快。

多快？这就轮到眼睛出场了。

4.3 视觉暂留：为什么轮流亮看起来是同时亮

人眼有一项特性（习惯上叫视觉暂留，生理机制比这个名字复杂，但对工程师来说结论够用）：当一个亮点以足够高的频率重复出现时，你看到的不再是一闪一闪，而是一个稳定的、亮度略低的亮点。

这个「足够高」大约是多少？经验值是 50Hz 以上——也就是每 20ms 之内至少重复一次。低于这个频率，你会开始感觉到抖；低到 25Hz 左右，就是老式日光灯那种「用眼角余光能看到闪」的感觉。

于是动态扫描的全部设计目标可以写成一句话：

让每一位数字，每 20ms 之内至少被点亮一次。

四位平摊，每位最多 5ms。工程上一般取 1~2ms（留足余量），也就是：

每位 2ms  ->  一帧 8ms  ->  刷新率 125Hz   （很稳）
每位 1ms  ->  一帧 4ms  ->  刷新率 250Hz   （更稳，但 CPU 更忙）
每位 5ms  ->  一帧 20ms ->  刷新率 50Hz    （临界，勉强）

一帧（frame）就是「四位各亮一次」的完整循环。刷新率 = 1000 / 一帧毫秒数。

4.4 一帧里到底发生了什么

把镜头放慢，一帧是这样四步：

时间轴 ──────────────────────────────────────────────────►
        │ 位0  │ 位1  │ 位2  │ 位3  │ 位0  │ 位1  │ ...
        │ 2ms  │ 2ms  │ 2ms  │ 2ms  │ 2ms  │ 2ms  │
        └──────┴──────┴──────┴──────┴──────┴──────┘
          ↑
        每一步内部还有三个小动作：消隐 → 换位 → 送段码

四步循环的骨架只有三行：

P0 = 0x00;                          /* ① 消隐：先把段选全关，屏幕上什么也没有 */
P2 = (unsigned char)~(1u << pos);   /* ② 换位：只让第 pos 位通电 */
P0 = SEG_CC[g_disp[pos]];           /* ③ 送段码：把这一位该显示的字符送上去 */

这三行的顺序不能换，原因在 §5。现在你只需要记住它的形状：关 → 换 → 开，像舞台换景：先拉幕、再换布景、最后开灯。

4.5 亮度的账：占空比只有 1/4

动态扫描不是免费的。每一位只在自己那 2ms 里亮着，一帧 8ms 里它只亮了 1/4 的时间：

占空比 = 1 / 位数 = 1/4 = 25%

人眼看到的是平均亮度，所以动态扫描的四位数码管，看起来会比同样电流下的静态显示暗一些。想补回来，只有两条路：

  1. 提高峰值电流：把段选电阻从 1k 降到 330Ω，峰值从 3mA 提到 9mA，平均下来才够看。开发板上动态扫描的板子段电阻普遍比静态的小，原因就在这里；
  2. 减少扫描位数：两位当然比四位亮。但题面要四位，这条没得选。

提高峰值电流有上限：单段电流、单脚总电流、整片总电流，三道门都得过（以数据手册为准）。别为了亮度把电阻短接——那是拿芯片换亮度。

4.6 所以，四个数字为什么不能「真同时」

回到 §2 的死结。

段选线是一根总线，不是四份存储。要让四位在同一瞬间显示四个不同字符，硬件上必须有四份独立的段锁存器——每份记住自己那一位的段码，同时驱动。这正是「静态显示」做的事，也是很多开发板上那几片 74HC573（八路锁存器）的用途：用锁存器把段码「存住」，一个 IO 口分时写给四片锁存器，锁存器再同时输出。

所以完整的答案是这样一句话：

「同时显示四个不同数字」在电气上要求四份独立的段驱动；51 的 IO 不够，于是我们用「时间上分开、视觉上合并」来伪造它。动态扫描伪造的是「同时」，不是「不同」。

理解了这句话，后面所有的现象——重影、闪烁、亮度不均——都只是「伪造得不够好」的具体表现。

5. 核心概念三：消隐与重影

5.1 重影长什么样

假设你按 §4.4 的三行写了扫描，但把顺序写成了「先换位、再送段码」。烧进去，会看到这样的现象：

  • 1 旁边拖着 4 的一横；
  • 3 的右下角多出一个小数点；
  • 或者整体发虚、发灰，每个数字都像被描了一遍边。

这叫重影（ghosting）。它的成因只有一句话：在换位的那一瞬间，段选线上还挂着上一位的段码。

慢动作回放：

时刻 T1：位0 通电，段选 = 0x06（字符 1）    -> 第 0 位显示 1   ✓
时刻 T2：位1 通电，段选 还是 0x06           -> 第 1 位显示 1   ✗ 本该显示 2
时刻 T3：段选改成 0x5B（字符 2）             -> 第 1 位显示 2   ✓

T2 到 T3 之间那几十纳秒到几微秒，第 1 位用上一位的内容亮了一下。这段时间短到你看不清「1」，但它的光通量是实实在在的——眼睛把它积分进去了，于是你看到的是「2 上面蒙了一层 1 的笔画」。扫描越快、这段「错位时间」占比越大，重影越明显。

5.2 两种错误写法，错在不同地方

新手常见的两种顺序，其实都错：

写法 动作序列 错在哪
A（先换位） 换位选 → 送段码 新位先看到旧段码
B（先换段） 送段码 → 换位选 旧位先看到新段码（旧位还没关，被「重画」了一下）
C（正确） 关段选 → 换位选 → 送段码 换位的整个过程中，段选是灭的，谁也画不出来

写法 B 比 A 更隐蔽：它把新段码画在了上一位上。你盯着第 1 位看半天，发现多出来的是第 2 位的笔画——两个位置的症状刚好反过来。

正解的思路叫消隐（blanking）：在动任何一根线之前，先把「内容」关掉。 屏幕上先黑一下（几十微秒，人眼完全无感），再换位置、再上新内容。这样任何瞬间都不会出现「位置已经换了、内容还是旧的」这种错配。

5.3 现场：把每一个瞬间都打印出来

下面这段程序把一帧拆成一步步的「总线快照」，逐时刻打印「段选是什么、位选是什么、此刻屏幕上真正亮着什么」。它不跑在单片机里，它跑在你的显示器上——但它把单片机里那几十微秒的事，放大成了你能一行行读的表格。

/* 示例 B —— 一帧 4 步：有消隐 vs 无消隐，逐时刻打印总线状态 */
#include <stdio.h>

static const unsigned char SEG_CC[10] = {
    0x3F, 0x06, 0x5B, 0x4F, 0x66, 0x6D, 0x7D, 0x07, 0x7F, 0x6F
};

/* 要显示的 4 位：从左到右是第 0 位、第 1 位、第 2 位、第 3 位 */
static const unsigned char g_disp[4] = {1, 2, 3, 4};

static void desc(unsigned char p0, unsigned char p2, char *out, int cap)
{
    int pos, n = 0, first = 1;

    if (p0 == 0x00) {
        snprintf(out, (size_t)cap, "段选 0x00，四位全灭");
        return;
    }
    n += snprintf(out + n, (size_t)(cap - n), "亮:");
    for (pos = 0; pos < 4; ++pos) {
        if (((p2 >> pos) & 1u) == 0) {
            n += snprintf(out + n, (size_t)(cap - n), "%s[%d]=0x%02X",
                          first ? "" : ",", pos, (unsigned)p0);
            first = 0;
        }
    }
    if (first) {
        snprintf(out, (size_t)cap, "没有一位被选通");
    }
}

int main(void)
{
    unsigned char p0 = SEG_CC[g_disp[3]];    /* 上一帧结束时，段选上停着最后一位的段码 */
    unsigned char p2 = (unsigned char)~(1u << 3);
    int pos;
    char buf[128];

    puts("要显示 1 2 3 4；段选共用 P0（共阴，1=亮），位选 P2.0~P2.3（0=选通）");
    puts("相位：a=换位选  b=送段码  c=关段选（消隐）");
    puts("");
    puts("== 一、不消隐：先换位选，再送段码 ==");
    for (pos = 0; pos < 4; ++pos) {
        p2 = (unsigned char)~(1u << pos);
        desc(p0, p2, buf, (int)sizeof buf);
        printf("step %da  P0=0x%02X  P2=0x%02X  %s  <-- 上一位的段码画到了这一位\n",
               pos + 1, (unsigned)p0, (unsigned)p2, buf);
        p0 = SEG_CC[g_disp[pos]];
        desc(p0, p2, buf, (int)sizeof buf);
        printf("step %db  P0=0x%02X  P2=0x%02X  %s\n",
               pos + 1, (unsigned)p0, (unsigned)p2, buf);
    }

    puts("");
    puts("== 二、消隐：先关段选，再换位选，最后送段码 ==");
    p0 = SEG_CC[g_disp[3]];
    p2 = (unsigned char)~(1u << 3);
    for (pos = 0; pos < 4; ++pos) {
        p0 = 0x00;
        desc(p0, p2, buf, (int)sizeof buf);
        printf("step %dc  P0=0x%02X  P2=0x%02X  %s\n",
               pos + 1, (unsigned)p0, (unsigned)p2, buf);
        p2 = (unsigned char)~(1u << pos);
        desc(p0, p2, buf, (int)sizeof buf);
        printf("step %da  P0=0x%02X  P2=0x%02X  %s\n",
               pos + 1, (unsigned)p0, (unsigned)p2, buf);
        p0 = SEG_CC[g_disp[pos]];
        desc(p0, p2, buf, (int)sizeof buf);
        printf("step %db  P0=0x%02X  P2=0x%02X  %s\n",
               pos + 1, (unsigned)p0, (unsigned)p2, buf);
    }
    puts("");
    puts("不消隐那一半，每个 a 相位都是「新位 + 旧段码」——这就是重影。");
    puts("消隐那一半，每个 c/a 相位段选都是 0x00，换位的过程谁也看不见。");
    return 0;
}

step 4a  P0=0x00  P2=0xF7  段选 0x00，四位全灭
step 4b  P0=0x66  P2=0xF7  亮:[3]=0x66

不消隐那一半，每个 a 相位都是「新位 + 旧段码」——这就是重影。
消隐那一半，每个 c/a 相位段选都是 0x00，换位的过程谁也看不见。

请注意这两段输出的第一列（step 1a、1b、1c）：

  • 不消隐的那一半里，每一个 a 相位都是「新位 + 旧段码」——step 2a 里第 1 位亮着 0x06（字符 1），而它应该显示 2。那个 0x06 就是重影；
  • 消隐的那一半里，每一个 c 相位（关段选）和紧跟的 a 相位（换位），段选都是 0x00。换位这件事发生在「全黑」的掩护下，眼睛什么也看不见。

还有一个小细节值得注意：不消隐版的 step 1a 里，段选是 0x66——那是上一帧最后一位（字符 4）留下的残值。这说明重影不只发生在「本帧的位之间」，也发生在「帧与帧之间」。只要你不关段选就动位选，任何时刻都可能亮出上一次的内容。

5.4 消隐要花多少时间

你可能会担心：每换一位都黑一下，亮度是不是掉很多？

算一笔账。一次消隐 + 换位 + 送段码，在 12MHz 的 51 上是几条指令的事，大约几微秒到十几微秒。而每一位的停留是 1000~2000 微秒。也就是说：

消隐占的比例 ≈ 10μs / 2000μs = 0.5%

亮度损失半个百分点，肉眼绝对看不出来。代价可以忽略，收益是彻底消除重影——这笔买卖没有理由不做。

但有一个前提：消隐期间不许加 delay。 有人为了「让消隐更彻底」，在 P0 = 0x00 后面加一句 delay_us(10)。结果每位多花 10μs，四位多花 40μs，看起来不多——可一旦你把这个 delay 写成 delay_ms(1)，亮度立刻掉一半，而且主循环被拖慢。消隐靠的是指令顺序，不是时间。

5.5 位选也要「先关后开」

还有一条同样重要的规矩：任意时刻只允许一位通电。

如果两位同时通电，会发生什么？

  • 两位显示同一个字符（因为段选共享）——于是你看到两个位置出现同样的数字，而不是各显示各的；
  • 这一瞬间的电流是两位之和，峰值直接翻倍；
  • 亮度不均：两位同时亮时，每一位分到的电流略少，看起来比单独亮时暗一点。

所以位选的操作也应该是「先关后开」：要么靠「写一个只有一位是 0 的字节」一次完成（P2 = ~(1u << pos) 本身就是原子的整体赋值，从 0xFE 直接跳到 0xFD，中间没有「两位都通」的状态），要么在切位之前先把位选写成全灭。用整体赋值是最省事的做法——这也是 §3.5 里说「位选适合整体写」的原因。

6. 核心概念四：扫描节拍、亮度与「时间片」

6.1 三个数：每位停留、一帧、刷新率

动态扫描的参数只有三个，它们互相锁死：

一帧 = 位数 × 每位停留
刷新率 = 1000 / 一帧(ms)
占空比 = 1 / 位数

下面这段程序把常见的几组取值算给你看，并给出「多少算够」的判断：

/* 示例 C —— 扫描周期、刷新率、占空比：三个数是怎么互相锁死的 */
#include <stdio.h>

int main(void)
{
    static const int dwell[] = {1, 2, 3, 5, 10};
    const int digits = 4;
    int i;

    puts("前提：4 位一体数码管，一位一位轮流点亮，每位停留 dwell 毫秒");
    puts("");
    for (i = 0; i < (int)(sizeof dwell / sizeof dwell[0]); ++i) {
        int frame = digits * dwell[i];        /* 扫完一圈（一帧）要多久 */
        int hz = 1000 / frame;                /* 每秒能扫多少圈 */
        printf("每位 %2dms -> 一帧 %2dms -> 刷新率 %3dHz -> 占空比 %d%% -> %s\n",
               dwell[i], frame, hz, 100 / digits,
               hz >= 100 ? "稳如常亮" : (hz >= 50 ? "勉强够用，眼角余光可能看到抖"
                                                  : "肉眼可见地闪，像坏了的日光灯"));
    }

    puts("");
    puts("反推：想让刷新率不低于 50Hz，一帧最多 1000/50 = 20ms，");
    printf("      4 位平摊，每位最多 %dms；想做到 100Hz，每位最多 %dms。\n",
           1000 / (50 * digits), 1000 / (100 * digits));
    puts("");
    puts("再算一笔账：12MHz 晶振、一位扫描大约几十条指令（几十微秒），");
    puts("1ms 一位对 CPU 来说非常宽裕——难的从来不是速度，是「别忘了来扫」。");
    return 0;
}

输出：

每位  2ms -> 一帧  8ms -> 刷新率 125Hz -> 占空比 25% -> 稳如常亮

反推：想让刷新率不低于 50Hz，一帧最多 1000/50 = 20ms，
      4 位平摊，每位最多 5ms；想做到 100Hz，每位最多 2ms。

再算一笔账：12MHz 晶振、一位扫描大约几十条指令（几十微秒），
1ms 一位对 CPU 来说非常宽裕——难的从来不是速度，是「别忘了来扫」。

对照输出记两条结论：

  1. 每位 1~2ms 是甜点区（刷新率 125~250Hz），既稳又不过分占用 CPU；
  2. 每位 5ms 是红线（刚好 50Hz）。到 10ms 就一定看得出闪。如果你在板子上看到「数码管轻微抖」，先量一下你的扫描周期，十有八九是某处偷偷加了延时。

6.2 为什么不能用 delay 来定这个节拍

最直觉的写法是这样：

/* 反面教材：用 delay 排扫描（片段，别照抄） */
while (1) {
    for (pos = 0; pos < 4; ++pos) {
        P0 = 0x00;
        P2 = ~(1u << pos);
        P0 = SEG_CC[g_disp[pos]];
        delay_ms(2);          /* 停在这里等 2ms */
    }
}

它确实能显示，而且看起来挺正常。但它把 CPU 100% 锁在了扫描上：一帧 8ms，其中绝大部分时间在 delay 里空转。这 8ms 里：

  • 按键没人读——你按一下，要等它转完一圈才被发现，响应迟钝；
  • 蜂鸣器没人管——该停的时候停不下来；
  • 业务逻辑没人跑——计数不会加。

一旦你加上第二件事（按键）、第三件事（蜂鸣器），这个结构立刻崩。不是因为它算错了时间，是因为它把「时间」当成了「独占资源」。

6.3 时间片：把「等」换成「问」

阶段十 §10.4 已经给过答案，这里把它变成标准写法。核心是三句话：

static unsigned int next = 0;        /* 我下次该干活的时刻 */

if (g_ms < next) {
    return;                          /* 没到点：立刻返回，把 CPU 让给别人 */
}
next = g_ms + SCAN_MS;               /* 到点了：干一小步，并约好下次 */

... 干这一小步 ...

三个要点，每一个都反直觉：

  1. 函数每次只干一小步。扫描任务一次只扫一位，不是扫完四位再返回。因为「扫完四位」要花 8ms，那 8ms 里你又把 CPU 借走了；
  2. 状态存在 static 局部变量里。pos、next 必须是 static，否则函数一返回就丢了（阶段三讲过的生命周期，在这里第一次变成刚需）；
  3. 用 if 判断，不用 while 等待。while (g_ms < next); 是阻塞，if (g_ms < next) return; 是非阻塞。一字之差，整个架构的生死。

g_ms 是什么？是「开机以来的毫秒数」。在 PC 模拟版里，它由 main 的循环变量喂进去；在真板子上，它由定时器中断每 1ms 加 1（下一篇的主题）。同一个变量，两个来源，任务代码一个字都不用改——这就是把硬件关进笼子的好处。

6.4 一张节拍表

人机界面的所有任务，最后都会收敛到这样一张表：

任务 周期 为什么是这个数 一次干多少
数码管扫描 1~2ms / 位 一帧 < 20ms，刷新率 > 50Hz 扫一位（关→换→开）
按键采样 5~10ms 抖动 5~20ms，采样要比它细 采一个电平，推进状态机一步
蜂鸣器 1ms 只为「到点就停」，不需要更细 看一眼 g_ms 和 beep_until
业务（计数） 100~1000ms 题面要求（任务 2 是 300ms） 改一次数值、刷一次缓冲
闪烁 300~500ms 人眼舒适区 翻转一个「亮/灭」标志

这张表建议抄在纸上。你以后写任何「多任务」的裸机程序，都是在这张表上加减行。

6.5 一个 51 特有的坑：g_ms 65.5 秒就轮回一次

PC 上 unsigned int 是 32 位，g_ms 能数 49 天。51 上 unsigned int 是 16 位，最大 65535——

65535ms ≈ 65.5 秒

也就是说，一分多钟之后 g_ms 会从 65535 跳回 0。如果你的代码写的是：

if (g_ms >= next) { ... }        /* 绝对值比较：回绕之后就永远不成立了 */

那么回绕那一刻，next 还停在 65000 附近，而 g_ms 已经变成 3——于是这个任务卡死 65 秒，直到 g_ms 重新爬过 next。表现是：数码管突然不刷新了（或者计数停住），过一分多钟又自己好了。这种 bug 极难复现，因为你要盯着它跑满一分钟。

正确的写法是用差值，不用绝对值：

static unsigned int last = 0;

if ((unsigned int)(g_ms - last) < SCAN_MS) {   /* 无符号减法，回绕也正确 */
    return;
}
last = g_ms;

为什么无符号减法不怕回绕？因为 3 - 65534 在 16 位无符号里会自动「绕回来」得到 5——数学上等于模 65536 的减法。这是阶段七「无符号整数的回绕是良定义的」那条规则的实战回报。

本篇的示例为了短、为了好读，用的是 if (g_ms < next) 这种绝对比较。它们在 3 秒的演示里完全正确，但你不能这样交作业——任务 2 的计数要跑几分钟，65 秒那道坎一定会来。写进你自己的工程时，请换成差值比较。

7. 核心概念五：按键抖动与两种消抖

7.1 抖是从哪儿来的

按键不是开关，是两块金属片。你按下去的时候，它们并不是「啪」一下就稳定贴合的，而是在几毫秒到二十毫秒里反复弹跳：碰上、弹开、再碰上、再弹开……直到动能耗尽，才真正稳定接触。

对 12MHz 的 51 来说，这段时间有多长？

1 个机器周期 = 1μs
20ms = 20000 个机器周期

两万个机器周期，足够 CPU 把「按了一次」读成七八次，甚至几十次。你在数码管上看到的现象就是：按一下，数字跳了 3；再按一下，跳了 1。

而且抖动不止发生在按下的时候。松开的那一瞬间，金属片同样会弹跳。所以严格来说有两种抖动：

名称 发生在 后果
前沿抖动（按下抖动） 手指按下的瞬间 一次按下被识别成多次「按下」
后沿抖动（松开抖动） 手指抬起的瞬间 一次松开被识别成多次「松开」；如果代码在等松手，可能提前退出

任务 3 的第 ② 小问专门考这件事：「前沿消抖，按下 m1 显示 1；后沿消抖，松开蜂鸣器响 500ms」。它在提醒你：按下和松开是两个事件，各要各的确认。

7.2 消抖窗口怎么定：20~50ms 的来历

消抖的原理朴素得可爱：抖动的特征是「忽高忽低」，只要要求「连续一段时间都一致」，抖动自然被过滤掉。

于是唯一要定的参数是：这段「一段时间」多长？

  • 不能太短：短于抖动持续时间，就挡不住。轻触开关典型抖动 5~20ms，脏了、老化了可能 30ms 以上。所以窗口的下限大约 20ms；
  • 不能太长：长过人手一次真实按下的时间，就会漏按。人手快速点击一次大约 50~100ms，所以窗口的上限大约 50ms；
  • 取中间值：20~30ms 是最常用的区间。要识别快速连点，就往 10~20ms 靠；要做「长按 2 秒」，那是另一个功能，不是消抖。

但「50~100ms」只是典型值，不是下限。很硬的轻触开关、用指甲弹一下、玩具枪的扳机、接触不良造成的窄脉冲，按下时间可以短到十几毫秒。这就是为什么 §7.3 要做那个极端实验：当事件本身比窗口还短时，窗口越大，你漏得越干净。

写成公式：

抗抖窗口 = 采样周期 × 连续确认次数

比如「每 10ms 采一次，连续 2 次一致」= 20ms 窗口；「每 5ms 采一次，连续 3 次」= 15ms 窗口。这两个数你要能心算。

7.3 两种写法：delay 版与状态机版

写法一：delay 阻塞版。 教科书和大多数开发板例程都这么写：

/* 写法一：delay 消抖（片段，能跑，但会阻塞） */
if (KEY == 0) {              /* 第一次看到低电平 */
    delay_ms(20);            /* 等 20ms，让抖动过去 */
    if (KEY == 0) {          /* 还是低 -> 认定按下 */
        do_something();
        while (KEY == 0) { } /* 死等松手 */
        delay_ms(20);        /* 松手也确认一下 */
    }
}

它的优点是短、好懂、一眼就对。缺点是三条，一条比一条要命：

  1. delay 期间 CPU 停摆。20ms 里数码管不刷新（一帧 8ms，等于黑了两帧半），蜂鸣器不停、按键不响——你按一下，屏幕会「顿」一下；
  2. 窗口固定死，改不了。想同时支持「慢按」和「快连点」，做不到；
  3. 它在「等」，不是在「记」。如果这 20ms 里发生了别的事（另一个键被按下），它完全不知道。

写法二：状态机非阻塞版。 阶段十 §10 的四状态机，这里升级成「带事件输出」的版本。它每 5ms 被调用一次，从不阻塞：

        level=0              连续 2 次低             level=1
  IDLE ────────► DEBOUNCE ──────────────► RELEASE ──────────► IDLE
   ▲                │                        │   连续 2 次高
   │                │ level=1（抖回去）        │
   └────────────────┘                        │ level=0（又按回去）
                                             └──► 回到「按着」

两个版本跑同一段抖动波形，结果会差多少？下面这段程序会告诉你——它把「波形」当成输入喂给两个版本，数一数各自被骗了几次。

/* 示例 D —— 同一段抖动波形，两种消抖写法各跑一遍，数一数谁被骗了几次 */
#include <stdio.h>

#define DEBOUNCE_MS   20        /* delay 版的确认窗口 */
#define SAMPLE_MS      5        /* 状态机版的采样周期 */
#define CONFIRM_CNT    2        /* 连续 2 次一致才认账 -> 抗抖窗口 10ms */

/* ---------- 波形：每格 1ms，'1' = 松开，'0' = 按下 ---------- */
static char wave[2048];
static int  wlen = 0;

static void w_add(int ms, char level)
{
    while (ms-- > 0 && wlen < (int)sizeof wave) {
        wave[wlen++] = level;
    }
}

static void w_str(const char *s)
{
    while (*s != '\0' && wlen < (int)sizeof wave) {
        wave[wlen++] = *s++;
    }
}

/* ---------- 指标一：完全不做处理时，会数出几次「按下」 ---------- */
static int raw_falling_edges(const char *w, int n)
{
    int i, cnt = 0;
    for (i = 1; i < n; ++i) {
        if (w[i - 1] == '1' && w[i] == '0') {
            ++cnt;
        }
    }
    return cnt;
}

/* ---------- 写法一：delay 阻塞版 ---------- */
static int delay_version(const char *w, int n, int *blocked_ms)
{
    int i = 0, events = 0, blocked = 0;

    while (i < n) {
        if (w[i] != '0') {
            ++i;
            continue;
        }
        blocked += DEBOUNCE_MS;          /* delay_ms(20)：这 20ms 主循环停摆 */
        i += DEBOUNCE_MS;
        if (i >= n) {
            break;
        }
        if (w[i] != '0') {               /* 20ms 后已经松手：当毛刺扔掉 */
            ++i;
            continue;
        }
        ++events;                        /* 确认按下 */
        while (i < n && w[i] == '0') {   /* 死等松手 */
            ++i;
        }
        blocked += DEBOUNCE_MS;          /* 松手后再 delay 一次，确认不是回弹 */
        i += DEBOUNCE_MS;
    }
    *blocked_ms = blocked;
    return events;
}

/* ---------- 写法二：状态机非阻塞版 ---------- */
typedef enum {
    K_IDLE = 0,
    K_DEBOUNCE,
    K_PRESSED,
    K_RELEASE
} key_state_t;

static int fsm_version(const char *w, int n)
{
    key_state_t st = K_IDLE;
    int cnt = 0, events = 0, i;

    for (i = 0; i < n; i += SAMPLE_MS) {
        int level = (w[i] == '0') ? 0 : 1;      /* 0 = 按下（低电平有效） */

        switch (st) {
        case K_IDLE:
            if (level == 0) {
                st = K_DEBOUNCE;
                cnt = 1;
            }
            break;
        case K_DEBOUNCE:
            if (level == 0) {
                if (++cnt >= CONFIRM_CNT) {
                    st = K_PRESSED;
                    ++events;                   /* 前沿确认：报一次「按下」 */
                }
            } else {
                st = K_IDLE;                    /* 抖回去了，不认 */
            }
            break;
        case K_PRESSED:
            if (level == 1) {
                st = K_RELEASE;
                cnt = 1;
            }
            break;
        case K_RELEASE:
            if (level == 1) {
                if (++cnt >= CONFIRM_CNT) {
                    st = K_IDLE;                /* 后沿确认：准备下一次 */
                }
            } else {
                st = K_PRESSED;                 /* 又按回去了 */
            }
            break;
        }
    }
    return events;
}

int main(void)
{

15ms 的按下时间，是故意压到极限的（正常人点击在 50ms 以上）。把参数推到极端，是为了把「窗口 > 事件」这个设计错误放大到肉眼可见——在 300ms 一次的业务里它可能只是「偶尔漏一下」，在快速连点、窄脉冲、或者你要数「谁先按」的场合，它就是致命的。

这两个场景合起来，才是对「两种消抖写法」的完整评价： delay 版不是「不抗抖」，它是「用阻塞换抗抖，并且窗口不可调」。 在只有一个按键、没有显示、没有蜂鸣器的作业里，它够用；在任务 3/4 这种「显示 + 按键 + 蜂鸣」同时在跑的场面里，它一定出问题。

7.4 把按键「事件化」：前沿和后沿都要报

任务 3 ② 要求「按下显示 1、松开响 500ms」——这意味着你的按键模块不能只返回「有没有按下」，而要返回发生了什么事件：

/* 按键事件码：一次调用最多返回一个事件（片段） */
#define KEY_EV_NONE   0
#define KEY_EV_DOWN   1     /* 前沿确认：按下了 */
#define KEY_EV_UP     2     /* 后沿确认：松开了 */
#define KEY_EV_HOLD   3     /* 可选：一直按着（用于连加） */

改写方法很简单：把状态机里「确认按下」和「确认松开」那两处，从「改状态」改成「改状态 + 返回事件码」。业务层拿到事件再决定干什么：

/* 业务层的写法（片段）：按键只报事件，干什么由业务决定 */
switch (key_scan(g_key_level)) {
case KEY_EV_DOWN:  /* 按下：亮灯 / 显示 / 计数 */  break;
case KEY_EV_UP:    /* 松开：响蜂鸣器 / 停表 */     break;
default:           break;
}

这样分层的好处是：同一个按键模块，任务 3 用它、任务 4 也用它，只是业务层的 switch 不一样。这就是阶段八「模块化」和阶段十「三文件工程」在这一篇的兑现。

7.5 连击与长按：两个容易混淆的功能

「按住不放，数字一直加」——这叫连击（auto-repeat），和消抖是两件不同的事：

功能 触发条件 实现要点
消抖 电平变化 连续 N 次一致才认
连击 一直按着 按下后先等一下（约 500ms），然后每 100~200ms 重复报一次
长按 按住超过 T 用一个「按住的毫秒数」计数器，到 T 报一次长按事件

任务 4 的「闪烁位切换、k1 加 / k4 减、k2 前移 / k3 后移」，到底要不要连击，以任务 PDF 的文字为准。如果题面只说「按一下加一」，那就别自作聪明加连击——多做的功能在验收时往往会被当成「不符合题面」。

8. 核心概念六：矩阵键盘——用 8 根线读 16 个键

8.1 先算一笔线数账

任务 3 的第三小问是「4×2 矩阵键盘行列扫描，键 1~8 对应显示 1~8」。为什么是 4×2？先看账：

方案 按键数 需要 IO 说明
一对一直接接 8 8 根 一个键占一根，最简单，最费线
4×2 矩阵 8 6 根（4 行 + 2 列） 省 2 根
4×4 矩阵 16 8 根（4 行 + 4 列） 同样 8 根线，键数翻倍
一对一直接接 16 16 根 半个 51 没了

省线这件事，在 51 上不是「优化」，是「能不能做完」：8 段段选 + 4 位位选已经吃掉 12 根，再拿 16 根接按键，P0/P1/P2/P3 就一根不剩了。

这里要纠正一个你在群里、在网上会反复听到的说法：「4 个 IO 能读 16 个键」。

这句话在纯开关矩阵里是做不到的。4 根线做成 2×2，只有 4 个交叉点，也就是 4 个键。想读 16 个键，行列各要 4 根，一共 8 根。真正能做到「少数几根线读很多键」的是另外两种技术：

  • Charlieplexing（查理复用）：利用 IO 的三态（高、低、高阻），N 根线可以驱动 N×(N−1) 个器件。4 根线理论上是 12 个，不是 16 个；
  • AD 键盘（电阻分压键盘）：所有按键接到一根 ADC 输入上，每个键串不同阻值，靠读电压区分。一根线能读很多键，但需要 ADC，而且不能同时按。

这两种都超出本阶段范围，你只要记住结论：矩阵键盘的省线倍数来自「行列交叉」，不是来自「复用 IO」。 4×4 用 8 根线读 16 个键，省了一半；这就是它的全部本事。

8.2 原理：一张网，按键是网线上的结

把 4 根行线（R0~R3）和 2 根列线（C0、C1）摆成一个网格，每个交叉点上放一个按键：

          C0        C1
          │         │
   R0 ────┼─────────┼────     每个 ┼ 是一个按键：
          │         │        按下时，这根行线和这根列线
   R1 ────┼─────────┼────    被短接在一起
          │         │
   R2 ────┼─────────┼────
          │         │
   R3 ────┼─────────┼────
  • 行线是输出（由单片机驱动）；
  • 列线是输入（读电平），并且必须上拉（准双向口的弱上拉就够，或者外接 10k）。

平时所有行都输出 1、所有列都被上拉成 1，读到的全是 1，表示没键。

一旦某个键按下，它就把自己的行和列短接。这时候只要把那一行拉低，那一列也会跟着变低——于是「行 r 拉低时，列 c 读到 0」就唯一确定了「第 r 行第 c 列」这个键。

把 R1 拉低（R0/R2/R3 保持 1）：
   C0 读到 0  ->  R1-C0 这个键被按下
   C1 读到 1  ->  R1-C1 没按

8.3 扫描流程：四步，重复 ROWS 次

① 所有行写 1（释放），列写 1（准备读）
② 第 r 行写 0，其余行保持 1
③ 读列线：哪一位是 0，就是「第 r 行 + 那一列」的键
④ r 换下一行，回到 ②；四行扫完 = 一轮

一轮扫描要读 ROWS 次列线。4 行就是 4 次，每次几条指令——整轮下来几十微秒，比数码管一位的停留时间还短。所以矩阵扫描完全可以塞进同一个 1ms 节拍里，不会拖慢任何东西。

8.4 现场：8 个键逐个按，把扫描过程摊开看

下面这段程序模拟一个 4×2 矩阵：8 个键、4 根行线、2 根列线，并且故意把「读前写 1」的坑也做进去了——它的 col_read() 会忠实模拟准双向口的行为。

/* 示例 E —— 4 行 x 2 列矩阵键盘：行输出、列读入、读前写 1 */
#include <stdio.h>

#define ROWS 4
#define COLS 2
#define KEY_NUM (ROWS * COLS)

/* 模拟三条「物理线」的锁存器：准双向口写进去什么，锁存器里就是什么 */
static unsigned char row_latch = 0xFF;     /* 行线：P1.0~P1.3，写 0 = 拉低这一行 */
static unsigned char col_latch = 0xFF;     /* 列线：P3.0~P3.1，读之前必须写 1 */

static int g_key[ROWS][COLS];              /* 1 = 这个交叉点上的键被按下 */

/* 读列线。真实的准双向口有两个规矩：
 *   ① 哪一行被拉低，这一行上按下的键就会把对应的列也拉低；
 *   ② 锁存器里是 0 的那一位，读回来永远是 0（所以必须先写 1）。 */
static unsigned char col_read(void)
{
    unsigned char v = 0xFF;
    int r, c;

    for (c = 0; c < COLS; ++c) {
        for (r = 0; r < ROWS; ++r) {
            if (((row_latch >> r) & 1u) == 0 && g_key[r][c] != 0) {
                v &= (unsigned char)~(1u << c);     /* 这一列被键拉低 */
            }
        }
    }
    return (unsigned char)(v & col_latch);          /* 锁存器里的 0 会「粘」在读数上 */
}

/* 扫描一轮：返回 1~8，0 = 没键，同时用 *multi 带回「这一轮一共发现几个键」。
 * write_one = 0 时故意不写 1，用来演示准双向口那个坑。 */
static int scan_matrix_ex(int write_one, int *multi)
{
    int r, c, found = 0, first_key = 0;

    *multi = 0;
    for (r = 0; r < ROWS; ++r) {
        unsigned char v;

        row_latch = (unsigned char)~(1u << r);      /* 只把第 r 行拉低，其余写 1 */
        if (write_one) {
            col_latch = 0xFF;                       /* 读之前先写 1：准双向口铁律 */
        }
        v = col_read();
        for (c = 0; c < COLS; ++c) {
            if (((v >> c) & 1u) == 0) {
                ++found;
                if (first_key == 0) {
                    first_key = r * COLS + c + 1;
                }
            }
        }
    }
    row_latch = 0xFF;                               /* 扫完把所有行释放，别一直拉着 */
    if (found > 1) {
        *multi = found;
    }
    return first_key;
}

static int scan_matrix(int *multi)
{
    return scan_matrix_ex(1, multi);
}

/* row < 0 表示「一个键都不按」，否则只按 (row, col) 这一个 */
static void press_only(int row, int col)
{
    int r, c;
    for (r = 0; r < ROWS; ++r) {
        for (c = 0; c < COLS; ++c) {
            g_key[r][c] = 0;
        }
    }
    if (row >= 0) {
        g_key[row][col] = 1;
    }
}

static void trace_one(int row, int col)
{
    int r;
    printf("  按着第 %d 个键（行 %d、列 %d）时，逐行扫描看到的是：\n",
           row * COLS + col + 1, row, col);
    for (r = 0; r < ROWS; ++r) {
        unsigned char v;
        row_latch = (unsigned char)~(1u << r);
        col_latch = 0xFF;
        v = col_read();
        printf("    行%d 拉低：列读回 0x%02X  %s\n", r, (unsigned)v,
               (v & 0x03u) == 0x03u ? "两列都高，这一行没键"
                                    : "有列被拉低，命中！");
    }
    row_latch = 0xFF;
}

int main(void)
{
    int k, multi, got;

    puts("== 一、8 个键逐个按一遍 ==");
    for (k = 1; k <= KEY_NUM; ++k) {
        int row = (k - 1) / COLS;
        int col = (k - 1) % COLS;
        press_only(row, col);
        got = scan_matrix(&multi);
        printf("  物理上按的是键 %d -> 扫描识别为 %d  %s\n", k, got,
               got == k ? "对" : "错");
    }

    puts("");
    puts("== 二、把扫描过程摊开看（按着键 3）==");
    press_only(1, 0);
    trace_one(1, 0);

    puts("");
    puts("== 三、两个键同时按：同排 vs 不同排 ==");
    press_only(-1, 0);                     /* 先清空：一个键都不按 */
    g_key[1][0] = 1;
    g_key[1][1] = 1;                       /* 同一行两列同时按 */
    got = scan_matrix(&multi);
    printf("  同一行的键 3、键 4 一起按 -> 返回 %d，本轮共发现 %d 个键（这一行两列同时低）\n",
           got, multi);

    press_only(-1, 0);
    g_key[0][0] = 1;
    g_key[2][1] = 1;                       /* 不同行不同列 */
    got = scan_matrix(&multi);
    printf("  不同行的键 1、键 7 一起按 -> 返回 %d，本轮共发现 %d 个键（扫描到第一行就返回，另一个被漏掉）\n",
           got, multi);

    puts("");
    puts("== 四、反面教材：读列线之前没写 1 ==");
    press_only(-1, 0);                     /* 一个键都没按 */
    col_latch = 0xFD;                      /* 上一次操作把 P3.0 留成了 0 */
    got = scan_matrix_ex(0, &multi);
    printf("  一个键都没按，却读出了键 %d —— 因为锁存器里那个 0 还在把线拽住\n", got);
    puts("  药方：每次读列线之前，先往列端口写 0xFF。");
    return 0;
}

四段输出，四个知识点：

第一段：8 个键逐个按，识别全对。注意键号是怎么算出来的：键号 = 行 × 列数 + 列 + 1。这个公式把「二维的交叉点」压成了「一维的编号」，是矩阵键盘最常用的一步。列数变了，公式里的乘数就要跟着变——4×4 时是 行 × 4 + 列 + 1。

第二段：按着键 3（行 1、列 0）时，只有「行 1 拉低」那一次读到了 0xFE，其余三次都是 0xFF。这就是「行列交叉」的直接证据：同一个键，只在它自己那一行被拉低时才现形。

第三段：两个键同时按，结果分两种：

  • 同一行的两个键（键 3 + 键 4）：这一行的两列同时变低，一次就读到两个 0。你能知道「这一行有两个键」，但分不清是「两个都按着」还是「一个在抖」；

第四段：一个键都没按，却读出了键 2。原因写在输出里：col_latch 里还留着上一次的 0。

8.5 读前写 1：准双向口第二次咬人

阶段十 §4 讲过这条铁律，当时是用按键举的例子；在矩阵键盘里，它会咬得更疼，因为列线是「一会儿输出、一会儿输入」的复用脚。

原理回顾：准双向口的引脚上有一个锁存器和一个弱上拉。你往端口写 0，锁存器变 0，那只强下拉的 MOS 管就导通，把引脚死死拽在地上；这时候你去读，读回来的永远是 0，跟外面接了什么无关。

写 0 之后再读：      读到 0（不管你按没按）
写 1 之后再读：      读到外部真实电平（上拉 = 1，被键拉低 = 0）

所以列线的正确用法是：每次读之前，先往列端口写 0xFF。

col_port = 0xFF;          /* ① 先把 8 个脚都「松手」 */
v = col_port;             /* ② 再读，读到的才是外面的世界 */

这条规矩在矩阵键盘里尤其容易忘，因为列线在扫描过程中只读不写，你很容易觉得「我又没写它，它怎么会是 0」。答案是：上电复位时它是 1，但只要你曾经往它写过一次 0（比如初始化时误操作、或者复用了这个端口的其他位），那个 0 就一直在。 更隐蔽的是：有些板子把列线和数码管位选复用在同一个端口上——扫描时写 0，读键时忘了恢复，于是「键一直是被按下的」。

一句话记法：输入脚在读之前，先把它写成 1。 51 的准双向口、AVR 的 PORTx 上拉、STM32 的「输入上拉」，本质都是同一件事。

8.6 鬼键：三个键能「变」出第四个

矩阵键盘有一个著名的硬伤，叫鬼键（ghost key）。假设你同时按下三个键，它们正好占住一个矩形的三个角：

        C0     C1
   R0 ──[K1]──[K2]──       K1 = R0-C0，K2 = R0-C1，K3 = R1-C0
   R1 ──[K3]── ?? ──       三个键按下 -> R0 和 R1 通过 K1/K2/K3 连成一片

因为按键是双向导通的（不像二极管有方向），R0 拉低时，电流可以走 R0 → K1 → C0 → K3 → R1 → K2 → C1 这条路，把 C1 也拉低。于是扫描结果里会多出一个「R1-C1 被按下」——这个键根本没人碰，它是「鬼」。

处理办法按成本从低到高：

做法 效果 代价
检测到多键就丢弃本轮 三个键同时按时不响应（而不是响应错的） 零成本，最常用
每个键串一只二极管 电流只能单向走，鬼键消失 16 只二极管 + 焊接
加专用键盘芯片 硬件扫描、去鬼、带 FIFO 成本、复杂度

初级处理就选第一条：数一数这一轮发现了几个键，> 1 就整轮作废、等下一轮。用户同时按三个键本来就是误操作，不响应比响应错了好。

8.7 矩阵键也要消抖——而且更麻烦

矩阵键盘的抖动比独立按键更讨厌，因为抖动会改变「哪个键被按下」的判断：

真实情况：按着键 3
抖动瞬间：这一行的列线在 0xFE / 0xFF 之间跳
扫描结果：键 3、无键、键 3、无键 ...

所以矩阵键必须消抖，思路和 §7 完全一样，只是「电平」换成了「键号」：

/* 矩阵键消抖的思路（片段，不是实现） */
key = scan_matrix();              /* 0 = 没键，1~8 = 键号 */
if (key == last_key) {            /* 和上一次扫描结果一样 */
    if (++stable >= 2) {          /* 连续 2 轮都一样 -> 认账 */
        /* 这里才认为「键 key 被稳定按下」 */
    }
} else {
    last_key = key;
    stable = 0;
}

注意这里的「连续一致」比较的是键号，不是电平——因为矩阵扫描的输出本来就是「哪一个键」，不是「哪一根线」。这个小小的视角转换，能让代码短一半。

9. 核心概念七：蜂鸣器——会叫的负载

9.1 有源与无源：名字很像，脾气相反

有源蜂鸣器 无源蜂鸣器
内部 自带震荡电路 只有线圈/压电片，没有震荡源
给直流电 持续响，音高固定 只「嗒」一声（一个瞬态）
给方波 也响，但音高不随方波频率变 按方波频率发声，能给什么调就唱什么调
控制难度 一个 IO 通断就行 需要持续输出方波（频率要准）
能奏乐吗 不能（只有一种音） 能
典型用途 报警、提示音 电子琴、音乐盒、门铃

怎么分辨？ 三个办法，从可靠到凑合：

  1. 看背面：有源蜂鸣器背面通常有一圈黑色封胶（里面是震荡电路），无源的多半能看见线圈或压电片；
  2. 加直流试：接 3~5V 直流（串个电阻），持续响的是有源，只「嗒」一下的是无源；
  3. 看丝印/型号：商家页面一般会写，但这个最不可靠——很多店把「无源」写成「有源」。以实测为准。

任务 3 ② 要求「松开蜂鸣器响 500ms」，任务 4 可能要求不同的提示音。如果你的板子是有源的，你能做的只有「响多久」；如果是无源的，你还能控制「什么调」。这两种板子写出来的代码不一样，所以 §15 的自查清单里有一条：先确认你的蜂鸣器是哪一种。

9.2 为什么不能拿 IO 直接灌

回忆 §3.5 的数字：51 单个引脚灌电流大约 10~20mA，整片还有总上限。

蜂鸣器呢？小型的电磁式蜂鸣器工作电流常见在 20~40mA，压电式的会小一些，但启动瞬间仍有冲击。更要命的是它是感性负载：断电那一瞬间，线圈会产生反向电动势（电压可能远高于 5V），直接顶在 IO 脚上。

所以正路是这样：

                 +5V
                  │
              [ 蜂鸣器 ]
                  │
   P1.x ──[1k]──┤ NPN (8050 之类)
                  │
                 GND
  • IO 只负责给三极管基极一点点电流（串 1k 电阻限流），三极管负责扛蜂鸣器那几十毫安；
  • 蜂鸣器接在集电极（NPN 低边驱动）或发射极（高边，少见），电源从 +5V 走，不从 IO 走；
  • 感性负载最好并一只续流二极管（反并联在蜂鸣器两端），把断电时的反向电动势引走。

如果板子上用的是 ULN2003 这类达林顿驱动阵列，那就更省事：一片芯片 7 路，每路能扛几百毫安，输入直接接 IO（内部已有基极电阻），输出接负载。它常被用来驱动步进电机、继电器、蜂鸣器。具体能扛多少、要不要外接续流二极管，以芯片数据手册为准。

一句话总结：IO 是信号，不是电源。 这句话在阶段十说过，在数码管说过，在这里第三次说——因为它是初学者烧板子的头号原因。

9.3 无源蜂鸣器怎么「唱」：方波与半周期

无源蜂鸣器要的是方波：高一半、低一半，来回翻转。方波的频率决定音高：

周期 T = 1 / f
半周期 = T / 2 = 1 / (2f)

以中央 C（262Hz）为例：

T = 1/262 ≈ 3.82ms
半周期 ≈ 1.91ms ≈ 1908μs

也就是说，你要每 1908 微秒翻转一次引脚，才能发出 262Hz。这个精度，用「1ms 的时间片」是做不到的（1ms 翻转一次 = 500Hz，只能发一个固定的音）。要发出准确的音高，必须用定时器中断——这正是下一篇的主题。

所以本篇对无源蜂鸣器只能做「概念演示」：告诉你频率和半周期的关系、告诉你占空比能调音量，但真正的音阶要等定时器。这不是偷懒，是诚实：用 delay 凑出来的《两只老虎》一定跑调。

9.4 现场：同一段旋律，两种蜂鸣器

下面这段程序把「有源 / 无源」的差别、节奏的排法、PWM 音量的算法都打印出来。它不真的发声（PC 上没有蜂鸣器），但它把该翻转多少次、该响多久、平均电压是多少都算清楚了。

/* 示例 F —— 有源 / 无源蜂鸣器、节奏、PWM 音量（全部非阻塞） */
#include <stdio.h>

typedef struct {
    unsigned int hz;      /* 0 表示休止符 */
    unsigned int ms;
} note_t;

/* 一段四个音的短句：do re mi + 休止 */
static const note_t MELODY[] = {
    {262, 200}, {330, 200}, {392, 400}, {0, 200}
};
#define NOTE_N ((int)(sizeof MELODY / sizeof MELODY[0]))

static unsigned int g_ms = 0;

/* 无源蜂鸣器：给什么频率就唱什么调；给方波，所以每半个周期翻转一次引脚 */
static void passive_note(unsigned int hz, unsigned int ms)
{
    unsigned int half_us, toggles;

    if (hz == 0) {
        printf("  休止 %ums：引脚保持高，不出声\n", ms);
        return;
    }
    half_us = 500000u / hz;                 /* 半周期，单位微秒 */
    toggles = (ms * 1000u) / half_us;       /* 这 200ms 里要翻转多少次 */
    printf("  %uHz 响 %ums：半周期 %uus，引脚翻转 %u 次\n", hz, ms, half_us, toggles);
}

/* 有源蜂鸣器：内部自带震荡源，你只要给它通电，它就一直唱它自己那个调 */
static void active_note(unsigned int ms)
{
    printf("  （有源）通电 %ums：不管代码里写 262 还是 392，听起来都是同一个音\n", ms);
}

/* PWM 调音量：频率决定音高，占空比决定「平均功率」 */
static void pwm_volume(void)
{
    static const int duty[] = {10, 50, 90};
    int i;

    puts("  PWM 调音量（假设 5V 供电、满占空比时最响）：");
    for (i = 0; i < 3; ++i) {
        int mv = 5000 * duty[i] / 100;      /* 平均电压，单位毫伏 */
        printf("    占空比 %2d%% -> 平均电压 %d.%02dV -> %s\n",
               duty[i], mv / 1000, (mv % 1000) / 10,
               duty[i] < 30 ? "很轻" : (duty[i] < 70 ? "中等" : "接近满响"));
    }
}

int main(void)
{
    int i;

    puts("== 一、同一段旋律，两种蜂鸣器 ==");
    for (i = 0; i < NOTE_N; ++i) {
        printf("第 %d 个音：\n", i + 1);
        if (MELODY[i].hz == 0) {
            printf("  休止 %ums：不论有源无源，都断电，安静\n", MELODY[i].ms);
            continue;
        }
        passive_note(MELODY[i].hz, MELODY[i].ms);
        active_note(MELODY[i].ms);
    }

    puts("");
    puts("== 二、节奏怎么排：不要用 delay，用「到期时间」 ==");
    {
        unsigned int t = 0;
        for (i = 0; i < NOTE_N; ++i) {
            printf("  t=%4ums 起音，t=%4ums 止音%s\n", t, t + MELODY[i].ms,
                   MELODY[i].hz == 0 ? "（休止）" : "");
            t += MELODY[i].ms;
        }
        printf("  整段 %ums。这段时间里主循环照转：扫描没停、按键没丢。\n", t);
    }

    puts("");
    puts("== 三、为什么不能拿 IO 直接灌 ==");
    puts("  51 单个引脚大约能灌 10~20mA，整片还有总上限（以数据手册为准）；");
    puts("  蜂鸣器动辄几十毫安，直接接上去，轻则声音发虚，重则烧脚。");
    puts("  正路：IO -> 三极管基极（串 1k 左右）/ ULN2003 -> 蜂鸣器，电源另走一路。");

    puts("");
    puts("== 四、PWM 音量 ==");
    pwm_volume();

    g_ms = 0;   /* 本节只是把概念跑一遍，真正的节拍在 §10 的骨架里 */
    return 0;
}

输出：

== 一、同一段旋律，两种蜂鸣器 ==
第 1 个音：
  262Hz 响 200ms：半周期 1908us，引脚翻转 104 次
  （有源）通电 200ms：不管代码里写 262 还是 392，听起来都是同一个音
第 2 个音：
  330Hz 响 200ms：半周期 1515us，引脚翻转 132 次
  （有源）通电 200ms：不管代码里写 262 还是 392，听起来都是同一个音
第 3 个音：
  392Hz 响 400ms：半周期 1275us，引脚翻转 313 次
  （有源）通电 400ms：不管代码里写 262 还是 392，听起来都是同一个音
第 4 个音：
  休止 200ms：不论有源无源，都断电，安静

== 二、节奏怎么排：不要用 delay，用「到期时间」 ==
  t=   0ms 起音，t= 200ms 止音
  t= 200ms 起音，t= 400ms 止音
  t= 400ms 起音，t= 800ms 止音
  t= 800ms 起音，t=1000ms 止音（休止）
  整段 1000ms。这段时间里主循环照转：扫描没停、按键没丢。

== 三、为什么不能拿 IO 直接灌 ==
  51 单个引脚大约能灌 10~20mA，整片还有总上限（以数据手册为准）；
  蜂鸣器动辄几十毫安，直接接上去，轻则声音发虚，重则烧脚。
  正路：IO -> 三极管基极（串 1k 左右）/ ULN2003 -> 蜂鸣器，电源另走一路。

== 四、PWM 音量 ==
  PWM 调音量（假设 5V 供电、满占空比时最响）：
    占空比 10% -> 平均电压 0.50V -> 很轻
    占空比 50% -> 平均电压 2.50V -> 中等
    占空比 90% -> 平均电压 4.50V -> 接近满响

三段输出，三个要点：

第一段：同一个 262Hz 的音符，无源蜂鸣器要在 200ms 里翻转 104 次引脚（200000μs / 1908μs），有源蜂鸣器只需要「通电 200ms」。这就是「有源省事、无源费事」的量化版本。顺便注意第 4 个音是休止符——休止就是断电，两种蜂鸣器都一样。

第二段：节奏不是用 delay 排的，而是用「起音时刻 / 止音时刻」排的。t=0 起音、t=200 止音、t=200 起音、t=400 止音…… 每个音只记两个时间点，中间那段时间 CPU 是自由的。这就是 §10 骨架里 beep_until 的来源。

第三段（PWM）：占空比 10% / 50% / 90%，平均电压 0.50V / 2.50V / 4.50V。频率决定音高，占空比决定响度——这是 PWM 的两条腿。

9.5 PWM 调音量：一个只赚不赔的小技巧

「PWM」这个词你在电机调速、LED 调光里都见过，在蜂鸣器上它的用法是：

在「响」的那半个周期里，再快速通断很多次：
  通 10% 时间  ->  平均功率 10%  ->  声音很轻
  通 50% 时间  ->  平均功率 50%  ->  中等
  通 90% 时间  ->  平均功率 90%  ->  接近满响

对无源蜂鸣器来说，音高由方波频率定，音量由占空比定，两者互不干扰。于是你可以做出「渐强」「渐弱」「按键音短促、报警音连续」这类效果。

51 没有硬件 PWM，要用定时器 + 软件计数做：定时器每 50μs 中断一次，中断里维护一个 0~99 的计数器，计数器小于「占空比」就输出高，否则输出低。这件事同样要等下一篇的定时器。

注意：占空比太低（比如 5%）时，很多蜂鸣器根本推不响，或者声音发沙。实际可用范围通常在 20%~80%，以你手上那只蜂鸣器的实测为准。

9.6 蜂鸣器的正确打开方式：beep_until

最后把「怎么让蜂鸣器响 500ms 然后自己停」这件事写死在心里：

/* 错：delay 500ms，主循环停摆，数码管黑一片 */
BEEP = 0;  delay_ms(500);  BEEP = 1;

/* 对：只记「响到哪一刻」，让蜂鸣器任务自己看表 */
g_beep_until = g_ms + 500;      /* 业务层：排一个 500ms 的闹钟 */
/* 蜂鸣器任务里：g_ms < g_beep_until ? 通电 : 断电 */

第二行的写法，把「等待」从 CPU 身上转移到了「时间」身上。CPU 不再需要「陪」着蜂鸣器，它可以去扫描、去看按键。这就是 §10 那个骨架的核心思想，也是整篇教程真正的主题：

不要用 CPU 去等时间，要让时间自己走到你面前。

10. 把机制拼起来：一个「人机界面」的最小骨架

10.1 数据流：谁改缓冲，谁读缓冲

前面七节各讲了一个零件。现在把它们装到一台机器上，你需要先看清这台机器的数据流：

   按键事件 ──────┐
                  ├──► 业务状态（计数 / 闪烁位 / 当前模式）
   蜂鸣器到期 ────┘            │
                              │ 只改这一个东西
                              ▼
                     ┌──────────────────┐
                     │  显示缓冲 g_disp  │  ← 唯一的「真相」
                     │  [0][1][2][3]     │
                     └────────┬─────────┘
                              │ 只读，不改
                              ▼
                       扫描任务（2ms/位）
                              │
                    ┌─────────┴─────────┐
                    ▼                   ▼
              P0 段选（8 根）      P2 位选（4 根）

这条数据流里有一条不容违反的规矩：

业务代码只许改「显示缓冲」，扫描任务只许读「显示缓冲」。谁也不许越过缓冲，直接去写 P0 / P2。

为什么？因为一旦有人越过缓冲直接写端口，扫描任务下一次执行时就会把它覆盖掉——你写的那一位会闪一下就没。更糟的是，两个地方同时写端口，出问题时你根本不知道是谁写的。

这条规矩还有一个附带好处：显示什么和怎么显示彻底分家了。业务层可以完全不知道「共阴还是共阳」「扫描到第几位」，它只管往 g_disp 里放数字。将来换板子、换段码表、改扫描速度，业务代码一个字不用动。

这正是阶段十 §11 三文件工程的思想——把变化关进笼子——只是这一次，笼子从「文件」变成了「一个 4 字节的数组」。

10.2 代码：四个任务，一个节拍，零个 delay

下面这 150 行是本篇的核心交付物。它同时做了四件事：

  1. 每 2ms 扫一位数码管（带消隐），把 g_disp 里的四个数字显示出来；
  2. 每 5ms 采一次按键，用 §7 的状态机消抖，认到按下就排一个 100ms 的蜂鸣；
  3. 每 1ms 看一眼蜂鸣器是否到期，到期就断电；
  4. 每 500ms 让一个 0~99 的数加 1，刷新显示缓冲（演示用：任务 2 要的是 300ms / 0~999，别照抄这里）。

四件事没有一个 delay，谁也挡不住谁。

先声明：这是「机制演示」，不是「任务答案」。 它的业务部分被故意做得极简（0~99、500ms，没有滚动、没有反向、没有闪烁），目的只是让你看到「缓冲被改写时，扫描照样跟得上」。任务 2/3/4 要的那些行为，本篇一个都没有替你写——§15 会告诉你，每一小问该用哪几节的机制去拼。

/* 示例 G —— 人机界面的最小骨架：显示缓冲 + 动态扫描 + 按键 + 蜂鸣器
 * 四个任务全部非阻塞：每 1ms 进来问一句「该你了吗」，该就干一小步，不该就立刻返回。
 */
#include <stdio.h>

#define DIGITS        4
#define SCAN_MS       2        /* 每 2ms 推进一位 -> 一帧 8ms -> 125Hz */
#define KEY_MS        5        /* 每 5ms 采一次按键 */
#define KEY_CONFIRM   2        /* 连续 2 次一致 -> 10ms 的确认窗口 */
#define TICK_MS       500      /* 业务节拍：演示用。任务 2 要的是 300ms，按题面自己改 */
#define BEEP_MS       100      /* 按键后蜂鸣器响多久 */

/* ---------- 模拟层：真机上这三行换成 sfr / sbit ---------- */
static unsigned char P0_seg = 0x00;    /* 段选：共阴，1 = 亮 */
static unsigned char P2_dig = 0xFF;    /* 位选低 4 位：0 = 这一位通电 */
static unsigned int  g_ms   = 0;       /* 开机毫秒数：真机由定时器中断累加 */

static const unsigned char SEG_CC[10] = {
    0x3F, 0x06, 0x5B, 0x4F, 0x66, 0x6D, 0x7D, 0x07, 0x7F, 0x6F
};

/* ---------- 唯一的「真相」：显示缓冲 ---------- */
static unsigned char g_disp[DIGITS] = {0, 0, 0, 0};

/* ---------- 业务状态 ---------- */
static unsigned int g_count      = 0;  /* 0~999 */
static unsigned int g_beep_until = 0;  /* 蜂鸣器响到哪一刻 */
static int          g_key_level  = 1;  /* 模拟引脚：1 松开 / 0 按下 */
static unsigned int g_frames     = 0;  /* 扫了多少帧 */
static unsigned int g_key_events = 0;  /* 认了几次按键 */

/* ---------- 任务 1：动态扫描，每 2ms 走一位 ---------- */
static void display_task(void)
{
    static int pos = 0;
    static unsigned int next = 0;

    if (g_ms < next) {
        return;                        /* 没到点：立刻返回，主循环继续 */
    }
    next = g_ms + SCAN_MS;

    P0_seg = 0x00;                            /* ① 消隐：先关段选 */
    P2_dig = (unsigned char)~(1u << pos);     /* ② 换位选：只让第 pos 位通电 */
    P0_seg = SEG_CC[g_disp[pos]];             /* ③ 送这一位的段码 */

    pos = (pos + 1) % DIGITS;
    if (pos == 0) {
        ++g_frames;
        if (g_frames == 1 || g_frames % 50 == 0) {
            printf("  [t=%4ums] 第 %3u 帧扫完，缓冲 = %u%u%u%u\n", g_ms, g_frames,
                   (unsigned)g_disp[0], (unsigned)g_disp[1],
                   (unsigned)g_disp[2], (unsigned)g_disp[3]);
        }
    }
}

/* ---------- 任务 2：按键，每 5ms 采一次 ---------- */
typedef enum {
    KEY_IDLE = 0,
    KEY_DEBOUNCE,
    KEY_RELEASE
} key_state_t;

static void on_key_press(void)
{
    ++g_key_events;
    g_beep_until = g_ms + BEEP_MS;              /* 交给蜂鸣器任务去「响到某刻」 */
    printf("  [t=%4ums] 按键：前沿确认 -> 蜂鸣器排上 100ms\n", g_ms);
}

static void key_task(void)
{
    static key_state_t st = KEY_IDLE;
    static unsigned int next = 0;
    static int cnt = 0;
    int level;

    if (g_ms < next) {
        return;
    }
    next = g_ms + KEY_MS;

    level = g_key_level;
    switch (st) {
    case KEY_IDLE:
        if (level == 0) {
            st = KEY_DEBOUNCE;
            cnt = 1;
        }
        break;
    case KEY_DEBOUNCE:
        if (level == 0) {
            if (++cnt >= KEY_CONFIRM) {
                st = KEY_RELEASE;
                on_key_press();
            }
        } else {
            st = KEY_IDLE;                       /* 抖回去了，不认 */
        }
        break;
    case KEY_RELEASE:
        if (level == 1) {
            if (++cnt >= KEY_CONFIRM) {
                st = KEY_IDLE;                   /* 后沿确认，准备下一次 */
            }
        } else {
            cnt = 0;                             /* 还按着：松手计数重新开始 */
        }
        break;
    }
}

/* ---------- 任务 3：蜂鸣器，每 1ms 看一眼「到期没」 ---------- */
static void buzzer_task(void)
{
    static int sounding = 0;
    int should = (g_ms < g_beep_until) ? 1 : 0;

    if (should && !sounding) {
        printf("  [t=%4ums] 蜂鸣器：通电\n", g_ms);
        sounding = 1;
    } else if (!should && sounding) {
        printf("  [t=%4ums] 蜂鸣器：断电\n", g_ms);
        sounding = 0;
    }
}

/* ---------- 任务 4：业务，每 500ms 让一个 0~99 的数加 1 ----------
 * 这一段是「演示用的业务」：只为了让你看到缓冲被改写、扫描照样跟得上。
 * 任务 2 要的是 0~999 / 300ms，还有滚动、反向、闪烁——那些请按题面自己写，
 * 别把这段照抄过去：它不是答案，只是一个「业务长什么样」的例子。 */
static void app_task(void)
{
    static unsigned int next = TICK_MS;

    if (g_ms < next) {
        return;
    }
    next += TICK_MS;

    g_count = (g_count + 1) % 100;
    g_disp[0] = (unsigned char)(g_count / 1000 % 10);
    g_disp[1] = (unsigned char)(g_count / 100 % 10);
    g_disp[2] = (unsigned char)(g_count / 10 % 10);
    g_disp[3] = (unsigned char)(g_count % 10);
    printf("  [t=%4ums] 计数 %u -> 显示缓冲 %u%u%u%u\n", g_ms, g_count,
           (unsigned)g_disp[0], (unsigned)g_disp[1],
           (unsigned)g_disp[2], (unsigned)g_disp[3]);
}

int main(void)
{
    unsigned int t;

    puts("=========================================================");
    puts(" 最小人机界面：4 位数码管 + 1 个按键 + 1 个蜂鸣器");
    puts(" 扫描 2ms/位、按键 5ms/次、业务 500ms/次、蜂鸣 100ms");
    puts("=========================================================");

    for (t = 0; t < 3200; ++t) {
        g_ms = t;

        /* 人为注入按键：1000ms 起抖三下，1004ms 稳住，1040ms 松开；
         * 2000ms 再干净地按一次，看两个任务之间的配合 */
        if (t == 1000 || t == 1002 || t == 1004) {
            g_key_level = 0;
        }
        if (t == 1001 || t == 1003) {
            g_key_level = 1;
        }
        if (t == 1040) {
            g_key_level = 1;
        }
        if (t == 2000) {
            g_key_level = 0;
        }
        if (t == 2030) {
            g_key_level = 1;
        }

        display_task();
        key_task();
        buzzer_task();
        app_task();
    }

    printf("\n3.2 秒过去了：扫了 %u 帧（约 %uHz），计数到 %u，按键认出 %u 次。\n",
           g_frames, (unsigned)(g_frames * 1000u / 3200u), g_count, g_key_events);
    puts("注意：整个过程里没有任何一个 delay —— 四个任务谁也没等谁。");
    return 0;
}

10.3 逐行读输出：四件事同时发生了

把输出按时间顺序读一遍，你会看到四个任务是如何「交错」的：

① 显示在跑，但打印是被抽样的。 t=6ms 扫完第 1 帧，t=398ms 是第 50 帧，t=798ms 是第 100 帧——每 400ms 打一行。实际帧率是 400 帧 / 3.2 秒 = 125Hz，正好等于 1000 / (4 位 × 2ms)。打印是抽样，扫描是连续的，这个区别要分清：板上每一帧都在扫，只是 printf 太慢，不能每帧都打。

② 按键在 t=1005ms 被确认，而不是 t=1000ms。 注入的抖动是 1000 低 → 1001 高 → 1002 低 → 1003 高 → 1004 低（稳住）。状态机每 5ms 采一次：

t=1000  低  -> IDLE 变 DEBOUNCE，计数 1
t=1005  低  -> 连续第 2 次，确认！报事件

那 5ms 的延迟，就是消抖窗口的代价。它换来的是：1001 和 1003 那两次「抖回去」被干净地忽略。如果你希望响应更快，就把采样周期调小、确认次数保持不变——窗口 = 采样周期 × 次数，这是个可以调的旋钮。

③ 蜂鸣器在 1005ms 通电、1105ms 断电。 on_key_press() 只做了一件事：g_beep_until = g_ms + 100。剩下的由 buzzer_task() 每 1ms 看一次表。这里没有任何一方在「等」——蜂鸣器不是因为「时间到了被叫醒」，而是因为「有人一直在看表」。

④ 计数在 t=1000ms 变成 2，按键没有打断它。 t=1000 计数 2，t=1005 按键，t=1500 计数 3——按键夹在中间，但 500ms 的节拍一秒没乱。这就是非阻塞的价值：事件是「插入」的，不是「打断」的。

最后那行总结是最好的证据：

3.2 秒过去了：扫了 400 帧（约 125Hz），计数到 6，按键认出 2 次。

三个数字对得上：400 帧 × 8ms = 3.2 秒；3.2 秒 / 500ms ≈ 6 次计数；两次按键一次带抖、一次干净，各认 1 次。

10.4 这个骨架为什么「能长大」

一个好的骨架，不是「能跑」，而是「加东西不用重写」。这个骨架在这四件事上都不用改结构：

你想加的功能 要改的地方 不用改的地方
多一位数码管 DIGITS 改 5，缓冲加一格 扫描任务、业务任务
换共阳数码管 段码表换成共阳，位选极性取反 数据流、节拍
加一个按键 key_task 里再放一个状态机 扫描、蜂鸣器
加一个 LED 闪烁 新写 led_task()，main 里加一句 其它三个任务
换成真定时器 g_ms = t 改成中断里 ++g_ms 所有任务函数
改成三文件工程 按模块拆（见 §10.5） 逻辑

最后两行是重点。g_ms 的来源是这个骨架里唯一和硬件绑死的东西，其余全部是纯逻辑。下一篇你把它换成定时器中断时，会发现四个任务函数一个字都不用改——那种感觉很像「原来我早就在写操作系统了」。

10.5 从骨架到三文件工程

阶段十的三文件工程是 main.c / led.c / led.h。这个骨架如果拆，建议这样分：

文件 职责 对外接口（只是形状）
seg.h / seg.c 段码表、显示缓冲、扫描任务、消隐 void seg_set_digit(int pos, unsigned char val);、void seg_scan_task(void);
key.h / key.c 按键状态机、事件输出 int key_scan_task(int level);（返回事件码）
beep.h / beep.c 蜂鸣器开关、到期判断 void beep_on(unsigned int ms);、void beep_task(void);
main.c 业务：计数、模式、把事件翻译成动作 int main(void);

依赖方向是单向的：

main.c ──► seg / key / beep        （main 用它们）
seg / key / beep ──► 硬件模拟层     （它们用硬件）
main.c ──✗──► 硬件                  （main 看不见 P0）

main.c 里不该出现 P0、0x3F、~(1u << pos) 这些字眼。 如果你发现自己在 main.c 里写位运算，说明有东西漏到业务层了。

11.3 同一份代码，在真实 Keil 工程里长什么样

PC 上的模拟层，到了 Keil 里要换成真的 SFR。对照如下：

你在 PC 上写的 真实 Keil C51 里对应

/* ===== 真实 Keil C51 写法：本机 GCC 不可编译，仅作对照 =====
 * 只画骨架：display_task() / key_task() / buzzer_task() / app_task()
 * 这四个函数在别的 .c 里（对应 §10.2 的 PC 版），这里省略它们的定义。 */
#include <reg52.h>

sfr  P0 = 0x80;                      /* reg52.h 里已经有，这里写出来只为对照 */
sfr  P2 = 0xA0;
sbit BEEP = P1^5;                    /* 蜂鸣器接 P1.5，经三极管 */

unsigned char code SEG_CC[10] = {    /* code：这张表放 Flash，不占 RAM */
    0x3F, 0x06, 0x5B, 0x4F, 0x66, 0x6D, 0x7D, 0x07, 0x7F, 0x6F
};

unsigned char g_disp[4] = {0, 0, 0, 0};
unsigned int  g_ms = 0;

void timer0_isr(void) interrupt 1    /* 每 1ms 进来一次 */
{
    TH0 = 0xFC;  TL0 = 0x18;         /* 重装初值：12MHz 下约 1ms */
    ++g_ms;                          /* 时间基准：主循环只管读它 */
}

void main(void)
{
    TMOD = 0x01;                     /* 定时器 0，方式 1（16 位） */
    TH0  = 0xFC;  TL0 = 0x18;
    ET0  = 1;  EA = 1;  TR0 = 1;     /* 开中断、启动 */

    while (1) {
        display_task();              /* 每个任务自己判断「到点没」 */
        key_task();
        buzzer_task();
        app_task();
    }
}

注意 while (1) 里没有任何 delay，四个任务被反复调用，各自看表。这个结构和 §10.2 的 PC 版一模一样，唯一的区别是 g_ms 由谁加。

11.5 Keil C51 的 C89 脾气（再提醒一次）

阶段十说过，这里再说一次，因为本篇代码里 for 循环特别多：

  • 变量必须在语句块开头声明。for (int i = 0; ...) 在 Keil 里编译不过，要先 int i;；
  • // 注释可以用，但 long long、变长数组、inline 这些 C99 特性基本没有；
  • 函数不能重名，C51 没有 C++ 的重载；
  • 递归很危险，栈很小；
  • printf 会拖进几 KB 的库，8KB Flash 的芯片经不起。

所以你在 PC 上写 -std=c99 的代码时，心里要留一根弦：能用 C89 写法的地方就用 C89 写法，将来搬去 Keil 会少改很多。

  5. 最后才怀疑芯片。 51 很皮实，坏的概率远低于你的接线和代码。

14. 安全与规范：本阶段三条铁律

铁律一：不烧 IO、不短接电源。

  • 数码管的每一段都要串限流电阻（330Ω~1kΩ，以原理图为准）。不串电阻的数码管，亮度会「特别好」，然后某一晚突然有一段永远不亮了；
  • 蜂鸣器、继电器、电机一律不许直接接 IO，必须经三极管 / ULN2003 / 专用驱动。IO 是信号，不是电源；
  • 接线、拔线、换模块先断电。上电前用眼睛过一遍 VCC 和 GND 有没有被一根线直接连起来；
  • P0 当普通 IO 用必须上拉；共阴数码管用 P0 直驱段选，等于让开漏口去「推高」，推不动的；
  • 动态扫描的峰值电流要算：一位 8 段同时亮，电流是一位静态显示的 8 倍。别为了亮度把电阻短接——那是拿芯片换亮度。

铁律二：业务只改缓冲，扫描只读缓冲。

  • main.c（业务层）里不许出现 P0、P2、0x3F、~(1u << pos)。业务要知道「显示什么」，不需要知道「怎么显示」；
  • 所有显示内容先进 g_disp[]，扫描任务只读它。只有一个地方写端口，出问题时你只需要看那一个函数；
  • 位选、段选、消隐的顺序只在扫描任务里出现一次。别在业务代码里「顺手补一句 P0 = ...」——那句话会在下一次扫描时被覆盖，表现为「闪一下就没」。

铁律三：节拍里不许阻塞。

  • 每个 xxx_task() 里不许有 delay、不许有 while 等待、不许有长循环。任务函数只做「一小步」，做完立刻返回；
  • 状态（pos、next、state、cnt）用 static 局部变量保存；函数返回了，值还在；
  • 时间比较用差值，不用绝对值（unsigned 回绕问题，§6.5）；
  • 中断服务程序里只置标志、改计数，不扫描、不延时、不 printf。中断里待久了，整个节拍全乱（下一篇会反复强调这一条）。

  • 「闪烁」不是「把这一位改成 0 再改回来」——那样你会丢掉原来的数字。正确做法是：数值照旧存在缓冲里，扫描任务在「这一位正好是当前位、且相位是灭」的时候，临时送 0x00 段码。数据与显示再一次分家；
  • 前移/后移要在 0~3 之间环绕，不是到边界就停。环绕用取模，或者用 if (idx == 0) idx = 3; else --idx;；
  • 加/减要明确是「这一位的数字」还是「整个四位数」——题面说的是哪个，就做哪个，别猜。如果是「整个四位数」，还要考虑 9999 之后回 0、0 减 1 变 9999 这类边界；
  • 四个键的事件处理放在同一个 switch 里，一个 case 一个动作。别写四个独立的 if 到处乱窜——那会让你在后面加第五个键时无从下手。

提交前自查清单（任务 4）：

  • 上电后有一位在闪，其余三位稳定显示；
  • 闪烁频率看起来舒服（约 2~5Hz），不刺眼、肉眼看不出跳变；
  • k1 加、k4 减，作用在正确的那一位上；
  • 加到 9 再按、减到 0 再按，行为符合题面（回绕或不变），不会出现 10 或 −1；
  • k2 前移、k3 后移，到两端能环绕，不会卡死或越界；
  • 换位之后，原来那一位的数字还在（没有因为闪烁被清掉）；
  • 闪烁位切换时，显示的数值不跳变（说明数据没被显示逻辑污染）；
  • 四个键都不连击、不串扰（按 k1 不会触发 k2 的动作）；
  • 按键响应及时（按下到画面变化 < 100ms），数码管不闪；

复盘三问：

你现在的状态：

  • 你会在 PC 上模拟一整套人机界面：扫描、按键、蜂鸣、节拍，全部非阻塞；
  • 你能把「同时干四件事」拆成「四张时刻表」，并且知道每张表该多久看一次；
  • 你知道了数码管、按键、蜂鸣器这三样东西的电气脾气：限流、上拉、准双向口、灌电流；
  • 你还欠着一样东西：真正的时间基准。g_ms 现在是 main 里喂出来的，一上板子就没了。

衔接预告（下一篇：定时器中断与串口）：

下一篇会把你欠的东西补上，而且是加倍补：

  • 定时器中断：TMOD / TH0 / TL0 / ET0 / EA / TR0 六个寄存器，把 g_ms 从「main 喂」换成「硬件数」。届时 §10 的四个任务函数一个字都不用改，你只改 g_ms 的来源；
  • 精确的音高：有了 1ms（甚至 50μs）的中断，无源蜂鸣器终于能唱准 262Hz、330Hz、392Hz；PWM 调音量也终于能落地；
  • 串口：SCON / SBUF / 波特率，printf 重定向——你终于能把 printf 搬回单片机，虽然它很贵；
  • 按键的长按与连击：有了稳定的 1ms 节拍，长按 2 秒、连击每 100ms 一次，都是几行代码的事；
  • 51-任务5（10 秒游戏）：那是定时器 + 数码管 + 按键的第一次合体，也是对你这一篇的期末考。

再往远看一层：这一篇你手写的「四个任务 + 一张节拍表」，其实就是调度器的雏形。RTOS 里的任务、优先级、时间片，说白了都是这张表的放大版。等你哪天在 FreeRTOS 里写下 vTaskDelay(2) 的时候，会想起今天这个 if (g_ms < next) return;——它们是同一个东西，只是换了个人替你数数。
