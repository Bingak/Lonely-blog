练习 1 四类错误的典型报错与翻译（MinGW GCC 实测风格）

  1. 少分号：error: expected ';' before 'return'（报错位置指向下一行） 翻译：编译器读到 return 时发现前一句还没结束——往前找一行补分号。属于编译阶段。
  2. main 拼成 mian：undefined reference to 'WinMain'（或 'main'） 翻译：代码全编译通过，但链接器找不到程序入口 main。属于链接阶段—— 这个错误最迷惑，因为看起来"代码都对"。
  3. printf 拼成 print：warning: implicit declaration of function 'print'（常伴随链接错误 undefined reference to 'print'） 翻译：编译器说"没人告诉过我 print 是什么，我先假设你是对的"（警告）， 链接器随后找不到 print 的实现（错误）。两个阶段各报一次。
  4. b 未声明：error: 'b' undeclared (first use in this function) 翻译：这个名字第一次出现，我不认识。属于编译阶段。

练习 2 输入 907 的推演表（标准答案）

轮次 num（轮初） digit ret（轮末） num（轮末）
1 907 7 7 90
2 90 0 70 9
3 9 9 709 0

循环结束。第二个 while 打印：ret%10=9 → 打印 9，ret=70； 再 ret%10=0 → 打印 0，ret=7；再打印 7，ret=0 结束。 屏幕输出：9 0 7（注意末尾带一个空格）。 推演表与实际运行一致才叫通过；不一致就把差异写进错题本。

练习 3 "反转"与"倒序"的区别（标准答案）

输入 120：程序输出 0 2 1。 - 代码做的其实是"数字反转再倒序打印"：120 → 反转成 21（开头的 0 被反转丢了）→ 倒序打印出 0 2 1。 - 若需求是"逐位倒序打印"（120 → 打印 0 2 1），这道题碰巧对； - 若需求是"反转数"（120 的反转是 21，因为 021 不是合法的三位数），这道题也对； - 但若需求是"保留所有位打印 0 2 1 且不经过反转"，直接对原数 while(num>0) printf(num%10) 即可，第一段代码根本不需要。 - 教训：两种需求都成立，但你必须知道自己在写哪一种。这就是"边界+需求意识"，任务五数连续 UPRE 时它还会回来（末尾恰好是 UPRE 的情形）。
