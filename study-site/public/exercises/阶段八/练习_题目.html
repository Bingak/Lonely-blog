阶段八 练习题（多文件工程与考核冲刺）先做后看答案

纪律：先做后看答案；练习 3 是纸上作业，必须做——它是从「一个文件」走向「一个工程」的地图。 本阶段只记一句话：编译器一次只认一个 .c，链接器才把 .o 拼成程序。 全程 gcc -Wall -Wextra -std=c99，警告必须清零；每个 .c 先能单独 -c 通过，再谈链接。

练习 1（基础）原型与声明

写一个程序，4 个函数的定义全部放在 main 之后：

  1. int max3(int a, int b, int c); —— 返回三个数中的最大值；
  2. int is_leap(int year); —— 闰年返回 1，否则返回 0（能被 4 整除且不能被 100 整除，或能被 400 整除）；
  3. int digit_sum(int n); —— 返回非负整数 n 的各位数字之和（如 2026 → 10）；
  4. void print_rule(int width); —— 打印 width 个 - 再换行。

要求：

  • main 之前只写 4 行函数原型，函数体全部写在 main 之后；
  • main 里逐个调用并打印结果（含边界：max3(3, 9, 4)、is_leap(2024)、is_leap(1900)、 digit_sum(0)、print_rule(20)）；
  • 注释里回答：删掉其中一行原型，编译器会报什么？把原文关键词抄下来； 为什么 C99 不允许「用到才声明」？

禁止事项：

  • 禁止把函数定义挪到 main 前面来「绕过」问题（本题练的就是原型）；
  • 禁止改 -std=gnu89 或关掉 -Wall 来掩盖报错。

自检要点：

  • gcc -Wall -Wextra -std=c99 -c 你的文件.c 零错误零警告；
  • 备份后故意删一行原型，亲手复现一次报错，再还原；
  • 能说清「声明可以重复、定义只能一次」。

练习 2（基础）头文件守卫

写三个文件：

  1. mylib.h：头文件守卫、MYLIB_VERSION、宏 MYLIB_MAX(a, b)、 typedef struct { int x; int y; } MyPoint;、extern int mylib_calls;、两个函数原型 （曼哈顿距离 int mylib_manhattan(const MyPoint *p);、打印点 void mylib_print_point(const MyPoint *p);）；
  2. mylib.c：#include "mylib.h"，定义 mylib_calls 与两个函数（每次调用把计数 +1）；
  3. main.c：故意 #include "mylib.h" 两次，调用上面两个函数并打印计数。

要求：

  • 先注释掉守卫的三行，编译一次，把报错原文关键词记下来；再把守卫加回去，确认零警告；
  • 注释里说明：为什么第二次包含时整段内容会被跳过？#include 的本质是什么？
  • 文字回答（写在注释里）：#pragma once 与 #ifndef 守卫各自的优缺点，什么场合选哪个。

禁止事项：

  • 禁止在头文件里写函数体或变量定义；
  • 禁止用 #pragma once 代替守卫来完成本题（可以额外试一下，但主答案必须是守卫）；
  • 禁止把 mylib_calls 定义两次。

自检要点：

  • gcc -E main.c 观察预处理结果，确认 MyPoint 只出现一份；
  • 三个文件都能单独 -c 通过（main.c 用 -I. 找头文件）；
  • 能说清「头文件里放什么、不放什么」。

练习 3（基础 · 纸上作业，必须做）编译链接推演

给定下面这个 3 个 .c + 1 个 .h 的小工程（不用抄代码，读懂即可）：

/* student.h */
#ifndef STUDENT_H
#define STUDENT_H

#define STU_NUM 3

typedef struct {
    char name[16];
    int  score;
} Stu;

int    stu_total(const Stu *list, int n);
double stu_average(const Stu *list, int n);
void   stu_print(const Stu *list, int n);

#endif

/* student.c */
#include "student.h"

int stu_total(const Stu *list, int n)
{
    int i, sum = 0;
    for (i = 0; i < n; i++) sum += list[i].score;
    return sum;
}

double stu_average(const Stu *list, int n)
{
    if (n <= 0) return 0.0;
    return (double)stu_total(list, n) / n;
}

/* util.c */
#include <stdio.h>
#include "student.h"

void stu_print(const Stu *list, int n)
{
    int i;
    for (i = 0; i < n; i++) {
        printf("%-8s %3d\n", list[i].name, list[i].score);
    }
}

/* main.c */
#include <stdio.h>
#include "student.h"

int main(void)
{
    Stu list[STU_NUM] = { {"Alice", 90}, {"Bob", 75}, {"Cara", 88} };
    stu_print(list, STU_NUM);
    printf("总分 = %d，平均分 = %.2f\n",
           stu_total(list, STU_NUM), stu_average(list, STU_NUM));
    return 0;
}

不写代码、先不运行，在纸上回答：

  1. 三个 .c 各自执行 gcc -Wall -Wextra -std=c99 -c 后，产物分别叫什么？这些 .o 里有什么？
  2. 写出把三个 .o 变成 score.exe 的完整链接命令（带 -Wall -Wextra -std=c99）；
  3. 如果 main.c 里把 stu_average 拼成了 stu_averge，会发生什么？ 请分「编译期」和「链接期」两种情况，写出报错原文里的关键词；
  4. 如果 student.h 里声明的是 double stu_average(const Stu *list, int n);， 而 student.c 里定义成 double stu_average(const Stu *list)，会发生什么？ 如果 student.c 忘了 #include "student.h"，又会发生什么？为什么后者更危险？

要求：

  • 四问全部用文字写清「哪个阶段、谁报错、关键词是什么」；
  • 写完再上机逐个验证，把实际报错原文补在旁边；
  • 第 4 问要能解释「签名不一致但链接器不查签名」这件事。

自检要点：

  • 能不看答案说出 .o、.exe、undefined reference、conflicting types 各属于哪个阶段；
  • 能解释链接器为什么只认符号名、不认参数表。

练习 4（提高）无库字符串工具

不许 #include <string.h>，手写下面 5 个函数（全部用指针实现，函数体内禁止 [ ] 下标）：

函数 语义
int my_strlen(const char *s) 返回字符个数，不含 '\0'
int my_strcmp(const char *a, const char *b) 相等返回 0；a > b 返回正数；a < b 返回负数（不要求具体数值）
char *my_strcpy(char *dest, const char *src) 复制含 '\0'，返回 dest 首地址
char *my_strcat(char *dest, const char *src) 追加含 '\0'，返回 dest 首地址
const char *my_strchr(const char *s, char ch) 找到返回指向该字符的指针；找不到返回 NULL；找 '\0' 返回指向结尾的指针

要求：

  • 测试用例必须覆盖：空串、相同串、前缀关系（"app" vs "apple"）、大小写、找不到字符、 拼接到已有内容之后；
  • 每个用例打印「期望值 vs 实际值」，方便肉眼对拍；
  • my_strcpy / my_strcat 的容量由调用者保证，注释里写明这一点（缓冲区给足，禁止故意越界）。

禁止事项：

  • 禁止调用任何 <string.h> 里的函数，也禁止用 sprintf 冒充复制；
  • 禁止故意越界写来「看看会怎样」——真会崩的实验不跑；
  • 禁止写成一行 while (*d++ = *s++) 后不补 '\0' 的紧凑式（本题要求显式补）。

自检要点：

  • gcc -Wall -Wextra -std=c99 零警告；
  • 能默写 my_strlen 与 my_strcpy（考核禁库函数时最常用）；
  • 能口述「目标缓冲区不够长是谁的责任」。

练习 5（提高）多文件拆分

把「学生成绩管理」拆成三个文件：

  • student.h：头文件守卫、STU_MAX、COURSE_NUM、结构体 Student（char name[32]、int id、int scores[3]、double average）、 4 个函数原型（录入、算平均、打印、按平均分排序）；
  • student.c：实现上述函数，第一行 #include "student.h"；
  • main.c：定义 Student list[STU_MAX]，调用录入 → 打印 → 排序 → 再打印。

要求：

  • 录入用 scanf 并检查返回值；人数范围 1 ~ STU_MAX；姓名用 %31s 防止溢出；
  • 平均分 = 三门课平均；排序从高到低（选择排序或冒泡，交换整个结构体）；
  • 三个 .c 分别 -c 零警告，再链接运行，输入 3 个学生验证排序结果。

禁止事项：

  • 禁止在头文件里写函数体或变量定义；
  • 禁止用全局变量传学生数组（要通过参数传）；
  • 禁止用 malloc（阶段九才学）和 qsort（先手写排序）。

自检要点：

  • 只改某个学生的成绩，平均分与排序结果应随之变化；
  • 边界：1 个学生、平均分相同、人数输错；
  • 能画出「main.c → student.h ← student.c」的依赖箭头。

练习 6（提高）Makefile 与增量编译

给练习 5 的工程写一个 Makefile：

  • 变量：CC、CFLAGS（-Wall -Wextra -std=c99）、TARGET（grade.exe）、OBJS；
  • 规则：最终目标依赖两个 .o；每个 .o 依赖自己的 .c 和 student.h；
  • clean 目标 + .PHONY；
  • 命令行缩进必须是 TAB。

要求：

  1. mingw32-make 全量构建成功；mingw32-make clean 后目录只剩源码；
  2. 只改 student.c 里的一个空格，再 mingw32-make，观察输出：只重编哪一个？链接执行了吗？
  3. 解释「只改一个 .c 为什么只重编一个」——用「目标 / 依赖 / 时间戳」三个词回答；
  4. 解释 .PHONY 的作用；如果目录里真的有一个叫 clean 的文件，会发生什么？
  5. 把 CFLAGS 临时改成 -std=c89，观察 // 注释或混合声明报错，再改回来。

禁止事项：

  • 禁止把三条编译命令用 ; 串成一行来「绕过」依赖关系；
  • 禁止用空格缩进命令行；
  • 禁止在 clean 里写 del *.* 这类通配删除（只删自己的 .o 和 .exe）。

自检要点：

  • 能读懂 mingw32-make -n 打印的命令；
  • 能解释 $@、$<、$^ 各代表什么（用到哪个解释哪个）；
  • clean 执行后再 mingw32-make，应能从头完整重建。

练习 7（挑战）函数指针菜单分派

用「函数指针数组 + 菜单」实现一个可扩展的命令分派器：

typedef void (*CommandFn)(void);

typedef struct {
    const char *name;    /* 命令名，如 hello */
    CommandFn   run;     /* 对应的函数 */
    const char *help;    /* 一行说明 */
} Command;

要求：

  1. 命令表里至少 4 条：hello（打招呼）、sum（求 1..n 的和）、upper（小写转大写）、 help（列出所有命令）；quit 在循环里单独判断（不进表）；
  2. 主循环读一整行命令，遍历命令表用 strcmp 找到就调用，找不到提示「未知命令」；
  3. 加一个新命令（例如 pi 打印 3.14159）只允许改命令表 + 新增一个函数，主循环一行不动；
  4. 注释里回答：函数指针数组比 switch 好在哪（至少 3 点）；函数指针的签名为什么必须一致？
  5. 边界：空行忽略、未知命令提示、EOF 正常退出。

禁止事项：

  • 禁止用 if-else 链或 switch 代替查表分派；
  • 禁止把命令的具体实现写进 main；
  • 禁止用全局变量在命令之间传状态（每个命令自己读输入）。

自检要点：

  • gcc -Wall -Wextra -std=c99 零警告；
  • 亲手加一次 pi 命令，确认只动了「表 + 一个函数」；
  • 能说清 void (*f)(void) 与 void *f(void) 的区别（这是面试常问）。

验收提醒

  • 练习 3、6 是工程能力题，考核提交前必须会；练习 3 的四个阶段判断错一个，后面调试就靠猜；
  • 练习 4 是考核「禁用库函数」的直系积木，my_strlen / my_strcpy 要练到能默写；
  • 练习 5 的三文件结构就是考核建议的提交结构（main.c + 模块 .c/.h），提前按这个结构写；
  • 本阶段不提供登录 / 密码 / 用户管理系统的任何代码——那部分必须自己设计， 抄现成答案一律按「不会」处理；
  • 全部完成后，用 -Wall -Wextra 把整个工程重编一遍，警告清零再提交 Gitee。
