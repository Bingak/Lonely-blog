阶段十 练习题（51 单片机 C 语言预备）先做后看答案

纪律：先做后看答案；练习 3 是纸上作业，禁止跳过——位运算、段码、读原理图是进实验室的三块敲门砖。 本阶段全部练习都在 PC 上做：用 volatile unsigned char 模拟 P1，用逐位打印「看灯」，不需要 Keil、不需要烧录。 全程编译加 -Wall -Wextra -std=c99，警告必须清零。 统一约定：LED 阳极经 470Ω 接 +5V、阴极接 P1.n（低电平点亮），所以 0 = 亮、1 = 灭。 打印统一用 print_bits8(const char *name, unsigned char v)，输出形如 P1 = 0xFE 二进制 11111110 LED[0..7]=亮灭灭灭灭灭灭灭。

练习 1（基础）位运算点灯

初始 P1 = 0xFF（8 个灯全灭）。只用 &= ~、|=、^= 三种写法完成：

  1. 只点亮第 3 个灯：P1 &= ~(1u << 3);，操作前后各打印一次；
  2. 全部熄灭后再点亮第 0、7 个：先让 8 位全回到 1（可以写 P1 = 0xFF;，也可以写 P1 |= 0xFF;）， 再分两次 P1 &= ~(1u << 0);、P1 &= ~(1u << 7);，每步都打印 （第 0 步后应只剩 LED0 亮，第 7 步后 LED0、LED7 都亮）；
  3. 奇偶交替闪烁：让「偶数号灯亮」与「奇数号灯亮」交替 4 轮， 要求用 P1 ^= 0xFF; 实现整体翻转（提示：先算出偶数号亮时的那个字节，之后每翻一次就换一种）。

要求： - 不许写 P1 = 0xF7; 这种「直接抄结果」的赋值（第 2 问里把 8 位全置回的 P1 = 0xFF 除外）； - 每一步都打印 P1 的十六进制、二进制、8 个灯的亮灭； - 注释里写清楚：为什么「点亮」是清 0 而不是置 1； - 注释里再回答：^= 写「闪烁」比 = 好在哪？

练习 2（基础）段码表查表

数码管段码位序：P0.7=dp P0.6=g P0.5=f P0.4=e P0.3=d P0.2=c P0.1=b P0.0=a。

  1. 写出共阴段码表 SEG_CC[16]（下标 0~9 对应数字，10~15 对应 A~F）；
  2. 写 unsigned char seg_code(int n, int common_anode)： - n 越界（小于 0 或大于 15）返回 0xFF 当错误标记； - common_anode 非 0 时返回共阳码（= 共阴码按位取反，只在 8 位内取反）；
  3. main 里把 0~9 全部打印出来（数字、共阴码、二进制、点亮了哪几段）， 并且先在纸上把 0~9 的段码手推一遍，再跟程序输出逐行核对，对不上就找原因；
  4. 加自检（两项都要打印通过与否）： - 对 0~15 每个 n，验证 seg_code(n, 1) == (unsigned char)~seg_code(n, 0)； - 对 0~9 每个 n，验证 seg_code(n, 0) 等于你自己另写一份的「手算表」；
  5. 思考（注释里回答）：为什么共阳码不是「共阴码 + 1」，也不是「共阴码取反再加 1」？

练习 3（基础 · 纸上作业，必须做）位运算推演 + 段码推导 + 读原理图

A 部分 位运算推演（不写代码、不运行，纯手推）

初始 P1 = 0xFF，依次执行下面 5 行：

P1 &= ~(1u << 2);
P1 |=  (1u << 5);
P1 ^=  (1u << 0);
P1 &= ~((1u << 4) | (1u << 6));
P1 ^=  0x0F;

要求列一张表，每行写：这一步做了什么 → 十六进制值 → 二进制 → 低电平点亮接法下哪几个灯亮。 最后回答：最终值是多少？亮的是哪几号灯？（提示：前两步里其实有一步是「空操作」，想想是哪步、为什么。）

B 部分 段码推导（不许查表，从 a~g 布局自己推）

段码位序同上，共阴（1 = 亮）。

  1. 数字 8 要点亮哪几段？逐位填出 bit7~bit0，写出十六进制；
  2. 数字 3 要点亮哪几段？逐位填出 bit7~bit0，写出十六进制；
  3. 把这两个值的共阳码也写出来（按位取反，8 位内）；
  4. 补充：数字 1 的共阴码是多少？为什么它只有两位是 1？

C 部分 读原理图

某块板子的 LED 接法描述如下：

8 个 LED 的阳极各自串一只 470Ω 电阻，全部接到 +5V；8 个阴极分别接到 P1.0 ~ P1.7。引脚输出低电平时，电流从 +5V 经电阻、LED 流入引脚，灯亮。

回答： 1. 当 P1 = 0xFE 时，哪几个灯亮？为什么？ 2. 如果把 LED 全部反接（阴极接地、阳极经电阻接 P1），P1 = 0xFE 时又是哪几个灯亮？ 3. 一句话说明：为什么「P1 等于某个值，就一定是某几个灯亮」这句话不严谨？ 4. 再补一句：如果原理图上还串了三极管/驱动芯片（比如 ULN2003），结论会多出哪一层依赖？

练习 4（提高）按键消抖状态机

按键一端接 P3.2、一端接 GND，P3.2 内部上拉：松开读到 1，按下读到 0。 机械按键按下/松开的瞬间触点会弹跳 5~20ms，采样会读到一串乱跳的 0/1。

  1. 造一段模拟采样序列（至少 40 个 tick），要求包含：一段空闲、一次「带抖动的按下」、 一段稳定按下、一次「带抖动的松开」、再一段空闲、第二次「短抖动按下」； 用固定数组最简单，也可以用固定种子的线性同余随机数 （seed = seed * 1103515245u + 12345u; 再取高位当 0/1）， 但必须每次运行结果一样，否则没法核对输出；
  2. 写消抖状态机：连续 N = 3 个 tick 采样一致，才承认状态真的变了； 状态只有两个：松开 / 按下；
  3. 每处理一个 tick，打印：tick 号、本次采样、连续计数、当前状态 （可以只打印「采样变化」和「状态转移」的行，别刷屏）；
  4. 每次状态转移单独打印一行，形如 >>> tick 16：松开 → 按下（连续 3 次采到 0，确认按下）；
  5. 统计并对比：消抖后数出几次「按下」？如果直接用裸采样数下降沿（1→0），又会数出几次？ 在注释里回答：为什么差这么多？

练习 5（提高）流水灯状态机

用「步进函数 + 时间片」实现 8 灯流水灯的 4 种模式：

  1. 左移（LED0→LED7，到头绕回）；
  2. 右移（LED7→LED0）；
  3. 往返（0→7 再 7→0，撞到边界掉头）；
  4. 呼吸近似（没有 PWM，就用「点亮的灯数 0→7→0」近似亮度变化）。

要求： 1. 状态全部装在一个结构体里（当前模式、亮灯位置、方向、时间片计数…）， void water_step(water_t *w); 每调一次只推进一步，函数里不许有 delay / sleep / 长循环； 2. 主循环每片调用一次 water_step，并打印 [tick n|模式|本模式第 k 步] + 8 位 LED 状态； 3. 每 10 片自动切一个模式（真机上换成按键切换），切换时打印一行事件； 4. 注释里回答： - 为什么这种写法能「一边流水一边响应按键」，而 P1 = ...; delay(200); 不行？ - 真机上这个「时间片」由谁提供？ - 呼吸模式真机上该怎么做（提示：PWM 占空比，而不是点亮个数）？

练习 6（提高）三文件工程拆分

把练习 5 的流水灯拆成 led.h / led.c / main.c：

  1. led.h：头文件守卫 + 对外接口，至少包含 led_init / led_mode_set / led_step / led_read / led_write / led_print / led_mode_name；
  2. led.c：实现，内含模拟寄存器 static volatile unsigned char P1_SIM;， 并用 #define 起个和真机一致的名字； 模块内部状态（当前模式、位置、方向）必须藏在 led.c 的 static 变量里，头文件里不暴露；
  3. main.c：#include "led.h"，4 种模式各跑 8 步并打印；
  4. Makefile：CC / CFLAGS = -Wall -Wextra -std=c99 / 目标 / .PHONY clean， 命令行缩进必须用 TAB；
  5. 验收（三条都要过）： - 每个 .c 能单独编译：gcc -Wall -Wextra -std=c99 -I. -c led.c； - 链接跑通：gcc -Wall -Wextra -std=c99 main.c led.c -o led_demo.exe； - mingw32-make 能构建、mingw32-make clean 能清理。

练习 7（挑战）数码管动态扫描 + 秒表

模拟 2 位数码管的动态扫描，做一个 0.0 ~ 9.9 秒的秒表。

硬件模型： - 段码口 P0（共阴，1 = 段亮），段码表自己写； - 位选口 P2：P2.0 = 0 选中第 1 位（秒位），P2.1 = 0 选中第 2 位（十分位），其余位保持 1； - 第 1 位要带小数点（dp = bit7 置 1），整体显示成 0.0 的样子。

时间模型： - 每一位点亮 5ms，一帧 = 两位 = 10ms（刷新率 100Hz）； - 10 帧 = 100ms = 0.1 秒。

要求： 1. unsigned char seg_code(int n)（共阴版）+ void scan_frame(int tenth, int frame_no)： 一帧里先送第 1 位的位选和段码，再送第 2 位的位选和段码； 2. 每帧打印一行：帧号、秒表读数、两个位选值、两个段码值； 3. 用 tick 推进到 9.9 秒然后回绕到 0.0。 （说明：完整 0.0~9.9 要 1000 帧，全打印会刷屏，所以只详细打印前 0.2 秒， 中间快进，最后打印 9.9 的那一帧和回绕帧——逻辑仍要跑完整圈。） 4. 注释里回答： - 为什么两位不能同时点亮（同时送两个不同的段码会怎样）？ - 为什么人眼看到的是稳定的 9.9 而不是乱跳的两半？ - 帧率多少才不闪？如果把一帧拖到 200ms，会看到什么？ 5. 加分：把「每 10 帧加 0.1 秒」的除法写清楚（为什么是 10 不是 100）， 并说明真机上该用定时器中断还是主循环数帧。
