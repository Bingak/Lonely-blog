阶段十 参考答案（练习 3 · 纸上作业）参考答案

先自己做，再对答案。三部分必须全过一遍：位运算推演、段码推导、读原理图。 全程约定：低电平点亮（LED 阳极接 +5V、阴极接引脚）→ 0 = 亮、1 = 灭。

A 部分 位运算推演（初始 P1 = 0xFF）

逐步推演表

步骤 操作 8 位掩码 运算 P1 结果（二进制） P1 亮的灯（0 = 亮）
0 初始 — — 1111 1111 0xFF 无（全灭）
1 P1 &= ~(1u << 2); ~(0000 0100) = 1111 1011 1111 1111 & 1111 1011 1111 1011 0xFB LED2
2 P1 |= (1u << 5); 0010 0000 1111 1011 | 0010 0000 1111 1011 0xFB LED2（空操作）
3 P1 ^= (1u << 0); 0000 0001 1111 1011 ^ 0000 0001 1111 1010 0xFA LED0、LED2
4 P1 &= ~((1u << 4) \| (1u << 6)); ~(0101 0000) = 1010 1111 1111 1010 & 1010 1111 1010 1010 0xAA LED0、2、4、6
5 P1 ^= 0x0F; 0000 1111 1010 1010 ^ 0000 1111 1010 0101 0xA5 LED1、3、4、6

逐步说明

  • 第 1 步：~(1u << 2) 在 32 位里是 0xFFFFFFFB，但和 8 位值相与之后只看低 8 位， 所以心算时直接写 1111 1011。清 bit2 → LED2 亮（低电平点亮）。
  • 第 2 步：0xFB 的 bit5 本来就是 1（1111 1011），再置一次什么也没改变。 这一步是空操作——|= 只保证「这一位是 1」，不负责让它变 0，所以不会「灭掉」任何灯。 新手常以为「又点亮一次」会切换状态，那是 ^= 的行为。
  • 第 3 步：^= 才翻转。bit0 由 1 变 0 → LED0 亮。
  • 第 4 步：先把两个掩码或起来 0101 0000（bit4 和 bit6），取反得 1010 1111， 与运算一次清掉两位。0xFA 的 bit4、bit6 都是 1，清完后是 1010 1010。
  • 第 5 步：^= 0x0F 只翻低 4 位：1010 ^ 1111 = 0101，高 4 位 1010 不动 → 1010 0101。

答案

  • 最终 P1 = 0xA5 = 1010 0101（二进制），十进制 165。
  • 低电平点亮接法下，值为 0 的位是 bit1、bit3、bit4、bit6 → 亮的是 LED1、LED3、LED4、LED6，共 4 个。
  • 若换成共阴（高电平点亮）接法，同一个 0xA5 亮的就是 LED0、LED2、LED5、LED7—— 十六进制值不变，亮的灯正好反过来。

B 部分 段码推导（共阴，1 = 亮）

位序固定：bit7 = dp，bit6 = g，bit5 = f，bit4 = e，bit3 = d，bit2 = c，bit1 = b，bit0 = a。

数字 8

要点亮 a、b、c、d、e、f、g 全部七段，dp 不亮：

段 dp g f e d c b a
亮灭 0 1 1 1 1 1 1 1
  • 二进制：0111 1111
  • 十六进制：0x7F
  • 共阳码（取反）：1000 0000 = 0x80（注意共阳下 0x80 才是「只有 dp 不亮」的 8）

数字 3

要点亮 a、b、c、d、g 五段，e、f 不亮：

段 dp g f e d c b a
亮灭 0 1 0 0 1 1 1 1
  • 二进制：0100 1111
  • 十六进制：0x4F
  • 共阳码（取反）：1011 0000 = 0xB0

补充：数字 1

只要 b、c 两段亮：

段 dp g f e d c b a
亮灭 0 0 0 0 0 1 1 0
  • 二进制：0000 0110 = 0x06；共阳码 1111 1001 = 0xF9。
  • 为什么只有两位是 1：数码管是「日」字布局，数字 1 就是右边那一竖，只有 b（右上）和 c（右下）两段。

自查口诀

把「要亮的段」写成 1，按 dp g f e d c b a 从高到低排好，四位一组转十六进制。 转完再取反就是共阳码；0x7F（8）、0x3F（0）、0x06（1）这三个最该背下来当锚点。

C 部分 读原理图

题面接法：8 个 LED 阳极各串 470Ω 到 +5V，阴极接 P1.0~P1.7，引脚低电平才有电流。这是「共阳（灌电流）」接法。

1. P1 = 0xFE 时哪几个灯亮？

0xFE = 1111 1110，逐位看：

引脚 P1.7 P1.6 P1.5 P1.4 P1.3 P1.2 P1.1 P1.0
电平 1 1 1 1 1 1 1 0
LED 灭 灭 灭 灭 灭 灭 灭 亮
  • P1.0 = 0（低电平）→ 电流从 +5V 经电阻、LED0 流入 P1.0，LED0 亮；
  • P1.1~P1.7 = 1（高电平）→ LED 两端都是约 5V，没有压差，没有电流，其余 7 个全灭。

结论：只亮 LED0 一个。

2. 若全部反接（阴极接地、阳极经电阻接 P1）

这时变成「共阴（拉电流）」接法，高电平才亮：

  • P1.0 = 0 → LED0 两端都是 0V，不亮；
  • P1.1~P1.7 = 1 → 7 个 LED 都亮。

结论：同一个 0xFE，反接后变成 LED0 灭、LED1~LED7 亮，共 7 个。

3. 为什么「P1 = 某个值 → 一定是某几个灯亮」不严谨？

因为「电平 → 亮灭」的映射是硬件接法决定的，软件只给出电平：

  • 共阳（阳极接 VCC）：0 亮；
  • 共阴（阴极接 GND）：1 亮；
  • 中间若还有三极管 / ULN2003 / 74HC245 这类驱动，还可能再反相一次或加使能端。

同一个 0xFE，在不同板子上可能是「亮 1 个」，也可能是「亮 7 个」。所以写点灯代码前， 先确认原理图：LED 公共端接哪、限流电阻在哪、有没有驱动芯片、位选是高有效还是低有效。

4. 若中间串了 ULN2003（达林顿反相驱动）

ULN2003 是反相的：输入高 → 输出低（把负载拉低导通）。 于是链路变成「单片机输出 1 → 驱动输出 0 → 若 LED 接成共阳则亮」， 等于在原来的结论上再翻一次。这时候「P1 = 0xFE 亮几个」就要按 「单片机 → 驱动 → LED」三级重新推一遍，不能只看单片机这一端。

常见错误（自查）

  • ❌ 把第 2 步当成「又点亮一次」——|= 不翻转、不清零，它只保证那一位是 1；
  • ❌ ~(1u << 4) 只写 4 位取反（写成 1011）——取反是对整个类型翻的，和 8 位值相与时才截成 8 位；
  • ❌ 段码位序记反（把 a 放 bit7）——那样 0 会算成 0xFC，整张表全错；
  • ❌ 数 1 的个数当亮灯数——低电平点亮时亮的个数 = 0 的个数：0xFE 只亮 1 个，不是 7 个；
  • ❌ 忘了共阳码还要在 8 位内取反（写成 ~0x7F = 0xFFFFFF80，忘了截断成 0x80）。
