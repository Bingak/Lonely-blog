51 实战三 练习题（DS1302 / LCD1602 / AD / DS18B20 / 综合架构）先做后看答案

纪律：先做后看答案；练习 3 是纸上作业，必须动笔——命令字节、LCD 指令、AD 换算、一线时序是这一阶段的四块地基。 全部练习都在 PC 上做：用数组/结构体模拟芯片，用 printf 打印总线电平与屏上内容，不需要 Keil、不需要烧录。 全程编译加 -Wall -Wextra -std=c99，警告必须清零；每个 .c 都要能单独编译运行。 统一约定：DS1302 三线为 RST/SCLK/IO，时间寄存器 BCD；LCD1602 为 8 位并口、2×16； AD 满量程码 = 2^n − 1；DS18B20 为 12 位、LSB = 0.0625℃。 打印里不要出现英文双引号，中文引号统一用「」。

练习 1（基础）BCD 与时间读写

DS1302 的时间寄存器是 BCD 码，命令字节格式：bit7=1 | bit6 选 CLK(0)/RAM(1) | bit5~1 地址 | bit0 读写。 秒、分、时、日、月、星期、年的地址分别是 0~6，写保护寄存器地址是 7。

  1. 写 unsigned char bcd2dec(unsigned char b) 和 unsigned char dec2bcd(unsigned char d)， 用 0x59→59、0x23→23、23→0x23、0x99→99 四组值验证，四行打印都要有；
  2. 写 unsigned char ds1302_cmd(int addr, int is_ram, int is_read)， 打印「写秒 0x80」「读秒 0x81」「写分 0x82」「读时 0x85」四个命令字节 + 二进制；
  3. 用 unsigned char reg[8] 模拟寄存器堆，写保护位放在 reg[7] 的 bit7。 先写时间 2026-03-08 星期日 09:05:57（年 26、月 03、日 08、星期 7），全部用 BCD 写；
  4. 写 rtc_write(addr, val) / rtc_read(addr)：写保护 bit7=1 时拒绝写 0~6 号寄存器， 但允许写 7 号（写保护寄存器自己）。演示一次「锁定 → 写秒失败 → 解锁 → 写秒成功」；
  5. 写 rtc_tick() 走 1 秒，连续调用 4 次，每次打印完整时间； 要求看到 09:05:59 → 09:06:00 → 09:06:01，秒、分都按 60 进制进位；
  6. 注释里回答：为什么 BCD 不能直接 +1？举一个直接加会出错的例子。

练习 2（基础）LCD1602 初始化与定位

LCD1602 的 DDRAM 可见地址：第一行 0x00~0x0F，第二行 0x40~0x4F。 写指令时 RS=0，写数据时 RS=1，两者都在 E 的下降沿被芯片取走。

  1. 用 32 字节数组模拟显存，实现 lcd_write_cmd() / lcd_write_data()， 每条指令打印「十六进制 + 二进制 + 一句人话解释」（至少解释 0x38、0x0C、0x06、0x01）；
  2. 写完整初始化 lcd_init()：0x38 → 0x38 → 0x0C → 0x06 → 0x01， 并在注释和输出里写清每步延时：上电 15ms、第一条 0x38 后 4.1ms、普通指令 37us、清屏 1.52ms；
  3. 写 lcd_set_cursor(row, col)：把「第几行第几列」换算成 DDRAM 地址，再发 0x80|addr； 打印这四组换算：(0,0)→0x00、(0,15)→0x0F、(1,0)→0x40、(1,15)→0x4F；
  4. 越界保护：col=16 或 row=2 必须拒绝并打印原因，不能写到数组外面；
  5. 写两行，每行必须正好 16 字符（少了会残留旧字符，多了会串到下一行）： 第一行 UPRE 51 LAB（后面补空格补到 16），第二行 2026-03-08 09:05；
  6. 最后按 2×16 打印屏幕，带 +、-、| 边框；再用一行打印光标停在哪个地址；
  7. 注释里回答：为什么定位第二行是 0x40 而不是 0x10？

B 部分 LCD1602 指令序列

LCD 指令：0x38 功能设置、0x0C 显示开关、0x06 输入模式、0x01 清屏、0x80|addr 设地址。 写出下面每一步的二进制，并说明每一位的含义：

  1. 0x38（DL、N、F 分别是哪一位？）；
  2. 0x0C（D、C、B 分别是哪一位？）；
  3. 0x06（I/D、S 分别是哪一位？写入后地址加还是减？）；
  4. 0x01（清屏后光标在哪？要等多久？）；
  5. 定位第一行第 10 列、第二行第 1 列，各发什么指令？
  6. 如果先发 0x80|0x0F 再连写 3 个字符，三个字符分别落在哪个地址？

D 部分 一线总线时序

DS18B20 的 1-Wire 时序（单位 us）：

  1. 复位脉冲：主机拉低至少多少 us？释放后等多久？器件回的存在脉冲是低电平还是高电平？持续多久？
  2. 写 0：主机拉低多久？写 1：主机拉低多久后释放？每一位的总时隙是多少 us？
  3. 读时隙：主机先拉低多久，然后在什么时刻采样？为什么读的时候主机必须先释放总线？
  4. 画出（文字描述即可）一条命令 0xCC 的 8 个 bit 的发送顺序（低位先出）；
  5. 三个关键命令 0xCC、0x44、0xBE 的作用各是什么？0x44 之后为什么要等 750ms？

练习 4（提高）AD 电压换算与滤波

条件：Vref = 3.300V，12 位 AD，满量程码 4095。

  1. 打印换算表（至少 6 行）：code 取 0、1、1024、2048、3072、4095，输出码值与电压；
  2. 量化误差：模拟电压 1.2345V，算出理想码、取整码、读回电压、误差（mV）， 再对 8 位和 10 位各做一次，三行对比；
  3. 给一组 12 位采样（目标约 0.82V，含一个尖峰）： 1024 1020 1030 1600 1018 1022 1026 1015 1021 1024 分别算：直接均值、整组中值、滑动中值（窗 5，打印 6 个结果）；
  4. 把均值、中值都换算成电压，打印「均值比中值高多少 mV」；
  5. 注释里回答： - 为什么分母是 2^n − 1 而不是 2^n？ - 尖峰为什么对中值几乎没影响，却能把均值拉偏？ - 如果噪声是持续的高频抖动而不是偶发尖峰，应该选哪个？为什么？

练习 5（提高）温度换算与负温

DS18B20 12 位温度：16 位补码，temp = raw × 0.0625，低 4 位是小数。

  1. 写 double raw_to_temp(unsigned raw)：最高位为 1 时按补码减 65536，再乘 0.0625；
  2. 对下面 6 个 raw 值逐个打印「十六进制、十进制（有符号）、二进制、温度」： 0x0190、0x0001、0xFFF8、0xFE6F、0x0550、0x07D0；
  3. 其中必须能正确解释： - 0x0190 = +25.0℃； - 0xFFF8 = −0.5℃（负的小数）； - 0x0550 = +85.0℃（上电默认值，说明它意味着什么）； - 0x07D0 = +125℃（12 位量程上限附近）；
  4. 写 temp_to_raw(double temp) 做反向换算（四舍五入到 1/16℃）， 对 25.0、−10.125、85.0 三个温度验证「换算回去再解出来」等于原值；
  5. 打印「1 LSB = 0.0625℃」的台阶表：raw = 0、1、2、3、15、16 对应的温度；
  6. 注释里回答：为什么负温度不能直接用 raw * 0.0625？0xFFF8 直接乘会得到什么？

练习 6（提高）显示模式切换状态机

做一个「三页显示」的界面骨架（不是实验室任务，不涉及密码/闹钟/整屏移动）：

  • 三个页面：PAGE_CLOCK（时钟）、PAGE_DATE（日期）、PAGE_TEMP（温度）；
  • 事件：EV_KEY_NEXT（按键，切到下一页）、EV_TIMEOUT（4 个 tick 没有按键，自动回时钟页）；
  • 每 500ms 一个 tick，主循环只调用 app_step(&app, ev)，函数里不许 delay。

要求：

  1. 状态全部装在结构体里：当前页、停留 tick 数、按键次数、总 tick；
  2. app_step() 只做「事件 → 状态迁移」，返回是否发生了迁移；
  3. ui_render() 按当前页打印一行内容（时钟页印时间、日期页印日期、温度页印温度）， 数据用桩函数返回固定值；
  4. 迁移时打印轨迹，形如 >>> tick 3：CLOCK --按键--> DATE（停留 0 tick）；
  5. 演示序列：tick 1~12，在 tick 3、tick 5 各来一次按键，之后不再按键， 观察「CLOCK→DATE→TEMP→超时回 CLOCK」的完整过程；
  6. 注释里回答： - 为什么「当前页」不能用一个全局 int page 加一堆 if 散在 main 里？ - 超时回时钟页这个规则，放在 app_step 里和放在 ui_render 里有什么区别？ - 真机上按键抖动要怎么处理？这一题为什么不处理？

练习 7（挑战）综合项目架构设计

为「51 综合项目」设计一套可扩展的架构骨架，只交架构，不写业务。 交付物（.c 一个 + 说明文字）：

  1. 模块划分表：至少 6 个模块（串口、时钟、显示、传感器、按键/输入、应用状态机）， 每个模块写：职责、对外接口、依赖谁、被谁依赖；
  2. 接口清单：每个模块 2~4 个函数，写清参数、返回值、失败时返回什么； 接口里不允许出现具体业务名词（密码、闹钟、菜单项名称都不行）；
  3. 状态机转换表：状态 × 事件 → 下一状态，至少包含 BOOT / MENU / SUBMENU / ERROR； 非法迁移要写明「保持原状态」；
  4. 命令分派表：命令字符串 → 事件 → 处理函数，加命令只改表；
  5. 写一个可运行骨架： - 用函数指针表注册模块（每个模块有 init / poll 两个钩子）； - 主循环只做「轮询输入 → 分派 → 迁移 → 渲染」； - 跑 8~10 条命令，打印状态迁移轨迹；
  6. 边界声明（必须写进注释和输出）：本骨架不实现密码验证、不实现闹钟、不实现整屏移动， 这些属于具体任务，等架构验收通过后再往桩里填；
  7. 注释里回答：如果明天要加一个「设置」页，需要改哪几个文件/哪几行？为什么架构要保证「只改表」。

验收提醒

  • 练习 3 是纸上作业，必须做：命令字节、LCD 指令、AD 表、1-Wire 时序，四张表都要能默写；
  • 练习 1、2 是「协议看得见」的基本功：BCD 进位和 LCD 地址换算错一次，后面所有显示都是乱的；
  • 练习 4、5 是「把物理量算对」：分母 2^n−1、补码、0.0625 这三个坑必须踩平；
  • 练习 6 是状态机从「点灯」升级到「界面」的一步，重点在迁移表而不是页面内容；
  • 练习 7 只交架构，不交业务——先证明你的架子能装东西，再往里装东西；
  • 全部完成后对照教程的阶段验收清单，把错题记进错题本。
