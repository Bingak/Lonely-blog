练习 1 修 7_循环_正序分解.c（排雷）

两处 bug 的确切位置

编号 原代码 症状 修法
P1 int ret; 后面直接 ret = ret * 10 + digit; 结果是随机垃圾值（栈上残留），有时看着「对的」纯属运气 int ret = 0; 出生即初始化
P2 while (num > 10) 输入 23 只输出 3，十位 2 丢了 while (num >= 10)，循环退出后再补一轮 ret = ret * 10 + num;

为什么 P2 是「边界差一个等号」

while (num > 10) 在 num == 10 时就退出，此时 num 还剩一个有效的十进制位没被处理。改成 >= 后，num 降到 0~9 才退出，最后一位靠循环外那一行并入。

用 5、23、100、12345 四组数据自查——0~9 的单数字是这条逻辑最容易崩的输入：

输入 5  : num=5, 不进循环, ret = 0*10+5 = 5      → 打印 5
输入 23 : 23>=10 → ret=3,num=2 ; 2>=10 不成立 → ret = 3*10+2 = 32 → 打印 2 3
输入 100: 100>=10 → ret=0,num=10 ; 10>=10 → ret=0,num=1 ; 退出 → ret=1 → 打印 1
输入 12345 → 54321 → 打印 1 2 3 4 5

输入 100 时注意：ret 在中间两次迭代里都乘到了 0，最终靠循环外那行才拿到 1。这就是「末尾补一轮」不可省的原因。

本题要带走的习惯

  • 变量声明处就给它一个有意义的值，别指望编译器、也别指望「刚好是 0」；
  • 循环边界写完后，立刻用「最小、刚好在边界上、最大」三个值各跑一次，别等交作业才发现。

练习 2 圆的周长与面积（%lf 与 %f 的不对称）

核心知识点

场景 占位符 记住它的方式
scanf 读 double %lf l 是「long」的提醒：告诉 scanf 要往 8 字节里写
printf 打印 double %f printf 里 %f 本来就指 double，加 l 反而多余（%lf 在 C99 里也能用，但没必要）

为什么 scanf 必须区分？ scanf 拿到的是地址，它必须知道该往这块内存写几个字节。%f 会按 float（4 字节）写，而你的 double 变量有 8 字节——写进去的只是低 4 字节，高 4 字节是垃圾，读出来就是一个天文数字或 0。

实现要点

周长 = 2 * PI * r
面积 = PI * r * r      ← 写成 r*r，不要写 pow(r,2)

PI 用 #define PI 3.14159265358979 或 const double PI = ...，别在公式里手打 3.14——保留 4 位小数时误差会露出来。

负数半径的两种处理

  1. 提前拦截：if (r < 0) { printf("半径不能为负\n"); return 1; } ——本题要求这种；
  2. 让它算：面积会变成正的（负数平方），周长变负——物理上荒谬，但程序不报错。这正是「输入校验」存在的理由。

顺带记：r == 0 是合法输入（退化成一个点），不要顺手把它也拦掉。

练习 3 推演猜数修正版（纸上作业标准答案）

题面：number = 38，依次输入 50、25、30、38。

轮次 输入 guess 比较 打印内容 count
1 50 50 > 38 猜大了 1
2 25 25 < 38 猜小了 2
3 30 30 < 38 猜小了 3
4 38 相等 猜对了，共猜 4 次 4

推演时最容易漏的三件事

  1. count 的初值与自增位置：若写 count++ 在比较之后、打印之前，打印的「共猜 N 次」就会比实际多 1。标准写法是进入循环立刻 count++。
  2. 相等的那一轮也要计数：38 是第 4 次猜，不是第 3 次。
  3. while (guess != number) 与 for (;;) 的区别：前者在猜中时循环体不执行，若把「猜对了」的打印放在循环体内，就会漏掉最后一句——正确做法是循环内只处理「大了/小了」，循环外统一打印「猜对了」。

推演表的价值不在答案，在于让你在没运行程序前就能预言输出。能预言，才说明你真的懂这段控制流。

练习 4 个税计算器（边界连续性是唯一的考点）

三档结构

收入 x              税额
0 <= x <= 3000      0
3000 < x <= 12000   (x - 3000) * 3%
x > 12000           (x - 12000) * 10% + 270

270 从哪来？上一档满额时的税：(12000 - 3000) * 3% = 270。它必须被加上，否则 12000.01 的收入会算出比 12000 更少的税——这叫「税档断裂」。

三个边界点的期望值

收入 税额 说明
2999.99 0.00 第一档
3000.00 0.00 边界归第一档（用 <=）
3000.01 ≈ 0.00 0.01 * 3% = 0.0003，保留 2 位后仍是 0.00
12000.00 270.00 第二档满额
12000.01 270.00 0.01 * 10% = 0.001，四舍五入后 270.00

常见错误

  • ❌ 写成 if (x > 3000 && x <= 12000) 然后 else if (x > 12000)，第一档却写成 if (x < 3000)——3000 这个点两边都不接，落进 else 变成 0 或垃圾；
  • ❌ 第三档忘了 + 270；
  • ❌ 用 int 存收入——2999.99 会被截成 2999，边界直接失真。

分层写法（推荐）

if (x <= 3000)          tax = 0;
else if (x <= 12000)    tax = (x - 3000) * 0.03;
else                    tax = (x - 12000) * 0.10 + 270;

只判上界、不判下界——因为 else-if 的链条已经保证了「上面都不成立，所以一定大于 3000」。这样写不会有缝隙，也不会有重叠。

练习 5 水仙花去 pow 化（P3 修正）

原版为什么会漏判

pow(153 % 10, 3) 这类调用返回 double。double 的 125.0 存得很准，但 27 * 1.0 之类的累加在某些实现下会出现 152.9999999——再和 153 比就不相等，于是漏掉。这不是你的错，是浮点数的固有特性。

不用 pow 的写法：循环累乘

int ipow(int base, int n) {
    int r = 1;
    for (int i = 0; i < n; i++) r *= base;
    return r;
}

纯整数运算，结果精确，永不出现 152.9999999。

验证清单

n=3 时必须且只能找出 153、370、371、407 四个。

153: 1+125+27 = 153 ✔
370: 27+343+0 = 370 ✔
371: 27+343+1 = 371 ✔
407: 64+0+343 = 407 ✔

若你的程序只输出 3 个，先看是不是漏了 407（4^3 + 0^3 + 7^3），再检查是不是用了 pow。

本题真正的收获：能不用浮点就不用浮点。「整数问题用整数解」是最省心的排错策略。

练习 6 单位换算菜单（do-while + switch 的骨架）

为什么必须是 do-while

菜单要先显示一次再问选项。while 是「先判断后执行」，第一次进来条件还不存在；do-while 是「先执行后判断」，天然贴合菜单。

三个必须处理的细节

  1. 非法选项要回到菜单，不是退出：default: 分支打印提示后 break（跳出 switch），do-while 的条件仍然成立，菜单重新显示。
  2. 输入非整数（比如输入字母）会死循环：scanf("%d", &choice) 失败时，那个字母留在缓冲区里，下一轮 scanf 又读到它、又失败——无限循环刷屏。修法： if (scanf("%d", &choice) != 1) { while (getchar() != '\n') ; /* 清空这一行 */ printf("请输入数字\n"); continue; }
  3. 只有 0 才退出：} while (choice != 0);

骨架

do {
    printf("==== 单位换算 ====\n");
    printf("1. 厘米 -> 英寸\n2. 公斤 -> 磅\n3. 摄氏 -> 华氏\n0. 退出\n");
    printf("请选择：");
    if (scanf("%d", &choice) != 1) { 清缓冲区; continue; }
    switch (choice) {
        case 1: ... break;
        case 2: ... break;
        case 3: ... break;
        case 0: printf("再见\n"); break;
        default: printf("没有这个选项\n"); break;
    }
} while (choice != 0);

换算系数（保留 4 位小数用 %.4f）

换算 系数
厘米 → 英寸 ÷ 2.54
公斤 → 磅 × 2.20462
摄氏 → 华氏 × 9 / 5 + 32

⚠️ 摄氏转华氏写成 c * 9 / 5 + 32 时，如果 c 是 int，9/5 会先做整数除法得 1，结果全错。要么把 c 声明成 double，要么写 c * 9.0 / 5.0 + 32。
