阶段九 参考答案（练习 3 · 纸上作业）参考答案

先自己做，再看答案。本题禁止上机——真正的堆破坏不会给你打印行号。 下面所有地址都是示意值（0x...），64 位环境：int 4 字节、指针 8 字节。

练习 3 内存图与泄漏推演（标准答案）

0. 先给代码标行号

为方便下文引用，main 里的语句在注释中另编 1~12 号；左侧是整段代码的物理行号，两者不同。

 1  int *make_block(int n)
 2  {
 3      int *p = malloc(n * sizeof(int));   /* M1：申请 */
 4      p[0] = 1;                            /* M2 */
 5      p[1] = 2;                            /* M3 */
 6      p[2] = 3;                            /* M4 */
 7      return p;                            /* M5：交出门牌号 */
 8  }
 9
10  int main(void)
11  {
12      int *a = make_block(3);              /* 行 1 */
13      int *b = a;                          /* 行 2 */
14      printf("%d\n", b[0]);                /* 行 3 */
15      free(a);                             /* 行 4 */
16      printf("%d\n", a[0]);                /* 行 5 */
17      b[1] = 99;                           /* 行 6 */
18      free(b);                             /* 行 7 */
19      a = NULL;                            /* 行 8 */
20      int *c = malloc(4 * sizeof(int));    /* 行 9 */
21      c = malloc(8 * sizeof(int));         /* 行 10 */
22      free(c);                             /* 行 11 */
23      return 0;                            /* 行 12 */
24  }

1. 三块堆内存的账本

堆块 申请语句 大小 谁指着它 结局
A make_block(3) 里的 malloc 3 × 4 = 12 字节 a、b 行 4 被 free，已释放
B 行 9 malloc(4 * sizeof(int)) 4 × 4 = 16 字节 c（行 9）→ 无人 行 10 丢钥匙，泄漏
C 行 10 malloc(8 * sizeof(int)) 8 × 4 = 32 字节 c 行 11 被 free，已释放

一句话：申请了 3 块——A、C 各正确释放一次，B 泄漏；此外 A 还被非法二次释放。

2. 行 2 之后：一个堆块，两把钥匙

       栈（main 栈帧，地址示意）                     堆（低地址 → 高地址）
  ┌──────────────────────────────┐
  │ a  @0x...30  = 0x...A000     │──────┐
  │ b  @0x...28  = 0x...A000     │──────┤
  └──────────────────────────────┘      │
                                        ▼
                           ┌────────────────────────────┐
                           │ 块 A @0x...A000（12 字节）  │
                           │ [0]=1   [1]=2   [2]=3       │
                           └────────────────────────────┘

b = a; 只复制了门牌号，没有复制房子。此时改 b[1] 和改 a[1] 是同一间房。

3. 行 4 free(a) 之后：两块牌子全悬空

  a = 0x...A000 ──┐   （a 还写着旧门牌号 → 悬垂）
  b = 0x...A000 ──┤   （b 也写同一张旧门牌号 → 悬垂）
                  ▼
            ┌ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ┐
              块 A：已 free，房子退租
            └ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ┘

关键：free(a) 不会把 a 变成 NULL，更不会管 b。此时：

  • a 和 b 都是悬垂指针（dangling pointer）；
  • 行 5 的 printf("%d\n", a[0]); 是读已释放内存（use-after-free）；
  • 行 6 的 b[1] = 99; 是写已释放内存，可能踩坏堆管理器的簿记信息。

这两行都是未定义行为：可能打印 1、可能打印垃圾、可能当场崩，也可能什么都不发生—— 不崩不代表写对了，它只是把炸弹留到了下一次 malloc/free。

4. 行 7 free(b)：同一块内存的第二次 free

  a = 0x...A000（悬垂）
  b = 0x...A000（悬垂）
        │
        └──► 块 A 已在行 4 退租
             行 7 再 free(b) = 拿同一把钥匙退租两次 = double free

这是非法 free：double free 会破坏堆的空闲链表，典型后果是 「在完全无关的下一行 malloc 时崩溃」，或者被攻击者利用。绝不能执行。

5. 行 10 之后：泄漏现场

  a = NULL                              （行 8 只救了 a）
  b = 0x...A000                         （仍然悬垂，且那块已 free）

  c = 0x...C000 ──► ┌────────────────────────────┐
                    │ 块 C @0x...C000（32 字节）  │  ← 行 11 free(c)
                    └────────────────────────────┘

                    ┌────────────────────────────┐
                    │ 块 B @0x...B000（16 字节）  │  ← 没有任何指针指向它
                    │ 行 10 的 c = malloc(...)    │     泄漏！
                    │ 把行 9 的唯一门牌号覆盖了    │
                    └────────────────────────────┘

行 10 的问题不是「又申请了一块」，而是赋值把旧门牌号直接盖掉：

int *c = malloc(4 * sizeof(int));   /* 块 B，门牌号存在 c */
c = malloc(8 * sizeof(int));        /* 块 C，c 被改写；块 B 的门牌号永久丢失 */

正确写法是先 free(c); c = NULL;，再申请第二块。

6. 逐行判定表

下表行号从 main 的第一行算起（即代码注释里的行 1~12）。

行 语句 a b c 堆的变化 判定
1 a = make_block(3); 0x...A000 — — 申请块 A（12 字节） OK（但内部没查 NULL）
2 b = a; 0x...A000 0x...A000 — 无 OK，两个指针指同一块
3 printf(b[0]); 0x...A000 0x...A000 — 无 OK，输出 1
4 free(a); 0x...A000 0x...A000 — 块 A 释放 a、b 从此悬垂
5 printf(a[0]); 悬垂 悬垂 — 读已释放内存 非法：use-after-free 读
6 b[1] = 99; 悬垂 悬垂 — 写已释放内存 非法：use-after-free 写
7 free(b); 悬垂 悬垂 — 块 A 第二次释放 非法：double free
8 a = NULL; NULL 0x...A000 — 无 只修好 a；b 仍悬垂
9 c = malloc(4 * int); NULL 悬垂 0x...B000 申请块 B（16 字节） 暂时 OK
10 c = malloc(8 * int); NULL 悬垂 0x...C000 申请块 C；块 B 失联 泄漏块 B（16 字节）
11 free(c); NULL 悬垂 悬垂 块 C 释放 free 本身合法；c 未置 NULL
12 return 0; NULL 悬垂 悬垂 块 B 仍无人管 进程退出才由 OS 回收

7. 结论（对着题目要求逐条回答）

  1. 悬垂指针：a 从行 4 起悬垂；b 从行 4 起悬垂；行 8 只把 a 置 NULL，b 一路悬垂到程序结束。c 在行 11 后也悬垂（但没再使用）。
  2. 非法 free：行 7 的 free(b)。b 与 a 指向同一块 A，行 4 已经 free 过，行 7 是 double free。
  3. 泄漏：1 块，共 16 字节——行 9 申请的块 B，被行 10 的赋值覆盖了唯一指针。
  4. 另一个隐患：make_block 里 malloc 后没有检查 NULL。如果分配失败，p[0] = 1; 就是空指针解引用，必崩；另外它默认 n >= 3，若传入 n < 3，p[2] = 3; 就是越界写。
  5. 改正版见下一节。

8. 改正版代码

#include <stdio.h>
#include <stdlib.h>

int *make_block(int n)
{
    if (n < 3) {
        return NULL;                         /* 参数不满足前提，拒绝 */
    }
    int *p = malloc((size_t)n * sizeof *p);
    if (p == NULL) {
        return NULL;                         /* 申请失败必须报给调用者 */
    }
    p[0] = 1;
    p[1] = 2;
    p[2] = 3;
    return p;
}

int main(void)
{
    int *a = make_block(3);
    if (a == NULL) {
        printf("分配失败\n");
        return 1;
    }

    int *b = a;
    printf("%d\n", b[0]);

    free(a);
    a = NULL;
    b = NULL;                                /* 同一块的两个门牌号都要撕掉 */

    int *c = malloc(4 * sizeof *c);
    if (c == NULL) {
        printf("分配失败\n");
        return 1;
    }
    free(c);                                 /* 先释放块 B，再申请下一块 */
    c = NULL;

    c = malloc(8 * sizeof *c);
    if (c == NULL) {
        printf("分配失败\n");
        return 1;
    }
    free(c);
    c = NULL;

    printf("没有泄漏，也没有悬垂指针\n");
    return 0;
}

9. 常见错误画法（自查）

  • ❌ 以为 b = a; 复制了一块新内存——它只抄了门牌号，堆上仍然只有块 A；
  • ❌ 以为 free(a); 会自动把 a 置 NULL——free 只认地址，不改指针变量；
  • ❌ 以为 free(b); 是「释放另一块」——b 和 a 是同一块，这是 double free；
  • ❌ 以为行 5 一定打印 1——已释放的内存内容不确定，读到什么全看堆管理器心情；
  • ❌ 数泄漏时把块 A 或块 C 也算进去——C 正常释放，A 虽然 free 过但又被非法二次释放， 真正「有申请、无释放」的只有块 B；
  • ❌ 觉得「进程都要退出了，泄漏无所谓」——短命程序确实看不出来，但服务器、单片机、 长期运行的机器人主控程序会越漏越多，最后 malloc 返回 NULL。
