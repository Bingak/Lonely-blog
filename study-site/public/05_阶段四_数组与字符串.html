2. 场景引入：仓库——而不是一百个口袋

阶段二你算过一个成绩的平均分；现在想象统计全班 50 人的成绩：难道定义 int score1, score2, ..., score50; 然后写 50 行 scanf？

变量是"一个口袋"，你口袋再多，找东西也要翻半天。数组是一排编了号的抽屉柜：一个名字（scores）+ 一个编号（下标），就能访问任意一格。更妙的是——编号可以是变量：scores[i] 让"循环"和"批量数据"一拍即合，你写过的所有循环功夫瞬间全部复用。

至于字符串：C 语言里根本没有"字符串类型"——所谓字符串，就是"字符数组 + 一个约定：用 '\0' 表示到头了"。这个朴素的约定，就是任务五、考核任务所有字符串处理的底层逻辑。

3. 核心概念一：一维数组——定义、初始化、下标

3.1 三种出生方式

int a[5] = {1, 2, 3, 4, 5};        /* 全部初始化 */
int b[5] = {1, 2};                 /* 剩下的自动补 0：{1,2,0,0,0} */
int c[]  = {1, 2, 3};              /* 不写长度：编译器数一遍，等价 c[3] */
int d[5] = {0};                    /* 实战常用：5 格全 0 */

3.2 下标从 0 开始（不是数学家的习惯，是地址的必然）

int a[5] 的五格编号是 0、1、2、3、4——没有第 5 格！为什么？数组在内存里是连续的一排，a[i] 的地址 = 首地址 + i × 每格大小。从首地址"偏移 0 格"自然就是第一个元素——下标本源是"偏移量"。这个理解直通阶段五指针：a[i] 与 *(a+i) 在 C 里是同一件事（现在先记下这句话，阶段五揭晓）。

3.3 越界：C 语言不装护栏

int a[5] = {0};
a[5] = 99;        /* 写越界：改坏了隔壁的内存！编译器不报错、不警告、运行也不报错 */
a[-1] = 1;        /* 更离谱但同样"合法"地跑过去 */

这是 C 最臭名昭著的危险点：越界不会立刻报错，程序甚至可能"看起来正常"——它在偷偷破坏其他变量、函数返回地址。数据科学一点说：越界是未定义行为，你的程序此刻起已"脱离剧本"。纪律：写每个 a[i] 前，心里默问一遍 i 的合法范围；每个循环写完，检查 i 的终值。配套 01_array_basics.c 演示了越界的"现场"（用越界改坏隔壁变量的实验——跑之前先预测！还有 sizeof 求元素个数的惯用法）。

4. 核心概念二：数组四大基本功

配套 02_array_algorithms.c，四段模式全部要练到能默写：

/* 1) 遍历 + 累计 */
int sum = 0;
for (i = 0; i < n; i++) sum += a[i];

/* 2) 最值 + 下标追踪（擂台法） */
int max_i = 0;
for (i = 1; i < n; i++) if (a[i] > a[max_i]) max_i = i;

/* 3) 查找（第一个等于 target 的位置，找不到返回 -1） */
int find = -1;
for (i = 0; i < n; i++) { if (a[i] == target) { find = i; break; } }

/* 4) 逆置（两头互换，向中间夹） */
for (i = 0; i < n / 2; i++) {
    int t = a[i]; a[i] = a[n-1-i]; a[n-1-i] = t;
}

擂台法细节（你的旧习惯可能只记值不记下标）：max_i 记"当前擂主的位置"，比较用 a[i] > a[max_i]。练成这个形态，将来"输出最高分是谁"这种需求随手就解。四大件全部是"for 循环 + 下标"的组合——你阶段二练的循环边界功夫（< 还是 <=）在这里精确复用：遍历 n 个元素，i 从 0 到 n-1，条件 i < n。

5. 核心概念三：二维数组——乘法表的本体

你写过乘法表（打印），现在把它"存起来"：

int table[11][11];                 /* 11 行 11 列：table[行][列] */
table[3][4] = 12;                  /* 3×4 格存 12 */

int m[2][3] = {{1, 2, 3},
               {4, 5, 6}};         /* 分行初始化，看得清楚 */
  • 本质："数组的数组"——m[0] 是一个 3 格的一维数组，m[1] 也是；
  • 遍历永远双层循环：外层行、内层列；
  • 越界同样没有护栏，m[2][0] 对 int m[2][3] 就是越界（合法行号 0、1）。

配套 03_matrix.c：存乘法表进二维数组、按行打印、转置打印。你阶段二的乘法表代码可对照升级——同一个问题，从"边算边打印"到"先存储再加工"，就是数组带来的思维升级。

6. 核心概念四：字符数组与字符串——'\0' 的故事

6.1 一图看懂

char s[] = "UPRE";

内存里真实的样子（5 格！）：

下标:    0    1    2    3    4
      ┌────┬────┬────┬────┬────┐
      │'U' │'P' │'R' │'E' │'\0'│
      └────┴────┴────┴────┴────┘
sizeof(s) = 5    ← 带上 '\0' 的总字节数
strlen(s) = 4    ← '\0' 之前的字符数（"有效长度"）

'\0'（ASCII 0）是字符串的"封底"：所有字符串函数（printf 的 %s、strlen、strcmp……）见到它就停。它不占"长度"，但占内存——这就是"装 50 个字符的字符串需要 51 格"的原因，也是任务五"长度不超 50"的内存预算。

6.2 三个立刻要懂的差别

  1. sizeof(s) vs strlen(s)：前者是数组总大小（含封底，编译期定死），后者是有效长度（运行时数到 \0 为止）。
  2. 初始化 vs 赋值： c char s[10] = "hello"; /* ✔ 初始化：合法 */ char t[10]; t = "hello"; /* ✘ 编译错误！数组不是能整体赋值的变量 */ t[0]='h'; t[1]='e'; ... /* 只能逐格写（或者用 strcpy——考核不让用，阶段五教原理） */
  3. 字符串不能用 == 比较：s1 == s2 比较的是两个数组的地址（永远是"不等"的错觉）。比较内容必须逐字符比——这正是考核要你手写的东西，6.6 节直接教原理。

6.3 手写 my_strlen（考核第一块砖）

int my_strlen(const char s[])     /* const：承诺只读不改 */
{
    int i = 0;
    while (s[i] != '\0') {       /* 从头往后走，直到撞见封底 */
        i++;
    }
    return i;
}

三行核心，道出 strlen 的本质：沿着数组走到 \0 前面那一格。配套 04_string_basics.c 里用它和 <string.h> 的 strlen 对拍验证。请练到能默写——考核现场不许 #include <string.h> 用库版。

6.4 字符串比较原理（考核第二块砖）

/* 返回：0 表示相等；非0 表示第一个不同位置字符的差值 */
int my_strcmp(const char s1[], const char s2[])
{
    int i = 0;
    while (s1[i] != '\0' && s1[i] == s2[i]) {   /* 并肩走到第一个不同 */
        i++;
    }
    return s1[i] - s2[i];     /* 都到'\0'时差值0=相等；否则首个差异的差 */
}

考核的登录验证（用户名/密码比对）的内核就是它。这里教的是"原理"，考核的整个登录系统组织由你独立完成。

7. 核心概念五：字符串输入三招与缓冲区安全（任务五的入场券）

7.1 三招对比

招式 写法 特点 风险
① scanf("%s") scanf("%49s", s); 遇空格/回车就停——读不了带空格的串 不写宽度 %s 会溢出（用户敲多长它读多长，写爆数组）
② scanf("%49s") 带宽度 同上 最多读 49 字符，留 1 格给 \0 仍不读空格；残留留在缓冲区
③ fgets（推荐） fgets(s, sizeof(s), stdin); 连空格一起读，到换行/装满为止，自动保证不越界（最多读 sizeof-1 格） 读进来的 \n 会被留在串尾，需要手动清理

宽度 49 怎么来的：数组 50 格，留 1 格给 \0 → 最多读 49 个字符。任务五"长度不超 50"的输入，char s[51]; fgets(s, sizeof(s), stdin); 一行搞定且绝对安全。

7.2 fgets 的三件小事

  1. 它会把用户敲的回车 \n 也读进数组（如果装得下）。所以"实际内容长度"可能多一个换行——用 my_strlen 检查末位，是 \n 就替换成 \0： c int len = my_strlen(s); if (len > 0 && s[len-1] == '\n') { s[len-1] = '\0'; /* 把换行改写成封底 */ }
  2. 若用户输入超过容量，剩余字符留在缓冲区——阶段二的 while (getchar() != '\n'); 清空法在这里正式上岗（配套 05_string_io.c 有"清空缓冲区"函数的完整封装）。
  3. fgets(s, sizeof(s), stdin) 三个参数：往哪存、最多存多少（含\0）、从哪读（stdin=标准输入）。

7.3 配套实操

05_string_io.c 演示：三招各来一遍 + 观察每招读到什么、缓冲区剩什么。跑之前对每招先写预测（比如输入 hello world，%s 读到什么？fgets 读到什么？），再看结果——这组实验是本阶段含金量最高的 10 分钟。

8. 核心概念六：逐字符处理——任务五的核心能力

8.1 字符即数字

C 里 char 本质是一个小整数（通常是 0~255 的 ASCII 码）： - 'A' 是 65、'a' 是 97、'0' 是 48——字符字面量加单引号就是数字； - 'a' - 'A' = 32：大小写字母相差固定 32；大写转小写：c - 'A' + 'a'（不要写死 32，用字面量表达意图）； - 判断数字：c >= '0' && c <= '9'；判断字母：(c >= 'A' && c <= 'Z') || (c >= 'a' && c <= 'z')。

8.2 逐字符遍历字符串的标准形态

int i;
for (i = 0; s[i] != '\0'; i++) {      /* 走到封底为止——不用 strlen！ */
    if (s[i] >= 'A' && s[i] <= 'Z') {
        upper_count++;                 /* 例如：数大写字母 */
    }
}

配套 06_char_processing.c：大小写转换（打印"加密风格"的大写版）、元音判断、字符分类（字母/数字/空格/其他各多少个）。这些模式的任意组合，就是你完成 UPRE 统计所需的全套零件。

8.3 大小写判断的边界提醒

c >= 'A' && c <= 'Z' 判大写——别写成 c == 'U' || c == 'P' || ... 去数"大写"，判"是不是大写"和判"是不是某字母"是两件事，任务五两个都要，别混。

9. 核心概念七：连续模式计数——数"连排"的思想（不给任务答案，给钥匙）

任务五要数"连续的 UPRE 出现几次"。同类的简化问题拿来练思想：

数字符串 "haahaaahaah" 里连续的 "aa" 出现几次？

/* 通用模式：在位置 i 检查"从这里开始，模式 pattern 是否匹配" */
int count = 0;
for (i = 0; s[i] != '\0'; i++) {          /* 枚举每个起点 */
    int j = 0;
    while (pattern[j] != '\0' && s[i+j] == pattern[j]) {
        j++;
    }
    if (pattern[j] == '\0') {             /* 模式走完了 = 全部匹配上 */
        count++;
    }
}

两个必须想清楚的边界（自查清单会再问你）： 1. 起点枚举会不会越过末尾？——s[i+j] 在 i 接近末尾时越界吗？s[i+j] == pattern[j] 与 pattern[j] != '\0' 的判断顺序怎么配合才能既不越界又不错判（提示：短路求值）； 2. 重叠怎么算？——"UPUPRE"：位置 2~5 是一个 UPRE；位置 0 的 UP 匹配一半就断。你的计数是"数所有起点"，每处起点独立判断——重叠（如 "aaa" 数 "aa" 有 2 处）自然数得到，不重叠的需求则要用"匹配后跳过整段"的变体。任务五按 PDF 样例确定语义，样例 "12UPRE35UklkPuREpPee2eeupre" 里 UPRE=1 个，你设计的测试组必须能区分这两种语义。

配套 07_pattern_count.c 用 "aa" 在 "haahaaahaah" 上跑通（答案 3 处），并且带越界保护写法。把它的思想平移到你的任务五代码里——模式更长、条件更多（只数大写），骨架不变。

11.5 零基础补充：数组与字符串的「一图流」

11.5.1 一维数组的内存图（所有数组问题的地基）

int a[5] = {10, 20, 30, 40, 50};

下标:      a[0]   a[1]   a[2]   a[3]   a[4]
         +-----+-----+-----+-----+-----+
内容:    |  10 |  20 |  30 |  40 |  50 |
         +-----+-----+-----+-----+-----+
地址:    0x100 0x104 0x108 0x10C 0x110   （每个 int 占 4 字节，首地址 +4×i）

三件事必须刻进脑子：

  1. 下标从 0 开始，最后一个下标是 长度-1。a[5] 越界，但它能编译通过——C 语言不装护栏，越界读写的是别人家的内存。
  2. 内存是连续的。所以 a[i] 的真实含义是「首地址 + i × sizeof(int)」，这就是阶段五 *(a+i) 的来历。
  3. 数组名在大多数表达式里退化成「首元素的地址」。a 和 &a[0] 数值相同。这也是为什么 sizeof(a) 在定义处是 20，传给函数后只剩 4（变成指针了）。

11.5.2 四种初始化，区别在哪

int a[5] = {1, 2, 3};        /* 1,2,3,0,0 —— 剩下的自动补 0 */
int b[5] = {0};              /* 全 0，最常见的「清零」写法 */
int c[]  = {7, 8, 9};        /* 编译器数出来长度是 3 */
int d[5];                    /* 五个格子全是垃圾值，用前必须自己填 */

常见错误：int a[5] = {1,2,3,4,5,6}; —— 初始值比数组长，编译报错 excess elements in array initializer。这正是编译器在帮你，别绕过它。

11.5.3 字符串就是「以 \0 结尾的字符数组」

  "Hi" 在内存里其实是 4 个字符：
         +---+---+---+----+
         | H | i | \0| ……|
         +---+---+---+----+
                   ↑
              字符串结束标志，值就是整数 0

所以 char s[10] = "Hi"; 之后 s[2] 是 \0，s[3]~s[9] 也是 \0（C 规定字符数组用字符串初始化时剩余部分补 \0）。

推论（都很重要）：

规则 后果
字符串靠 \0 定长 char s[10] 装 "hello" 只用了 6 格，剩下 4 格是 \0
没有 \0 就不是字符串 char s[3] = {'H','i'}; 是字符数组，printf("%s", s) 会一直打印到碰巧遇到一个 0 为止——可能打印出乱码
strlen 数到 \0 之前 所以 strlen("Hi") 是 2，不是 3，也不是容量 10
sizeof 与 strlen 不同 sizeof(s) 是数组容量（编译期定），strlen(s) 是实际字符数（运行时算）

11.5.4 标准库 string.h 常用函数速查

函数 作用 新手最常犯的错
strlen(s) 数长度 忘了它是 size_t（无符号），int i 比较有时出怪事
strcpy(dst, src) 整串复制 不检查 dst 容量，源串比目标长就缓冲区溢出
strncpy(d, s, n) 最多复制 n 个 可能不补 \0，要自己 d[n-1] = '\0';
strcat(dst, src) 拼接 同样不检查容量
strcmp(a, b) 比较内容 字符串不能用 == 比！== 比的是地址
strchr(s, c) 找字符 返回指针，没找到返回 NULL，用前要判
sprintf(buf, "%d", n) 数字转字符串 容量不够就溢出，优先用 snprintf

strcmp 的返回值：小于 0 表示 a 在字典序上更小，等于 0 表示内容相同，大于 0 表示 a 更大。判断「相等」要写 strcmp(a,b) == 0，不是 == 1。

11.5.5 二维数组：把乘法表画成表格

int m[3][4];

          列0   列1   列2   列3
行0      +----+----+----+----+
         |    |    |    |    |

行1      |    |    |    |    |
         +----+----+----+----+

内存里其实是「一行接一行」铺平的（行优先）：m[1][2] 的地址 = 首地址 + (1×4 + 2) × sizeof(int)。

13. 安全与规范：本阶段三条铁律
