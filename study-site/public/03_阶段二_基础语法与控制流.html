2. 场景引入：三个"我明明会循环，怎么还是错了"的现场

现场一（P1）：你的 7_循环_猜数.c：

int a;                 // a 出生时没有值
while (a != number) {  // 第一次比较时，a 里是上一次程序留下的垃圾

那一次程序碰巧跑对了，因为垃圾值恰好不等于 number。但如果垃圾值恰好等于 number，循环一次都不进，你连输入的机会都没有。你的程序正确与否，取决于上一个人在内存里留下了什么——这就是"未定义行为"。

现场二（P2）：你的 7_循环_正序分解.c：

while (num > 10)   // 想要"num 还有两位以上"

输入 23：23 > 10 成立，处理完个位变 2；2 > 10 不成立，退出，十位的 2 没被处理。想表达"至少还有两位"必须写 >= 10。一个等号，漏掉一整类输入。

现场三（P3）：你的 7_循环_水仙花.c：

sum += (int)pow(d, n);   // pow 是 double 世界的人

pow(9, 3) 合法的结果是 729.000000~729.000001 之间的任何值（IEEE 浮点允许一点误差），9³ 在某些实现上算出来是 728.9999…，(int) 强转直接砍成 728。水仙花数 927 类的漏判就是这么发生的。 整数的世界用整数的工具：循环累乘。

这三个现场有一个共同点：程序"能跑"，但脑子里没有一张"变量取值过程表"。本阶段的核心训练，就是写每个循环前先在纸上把这张表画出来。

3. 核心概念一：变量的一生——声明、初始化、作用域

3.1 为什么要懂这个

考核任务有 5 次登录机会的循环计数，任务五要数连续 UPRE——全都要靠"变量从哪出生、值怎么变、什么时候死"这三问。没这三问，调试只能靠猜。

3.2 三条纪律

  1. 声明时立刻初始化：计数器 int cnt = 0;、累加器 int sum = 0;、标志 int found = 0;。写任何新变量时手比脑快地补 = 0（或 = 初值）。
  2. 局部变量的值是垃圾：int a; 之后 a 不是 0，是"这块内存上一次的残值"。全局变量和 static 变量才会自动为 0——现在先记住结论，阶段九讲原理。
  3. 每轮循环开始处复位：嵌套循环里内层每轮用的临时计数器，要在内层循环开始前重置。你的 7_循环_无重复数字.c 之所以对，就是因为 cnt 的重置位置放对了——回头去确认一遍，把它变成"肌肉知道"而不只是"碰巧写对"。

3.3 配套示例 01_init_rules.c

/* 01_init_rules.c —— 阶段二：初始化三纪律 + 边界训练
 * 编译：gcc -Wall -Wextra -g 01_init_rules.c -o 01_init_rules.exe
 * 预期输出见文件底部注释。
 */
#include <stdio.h>

int main(void)
{
    /* ── 纪律1：出生即初始化 ─────────────────────── */
    int total = 0;          /* 累加器必须从0开始 */
    int i;

    /* ── 纪律2：边界条件自证 ─────────────────────── */
    /* 需求：把 1~5 的平方累加。边界"含不含 5"要一眼可读。 */
    for (i = 1; i <= 5; i++) {       /* 写 <= 时读出声："i 小于等于 5，包含 5" */
        total += i * i;
    }
    printf("1~5 的平方和 = %d\n", total);   /* 55 */

    /* ── 训练：同一个需求，故意写出错边界给你看 ──── */
    int bad = 0;
    for (i = 1; i < 5; i++) {        /* 少算一个：只加到 4 */
        bad += i * i;
    }
    printf("写错边界的结果 = %d（少了 5^2=25，验证你看出区别）\n", bad);  /* 30 */

    /* ── 纪律3：内层循环的临时变量每轮复位 ───────── */
    /* 需求：数一数 1~20 里每个数 i 有几个因数 */
    int num;
    for (num = 1; num <= 20; num++) {
        int cnt = 0;                       /* ★ 复位写在这里（每轮新建） */
        for (i = 1; i <= num; i++) {
            if (num % i == 0) {
                cnt++;
            }
        }
        printf("%d 的因数个数 = %d\n", num, cnt);
    }
    return 0;
}
/* 预期输出（节选）：
 * 1~5 的平方和 = 55
 * 写错边界的结果 = 30（少了 5^2=25，验证你看出区别）
 * 1 的因数个数 = 1
 * 2 的因数个数 = 2
 * ...
 * 20 的因数个数 = 6
 */

纸上训练法（本阶段每天 10 分钟）：写完循环先不动键盘，画表格——列头是变量名，行号是循环轮次，一行行填值。填得下去 = 理解了；填不下去 = 回去改。这就是练习 3 要你做的事。

4. 核心概念二：浮点数——第一次正经用 double

4.1 为什么现在必须学

任务三解一元二次方程要算判别式 b²-4ac，它在数学上天然是小数；任务四算模长 √(x²+y²+z²)，要求输出 3.741657——6 位小数。你到今天为止所有程序都是整数世界，从本节起必须会浮点。

4.2 三个必须建立的认知

  1. 字面量要带小数点：double x = 1 / 3; 得到 0（整数除法先完成，再转 double）；double x = 1.0 / 3; 才得到 0.333…。"表达式里只要有一个操作数是 double，整条式子就按 double 算"——这是记法，也是原理解释。
  2. 打印格式 %f（默认6位小数）/ %.2f / %.6f：任务四要求输出 3.741657，printf("%.6f", v) 就是为它准备的。
  3. 浮点不能精确表很多十进制小数，所以浮点之间不用 == 比较：0.1 + 0.2 == 0.3 结果是 0（假）！要比较差值：fabs(a-b) < 1e-9。这是阶段三做 equation 函数时防止"明明该相等却判不等"的关键。

4.3 配套示例 02_double_basics.c

/* 02_double_basics.c —— 阶段二：double 正规军
 * 编译：gcc -Wall -Wextra 02_double_basics.c -o 02_double_basics.exe
 */
#include <stdio.h>
#include <math.h>     /* fabs 所在；编译不用加 -lm（Windows GCC 通常自动），
                        若报 undefined reference，加参数 -lm 再试 */

int main(void)
{
    /* 1) 字面量陷阱 */
    double a = 1 / 3;        /* 整数除法：0 */
    double b = 1.0 / 3;      /* 浮点除法：0.333... */
    printf("a = %f, b = %f\n", a, b);          /* a = 0.000000, b = 0.333333 */

    /* 2) 格式化输出：宽度与小数位 */
    double v = 1 + 4 + 9;    /* = 14 */
    v = sqrt(v);             /* 模长练习：sqrt(14) */
    printf("默认  : %f\n", v);        /* 3.741657 */
    printf("两位  : %.2f\n", v);      /* 3.74 */
    printf("六位  : %.6f\n", v);      /* 3.741657 —— 任务四要的格式 */
    printf("带符号占位演示: [%12.4f]\n", v);  /* 总宽12、4位小数、右对齐 */

    /* 3) 浮点比较的正确姿势 */
    double x = 0.1 + 0.2;
    if (x == 0.3) {
        printf("x 等于 0.3\n");               /* 实际上不会打印！ */
    }
    if (fabs(x - 0.3) < 1e-9) {
        printf("x 与 0.3 的差小于一亿分之一（这才是相等）\n");
    }
    return 0;
}
/* 预期输出：
 * a = 0.000000, b = 0.333333
 * 默认  : 3.741657
 * 两位  : 3.74
 * 六位  : 3.741657
 * 带符号占位演示: [      3.7417]
 * x 与 0.3 的差小于一亿分之一（这才是相等）
 */

P3 的正确修法预告：水仙花里 (int)pow(d,n) 改成 d*d*d（三位数时）或写一个小循环累乘——阶段三你还会再见到它。

5. 核心概念三：scanf 的正确打开方式（输入是你的敌占区）

5.1 你目前的用法缺什么

你现在写 scanf("%d", &a); 从不看返回值。但考核任务要求"输入错误给 5 次机会"——你必须能判断"用户这次到底输入了没有、输入对不对"。scanf 的返回值就是答案：返回成功读取的项目数。

  • scanf("%d", &a) 用户输入 42 → 返回 1（读成了1项）
  • 用户输入 abc → 返回 0（一项都没读成），而且 abc 留在输入缓冲区里，下次 scanf 再读还是它——死循环的地雷就在这。

5.2 三段式输入检查（背下来，任务一直接用）

if (scanf("%d", &a) != 1) {
    printf("输入不合法，请输入整数\n");
    /* 高级：清空缓冲区。现阶段可先 return 1 结束程序，
       阶段四学循环重试的完整写法（while + getchar 清空）。 */
    return 1;
}

5.3 配套示例 03_scanf_safety.c

/* 03_scanf_safety.c —— 阶段二：scanf 返回值检查
 * 编译：gcc -Wall -Wextra 03_scanf_safety.c -o 03_scanf_safety.exe
 * 实验：分别输入 5、abc、3.14，观察三种行为的差异。
 */
#include <stdio.h>

int main(void)
{
    int age;
    int ok = scanf("%d", &age);    /* ★ 接住返回值 */
    if (ok != 1) {
        printf("你输入的不是整数（scanf 返回 %d）\n", ok);
        return 1;
    }
    printf("读到整数 %d\n", age);

    /* 顺带体验一个现象：上次输入 3.14 时，".14" 会残留在缓冲区，
       被下一个 %c 读走。这就是"缓冲区"的初体验，阶段四展开。 */
    char next;
    scanf(" %c", &next);      /* %c 前面的空格：跳过空白字符（现在有印象即可） */
    printf("缓冲区里下一个字符是 '%c'\n", next);
    return 0;
}

6. 核心概念四：do-while 与输出对齐——把任务一、二的最后两块拼图凑齐

6.1 do-while 的选型场景（用你的猜数游戏讲）

需求本质：先做一次（读入），再判断（是否继续）。这正是"猜数循环"的正确结构：

/* 猜数修正版 —— 与 code\阶段二_基础与控制流\04_guess_fixed.c 对应 */
int number = rand() % 100 + 1;
int guess;
int count = 0;
do {
    printf("请猜一个 1~100 的数：");
    scanf("%d", &guess);          /* 先读入，值才有意义 */
    count++;
    if (guess > number)      printf("大了\n");
    else if (guess < number) printf("小了\n");
} while (guess != number);        /* 再判断是否再来一轮 */
printf("猜中！共 %d 次\n", count);

选型口诀：先判断再循环 → while / for；至少做一次、做完再判断 → do-while。菜单类程序（考核任务！）、输入重试类程序天生是 do-while 的主场。

6.2 输出对齐：%4d 一类的"宽度占位符"

你的 7_循环_乘法表.c 直接打印 %d，数字一多就挤成一片。%4d 表示"占至少 4 格、右对齐、不足补空格"：

printf("%4d", 7);     /* 输出：'   7'（3个空格+7） */
printf("%-4d", 7);    /* 左对齐：'7   ' */

任务二要求"输入 11 打印 11 阶乘法表"，%4d + 行尾 \n 就是标准答案的一部分（具体版式请你按任务 PDF 自己排——提示到这个程度已经足够）。

8.5 零基础补充：把「懂了」变成「手感」

前面几节讲的是「排雷」和「补装备」。这一节反过来——把你已经会的知识，讲到能在纸上给别人讲明白。 下面每个小节都可以用 5 分钟读完，然后打开你的 D:\Programing\C 里对应的旧文件，亲手改一遍。

8.5.1 一行代码，编译器到底做了什么（以你的 2_变量_3.c 为例）

int a = 10;          // ①
int b = a + 5;       // ②
printf("%d\n", b); // ③

拆开看，就三件事：

步骤 编译器做的事 内存里发生什么
① 请求一块格子，写上 10，贴标签 a 某地址处多出 4 字节（int 在 32/64 位 Windows 上都是 4 字节）
② 再要一块格子，把 a 里的 10 取出来加 5，结果 15 写进去，贴标签 b 又一块 4 字节
③ 把 b 里的 15 换成字符 1 5，再拼上换行符交给操作系统打印 变量本身不变

关键认知：int b = a + 5; 之后，b 和 a 再无任何关系。 你把 a 改成 999，b 依然是 15。这就是「赋值是复制，不是连线」——阶段三学函数时，这条认知决定了你能不能理解「为什么函数里改了没用」。

8.5.2 内存示意图：把变量画成盒子

以后每次推演程序，都在纸上画这个图。以 5_条件_3.c 里的交换为例：

  a            b            tmp
+------+    +------+    +------+
|  10  |    |  20  |    |  ??  |
+------+    +------+    +------+

8.5.4 运算符优先级：不用背，用这张表 + 括号

完整优先级表有 15 级，没人背。你只需要记住三件事：

  1. () 最高——不确定就加括号，加括号永不犯错，不加括号可能错。
  2. 单目 > 算术 > 关系 > 逻辑 > 赋值（!x → *p → a+b → a<b → a&&b → x=）
  3. && 比 || 高——所以 a || b && c 等价于 a || (b && c)。想表达「(a 或 b) 且 c」必须自己加括号。

常见踩坑组合（都是你可能写错的）：

写法 实际含义 想表达的是
a & b == c a & (b == c) (a & b) == c
a << 1 + b a << (1 + b) (a << 1) + b
!a > b (!a) > b !(a > b)
a = b == c a = (b == c)，a 变成 0 或 1 先比较再分别赋值

8.5.6 类型转换：什么时候会自动转，什么时候必须手动转

int i = 7;
double d = 2;      // 自动：int → double，d = 2.0
double e = i / 2;  // 先算 i/2（整数除法）= 3，再转 double，e = 3.0  ← 经典坑
double f = i / 2.0; // 2.0 让 i 提升为 double，7.0/2.0 = 3.5  ← 想要的结果

三条规则：

  1. 整数相除，结果还是整数，直接截断（不是四舍五入）。7/2=3，-7/2=-3（向零取整）。
  2. 混合运算时，往「能表示范围更大」的类型靠：int + double → double。
  3. 强制转换 (类型) 是程序员在说「我知道会丢精度，我负责」。(int)3.99 得 3，不是 4。

可变参数函数的隐藏规则：printf 是可变参数，float 实参会自动提升为 double，所以 printf("%f", 3.14f) 是对的；char/short 提升为 int，所以 printf("%d", c) 对字符也成立。但 scanf 是指针参数，不做提升，%f 配 &f（float）、%lf 配 &d（double），写错就是往内存里写错字节数。

10. 安全注意事项（从现在成为习惯）
