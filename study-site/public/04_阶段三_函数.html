目标： 1. 掌握函数的定义、调用、原型声明、返回值四件事，能独立写出"定义一次、到处调用"的函数。 2. 理解传值调用（"复印件定理"）——为什么函数里改形参，外面的实参纹丝不动。这是本阶段最重要的一个认知，也是阶段五指针的钥匙。 3. 掌握数组作函数参数的特例现象（函数里改的居然是真数组！）——任务三的 result 数组全靠它。 4. 把你已经会的算法（素数、最大公约数、拆位）函数化，学会用函数组织程序——让 main 变成"目录页"。 5. 独立完成任务三。

2. 场景引入：你其实早该发明函数了

翻开你的 D:\Programing\C：7_循环_素数.c、7_循环_素数求和.c、7_循环_嵌套.c 里各有一段几乎一样的"试除判素数"代码；7_循环_最大公约数.c 和 7_循环_约分最简分式.c 里各有一段一模一样的辗转相除。

三遍素数、两遍 GCD——重复，就是函数诞生的时刻。更早的时候，数学家也遇到过同样的问题：每次写 "3.14159265358979" 太烦了，于是给它起名 π。函数做的事一模一样：给一段代码起个名字，以后用名字调用它。

函数解决三个问题： 1. 重复：写一次，用一百次； 2. 命名：is_prime(n) 比 for(i=2;i<n;i++)... 一眼能看懂"这在干嘛"； 3. 分工：main 负责"流程"，函数负责"手艺"——考核任务要求的"模块化"，起点就在这。

3. 核心概念一：函数解剖学——四要素与一次调用

3.1 一个函数的四要素

返回类型 函数名(参数类型1 形参名1, 参数类型2 形参名2, ...)   ← 函数头（签名）
{                                                            ← 函数体开始
    ...干活...
    return 结果;                                             ← 交还结果（void 函数可省）
}                                                            ← 函数体结束

对照配套的 code\阶段三_函数\01_function_anatomy.c（完整可编译，此处讲解逻辑）：

int max3(int a, int b, int c)     /* 四要素：返回类型int / 名字max3 / 三个int形参 / 函数体 */
{
    int m = a;                    /* 假设 a 最大 */
    if (b > m) m = b;             /* b 更大就换 */
    if (c > m) m = c;             /* c 更大就换 */
    return m;                     /* 把结果交还给调用方 */
}

return 的两个作用（考试级知识点）： 1. 交还结果：return m; 把 m 的值作为函数的"输出"送回调用处； 2. 结束函数：return 一执行，函数立即结束——哪怕后面还有代码。

3.2 调用与"表达式的零件"

int biggest = max3(12, 99, 37);       /* 调用1：用返回值 */
printf("最大的是 %d\n", max3(12, 99, 37));  /* 调用2：直接嵌进更大的表达式 */

认知升级点：函数调用完成后，max3(12,99,37) 这个整体就是一个值（99），它可以出现在任何"99 能出现的位置"。你以前写 x = 1 + 2;，现在写 x = 1 + max3(...)——对编译器来说没有本质区别。"函数调用是值的工厂"，记住这句话。

3.3 void 函数：只干活、不交货

有的函数不需要返回结果，比如"打印一条分隔线"：

void print_bar(void)      /* void：没有返回值；(void)：不要参数 */
{
    printf("========\n");
    /* 不写 return，函数体执行完自然结束 */
}

调用：print_bar();——注意不能写 int x = print_bar();（没有"货"可接）。

3.4 历史包袱与规范

你旧代码里 int main() 空括号的写法，表示"参数表 unspecified"（C 的历史遗留）；现代写法是 int main(void)——明确"我不要参数"。从本阶段起统一写 int main(void)，考核看到的是规范代码。

4. 核心概念二：传值调用——"复印件定理"（本阶段最重要的一节）

4.1 现场实验：一次失败的交换

配套 code\阶段三_函数\02_swap_fail.c，核心逻辑：

void swap_wrong(int a, int b)      /* 想交换两个整数 */
{
    int t = a;
    a = b;
    b = t;                          /* 函数里明明换成功了…… */
}

int main(void)
{
    int x = 1, y = 2;
    swap_wrong(x, y);
    printf("x=%d y=%d\n", x, y);    /* 打印 x=1 y=2 —— 没换！ */
    return 0;
}

为什么失败？ 因为 C 的函数调用是传值（pass by value）： 1. 调用时，把实参 x、y 的值（1 和 2）复制一份，交给形参 a、b——a、b 是复印件； 2. 函数里换的是复印件，原件 x、y 从头到尾没被碰过； 3. 函数结束，复印件（a、b、t）全部销毁，交换成果随之消失。

用断点验证（必做实操）：在 swap_wrong 里打断点，观察 VARIABLES 面板：a=1, b=2 进入，a=2, b=1 出去；main 里的 x、y 纹丝不动。再把鼠标悬停在 main 的 x 和 swap_wrong 的 a 上，对比显示的地址（形如 0x61fe1c 与 0x61fe08）——不同的地址 = 不同的内存格子 = 复印件。

4.2 为什么 C 要这样设计？

三个理由，现在就能体会前两个： 1. 安全：函数拿的是复印件，就不会"手滑"改坏调用方的数据（你看，max3 根本不该有权限改你的 x、y）； 2. 可预测：看一个函数的参数表，就知道它"吃进去什么、吐出来什么"（数学函数 f(x)=x² 不会顺手偷改你输入的 x）； 3. （代价）：想真的改原件怎么办？——把原件的地址抄给它。这就是阶段五的指针。现在埋下伏笔："复印件定理"是理解指针的全部心理基础——先彻底理解为什么复印件改不了原件，阶段五你才知道指针是在解决什么问题。

4.3 返回值也一样是"复印"

int count = 10;
int twice = count * 2;    /* count 没变 */

函数返回后，"result 的值"被复制到接它的变量里。值在 C 里像水一样被倒来倒去，而"变量的本体（那块内存）"默认不被触碰——这个心智模型先立住。

5. 核心概念三：函数原型——编译器的"先看目录再看正文"

5.1 一个真实会发生的编译错误

把 swap_wrong 的定义写到 main 下面，再编译：warning: implicit declaration of function 'swap_wrong'（旧编译器）或直接报错——因为编译器从上往下单遍阅读你的代码，读到 main 里的调用时它还不认识这个名字。

两种解法： 1. 调整顺序：把被调用的函数写在调用者前面（小项目可以，大项目会乱）； 2. 原型声明（正解）：在文件开头先"报名字"：

void swap_wrong(int a, int b);   /* 原型：只写签名，以分号结尾，不写函数体 */
int  max3(int a, int b, int c);  /* 形参名可以省：int max3(int, int, int); */

5.2 原型与 #include 的关系（呼应阶段一）

#include <stdio.h> 的本质是什么？stdio.h 里面就是一大堆原型声明（printf、scanf 的签名）！阶段一说过：include 只是复制粘贴头文件内容。现在你完全理解了那条链： - stdio.h 给编译器看 printf 的原型（声明"有这个东西"）→ 编译阶段通过； - 链接阶段从标准库把 printf 的实现（定义）接进来。

声明说"有"，定义给"实现"——这句话是从函数到多文件工程（阶段八）再到 51 单片机（阶段十）一路通用的总纲。

6. 核心概念四：数组作参数——复印件定理的第一个"例外"

6.1 现象先行

配套 code\阶段三_函数\03_array_param.c，核心逻辑：

void double_all(int arr[], int n)    /* 数组参数：方括号里不写长度！ */
{
    int i;
    for (i = 0; i < n; i++) {
        arr[i] = arr[i] * 2;          /* 函数里直接改！ */
    }
}

int main(void)
{
    int data[3] = {1, 2, 3};
    double_all(data, 3);
    printf("%d %d %d\n", data[0], data[1], data[2]);  /* 2 4 6 —— 真的被改了！ */
    return 0;
}

咦？不是说传值吗？ 数组怎么就被真改了？——因为传给函数的其实是"数组首元素的地址"这个值。复印件定理没有失效：复印的是"地址"，而拿着同一个地址，函数和 main 访问的是同一排内存格子。（地址是什么、为什么拿地址就能改原件——阶段五指针全揭晓。现在请把这条现象牢牢记为："单个变量传复印件，数组传的是地址"。）

6.2 三条立刻要用的规矩

  1. 方括号里不写长度（写了也被忽略）：所以数组参数必须搭配一个长度参数 int n——double_all(data, 3) 里的 3 就是干这个的。C 语言里函数无法自己知道数组多长（这是 C 的现实，记住就好）。
  2. main 里必须记长度：sizeof(data)/sizeof(data[0]) 可以算出数组元素个数（只在定义数组的那一层作用域里有效，传给函数后失效——03 示例里有演示）。
  3. 函数内越界无护栏：传 n=10 但数组只有 3 格，函数会欢快地写坏第 4~10 格内存。调用者对长度负责——这条纪律会保护你到阶段九动态内存。

6.3 这跟任务三有什么关系？——任务三的 result 数组正是靠它

任务三要求 equation(5, 2, -1, result)：把根从函数里"带出来"。普通 int 返回值一次只能带一个数，而方程有两根——所以用 result[0]、result[1] 数组装两根，靠"数组参数传地址"的特性，函数内的写入直接落到 main 的 result 数组上。函数返回值只用来报告"有没有解"（1/0）。

一次函数调用，两条信息通道：返回值报状态，数组参数带数据——这是 C 程序几十年的经典设计模式，任务三就是你第一次亲手实现它。

7. 核心概念五：作用域、生命周期与命名规范

7.1 局部变量的一生

int max3(int a, int b, int c)   /* a,b,c 和函数体里定义的 m 全是局部变量 */
{
    int m = a;                  /* m 出生于这一行 */
    ...
    return m;                   /* return 一执行，a,b,c,m 全部"死亡"，内存格子归还 */
}
  • 作用域（名字在哪可见）：从定义处到所在 {} 结束；
  • 生命周期（内存何时存在）：函数返回即销毁。
  • 推论：两个函数里的同名变量互不相干（各是各的复印件）；main 里的 int ret 和 max3 里的 int m 互不干扰。

7.2 全局变量初见（但立一条规矩）

定义在所有函数之外的变量叫全局变量，全程存活、所有函数可见。先知道存在即可；本计划立规矩：任务三到考核一律不用全局变量——它是"谁都能改的公共黑板"，滥用会让程序失控，而考核看重的恰恰是"数据通过参数和返回值有序流动"的功力。

7.3 命名规范（考核显性要求，现在开始练）

对象 规则 例子
函数名 动词或动宾，小写+下划线 is_prime、count_digits、swap_students
普通变量 名词，小写+下划线 digit、total、first_root
布尔型语义（0/1） 以 is/has/can 开头 is_valid、has_solution
常量 全大写 #define MAX_LEN 50 或 const int MAX_LEN = 50;
杜绝 单字母 a、b、t 只允许出现在 swap 这种"交换"场景

9. 扩展视野：递归初见（看懂即可，暂不强制掌握）

函数可以调用自己，这叫递归。看一个最小的例子：

void countdown(int n)
{
    if (n == 0) {                 /* 出口：没有它就永远递归下去（栈溢出崩溃） */
        printf("发射！\n");
        return;
    }
    printf("%d\n", n);
    countdown(n - 1);             /* 自己调用自己，规模变小 */
}

countdown(3) 打印 3 2 1 发射！——效果和循环一样。递归的每一层调用都有自己独立的 n（又是复印件定理！每层调用的 n=3、2、1 是三份不同的复印件）。递归在树、图等结构里有循环替代不了的价值，51 单片机的菜单程序里也常见。现在只求看懂，阶段九再练手写；本阶段所有任务用循环完成。

11.5 零基础补充：把函数讲到能给别人讲明白

11.5.1 函数调用的完整生命周期（一张时序图）

以你的 8_函数_3.c 为例：

int max3(int a, int b, int c) {   /* 定义：一张可重复使用的图纸 */
    int m = a;
    if (b > m) m = b;
    if (c > m) m = c;
    return m;
}

int main(void) {
    printf("%d\n", max3(3, 7, 5));   /* 调用：按图纸开工一次 */
    return 0;
}

执行顺序（这四步是所有函数问题的总纲）：

main 第 N 行：计算实参 3、7、5
   ↓  复制到形参 a、b、c（此时 main 暂停）
max3 函数体逐句执行，局部变量 m 出现
   ↓  return m; 把 m 的值（7）拷贝出来
max3 的 a/b/c/m 全部销毁，控制权还给 main
   ↓
printf 收到 7，打印

关键认知：形参和实参是两套不同的内存。 在 max3 里把 a 改成 999，main 里的 3 毫无变化——这就是阶段二说的「赋值是复制」在函数上的延续。阶段五的指针，才是绕过这条规则的正道。

11.5.2 函数设计的五问（写每个函数前在纸上过一遍）

# 问题 反面教材
1 它只做一件事吗？名字能概括吗？ do_all() 既读输入又算又打印
2 需要几个参数？每个参数是输入还是输出？ 用返回值当输出，却还想改调用者的变量
3 返回值类型是什么？void 是不是更合适？ int 返回值从没人接过
4 出错时怎么办？（return 0/1 表示成败） 输入非法也照样往下算
5 这个名字会不会和库函数撞车？ 自己写个 sqrt()

命名规范：动词开头表示动作（fill_squares、print_menu），is_ / has_ 开头表示判断（is_leap_year），名词表示取数据（count_digits）。全小写 + 下划线，见名知意。

11.5.3 函数原型 vs 定义 vs 调用（三者的分工）

原型（.h 里）   int max3(int a, int b, int c);     ← 目录：编译器只看这个
定义（.c 里）   int max3(int a, int b, int c) { … } ← 正文：链接器要这个
调用（任意处）  max3(3, 7, 5)                       ← 使用：只关心返回值

原型和定义只差一个分号。参数名在原型里可以省略（int max3(int, int, int); 合法但可读性差），写上更好。

11.5.4 值传递 / 数组参数 / 返回指针：一张对照表

场景 写法 函数内能改调用者的数据吗 什么时候用
传值 f(int x) ❌ 不能 只需要读这个值
传数组 f(int a[], int n) ✅ 能 要改一批数据（任务三）
传指针 f(int *p) ✅ 能 要改单个值 / 可选参数（阶段五）
返回值 int f(void) — 只有一个结果
传出参数 f(int *out) ✅ 能 要返回多个结果

数组作参数的真相：void f(int a[]) 等价于 void f(int *a)。传进去的不是整个数组的复印件，而是「首元素的地址」。所以函数内 a[i] = 0 改的是调用者的真数组——这也是为什么数组参数必须额外传长度（函数内无法知道数组有多长）。

13.3 专门一节：任务三里"用 char 接 int 返回值"是怎么回事

任务三原文让你用 char a; a = equation(5,2,1,result); 接收 int 函数的返回值。这恰好安全（返回值只有 0/1），但过程发生了隐式转换：int 的值被塞进 1 字节的 char。若函数返回的不是 0/1 而是大数（比如 300），char 只保留低 8 位——结果面目全非。任务这样写是在考你"知不知道转换在发生"。自查：解释为什么 0/1 用 char 接收永远不会错；再写一行代码把 300 硬塞进 unsigned char 并打印，看看得到了什么。
