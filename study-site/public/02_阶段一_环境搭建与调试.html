目标读者：已用 VSCode + MinGW 写过几十个小程序的你自己 预计学时：3~5 天（每天 1~1.5 小时） 本阶段对应的桌面任务：无直接任务，但产出一个 Gitee 仓库——所有任务的"考场" 配套代码：code\阶段一_环境与调试\（3 个 .c 文件）；练习：exercises\阶段一\

1. 本节目标与前置知识

目标： 1. 理解从 xxx.c 到 xxx.exe 中间发生了什么（四步流水线）——这不是理论，是你以后看懂一切报错的总纲。 2. 学会区分并快速消灭三类错误：编译错误（error）、警告（warning）、运行时逻辑错误。 3. 装好并跑通一次断点调试（gdb / VSCode F5），体验"看程序一步一步走"。 4. 注册 Gitee、建仓库、完成第一次提交——把 D:\Programing\C 的历史作业也传上去，这就是你的学习履历。

前置知识： 会打开 VSCode、会按 Ctrl+Shift+B 编译（你已有 tasks.json）、会运行生成的 exe。够了。

2. 场景引入：那次你改了半天，其实编译器早就告诉过你

先讲一个你大概率经历过的场景：

你写完一个循环，按编译，屏幕蹦出一串红字：expected ';' before '}'。你盯着自己的代码看了 20 分钟，觉得每一行都没错。你把括号删了又加，加了又删。最后发现是上一行 printf(...) 少了一个分号——报错位置在下一行。

这个场景背后的规律是：你缺的不是智商，是对"编译器在哪个阶段、按什么方式看你代码"的理解。今天这一节，就是把你和编译器之间的关系从"玄学"变成"流程"。理解了流程，报错信息就从"天书"变成"路标"。

3. 核心概念一：四步流水线——源文件如何变成可执行文件

3.1 为什么需要知道这个

你目前的体感是"按一下编译，出个 exe"。但你即将面对任务三（函数）、阶段八（多文件工程），那时报错会开始出现"undefined reference to xxx"这种链接错误——它发生在流水线的最后一步，而你现在所知的所有报错都发生在前面。不提前搭好认知，到时你会把链接错误当代码错误去改，白费几小时。

3.2 四步拆解（用你的日常命令就能观察）

假设存在 hello.c。完整流程是：

hello.c ──(预处理)──► hello.i ──(编译)──► hello.s ──(汇编)──► hello.o ──(链接)──► hello.exe
  1. 预处理（Preprocessing）：处理所有 # 开头的东西。#include <stdio.h> 就是把 stdio.h 的内容原样复制粘贴进你的文件；#define 做文本替换。产物是 .i（仍然是你看得懂的 C 代码，只是变长了很多）。
  2. 编译（Compilation）：把 C 翻译成汇编代码（.s）。你所有见过的 "expected xxx"、"'a' undeclared" 都发生在这一步——检查语法、检查类型。
  3. 汇编（Assembly）：把汇编变成机器码，产物是目标文件 .o。这步几乎不会出错。
  4. 链接（Linking）：把你的 .o 和标准库（printf 的真正实现在这里）拼在一起，生成 .exe。"undefined reference to 'winmain'"、找不到库的报错在这一步。

你可以在终端里亲手执行一遍（做一遍，别只看）：

# 在 D:\Programing\C 下随便建一个 test_compile.c，内容就一句 printf 的 hello world，然后：
gcc -E test_compile.c -o test_compile.i   # 只预处理，打开 test_compile.i 看看有多长
gcc -S test_compile.i -o test_compile.s   # 只编译到汇编，用文本方式打开 .s 文件看看
gcc -c test_compile.s -o test_compile.o    # 只汇编
gcc test_compile.o -o test_compile.exe    # 只链接
.\test_compile.exe

恍然大悟点：#include <stdio.h> 并没有让编译器"学会 printf"，它只是声明了 printf 长什么样（让编译这步不报错）；printf 的机器码是链接阶段从标准库里接进来的。"声明"和"定义"的分离，就是阶段三函数、阶段八多文件工程的全部秘密。

3.3 顺手验证你的现有认知

  • 你的 2_变量_1.c 没有 #include <stdio.h> 会怎样？（试试：报错发生在编译阶段，且信息是 implicit declaration——即"没声明就使用"）
  • 把 main 写成 mian 会怎样？（链接阶段报 undefined reference to 'main'/winmain——因为链接器找不到入口。记住这条，每年都有大量初学者被它折磨一晚上）

4. 核心概念二：错误三兄弟——error、warning、逻辑错误

4.1 error：编译失败，exe 根本不生成

遇到 error 的正确动作是：从第一条 error 往下看，不是最后一条。因为 C 编译器可能被前面一个缺失的分号"带偏"，后面连出 7 条假错误。修好第一条，重新编译，通常一大串都消失。

4.2 warning：编译"成功"，但程序可能在撒谎

你现在编译从不带参数，GCC 默认几乎不警告。从今天起，请把你的 tasks.json 加上 -Wall -Wextra（args 数组里、"-fdiagnostics-color=always" 后面加两项即可），或者命令行手动编译时写：

gcc -Wall -Wextra -g test_compile.c -o test_compile.exe

-Wall（all warnings 的缩写）会在你的 7_循环_猜数.c 上立刻抓到 P1 问题——类似 "'a' is used uninitialized"。把 warning 当 error 对待是本计划贯穿全程的纪律：考核任务、实验室训练看重的就是这种"确定性代码"的习惯。

4.3 逻辑错误：程序欢快地跑，结果就是不对

你实际写出来过的：7_循环_正序分解.c 里 while (num > 10) 差一个等号。编译器永远不会告诉你这种错。对付它的唯一武器是下一节的调试器 + 系统化的测试意识（阶段二会专门训练）。

5. 核心概念三：第一次断点调试（把程序当慢镜头看）

5.1 为什么你现在就需要它

到今天为止，你调试靠 printf("到这了%d", x)。这招有用，但遇到 100 轮循环里第 87 轮出错时，printf 法会让你打印 87 行垃圾。调试器能让你"暂停在任何一行、看任何变量的当前值、一步一步走"。任务三、四都有复杂计算，考核有 5 次登录循环，迟早用上。

5.2 实操（VSCode，10 分钟搞定）

  1. 你的编译参数已带 -g（tasks.json 里有），这步已经就绪——-g 就是"生成调试信息"。
  2. 打开 code\阶段一_环境与调试\02_bug_hunt.c（本教程配套，内容见下文）。
  3. 在 main 函数第一行行号左侧空白处点一下出现红点 = 断点。
  4. 按 F5（Run → Start Debugging），环境选 C/C++ (GDB)。
  5. 程序停在红点。工具栏四个按钮背下来： - F10 单步跳过（Step Over）：执行当前行，不进入函数内部； - F11 单步进入（Step Into）：进入函数内部（阶段三后高频使用）； - Shift+F11 单步跳出（Step Out）； - F5 继续（Continue）：跑到下一个断点。
  6. 左侧 VARIABLES 面板实时显示每个变量的值——看着它跑，比闭眼 printf 强一个量级。
  7. 把鼠标悬停在代码里的变量名上，也会浮窗显示当前值。

没有图形界面也不慌：MinGW 自带命令行版 gdb。gdb .\xxx.exe，然后 break main、run、next、print 变量名、quit。两套任选，图形版本质就是 gdb 的皮肤。

6. 示例代码（本阶段配套，共 3 个，逐个跑）

6.1 01_hello_env.c —— 环境自检与版本信息

场景：以后你写的每个程序都该有个"开机自检"的意识——确认环境没变、类型大小没记错。这个程序顺便回答"不同电脑上 int 多大"这个千古问题。

/* 01_hello_env.c —— 阶段一：环境自检
 * 编译：gcc -Wall -Wextra -g 01_hello_env.c -o 01_hello_env.exe
 * 作用：打印编译器版本与常用类型大小，建立"sizeof"的第一印象
 */
#include <stdio.h>

int main(void)
{
    printf("=== 我的环境自检 ===\n");
    printf("sizeof(char)  = %zu 字节\n", sizeof(char));   /* 恒为1 */
    printf("sizeof(short) = %zu 字节\n", sizeof(short));
    printf("sizeof(int)   = %zu 字节\n", sizeof(int));     /* 你机器上大概率是4 */
    printf("sizeof(long)  = %zu 字节\n", sizeof(long));    /* Windows 64位下是4，Linux 下是8 */
    printf("sizeof(double)= %zu 字节\n", sizeof(double));
    printf("\n__STDC_VERSION__ = %ld (199901=C99, 201112=C11)\n", __STDC_VERSION__);
    return 0;
}

预期输出（你的机器典型值）：int=4、double=8、标准版本 201112 或更高。注意 %zu 是 sizeof 的专用占位符——记不住没关系，现在先有个印象，阶段二正式讲。

6.2 02_bug_hunt.c —— 抓虫练习（本阶段的主菜）

场景：下面这段代码是"三个经典事故的集合"，全部改编自你自己的真实提交（没错，就是 正序分解 和 猜数）。它能编译，也可能"看起来能跑"。你的任务：先纸上找出 3 个 bug，再编译运行验证，最后用 F10 单步观察变量值的变化过程。

/* 02_bug_hunt.c —— 阶段一：抓虫练习
 * 任务：找出并修复 3 处问题（先用眼看+纸上推演，再用 gdb/断点验证）
 * 提示：3 个 bug 全部在你自己过去两周的代码里出现过。
 */
#include <stdio.h>
#include <stdlib.h>

int main(void)
{
    /* 【题目】把一个正整数的各位数字倒过来打印。
     * 输入 12345 应输出 "5 4 3 2 1"（空格分隔）
     */

    int num;
    int ret = 0;              /* ← 修改点提示之一：这里的初始化是有讲究的 */

    printf("请输入一个正整数：");
    scanf("%d", &num);

    while (num > 0) {         /* ← 想想：这里用 > 还是 >= ？和你的正序分解是同一类问题 */
        int digit = num % 10; /* 取出最后一位 */
        ret = ret * 10 + digit;
        num = num / 10;
    }

    /* 现在 ret 是 num 的倒序数，例如 12345 -> 54321 */
    while (ret > 0) {
        printf("%d ", ret % 10);
        ret = ret / 10;
    }
    printf("\n");

    return 0;
}

纸上推演示范（请模仿这个格式做练习 2）：输入 120 → 循环三轮得 ret = 0*10+0=0？不对：第一轮 digit=0，ret=0；第二轮 digit=2，ret=2；第三轮 digit=1，ret=21。于是打印 "1 2 0 "。诶？尾部的 0 打出来了吗？ 请自己走一遍第二个 while，想清楚 120 倒序打印到底是什么——这个"末尾 0"坑就是练习 3 的素材。

10. 本阶段复盘与下一阶段衔接

复盘三个问题（写进打卡表）： 1. 以前你面对报错的情绪是"烦"，现在你能不能把报错分到四个流水线阶段中去？——这就是本阶段最大的认知升级。 2. warning 你以前根本不看，现在明白为什么必须看吗？ 3. 调试器第一次让你"看见"变量在循环里的变化，哪个瞬间让你有"原来如此"感？
