2. 场景引入：13! 的真相——int 是个固定宽度的格子

阶段三你做过阶乘实验：12! 还好好的（479001600），13! 却打印出一个莫名其妙的怪数。当时留下的悬念，现在揭晓——

int 在你的机器上是 4 字节 = 32 个比特，最多能装 2147483647。而 13! = 6227020800，比它大。会发生什么？不是报错，不是警告，而是装不下的高位比特被直接丢弃，剩下的低位比特组成一个怪数。就像往 8 格的盒子里塞 10 个球——多出来的 2 个掉在地上，盒子一声不吭。

把视角放大：C 语言的每种类型都是固定宽度的格子。char 是 8 比特的小格，short 是 16 比特，int 是 32 比特，long long 是 64 比特。阶段一到阶段六你一直在用这些格子，但从今天起，你要能看见格子里的每一个比特——这就是位运算。

为什么非要看见比特？ 因为这是嵌入式世界的母语。51 单片机里，点亮流水灯写的是 P1 = 0xFE（P1 端口的 8 个引脚各对应 1 个比特，0xFE = 11111110，最低位置 0 点亮第一盏）；数码管的段码表是 8 个比特控制 8 段灯管；配置寄存器就是"把某几位置 1、某几位清 0"。本阶段的每一节都在为阶段十的 51 预备课打地基——任务七（8/16/32 位数据的存取转换）正是这个思维的第一次实战。

3. 核心概念一：整型家族宽度——sizeof 与 limits.h 现场查证

3.1 家谱

类型 你的机器上 C 标准只保证
char 1 字节（8 比特） 恰好 1 字节
short 2 字节 至少 16 比特
int 4 字节 至少 16 比特
long 4 字节（Windows 特色！64 位 Linux 上是 8） 至少 32 比特
long long 8 字节 至少 64 比特

注意 long 这一行——「long 一定比 int 长」是流传最广的错觉之一。在 Windows（含 64 位）上 long 和 int 一样都是 4 字节。所以教程从此不背"宽度表"，而是教你两个现场查证的工具：

sizeof(int);          /* 编译期求出类型的字节数，不是函数，是运算符 */
printf("%d\n", INT_MAX);   /* <limits.h> 里的极值宏：INT_MAX、INT_MIN、UINT_MAX、
                              CHAR_MAX、SHRT_MAX、LLONG_MAX…… */

配套 01_type_sizes.c 把这些全部打印出来。跑之前先预测每行的值，再对答案——尤其预测一下 UINT_MAX 和 LLONG_MAX。

3.2 有符号格子的容量怎么算

n 比特的有符号格子：1 比特当符号位，剩 n-1 比特表数值，范围是 −2^(n−1) ~ 2^(n−1)−1。 - 32 位 int：−2^31 ~ 2^31−1 = −2147483648 ~ 2147483647（INT_MAX 就是 2^31−1）； - 8 位 char：−128 ~ 127（CHAR_MAX=127）。

n 比特的无符号格子：全部 n 比特表数值，0 ~ 2^n−1。 - 32 位 unsigned：0 ~ 4294967295（UINT_MAX）； - 8 位 unsigned char：0 ~ 255。

一句话：有符号用一半地盘装负数；无符号把全部地盘给非负数，天花板高一倍。

4. 核心概念二：stdint.h 定宽类型——「说几比特就几比特」

上一节的坏消息：int 的宽度因平台而异（标准只说"至少 16 位"）。写普通程序无所谓，但做嵌入式、读写文件格式、网络协议时，"这个字段到底几比特"是生死问题。于是 C99 给了 <stdint.h>：

类型 含义
uint8_t / int8_t 恰好 8 比特，无符号 / 有符号
uint16_t / int16_t 恰好 16 比特
uint32_t / int32_t 恰好 32 比特
uint64_t / int64_t 恰好 64 比特

任务七说的「8 位、16 位、32 位数据」就是 uint8_t、uint16_t、uint32_t——名字里直接刻着宽度，没有任何平台歧义。51 单片机代码里满屏的 uint8_t（别名 u8、BYTE），你从现在起就要眼熟。

配套麻烦：打印它们。%d/%u 是为 int/unsigned int 设计的， uint32_t 在某些平台是 unsigned long，写死 %u 换个平台就错。C99 的解法是 <inttypes.h> 的格式化宏：

#include <inttypes.h>
uint32_t x = 4294967295u;
printf("%" PRIu32 "\n", x);    /* 打印 uint32_t 的无符号十进制 */
printf("%" PRIx32 "\n", x);    /* 十六进制版：PRIx32 */
printf("%" PRId32 "\n", (int32_t)-5);  /* 有符号 int32_t：PRId32 */

%" PRIu32 " 这种写法看着怪——其实 PRIu32 展开是一个字符串（你的平台上是 "u"），C 语言里相邻字符串字面量会自动拼接，所以 "%" "u" "\n" 拼成了 "%u\n"。宏帮你挑对了当前平台的格式符，这就是它的全部使命。还有 8/16/64 位版本：PRIu8、PRIu16、PRIu64，规律相同。

5. 核心概念三：signed vs unsigned——回绕的两种命运

5.1 无符号回绕：里程表效应（良定义）

无符号整数像一个 N 位的里程表：加到天花板再 +1，转回 0；从 0 再 −1，转到最大值。

uint8_t u = 255;
u = (uint8_t)(u + 1);   /* 256 装不进 8 位，只留低 8 位 -> 0 */
uint8_t z = 0;
z = (uint8_t)(z - 1);   /* 0-1 向下回绕 -> 255 */

这不是 bug，是写进标准的行为：无符号运算永远按「模 2^N」进行。数学上，uint8_t 世界里的一切结果都对 256 取余。配套 02_wrap_and_convert.c 实验一现场演示。

5.2 有符号溢出：未定义行为（UB）——雷区，不是实验田

int x = INT_MAX;
x = x + 1;    /* 未定义行为！标准不保证任何结果 */

有符号溢出时，标准什么都不保证：可能回绕成负数，可能被编译器优化得面目全非（编译器有权假设"有符号运算永不溢出"来优化你的代码，一旦你真的溢出，推理全部失效）。对照记牢：

unsigned 回绕 signed 溢出
性质 良定义（模 2^N） 未定义行为（UB）
能不能故意用 能（哈希、回绕计数都用它） 永远不能
类比 里程表转圈 脱离剧本

所以纪律是：可能溢出的有符号计算，先换更大的类型（long long）再算——这正是阶段三 13! 的正确解法。

6. 核心概念四：类型转换规则——提升、陷阱与截断

6.1 整型提升：小格子先变大再运算

uint8_t a = 200, b = 100; a + b 的实际过程：a、b 先被提升成 int 再相加（结果 300 是 int）。所以 a + b 本身不会丢——丢失发生在"存回小格子"那一刻：uint8_t c = a + b; → 300 塞回 8 位 → 44。配套 02、03 两个示例都反复演示"int 层面没丢 / 存回格子才丢"这个二分法，它是理解一切截断的钥匙。

6.2 隐式转换的著名陷阱：int 遇上 unsigned

规则：int 与 unsigned int 混合运算/比较时，int 被悄悄转成 unsigned。于是：

int i = -1;
unsigned w = 1;
if (i > w) { ... }    /* 成立！-1 被转成 4294967295，当然"大于"1 */

-1 > 1u 为真——无数程序员栽在这里（比如 i < strlen(s)-1 当串为空时 strlen 返回 0，0−1 回绕成巨大无符号数）。防御：先判负数再比较，或让两边类型一致。配套 02_wrap_and_convert.c 实验三用显式强转把"编译器偷偷做的事"摆到明面上给你看。

6.3 显式强转截断：只留低位（任务七的数学原理）

大格子塞进小格子，规则朴素得残酷：高位砍掉，只留低位。数学解释就是取余：

uint32_t big = 0x12345678;          /* = 305419896 */
uint16_t mid = (uint16_t)big;       /* = big % 65536 = 0x5678 = 22136 */
uint8_t  low = (uint8_t)big;        /* = big % 256   = 0x78   = 120   */

为什么截断 = 取余？二进制视角：uint32 是 32 个比特，uint8 只留最低 8 个比特，等价于十进制里"只留末两位"（12345 → 45 = 12345 % 100）。逐级截断与一步到位结果相同：先截到 16 位再截到 8 位，等于直接截到 8 位（02 示例的 low 与 low2 对照）。

历史呼应：你阶段二踩过的坑——pow(10, n) 是 double，赋值给 int 时浮点截断把 99.999… 砍成 99。那是小数部分截断；这里是高位比特截断。同一个家族：C 的隐式/显式转换从不舍入、从不报错，只会"砍"。看到强转就要条件反射地问：砍掉的 part 我丢得起吗？

7. 核心概念五：十六进制与二进制——比特世界的速记

7.1 为什么用十六进制

二进制是比特的真身，但 32 个 0/1 没人读得动。十六进制是每 4 个比特的速记：0x12345678 一眼能拆成 8 组 4 比特。C 里写法：

uint32_t x = 0x12345678;   /* 0x 前缀 = 十六进制字面量 */
printf("%X\n", x);         /* 大写十六进制打印：12345678 */
printf("%08X\n", x);       /* 补零到 8 位宽 */
printf("%02X\n", 120);     /* 补零到 2 位宽：78 —— 打印单个字节的标配 */

%02X 的 02 是"不足 2 位补 0"——观察字节时 0x0A 打成 0A 而不是 A，排版才齐。

7.2 0~15 心算表（本阶段必背，验收要抽查）

十进制 十六进制 二进制 十进制 十六进制 二进制
0 0 0000 8 8 1000
1 1 0001 9 9 1001
2 2 0010 10 A 1010
3 3 0011 11 B 1011
4 4 0100 12 C 1100
5 5 0101 13 D 1101
6 6 0110 14 E 1110
7 7 0111 15 F 1111

记忆锚点：8=1000（2^3），F=1111（全 1），A=1010（8+2），C=1100（8+4）。背熟后，0xFE = 1111 1110 就是张口就来——这就是 51 流水灯 P1 = 0xFE 能一眼看懂的前提。

8. 核心概念六：位运算六运算符与掩码四操作

8.1 六个运算符真值表（对每一对比特独立作用）

运算符 名字 规则 示例（取一对比特）
& 按位与 都是 1 才是 1 1&1=1，其余=0
\| 按位或 有一个 1 就是 1 0|0=0，其余=1
^ 按位异或 不同才是 1 1^1=0，1^0=1
~ 按位取反 0↔1 全翻（单目，连符号位一起翻） ~1=0
<< 左移 全体左移，低位补 0，高位丢出格子 —
>> 右移 全体右移，低位丢弃；unsigned 高位补 0 —

配套 03_bitwise_ops.c 用 a=12（00001100）、b=10（00001010）逐个演示，并配 print_bin8 把结果打成二进制——这个辅助函数值得你抄进自己的工具箱，观察位运算没有比这更顺手的。

8.2 掩码思想：一个整数 = 一排开关

把整数的每一位看成一个开关（1=开，0=关），一个 unsigned flags 就是 32 个开关。操作某一个开关的标准写法（MASK 是"只有目标位为 1"的数，如 1 << 2）：

flags & MASK      /* 取位/查询：结果非 0 = 该位是 1 */
flags |= MASK;    /* 置位：该位变 1，其他位不动 */
flags &= ~MASK;   /* 清位：该位变 0（~MASK 是「除了该位全 1」），其他位不动 */
flags ^= MASK;    /* 翻转：该位 0→1、1→0，其他位不动 */

逐个理解一次，终身受益： - 查询 flags & MASK：& 的规则是"都是 1 才是 1"——MASK 里只有目标位是 1，所以结果只可能保留目标位；目标位是 1 则结果非 0。 - 置位 |=：| 的规则是"有 1 就是 1"——目标位被强制 1，其他位和 0 做 | 保持原样。 - 清位 &= ~MASK：~MASK 只有目标位是 0——目标位和 0 做 & 强制归 0，其他位和 1 做 & 保持原样。 - 翻转 ^=：^ 的规则是"不同才是 1"——目标位和 1 异或必翻转，其他位和 0 异或保持原样。

配套 04_mask_flags.c 是完整小例：类 Unix 权限系统（r/w/x 各占一位），置位、清位、查询、翻转走一遍。这套写法就是 51 寄存器操作的原型——P1 |= 0x01（点亮某灯）、P1 &= ~0x01（熄灭某灯）到时候一行都不用新学。

9. 核心概念七：移位与乘除 2 的幂

  • 左移 n 位 ≈ 乘 2^n：a << 1 = a×2，a << 3 = a×8（二进制全体左移，低位补 0）；
  • 右移 n 位 ≈ 除 2^n（整数除法，舍去小数）：a >> 1 = a/2——对 unsigned 总是成立。

但左移会溢出：uint8_t big = 200; big << 1 在 int 层面是 400，存回 8 位格子只剩 144（400−256，高位被丢）。03 示例末尾现场演示。两个推论： 1. 用移位当乘法用时，先确认格子的宽度装得下结果； 2. 移位位数不能超过类型宽度（对 32 位类型移 32 位是未定义行为，见 §16）。

优先级警告（本阶段最容易丢分的语法点，先亮黄牌，§16 再立铁律）：== 的优先级高于 &！if (flags & MASK == 0) 被解析成 flags & (MASK == 0)——先算 MASK == 0 得 0，再 flags & 0 恒为 0，逻辑全错。位运算混进判断时，一律加括号：if ((flags & MASK) == 0)。

10. 核心概念八：大小端——多字节数据在内存里怎么排队

一个 uint32_t x = 0x12345678 占 4 个字节。问题：0x12 和 0x78 谁住低地址？两种排法：

大端（big-endian）：   低地址 [12] [34] [56] [78] 高地址   像人读数：高位在前
小端（little-endian）： 低地址 [78] [56] [34] [12] 高地址   像倒着放：低位在前
  • x86/Intel（你的电脑）是小端；
  • 网络协议字节序是大端；
  • 51 单片机（8051）的多字节寄存器场景也会撞上端序问题。

怎么亲眼看见？ 用阶段五的指针功夫：把 uint32_t 的地址强转成 unsigned char *，就能一个字节一个字节地读：

uint32_t x = 0x12345678;
unsigned char *p = (unsigned char *)&x;   /* 把 4 字节整数当作 4 个单字节来读 */
printf("%02X\n", p[0]);                    /* 小端机器打印 78 */

配套 05_endian_union.c 完整演示并自动判定你的电脑是小端。unsigned char 是 C 里唯一被标准允许"逐字节查看任何对象"的类型——这是它的特权，记进笔记。

11. 核心概念九：union 观察字节——阶段六伏笔回收

阶段六学过 union：所有成员共用同一块内存。当时问"有什么用"——答案之一就是端序观察：

union {
    uint32_t u32;      /* 看作一个 32 位整数 */
    uint8_t  b[4];     /* 同一块内存，看作 4 个字节 */
} u;
u.u32 = 0x12345678;
printf("%02X\n", u.b[0]);   /* 小端打印 78——和指针法结果一致 */

写 u32 成员、读 b 成员——同一片内存换一副眼镜看。05 示例把指针法与 union 法并排跑，两种方法看到同样的 78 56 34 12，互相印证。

12. 核心概念十：浮点 IEEE754 概念级——0.1+0.2 的终极解释

阶段二你亲眼见过 0.1 + 0.2 != 0.3。当时只说"浮点有误差"，现在给终极解释（只到概念级，不深讲）：

float/double 在内存里也是固定宽度的格子，分成三段：

部分 float（32 位） double（64 位） 作用
符号 S 1 位 1 位 正负
指数 E 8 位 11 位 决定数量级（能装多大/多小）
尾数 M 23 位 52 位 决定精度（有多少位有效数字）

值 ≈ (−1)^S × 1.M × 2^(E−偏移)。关键：尾数是二进制的——0.1、0.2 在二进制里是无限循环小数（就像 1/3 在十进制里），23/52 位尾数根本装不下，只能存一个"非常接近的值"。两个近似值相加，结果约等于 0.30000000000000004，自然不等于 0.3。

由此三条推论永久有效： 1. 浮点永不用 == 比相等——用 fabs(a-b) < 1e-9 比"够不够接近"； 2. 精度要求高的场景（钱）用整数（存"分"不存"元"）； 3. 浮点转整型是截断（阶段二 pow 教训）——它不是四舍五入。

16. 安全与规范：本阶段四条铁律

  1. 位运算与比较/判断混写时一律加括号——==、!=、> 的优先级都高于 & | ^；~ 和 <<、>> 也各有坑。宁可多写括号，不背优先级表；
  2. 位操作只作用在 unsigned 系类型上——signed 右移高位补 0 还是补 1 是"实现定义"，signed 溢出是 UB；要玩比特就用 uint8_t/uint16_t/uint32_t；
  3. 移位量必须满足 0 ≤ n < 位宽——对 32 位类型移 32 位及以上是未定义行为；
  4. 任何收窄转换（大格子→小格子）必须显式强转并自问：高位丢得起吗——丢得起才截，丢不起先换类型或先检查范围。

17.2 数学/原理提示（可教，且只教到这一层）

  • 截断 = 取低位 = 取余：uint32 值 v 转 uint16 后恒等于 v % 65536，转 uint8 后恒等于 v % 256。写完程序用这个恒等式自我对拍——输出不满足它，一定哪里错了；
  • 注意溢出回绕：输入超过目标宽度时不是"报错"而是"回绕/截断"——设计测试数据时，故意选一组超过 8 位（>255）和超过 16 位（>65535）的输入，观察并能在报告里解释输出为什么是这个数；
  • 逐级转换与一步到位：32→16→8 连转的结果应等于 32→8 直接转，两组都打印出来对比，是现成的自查点；
  • 打印格式正确性：32 位用 PRIu32/%u 系，16/8 位变量会被整型提升成 int，%u/%d 要小心符号——无符号类型配无符号格式符；想看清位模式就 %02X/%04X/%08X 按宽度补零。
