本尊一开始觉得，写程序嘛，把想算的东西放进去，再 `printf` 出来就好了。然后就被 `3 / 4` 教做人了。

```c
#include <stdio.h>

int main() {
    printf("算式在C语言里的结果是%d\n", 1 + 2 - 3 / 4 * 5);
    printf("算式在C语言里的结果是%d\n", 10 % 3);
    printf("算式在C语言里的结果是%d\n", 10 % -3);
    return 0;
}
```

本尊当时还在注释里特地写了“不等于 -0.75，而是 3”。两个整数相除，小数部分就这么没了；`3 / 4` 先变成 `0`，后面的乘法也跟着算。算式看上去没问题，结果完全不是脑子里那个结果。行吧，至少现在知道要先看变量是什么类型了。

## `printf` 里一个 `%` 也能有这么多事

变量刚开始就是赋值、打印。后来本尊把格式符挨个试了一遍：整数、小数、字符、字符串、地址，还有补零、左对齐、十六进制。代码很短，输出倒是一大串。

```c
int a = 100;
double b = 3.14159;
char c = 'A';
char s[] = "hello";

printf("%d\n", a);
printf("%05d\n", a);
printf("%x\n", a);
printf("%.2f\n", b);
printf("%c\n", c);
printf("%s\n", s);
printf("%p\n", (void *)&a);
```

同一个 `char` 用 `%d` 和 `%c` 打印，出来的东西不一样。不是它突然变身，是本尊给它选了不同的显示方式。`printf` 这位看着挺老实，格式字符串写错了可不会替你猜。

## 条件题写着写着，电梯楼层全乱了

开始写 `if` 之后，练习题就从“打印一个数”变成了“让程序选一条路”。判断流量够不够、商品价格在哪档、会员能打几折；后来又碰到 `switch`，拿楼层做了个小例子。

本尊的楼层代码里有一段现在看着很想删掉重写：

```c
case 3:
    printf("电梯到达3楼\n");
    break;
case 4:
    printf("电梯到达3楼\n");
    break;
case 5:
    printf("电梯到达3楼\n");
    break;
```

4 楼和 5 楼也到 3 楼，电梯业务挺忙，楼层倒是很专一。复制粘贴之后没把数字改掉，这种错不是什么高深问题，但确实很容易漏。`break` 也不能忘，不然选完一个 `case` 还会接着往下走。写这些的时候，本尊脑子里想的是“选中了就结束”，C：你没写，我怎么知道喵~

逻辑运算符也一起练了，`&&` 是同时满足，`||` 是满足其中一个，闰年那题把括号和优先级摆进去以后，看起来像一串密码。拆开看就还好，挤在一行里就开始怀疑自己。

## 终于能自己输入了

之前的值都写死在程序里，改一个数还得回去改代码。学了 `scanf`，就可以从键盘把整数交给程序：

```c
#include <stdio.h>

int main() {
    int a;
    scanf("%d", &a);
    printf("a=%d\n", a);
}
```

这里的 `&a` 不能少，`scanf` 得知道要把读到的值放到哪。后面我又把商品类别和价格一起读进来，再交给 `switch` 和 `if` 算折扣。格式字符串里的逗号也得和输入对上，空格、逗号这种小东西，错开了程序就不按我想的来。

## 现在是循环

`for` 先拿来从 1 打印到 10：

```c
for (int i = 1; i <= 10; i += 1) {
    printf("%d\n", i);
}
```

然后本尊又写了 `while` 和 `do while`，一边累加 1 到 100 的偶数，一边重复打印数字。两种循环差在检查条件的时机：`while` 先看要不要做，`do while` 是先做一次再看。光看这一句有点像绕口令，自己把两种都敲出来就好记一点。

```c
int i = 0;
while (i <= 10)
{
    printf("%d\n", i);
    i += 1;
}

int z = 1;
do
{
    printf("%d\n", z);
    z += 1;
} while (z <= 10);
```

循环变量要记得改。少写一行递增，程序就可能一直在原地转圈。写到这里，本尊已经开始理解为什么大家说括号和分号很重要了——它们平时安静得像背景板，真少一个就立刻出来找存在感。

C 还没学完，循环也只是刚摸到。现在能做的是把课上碰到的东西写成小程序，再看输出有没有跑偏。错了就回去找，找不到就多看几遍（报错有时候比我还会说废话）。
